## 3. 建议分成两个独立增量

### A：消费入口与既有物理交互接入

不引入新物理算法。默认仍生成一只团子，本地验证允许添加至三只，不增加账号、好友或同步语义。接入移动、下压、跳跃、拖动/释放、接地恢复、显示/隐藏、重置、退出；两种宿主分别验收。

### B：完整生命感动作闭环

补齐待机/自主移动、接近岛、爬岛、岛上活动、下岛、点击、抚摸与中断优先级。必须先完成独立动作设计及必要的物理接口扩展设计，再编写实施计划和代码。A 通过不能代替 B；A 的三体通过也不能代替单团子完整动作清单。

## 4. A 的接入契约（建议）

### 所有权、帧与标识

- 一个桌面场景拥有一个 `DangoPhysicsWorld`，由创建它的 UI 线程操作和释放。Window/WorkerW 仅消费同一个场景，不分别创建或推进世界。
- runtime 保存业务实体与 `DangoEntityId` 的显式映射；渲染、输入、移除均按稳定 ID，不把数组下标当实体。
- 每只实体保存一个显示适配器。移除仅销毁该实体，不重建幸存者；最后一只的移除在桌面层拒绝。第四只明确拒绝并向控制中心返回真实结果。
- 选中实体接受键盘输入；拖动命中实体成为操作目标。删除选中实体后回到最早存活实体，清空旧输入，不把持续按键或拖动转交给另一只。
- 场景时钟每固定步只调用一次 world.Step，提交全部存活 ID；显示回调不得再推进。保留 native 960 Hz 小步及版本 1 默认值。

### 坐标与宿主迁移

- 保持物理世界 X 向右、Y 向上；桌面适配完成 DIP/世界的双向映射，DPI 不进入物理解算。
- 以固定场景参考原点和组件尺度转换位置及拖动目标；宿主平移改变显示变换，不改变物理锚点或每帧重建世界。
- 保留既有轮廓归一化和二次 B 样条；不得靠缩放单只身体或移动碰撞轮廓掩盖间隙。
- 切换宿主、重复 Show/Loaded、改变 DPI/窗口尺寸必须验证不会重复推进、跳回出生点、错位抓取或产生第二个世界。跨屏可见范围策略继续沿用已有宿主约定；若实际约定与单一固定地面冲突，暂停相关切换并补设计，不能偷偷传送身体。

### 输入、暂停与故障

- 水平/下压映射现有方向输入；跳跃按上升沿提交，冷却仍由模块管理。不改速度、力、接触顺序或三体支撑选择规则。
- 拖动使用命中点的世界坐标。捕获失败、失焦、Esc、宿主隐藏、切换和关闭都取消拖动并清空按键。
- 隐藏暂停步进，恢复不补算隐藏期间积压时间；正常暂停不重建世界、不清除故障锁存。
- 运行故障保留最后安全帧并停止普通输入；显示可识别错误，允许显式重置或退出。缺库/错误 ABI 必须报告模块不可用，不能静默回到旧物理并显示成功。
- 重置保留当前存活 ID 和出生锚点，不恢复已删除实体。控制中心文案须说明此语义；“重新生成整个场景”若保留为另一操作，必须与模块 Reset 区分。
- 参数面板不能把旧预设自动写入已验收默认配置。动态调参不属于 A 的手感一致性验收；模块当前没有原地更新配置 API，不能伪装成无损热更新。接入前须确定面板在运行中只读或显式重建的产品行为。

## 5. B 必须先补完的动作设计

| 路径 | 必须明确的语义与证据 |
|---|---|
| 待机 → 自主移动 → 待机 | 调度触发、确定性种子、目的地与屏幕边界；只提交移动意图，不双重积分位置 |
| 接近岛 → 爬岛 → 岛上 | 岛的真实支撑几何、攀爬受力/约束、起止条件、失败回落；不能直接移动视觉位置冒充承重 |
| 岛上 → 下岛 → 下落 → 落地 | 离开支撑条件、碰撞事件来源、落地去抖、岛移动/消失后的结果 |
| 点击 → 反应 → 恢复 | 与拖动的阈值和互斥、反应时长、是否施力、腾空时是否允许 |
| 抚摸 → 反应 → 恢复 | 识别方式、采样节流、进出阈值、与拖动竞争、退出与失焦取消 |
| 任意动作 → 拖动/隐藏/退出/故障 | 每个状态的允许与拒绝转换、取消后返回状态、资源和输入清理 |
| 降低动画 | 减少表现与刷新成本但不改变物理动作结果；不能因此销毁世界或恢复旧算法 |

动作设计还须逐项指定 Core、物理模块、宿主、显示层的职责及真实接口；接地/支撑信息不足时先扩展只读反馈契约。Core 负责动作许可和流程，物理负责真实位姿/接触，显示不能反向裁定落地。

重要取舍：不采用纯视觉搬运爬岛，因为它绕过真实支撑；也不直接把旧 Core 位置轨迹叠加到新物理位移。推荐先设计岛静态支撑与受控攀爬，但具体接口、力学方案及中断矩阵尚未批准，不在 A 内实现。

## 6. A 的实施顺序与验收

1. 记录旧 DLL、新模块及对照产物哈希；隔离桌面输出目录，确认构建不会执行旧 native 覆盖脚本。
2. 在 `tests/Dango.Desktop.Tests/Rendering` 新增 runtime 行为测试：当前单体锁定实现必须在添加第二/三只、按 ID 操作、移除保持幸存者轨迹等用例失败。保留失败证据后再迁移旧单体锁定断言。
3. 在 `Physics/Presentation` 建立模块场景适配，`StackedDangoSceneRuntime` 消费它；复用现有视觉适配，不复制物理公式。
4. 调整 Window/WorkerW 输入目标、帧路由和控制中心数量/错误反馈。逐个检查既有 dirty 文件的重叠，保留无关内容。
5. 新 DLL 仅复制到隔离桌面输出，缺库/错误架构/错误 ABI 的负向测试必须失败可见。记录依赖版本及许可证。
6. 重跑模块回归及桌面适配对照：相同 world 输入与步序时，宿主适配前后物理输出逐帧完全一致；位移/DPI 变换另测往返误差，不得以像素容差放宽物理一致性。
7. 验证按键释放、长按不重复起跳、捕获失败、失焦/Esc、隐藏恢复、切换宿主、重复启动、重置、释放及异常锁存。注入重复步进、过期 ID、缺少输入等错误时测试必须拒绝。
8. 格式、Release 构建、Core/Desktop/Physics 测试、隔离 self-contained 发布及 smoke；已知失败逐项核实，不借新范围删除无关失败门禁。
9. 真实 Window 与 Wallpaper 各跑 1/2/3 体：移动、跳跃、下压、拖放、持续碰撞、偏心叠放、抽走支撑、反复拖放/重置。三体单列，不套用双体结论。至少两种分辨率或缩放，验证桌面图标、焦点、任务栏与退出无残留。
10. 用户人工确认两种宿主的重量、柔软、拖动和干扰程度。记录自动/实时/人工/交付四类状态；未确认前不称正式接入已验收。

测试与构建均只用虚构本地场景，不记录真实桌面内容、全局输入或用户文件。性能只记设备相关观察，不提前宣布 P1-005 的 1/6/12 门禁通过。
