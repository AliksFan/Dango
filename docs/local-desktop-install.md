# Dango 本机更新规范

2026-10-29 用户批准。日常只需说：**“更新当前 main。”** 由 Agent 完成版本递增、打包、本机更新和启动核对；只要求“打包”时只生成包。

## 一次授权的范围

- 覆盖必要且可恢复的管理工具升级、旧进程正常退出、程序版本切换和启动；核验工具来源并保留备份，无须为同一范围重复确认。
- 删除存档、不可逆数据迁移、丢弃未保存内容，以及对外发布另行确认；合并其他代码分支、推送、标签和部署不包含在本机更新中。
- 前台输入或占屏测试仍遵守 AGENTS 的窗口测试规则；用户已要求的正常启动无需再问一次。

## 每次更新必须做到

1. **版本明确。** 从干净、已提交的 main 准备；交付内容变化时递增版本，当前预览按 `preview.2 → preview.3` 延续。EXE、ZIP 和随包说明版本一致，记录来源提交和包校验值。同一内容的原样重建可沿用版本，文档整理不触发应用升版。
2. **存档保留。** 程序在 `%LOCALAPPDATA%\Programs\Dango`，数据在 `%LOCALAPPDATA%\Dango`；更新保留配饰工程、图片、团子、房间、旧版本和备份，不清空或用默认值覆盖坏存档。已批准的可回滚格式升级先备份并验证；程序回退须核对存档兼容性，不能只换 EXE。
3. **失败能恢复。** 先准备并完整校验新包，再正常退出旧进程并切换，最后启动；保存或退出未完成时保留现场，不强杀。管理工具升级先验证来源和恢复办法；任一步失败不继续盲目切换、不删除原件。
4. **确认运行新版。** 核对安装状态、快捷方式实际指向、运行 EXE 的路径及版本；确认真实存档正常载入、团子和主要入口可用。按变更风险补充保存／重读验证。进程存活、打包通过和人工验收分别记录，未覆盖项明确标注。
5. **交付说清状态。** 简要报告版本、来源提交、包位置／校验值，以及打包、安装、运行验证各自是否完成。只有安装已切换且新版启动核对通过，才能称“更新完成”；保留当前需用户处理的具体问题。

## Agent 执行入口与现状

复用现有[应用打包](../eng/publish-desktop-entry.ps1)、[ZIP 封装](../eng/package-desktop-preview.ps1)、[本机安装](../eng/install-desktop-entry.ps1)和[启动／状态管理](../eng/local-install/Manage-Dango.ps1)脚本，由 Agent 编排，用户无需逐条执行命令。

截至本规范整理时，管理工具迁移脚本仍有“一次性迁移”限制。规则简化不代表该能力已经补齐；遇到实现缺口应在已授权范围内定位并按开发工作流处理，不能绕过指纹、锁或备份校验，也不能把受阻操作报成已完成。

旧操作步骤与验收历史保留在[归档说明](archive/2026-10-29-local-desktop-install.md)，不再作为日常执行入口。
