# 眼帽双宿主隔离集成增量

用户在当前眼帽预览验收后批准“核对剩余项，然后进入双模式集成”。本增量保留已验收参数，只接入窗口/桌面宿主并验证生命周期，不切换正式默认入口。

## 核对结论

2026-09-17 更新：用户重新打开最终双宿主预览后明确“验收通过”，当前集成预览人工停止点通过。第二种 DPI、长测和完整故障矩阵未补充实测；正式默认未切换。以下盘点与实施顺序保留为本增量开始时记录，最新证据见 [验证记录](verification/phase-1-eye-hat-motion.md)。

- 已完成并人工认可：重绘眼形、130 ms 眨眼、7/5.25 DIP 非对称面向、跳跃纵向眼动、1.35 倍帽子和急停惯性，含自然弯曲/轴向变形。
- 原 EH-06/07 独立 BounceHat 指令、完整组合预算和降低额外动效设置仍未完成，不据自然变形通过宣称完成。此轮不新增独立弹帽动作；后续单列。
- 当前宿主只消费旧表现帧，缺少按实体保存的附件控制器。Window/Wallpaper 已共用一个 runtime，适合在其成功物理步后统一更新，再给宿主只读绑定。

## 实施顺序与边界

1. 保存既有脏工作区和库哈希；新增场景附件集合，按稳定 ID 创建、移除和重置 generation；只在成功步推进，暂停/隐藏冻结，移除旧命令失效。
2. 隔离入口启动前用同一已验收模块的临时单体场景运行 240 步，获取稳定帽根标定并立即释放；然后创建实际宿主场景。标定不改变实际场景初态、不保留第二个活跃 world，不影响旧入口。
3. runtime 可选开启附件，默认关闭；读取实际 CoreX/CoreY 和当前按键面向。宿主迁移仅换坐标，不重复推进附件，不重新标定帽根；渲染故障只冻结该实体附件并报告，不重置物理。
4. 新 `--eye-hat-review` 使用独立单实例名和输出目录内设置/草稿。构建脚本扩展 Hosts 模式，使用新 run 目录、只构建托管项目，校验源/副本 DLL。
5. 独立小面板提供帽子选择、眨眼和表情/恢复；实体选择、数量、双模式切换复用控制中心。面板通过场景命令路由调用，不直接改眼睛状态。关闭面板可通过控制中心入口重开。
6. 验证 1/2/3 体物理等价、ID/暂停/重置/移除/迁移、实际编译 WPF 绑定；完整 Core/Desktop/Physics 常规回归，历史失败照实保留。桌面交互、双模式往返和 DPI 仍须实际运行/人工检查，不用进程响应替代。

交付限隔离候选；不合并、推送、部署、替换源库或清理旧预览。已验收预览保留。
