# 单人桌宠交互参考与 Dango 取舍

> 日期：2026-09-12；性质：公开资料调研与候选建议，不是已批准产品规则。
> 用户授权：先参考类似项目，编写单人交互与动作设计；未授权新动作实现。

## 1. 来源与证据边界

本轮读取以下项目官方页面或项目 README 正文，未安装、运行或人工体验这些产品，也未逐帧检查动画。来源能支持功能存在，不能证明操作手感、性能、底层物理或输入阈值。公开页面可能更新，下面记录本次读取结论。

| 项目及一手来源 | 本轮可核实事实 | 对 Dango 的启发（推断） | 不直接借用的部分 |
|---|---|---|---|
| [VPet 项目 README](https://github.com/LorisYounger/VPet/blob/main/README.md) | 声明支持互动、投喂、创意工坊，列出摸头、提起、爬墙动画示例；核心可嵌入 WPF | 点击、摸头、提起应有清晰可辨的不同反馈；不需要先做很多动作才能建立回应感 | 不引入投喂/生病数值循环，不把 WPF 可嵌入理解成应替换现有物理；代码和动画授权分开，不能直接搬动画 |
| [VS Code Pets 项目 README](https://github.com/tonybaloney/vscode-pets/blob/main/README.md) | 在编辑器中提供宠物面板，支持增加宠物、改变背景、扔球互动；列明不同作者的美术资源来源 | 安静陪伴配合一个短互动就可以形成使用节奏；互动入口应容易找到 | 编辑器面板不是 Windows 桌面宿主验证；球会增加新的碰撞对象与动作链，本轮先不做 |
| [Shimeji-ee 官方页面](https://kilkakon.com/shimeji/) | 描述在屏幕上活动的小伙伴，Windows/Java 项目，提供角色、视频、教程和开源说明 | 小范围自主走动能增加存在感，角色差异可先来自少量动作节奏 | 本轮页面正文不足以核实具体攀爬/窗口操纵机制，不将其当成真实软体支撑证据；不引入 Java 或任意窗口交互 |

实际读取的 README 文本入口：[VPet raw](https://raw.githubusercontent.com/LorisYounger/VPet/main/README.md)、[VS Code Pets raw](https://raw.githubusercontent.com/tonybaloney/vscode-pets/main/README.md)。本轮不复制外部代码、图片、动画、音频，不新增依赖。未来若采用素材或代码，必须单独核对对应文件许可证，不能把仓库开源等同于所有素材可自由使用。

## 2. 三个候选方向

1. **安静的小室友（推荐）**：戳一下、摸一摸、提起放下；自己慢慢走、发呆、睡觉，偶尔上岛休息。已有物理是主体，表情让意图更容易理解。符合不设置照料惩罚的产品基线。
2. **桌面小玩具**：在上述基础上增加投球、追逐、弹跳玩具。主动可玩性更强，但需要新的物体物理和追逐失败路径；列为后续候选，不混入本轮单人闭环。
3. **轻养成宠物**：食物、心情、体力、工作奖励。内容容易扩张，也可能制造照料负担；本轮不推荐，不新增隐藏饥饿/好感/离线惩罚。

推荐不是三选一的永久定位：先验证 1，之后依据真实体验决定是否增加一个来自 2 的玩具。3 不在本次设计范围。

## 3. 从参考到本项目

- 借鉴“输入有回应、无人操作也自然活动”的体验结构，不复刻其他产品角色或技术架构。
- 与参考项目不同，Dango 已有真实软体承重、拖动、碰撞和三体基线；新动作只能提交意图，不能用预录位移替代物理。
- 本轮“单人”指一个本地用户，不改产品未来多人定位；设计和首轮验收主角是一只团子。现有第二/第三只仍保留为物理回归对象，不设计社交 AI。
- 不读取真实软件内容、键盘文本、桌面文件，不追随全局鼠标制造干扰，不抢夺光标或焦点。
- 岛是 Dango 自己的家具，不把任意应用窗口当作岛，也不以窗口标题或内容驱动行为。

具体体验、操作仲裁、物理扩展边界及验收见[单人完整交互与动作设计草案](../phase-1-single-player-interaction-design.md)。
