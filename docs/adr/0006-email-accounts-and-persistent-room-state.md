# ADR 0006：邮箱账号与持久房间事实

> 状态：Accepted
>
> 日期：2026-10-08
>
> 范围：本地正式后端首期，账号、主要团子与房间；用户同意开始实施

## 背景

现有 Phase 2A 服务仅验证匿名管道启动、虚构身份和内存房间同步，不能承担正式账号与跨进程持久化。本轮需要受邀者先验证邮箱再注册，每账号唯一团子，保留完整离线单人，并正确处理并发、失败与恢复。

产品范围与完整合同见[首期设计](../planning/2026-10-08-email-backend-design-proposal.md)，技术基础沿用[ADR 0002](0002-server-foundation-and-scaling.md)。

## 决策

1. 复用 ASP.NET Core Identity 的密码、安全戳、锁定与找回能力，自定义预注册编排；未验证邮箱不建立正式 User。完成注册在同一数据库事务内创建 User、Pet、默认桌宠房、房主席位及唯一归属，消费邀请并记录固定幂等结果。
2. 首期使用 Identity Cookie 与持久会话记录；每次 HTTP／Hub 操作及受保护出站通知重新验证当前会话和业务权限。WPF 使用受控 CookieContainer 与框架防伪头，浏览器同时验证 Origin。凭据只发送给明确配置的服务端。
3. 一个 EF DbContext 负责 Identity 与领域持久化，共用 PostgreSQL 事务；数据库结构只通过显式迁移改变，正常启动不自动迁移或种子写入。账号最多一只团子、默认房唯一等由数据库约束兜底；初始化完整性、额度和容量依赖用例事务与一致锁顺序。
4. `pet_room_states` 是唯一房间归属权威，`room_id` 可空；Pet 不再维护另一份独立归属字段。登录会话、设备在线租约与房间占位分别建模。控制代际拒绝旧设备操作，连接数不能当作团子占位数。
5. 邮件挑战状态和待发任务同事务落库；单个后台任务执行 SMTP，有限重试，原始证明与正文只在内存。允许重复发送尝试，挑战必须最多消费一次。业务事件使用同库 outbox、版本去重和权威快照恢复，不引入独立消息队列。
6. 正常重启使用持久事实恢复；旧备份还原使用维护隔离、新的外部恢复代际及 Data Protection 隔离。重新启用前使恢复库中的旧会话、继续秘密、挑战、邀请、公共码和租约失效，释放公共占位，保留身份与业务数据。所有恢复账号锁定，核对后续禁用／注销事实后，仅维护批准的账号通过新邮件挑战重置密码解锁；公开找回或旧密码不能解除锁定／禁用。该维护写入须精确数据授权。
7. API、外观和快照版本明确；列表与后台查询有界，必要索引随用例迁移加入。首期单实例，不预建微信、好友、情侣、家具、资产上传或分布式组件。

恢复审批只签发绑定审批版本与恢复代际的专用挑战。完成事务复查审批和账号状态、一次消费、更新密码与安全戳及撤销会话后激活；新密码不能与恢复 PasswordHash 匹配。恢复锁定不随普通登录锁定到期或公开找回解除。

## 替代方案与理由

- 默认 `MapIdentityApi` 注册先建用户再确认邮箱，不能满足本轮顺序，故采用受控编排并保留 Identity 密码实现。
- JWT 或独立身份服务会增加撤销、刷新与运维边界；当前 Windows 首期不需要这些成本。
- 自行实现密码算法、用内存会话充当持久撤销、只检查客户端角色均不能形成可靠的安全边界。
- 两份权威归属字段容易在部分失败后分叉；集中归属记录可用数据库与事务验证。
- 首期独立 MQ／多实例不能解决重复投递或业务幂等；同库任务与 outbox 足够，并保留将来拆分边界。

## 后果与验证

预注册继续秘密、挑战代际、结果幂等和维护恢复增加实现工作，但使响应丢失、SMTP 重试及旧备份回滚有明确结果。Cookie 要求防伪、Origin、持久密钥和逐次撤销检查；不能只依赖连接建立时的认证。

每批运行能失败的验证：输入边界、独立连接并发、事务故障、跨账号越权、重启、前向迁移、真实备份还原及旧凭据拒绝。依赖精确补丁版本与许可证在新增前核验；MailKit 的采用留给 B1。ADR 通过不表示数据库、SMTP、Windows／多人或容量已经通过验收，不授权 main 合并、推送、部署或破坏性数据操作。

## 重新评估

增加非 Windows 客户端、独立身份提供者、多实例、第三方登录或改变离线合并规则时新增 ADR，不默默修改本记录。恢复策略发生变化时重新验证全部旧凭据拒绝场景。
