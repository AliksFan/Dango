# ADR 0008：配饰共享连接点与 miniPaint 统一工程

> 状态：Accepted（用户明确统一实现和双向连接；下列有界工程取舍随本地实现验证，产品手感／性能未验收）
>
> 日期：2026-10-26
>
> 增补 ADR 0007；替代其单链制作／参数安排中与多组、双向连接、统一 UI 冲突的部分，不改变 miniPaint／WebView2、唯一 owner、身体与 native 世界隔离。

## 背景与授权

用户在本轮试用后明确：从骨节新建的根在物理上连接，拖动和受力应互相影响，不能按“父带子”求解；工具栏统一在左，右上图层／组、右下活动组骨架属性。用户同时要求在现有 miniPaint 内一体实现，避免独立骨架页面再迁回一遍。

独立 S0 已有的检查只保留历史，不作为新合同或正式产品验收。当前授权覆盖本地实现与隔离验证；不包括 main 合并、推送、安装、发布或真实库迁移／删除。

## 决策

1. **同一编辑器与同一历史。** 保留固定 miniPaint 源、图片工具／图层／历史与 WPF WebView2。Dango 输入命令接入 miniPaint `State.do_action`；图片修改、骨架、归组、名称和组参数作为完整工程修订撤销。S0 消费者仅作夹具，正式入口不依赖它。
2. **共享物理自由度。** 根引用仅记录组装身份；被连接 R/J 合为同一粒子，各组距离／角约束按逆质量双向作用。编辑时选择同点集合任意成员即移动该共享连接点，混选去重；不隐式平移其他普通骨节或图像。自由 R 仅移动其自身及同点根。原单父无环是组装校验，不是物理单向传播。
3. **有界全局约束。** 现有成功 owner 帧一次推进整件骨架；沿用最大 1/120 s 子步、最多 8 步。重复／倒退 tick、Refresh、隐藏不推进；长帧／Resume 重建静止姿态。不建新 timer/world，不向团子身体反推配饰力。每子步一次恢复，随后 96 轮交替双向约束投影；末步沿粒子森林精确闭合骨长，保持骨段方向。这消除有限迭代长度残差，但不保证严格能量守恒。
4. **参数单位独立。** 弯曲 0–1、默认 .7；伸缩 e 为 0–.5、默认 0，硬边界 `(1−e)L0..(1+e)L0`，拉伸压缩对称且不强制拉满；弯曲 0 不关闭伸缩。阻尼 0–30 s⁻¹、默认 6；恢复 0–30 rad/s、默认 5，同一恢复作用于初始角与长度，不新增伸缩恢复控件。组重力控制值 0–100、默认 0，质量加权后一次映射为 0–4 image-height/s²，世界向下；共享节点不累加两份加速度。外层整体重力保留既有 0–100 与自身 A–P／整体转动映射，不替代组值。
5. **独立绘制片。** 图层组仍占连续绘制区间；按最终可见栈的连续组／未分组块导出完整画布 PNG 片，各片保留真实透明叠放次序。空组无片，root-only 片按根参考姿态刚性变换，未分组片仅随整体 P。每组用最近两骨段距离绑定，轴向坐标可外推，法向距离随整体尺度；交叉／发卡／短非零段不被旧单链额外限制拒绝。此选择简化输入并有确定上界，不能推定复杂素材画质已经通过。
6. **明确版本。** 网页工程 schema 2、原生不可变工程 version 2／`minipaint-v2`、桥 protocol 2、清单 schema 3；骨架自身 version 1。工程包含 name、像素坐标 P/R/J、稳定组／节点／层身份、连接引用、组参数、可编辑层／资源及 renderPieces。桥 Open 只传完整 project；Preview／Confirm 只回 `{project,png}`。视图、选择、临时鼠标、速度和网格不持久化。原生独立检查版本、同点、无环、层归属与绘制片资源；模态确认只回草稿，外层应用继续以原子清单为提交点。
7. **旧数据保护。** 不把新字段塞进旧版本。旧清单 v2／工程 v1 保留原件并拒绝写入，不自动迁移、删除或用空库覆盖。清单文件路径保持原路径，使未知／旧内容仍触发保护，不用新路径绕过它。源码中的旧单链测试合同不作为新版的静默回退。

## 资源界限

| 范围 | 防御上限 |
| --- | --- |
| 每件组／节点 | 12 组、96 个编辑身份（含 P 和各组根） |
| 图层／内部资源／绘制片 | 16 层、48 个内部 PNG 资源、至多 16 片；资源散列去重 |
| 输出尺寸／像素 | 1–4096 边长、16,000,000 输出像素；资源累计 64,000,000 解码像素 |
| 工程／桥 | 64 MiB 编码工程与传输上限；现有分块、会话／请求／修订校验保留 |
| 网格 | 每片 15×15 格，最多 256 顶点／450 三角形；每件总 4096 顶点／7200 三角形 |
| 撤销 | 继续 miniPaint 20 步／64 MiB 保守 payload 预算；不使用 S0 的独立 40 步作为产品预算 |

上述为拒绝无界输入的门禁，不等于最大 8 件佩戴时的性能或总进程内存验收。工程按不可变 ProjectId 缓存；消费者按完整 immutable item 解析工程，不能用同 Id 的较新草稿替代保存版。

八件同时达到单件上限时，计数边界为 96 组、768 个编辑身份、32,768 顶点及 57,600 三角形；内部资源最多 512,000,000 解码像素，另有最多 128,000,000 成品图像像素。这些是防御上限的算术合计，不是堆内存、峰值资源或帧耗时实测，也不构成最大负载通过结论。

## 替代方案与后果

- 分组各自单向推进实现简单，但不满足用户要求的双向影响，已明确废止。
- 另起图片编辑器或独立骨架产品页会重复图片能力和历史维护，采用现有 miniPaint 统一装配。
- 严格能量守恒或新刚体世界增加工程复杂度，不在本轮引入；当前有界位置约束必须以反作用、端点、有限性和 owner 反例验证。
- 按组压成整件单 PNG 会丢失相对形变，禁止用这种呈现冒充多组；实际分片仍需真实素材画质、透明边缘和负载验收。

本 ADR 不将后台测试或样板截图写成人工手感、正式窗口、DPI、长时负载或发布验收。
