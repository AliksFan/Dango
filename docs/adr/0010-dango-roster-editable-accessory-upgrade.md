# ADR 0010：三栏位目录接入可编辑配饰工程与可回滚升级

状态：Accepted，2026-10-29。用户在授权本地收尾合并后，明确选择“保留原件备份，支持可回滚升级，继续使用已有栏位”。本轮仅使用虚构存档验证，不直接操作日常目录。

## 背景与决定

main的三栏位采用共享配饰Library及各profile的独立穿戴快照；配饰分支新增schema3库、schema2可编辑工程及多组骨架。原来的三参PNG保存接口、roster schema1旧字段集合不能承载工程，简单文本合并会编译失败或遗失工程。接口与实际生产adapter必须一起接入，不能以具体Store绕开原持久化边界。

1. **版本和集中提交。** roster明确升级为schema2，当前严格AccessoryItem／Rig／Skeleton及工程校验与独立配饰Store复用；完整PNG、源素材和renderPieces由不可变工程准备路径验证。共享Library和各profile保存快照维持原职责，`roster.json`仍是唯一提交点，不新增资源清理。取消、失败、未知结果及旧profile持有的工程引用不得部分提交或串值。
2. **生产adapter。** 绑定目标由已选中Dango身份和binding token限定；LoadProject与完整工程保存通过原持久接口传递。当前profile的完整有效配饰内容指纹用于识别编辑基线，roster仍校验完整版本／内容并执行原有观察式原子提交；保存外观等不相关动作不应误报配饰冲突。
3. **已知旧格式。** 仅严格有效的schema1及匹配的初始化身份可升级。首次读取时先将旧roster原字节写入并核验 `dangos/backups/roster-v1-<原字节SHA256小写>.json`；相同备份可复用，不得覆盖冲突或损坏备份。备份完成后才准备新工程并原子切换roster，revision加一，原初始化记录及原PNG不改。
4. **保留语义。** 三个栏位位置、身份、名称、外观和各自穿戴值保持。旧自制PNG按原图及各快照的图片P点、名称生成真实无骨架工程；不同profile的P不能被按图片ID合并。旧柔性字段保留在原字节备份，不猜造新骨架。坏图、缺图、未知字段、无效引用或备份失败保留原roster，不能用空库重建绕过保护。
5. **回滚。** 关闭产品，另存当前 `dangos/roster.json`，将对应hash备份逐字节恢复为该文件，并使用升级前旧版启动；原初始化和PNG仍在，无须反向猜测退役字段。当前新版再次打开schema1时会再次升级。回滚操作执行时仍须核对环境和目标，本轮只在虚构测试根验证。
6. **包兼容声明。** 新内部候选采用 `dango-desktop-settings-v4-roster-v2`，对实际17份持久化源码严格核验，已有六个合同的源哈希保持。管理工具的共用激活入口拒绝从该代自动降级至旧合同，拒绝前不写安装状态，并提示第5项的离线恢复步骤；前向升级、同代切换和旧代内部切换仍受原有完整性及进程门禁约束。此保护不自动操作存档，也不代表本轮执行安装或实际回滚。

## 替代与后果

- 将所有旧roster一律只读虽容易保护原件，却会使已验收三栏位不可编辑；用户明确选择有备份的版本升级。
- 把新字段塞回schema1会使旧校验合同含糊，因此不采用。旧DTO独立保留，当前校验不为迁就旧字段而放宽。
- 不可变资源在失败后可能留下未引用文件；本轮不执行垃圾清理，避免删除其他profile或回滚仍需要的工程和图片。
- 升级增加一次原件备份及工程写入成本；相同roster的重启必须幂等，写后异常通过观察已提交内容判定，未知结果继续保护现场。

实际故障点、严格旧DTO、跨profile工程引用、字节一致回滚与宿主交接的验证见[本地集成记录](../verification/2026-10-29-accessory-editor-main-integration.md)。该决定不授权推送、安装、删除日常数据或公开发布。
