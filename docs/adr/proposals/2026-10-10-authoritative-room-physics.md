## 背景

用户选择双人首版保留真实推挤、承重和堆叠，允许局部形变细微不同。当前本地 native 无家具世界已有双体真实接触，但它还不是正式在线玩法权威。正式后端只有准入、租约、控制与成员快照；旧 Phase 2A 的解析地面移动段没有跳跃或共享物理。

[ADR 0005](../0005-box2d-visual-soft-body-presentation.md)将 Box2D 限定为客户端表现，客户端不能裁定共享事实。要保留目前接触手感，必须新增服务器玩法物理边界；简化 C# 圆形阻挡会形成另一套效果。设计与分阶段验证见[双人设计](../../planning/2026-10-10-formal-ordinary-room-dual-player-design.md)和[实施计划](../../planning/2026-10-10-formal-ordinary-room-dual-player-plan.md)。

## 推荐决策

1. 正式业务层负责身份、归属、租约、控制代际和可接受命令；独立无 UI 的服务端物理 adapter 只计算已获准的运动及真实接触。Core／协议不引用 Box2D 句柄、类型或生命周期。
2. 服务端复用同源 native solver 作为单房间唯一玩法物理，统一推进所有团子。客户端只上传抽象输入意图，不上传坐标、形变、碰撞或支撑作为事实。
3. 服务端固定 1／60 秒步进，通过低频、有界的中立 DTO 发布中心、必要速度校正、朝向、落地／支撑及共同接触语义。客户端插值及局部软体表现不裁定跳跃、承重、碰撞最终位置或他人状态。
4. 不同步逐帧轮廓节点、弹簧、原始 PhysicsFrame 或逐帧碰撞流。必要速度与支撑校正是本 ADR 明确提出的新边界；若语义无法保持可信接触，停止并另案评估，不把完整轮廓共享当隐含授权。
5. native 的创建、步进、恢复与释放在同一专用物理工作线程；有界调度多个房间，不在固定步中 await／I/O，不用每房间一个 OS 线程。
6. 本机可见性不暂停服务端房间。保存／休眠按最新正式有效租约和领域生命周期事实判断，包含控制与观察设备；UI 隐藏、无渲染订阅或 SignalR 断线不能充当最后有效设备离开，保留现有 30 秒业务容错。故障发布全房最后安全状态并清持续输入；短输入 watchdog 不停止房间模拟。
7. 内部恢复 checkpoint 版本化，完全来自服务端且不对玩家公开；恢复后新的 PlayEpoch 使旧输入失效。持久单调 RuntimeRevision 与条件提交阻止旧运行者迟写，checkpoint revision／Tick 阻止倒序覆盖；保留最后合法成功存档。按 RoomId＋PetId＋PresenceGeneration 过滤成员，控制接管保留原身体，离房重入产生新生命周期。首次无存档可合法出生，已有坏存档阻止就绪。语义恢复与 native 完整恢复须独立证明，不能从当前 Add／Reset 接口推定精确重启续接。
8. 先准入无家具、两个团子的玩法世界和客户端呈现。平台／皮球／跨玩家手套、更多人数及新身体模型各自后置；不移除家具单团子 guard 充当该能力完成。
9. Windows headless 仅是开发证据；ADR 0002 的 Linux 服务端目标需要独立 Linux 构建、加载、步进与回收门禁。缺少可用 Linux 环境时保留未验证，不通过替换正式部署目标绕过。
10. 正式输入和受保护出站沿用逐次授权；命令按服务器接收时刻具有有界应用期限，出队重验，queued 不表示已应用。ready 挑战绑定当前租约、实际连接、归属／控制／成员生命周期、play／输入及模板版本与到期时间，确认时重验。要求可玩的准入在迁移提交前复查玩法适用性，不能以事后 PlayAttach 拒绝代替。

## 对已批准基线的影响

若获批，仅在本范围增加 ADR 0005 §1 条 2／3 的“服务端无 UI 玩法物理 adapter”例外，并细化条 4／7 的 server gameplay 与 client presentation 输出边界、条 9／10 的共同接触裁定、条 16／19 的服务器生命周期与平台准入。

ADR 0002 的 .NET 10／SignalR／PostgreSQL、单实例单房权威、有界队列及可演进分区保持；ADR 0003 的动作时间和纯 DTO、隐私边界保持。客户端 local native 输出仍不能回写服务端事实。批准仅在隔离实施树记录，不覆盖原Accepted文件，也不宣称主线或正式服务已有新能力。

## 替代方案

| 方案 | 原因与后果 |
|---|---|
| C# 简化逻辑碰撞＋本地软体 | 最轻，但不保持当前承重和真实推挤，适用于另选的简化产品范围 |
| 客户端／房主物理权威 | 信任、断线迁移与控制争用成本高，不能承担正式共享状态裁定 |
| 锁步、完整预测回滚 | 依赖确定性、可回滚状态和带宽／复杂恢复，现有模块不具备，不引入本批 |
| 每帧广播完整软体世界 | 传输及协议耦合成本高，违背现有同步边界，不作为自动兜底 |

## 代价、失败门与重新评估

服务器 CPU 成本、native Linux 打包、线程所有权、可恢复状态 ABI、客户端校正和数据库生命周期桥接都会增加工作。当前没有这些准入证据，也没有 200 人／50 房容量结论。先量测单房，再扩大规模。

准入至少包含同源双体反作用／承重／落地、旧单人对照、线程与资源、有限状态／故障安全、完整 checkpoint export／import、Linux 步进和只用低频语义的真实客户端表现。不能通过降低现有接触门槛或关闭碰撞消除失败。传输逐节点、改变部署平台、替换 solver、扩展人数／家具或新身体模型都要重新评估。

本提案批准与编码、真实数据库计划、双机人工验收、main 合并、推送、安装和部署分别记录。
