# ADR 0005：Box2D 视觉软体表现层

> 状态：Accepted
>
> 决策日期：2026-09-03
>
> 所属阶段：Phase 1 — 桌面生命感原型
>
> 取代：[ADR 0004](0004-lightweight-soft-body-secondary-motion.md)

## 背景

[ADR 0004](0004-lightweight-soft-body-secondary-motion.md) 选择了手工关键姿势与自有轻量弹簧—阻尼形变组合。用户在确认视觉权威边界后，明确希望使用更真实的二维物理内核，让团子的接触、挤压、回弹和配饰拖曳具有更自然、可爱的连续变化。

P1-003 已在 `phase/1-desktop-life-prototype` 的 `1ea0885` 完成并通过 C3：当前 Phase 1 可以使用已验收的原生分层 WorkerW 候选继续 P1-004。P1-003 的完成只解除宿主前置门禁，不证明动态轮廓、native 物理依赖或动画性能已经可行。

候选调查得到以下当前事实：

- 官方 Box2D `v3.1.1` 是稳定发布，采用 C17、MIT 许可证，提供碰撞、距离关节、弹簧、阻尼和接触力；
- Aether.Physics2D 已归档；
- VelcroPhysics 长期未更新，公开 NuGet 仍为 alpha；
- LiquidFun 已归档；
- Godot 会扩大为客户端和渲染栈替换，不适合只验证团子软体表现。

官方依据：[Box2D v3.1.1](https://github.com/erincatto/box2d/releases/tag/v3.1.1)、[Box2D README](https://github.com/erincatto/box2d/blob/v3.1.1/README.md)、[Box2D License](https://github.com/erincatto/box2d/blob/v3.1.1/LICENSE)、[Distance Joint API](https://box2d.org/documentation/group__distance__joint.html)。

## 决策

### 1. 物理内核与职责

1. P1-004 采用官方 Box2D 3.x C API 作为真实二维物理内核，首个依赖 Spike 以 `v3.1.1` 为候选固定版本。
2. Box2D 只存在于 `Dango.Desktop` 的 Physics Presentation Adapter 内；`Dango.Core`、服务端协议、资产事实和桌面宿主不得引用 Box2D 类型、句柄或 native 生命周期。
3. Box2D 负责表现层的质量、碰撞、弹簧关节、阻尼、接触力与次级惯性。它不得决定 Core 权威位置、动作状态、登岛、落地、拖动结果、权限或房间状态。
4. Box2D 没有直接提供本项目需要的软体角色。每只团子以一个跟随 Core 权威姿态的运动学核心锚点，加一圈动态节点、相邻弹簧关节和径向恢复关节组成受限软体环。
5. 节点数、质量、重力、刚度、阻尼、求解子步和形变上限只作为 Spike 参数比较，不在本 ADR 中冻结。

### 2. 数据流与同步

6. Core 向表现层提供权威姿态、动作意图、接触方向或语义锚点、开始时间、持续时间、强度、参数版本和变体种子。
7. 物理层返回的只是轮廓采样点、局部挂点和诊断数据，不能回写 Core 场景状态，也不能上传为服务端事实。
8. 物理世界使用固定步长和有界补步；渲染可以插值。相同 Windows 构建、输入和步长应在容差内可重复，但不要求不同 CPU 或客户端逐顶点位相同。
9. 多人客户端必须看到相同的动作语义、参与者、接触方向、开始/结束时间和最终状态；局部软体细节允许存在不影响语义的微小差异。
10. 双团子接触仍由一个 interaction director 生成共同的接触意图和成对约束。双方不能各自把物理结果提升为权威碰撞结论。

### 3. 动态轮廓与分层

11. WPF 首轮使用动态 `StreamGeometry` 将软体环节点转换为平滑闭合曲线，并只使用纯色填充；不得加入描边、光照、高光、渐变、阴影或纹理。
12. 身体必须始终保持无脚、无腿、无爪、无手臂的连续圆润轮廓。曲率、节点位移、面积变化和凹陷设置硬限制，避免尖刺、翻面或肢体状凸起。
13. 眼睛保持独立表情层，通过身体局部坐标或插值挂点跟随形变，并限制缩放和旋转，避免表情失真。
14. 帽子保持独立配饰层，通过顶部动态挂点跟随；允许单独的受限旋转弹簧，但默认不参与角色碰撞。
15. 已制作的手工关键姿势和分层 PNG 继续承担动作语义、无物理/降低动画模式、异常恢复和资源缺失 fallback，不因引入 Box2D 被废弃。

### 4. 运行与降级

16. 物理世界只在对象可见且需要连续表现时步进；隐藏、退出、宿主失效和长时间稳定空闲必须停止或休眠。
17. 降低动画模式默认关闭软体环连续求解，使用手工关键姿势；后续只有人工验证证明低干扰时才允许高阻尼低频模式。
18. 出现非有限数、节点翻转、超过形变上限、累计补步超限、native 初始化失败或 native 调用异常时，立即销毁该实例并切换 fallback，不允许拖垮桌面宿主。
19. 首轮只支持 `win-x64` self-contained 发布。native DLL 必须随发布物显式验证加载、版本、许可证和进程退出回收；不允许运行时联网下载。
20. WPF 动态轮廓是首轮验证方案。只有取得明确维护或性能失败证据后，才按 ADR 0003 比较 SkiaSharp；本决策不批准 Godot 迁移或双渲染器长期并存。

## 选择理由

- Box2D 是仍在维护的官方二维物理内核，能够提供真实碰撞、质量、关节、弹簧和接触力，而不是只播放预制缩放曲线。
- 运动学核心锚点把真实视觉物理限制在 Core 权威姿态周围，可以同时保留自然形变和服务端权威。
- 动态纯色轮廓适合当前无描边、无光影的极简视觉，不需要为每个形变导出位图。
- 保留手工姿势 fallback，使 native 依赖、降低动画和异常路径不会破坏动作语义。
- 先验证 WPF `StreamGeometry`，可以在不提前替换已验收桌面宿主的情况下取得真实性能证据。

## 代价与风险

- 官方 Box2D 使用 C17；.NET 需要维护一层小型 P/Invoke/native 打包边界。
- Box2D 的刚体和关节只是构造软体的基础，软体环拓扑、参数、轮廓平滑和防翻面仍需项目实现与调参。
- WPF 每帧重建几何可能增加 CPU 与分配，必须由 P1-004/P1-005 真实测量。
- 物理效果可能因机器、帧丢失和求解顺序产生细微差异，因此不得把视觉顶点用于多人权威判断。
- 过强物理会造成持续晃动、穿模或怪异表情；“更真实”必须服从安静、可爱和长期驻留体验。
- vendored source、固定构建产物或其他 native 获取方式需要在依赖 Spike 中以可复现构建、许可证和退出成本为依据选择。

## 验证门禁

按以下顺序验证，任一停止点失败都不继续扩大实现：

1. native 依赖与 self-contained 加载；
2. 无 WPF 的单团子软体环稳定性；
3. WPF 单团子动态纯色轮廓；
4. `Landing` 权威落点与物理回弹；
5. 双团子贴贴技术场景；
6. 眼睛、帽子和 fallback；
7. 1/6/12 只诊断与人工观感。

最低失败条件包括：Core 快照被物理修改、native DLL 无法从干净 self-contained 发布物加载、非有限数或无界形变、持续抖动、轮廓翻面、明显穿模、生成脚状凸起、眼睛失真、帽子漂移、隐藏后继续步进、降低动画仍持续振荡，或无法安全回退。

P1-004 只要求完成单团子生命感纵切与必要的双体技术证明；1/6/12 的正式性能结论仍属于 P1-005。人工验收必须单独确认重量、柔软、可爱、安静和长期驻留干扰程度。

## 对既有 ADR 的影响

- 本 ADR 取代 ADR 0004 的“自有轻量弹簧—阻尼且不引入 Box2D”选择。
- ADR 0004 中手工关键姿势负责语义、视觉物理不掌握权威、分层眼睛/帽子、同步意图不逐帧同步和 fallback 原则继续有效，并在本 ADR 中重新确认。
- ADR 0003 的独立资产契约、WPF 首轮验证、失败后再比较渲染后端和多人同步边界继续有效；其“轻量程序化二次运动”由本 ADR 细化为 Box2D 视觉软体表现层。
- ADR 0001 的 C#/.NET 10/WPF/Win32 客户端基础不变；Box2D 是封装在渲染表现层内的 native 依赖，不替换 App Shell 或桌面宿主。

## 重新评估条件

出现以下任一证据时新增 ADR：

- 官方 Box2D native 集成无法达到可复现构建、自包含发布或安全回收要求；
- WPF 动态轮廓在稳定宿主上无法达到已批准的单团子门槛；
- 软体环无法在合理参数范围内同时满足自然接触、无脚轮廓和安静驻留；
- 物理与 Core 权威隔离无法维持，或多人语义开始依赖本地物理结果；
- 维护 native adapter、软体拓扑和渲染路径的成本超过已评估替代方案；
- SkiaSharp 或完整引擎 Spike 取得明显更优且可维护的综合证据。
