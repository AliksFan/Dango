# ADR 0004：轻量软体二次运动

> 状态：Accepted
>
> 决策日期：2026-09-02
>
> 所属阶段：Phase 1 — 桌面生命感原型

## 背景

Dango 已在 [ADR 0003](0003-animation-assets-and-rendering-validation.md) 中确定“分层位图 + 少量逐帧轮廓动作 + 运行时 Transform/缓动 + 轻量程序化二次运动”。现有预生产样本已经用手工关键姿势表达 `Idle`、`Landing` 和 `ClimbUp` 的动作语义，但单靠固定帧难以让两个无肢体圆形团子接触时持续保持自然的挤压、回弹和轻微跟随。

完整软体物理或通用物理引擎能够提供更自由的模拟，但会同时引入碰撞裁定、稳定性、跨客户端确定性、调参、性能和渲染依赖。Phase 1 需要的是可控的视觉柔软感，而不是让物理解算器决定位置、权限或互动结果。

## 决策

### 1. 组合方式

1. 动作语义继续由手工关键姿势、动作事件和场景状态决定；程序化形变只负责接触挤压、衰减回弹和次级晃动。
2. P1-004 实现一个范围受限的弹簧—阻尼形变层，不引入完整软体物理、刚体世界、Box2D、Godot Physics 或同类通用物理引擎。
3. 求解输入使用统一交互坐标系中的接触锚点、接触法线、强度、开始时间、持续时间和变体种子。视觉形变不得反向修改 Core 权威位置、碰撞结果、权限、状态转换或动作事件。
4. 形变至少支持沿接触法线的轴向压缩、垂直于接触法线的有限横向补偿、最大形变限制和阻尼回弹；数值范围由 P1-004 Spike 测量后确定，不在本 ADR 中冻结。
5. 任一时刻的输出由手工姿势与有界程序化偏移合成。程序化层失效、超预算或被关闭时，必须安全回退到手工关键姿势。

### 2. 分层与挂点

6. 身体、眼睛和帽子继续作为独立图层；不增加嘴、腮红、阴影、光照、渐变或纹理。
7. 眼睛跟随身体局部形变，但表情切换仍是独立轨道，不能因身体弹性而改变表情语义。
8. 帽子通过随姿势和形变更新的动态挂点跟随身体，可以有很小的受限延迟；不得漂移、穿透主体或独立参与碰撞裁定。
9. 身体仍保持无脚、无腿、无爪、无手臂的连续轮廓，形变不得生成肢体状凸起。

### 3. 双体互动

10. 两只团子的接触由单个 interaction director 生成一份成对约束和共同时间线，再分别采样双方的镜像或互补形变；不得让双方独立检测、独立求解同一接触而产生争抢和抖动。
11. “贴贴”在 P1-004 中首先是双体接触与形变的技术 Spike 场景。它不代表房间、好友、关系动作、服务端协议或多人产品功能已经完成。
12. 同一动作意图、参与者、服务端开始时间、接触方向或锚点、参数版本和变体种子，在固定步长采样下必须得到可重复的视觉结果。运行时可以插值显示，但不能依赖机器帧率累积出不同结果。

### 4. 同步与可访问性

13. 服务端只同步动作意图、参与者、权威开始时间、持续时间或速度、接触方向或语义锚点、变体种子和协议/参数版本；不逐帧同步顶点、弹簧状态、缩放值或当前帧。
14. 降低动画模式保留动作状态、首次接触和最终姿势，减小形变幅度，关闭延迟振荡和非必要次级晃动，并允许使用更低目标刷新率。
15. 客户端资源或性能不足时使用协议声明的关键姿势 fallback，不得产生语义不同的互动结果。

## 选择理由

- 手工关键姿势可以稳定表达“准备、接触、转移、结束”，轻量弹性只补足连续触感，职责清晰。
- 有界弹簧—阻尼比完整物理世界更容易调出安静、治愈且不持续抖动的桌宠体验。
- 单一双体导演避免两个客户端对象互相推挤造成反馈振荡，也便于确定性重放。
- 同步意图和种子而非逐帧状态，符合服务端权威与低频协议边界。
- 保留关键姿势 fallback，使 WPF 能力、性能或无障碍设置不会阻塞基本动作语义。

## 后果

### 正面

- 落地和团子接触可以共享一套有限形变语言，同时保留每个动作的独特关键姿势。
- 身体颜色、眼睛表情和帽子仍可独立组合，不需要为每个组合重画完整动画。
- 运行时复杂度和性能风险被限制在 P1-004 可测范围内。

### 代价与风险

- 当前资产 Schema 尚不能表达程序化形变参数、接触法线、参数版本和动态帽子挂点，P1-004 必须先提出最小契约变更并验证 fallback。
- 透明位图的非均匀形变可能产生边缘采样瑕疵；WPF 是否满足观感和性能仍需真实运行验证。
- 弹簧参数过软会显得廉价，过硬则失去接触感；数值必须通过参考设备和人工观感共同确定。
- 双体接触需要明确共同坐标系、镜像规则和断线/中断后的收束方式。

## P1-004 验证门禁

P1-004 只有在 P1-003/C3 至少一个桌面宿主候选可行后才能接入。验证顺序为：

1. 单团子 `Landing`：证明关键姿势与弹簧—阻尼叠加、固定接地点、衰减和 fallback。
2. 双团子贴贴 Spike：证明单一 interaction director、成对接触法线、确定性采样、帽子和眼睛跟随。
3. 1、6、12 只压力场景：1 只验证产品预算，6/12 只记录参考设备基线，不冒充多人业务验收。

最低检查项：

- 无持续抖动、数值爆炸、明显穿模、接地点漂移、帽子漂移或透明边缘破损；
- 相同输入、固定步长和种子重复运行得到相同采样结果；
- 切换降低动画后不改变事件与最终位置，且不保留延迟振荡；
- 程序化层关闭或超预算时能回退到手工关键姿势；
- 一只空闲团子 CPU 不高于 1%，工作集不高于 250 MB；
- 一只普通活动团子 CPU 不高于 5%，目标 60 FPS；降低动画目标 30 FPS；
- 真实 Windows 桌面观感、干扰程度和贴贴自然度由用户单独人工验收。

这些数值是 Phase 1 Spike 门禁，不是正式发布承诺。GPU、帧时间以及 6/12 只场景结果必须记录实际设备和测量方法。

## 重新评估条件

出现以下任一证据时新增 ADR，不在实现中静默扩大方案：

- 有界二维形变无法避免可见穿模或挂点漂移；
- WPF 在稳定宿主上无法满足已批准的单团子性能或透明边缘要求；
- 动作与装扮规模证明需要网格、骨骼或更完整的碰撞系统；
- 跨客户端重放无法在现有意图同步边界内保持语义一致；
- 维护自有轻量求解器的成本高于引入已评估依赖的许可证、体积和迁移成本。
