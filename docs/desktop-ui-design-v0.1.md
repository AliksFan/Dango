# Dango 桌面界面设计规范 v0.1

日期：2026-10-10。范围：桌面端功能界面，包括首页、外观编辑、图库、设置及独立编辑窗口；手机端另行设计。

新界面以主界面与饰品界面的共同规则为依据，同时遵循页面自身的业务合同。本规范覆盖布局、视觉和交互，用统一的控件与验收规则减少逐页调整。

## 1. 规则状态与来源

| 内容 | 状态 | 使用方式 |
|---|---|---|
| 首页与捏脸的布局、图标及草稿合同 | 已批准页面规则 | 提炼为共同规则，具体行为仍以原设计为准 |
| 配饰分组、图库、工具、固定操作区及删除合同 | 已批准页面规则 | 保留对应页面差异 |
| 仅规范桌面端，布局、视觉和交互均纳入 | 本轮用户已确定 | 用于后续桌面界面设计 |
| 常用操作按钮优先有图标；排版空间充足时使用图标＋字 | 本轮用户明确规则 | 空间充足用图标＋短文字，紧凑布局用仅图标，必要文字按第 4 节保留 |
| 滚动条使用“常驻细条”，两类滑条都要调整、页面滚动需更顺滑 | 本轮用户已确定方向 | 不再使用默认粗滚动条作为新设计方向 |
| 控件尺寸、命中范围和滚轮缓动参数 | 本轮样板起点 | 正式 WPF 实现须校准并经过真实输入与人工验收 |
| 生产页面卡顿的根因和修复 | 尚未复现定位 | 不得把平滑动画或样板通过写成修复结论 |

页面依据：[首页与自身外观设计](planning/2026-10-06-home-and-appearance-design.md)、[配饰设计及后续修订](planning/2026-10-07-accessory-diy-design.md)、[设置页设计](planning/2026-10-01-settings-ui.md)。后续页面修订须明确更新了哪些规范条款，避免多个文档各自维护相互冲突的要求。

已有获批业务差异优先于本规范的通用建议。规范不改变账号、房间、权限、物理、数据格式或保存边界，也不授权批量重做已有页面。

本轮“空间充足时图标＋短文字”的规则更新早期仅图标的视觉偏好，不能将旧视觉偏好作为永久例外；实际页面迁移仍按后续授权安排，保留原业务合同。

## 2. 视觉基础

保持近白暖灰、棕色细强调、少字留白的方向。团子与创作内容是主体；诊断和技术信息按需展开。图标、状态和留白服务于操作，不增加重复标题、装饰性状态卡片或没有实际行为的入口。

桌面风格统一为**简约、轻盈、暖白、图标优先**。后续设计与已授权迁移按以下默认规则执行：

- 常用功能操作优先用小型线性图标；排版空间充足时采用图标＋短文字，紧凑布局采用仅图标，把空间留给团子、素材和参数。
- 图标使用细线、圆角端点和一致的视觉尺度，颜色继承组件状态；不混用彩色表情、厚重实心图标和多套图标风格。
- 常规控件采用透明或浅暖色底、细边界和轻反馈，棕色强调用于选中、焦点与主要操作。
- 页面保持清楚的信息层级与留白，去掉重复标题和说明；参数标签、数值、真实状态与必要解释继续可见。
- 同类操作的位置、组件和状态规则保持一致；具体动作集合及页面方向按各自业务设计保留。

### 2.1 颜色

以下是首页与配饰已使用的共同资源。新界面引用语义资源，不在各页面复制颜色表。

| 资源 | 值 | 用途 |
|---|---|---|
| `HomeBackground` | `#FDFCF9` | 页面背景 |
| `HomeInk` / `HomePrimaryInk` | `#443D34` | 主要文字与强调操作前景 |
| `HomeMuted` | `#807568` | 次要说明与非激活文字 |
| `HomeLine` | `#E9E4DA` | 细分隔线及参数滑条未经过部分 |
| `HomeSoft` | `#F3EFE8` | 轻底色、普通悬停及滚动轨道 |
| `HomeAccent` | `#885E3E` | 选中边界、焦点、滑条经过部分及激活滑块 |
| `HomeSelected` | `#EFE3D4` | 选中及主要操作背景 |

错误、警告、高对比等语义状态须可辨识，不能只靠颜色。不得为了调色改变用户选择的身体、眼睛或图片颜色。高对比模式使用系统可辨识颜色，保留边界和焦点。

### 2.2 字体与尺寸

正文沿用 `Segoe UI, Microsoft YaHei`、14 DIP；辅助文字使用已有页面层级，字号不足以清晰阅读时优先减少重复文字或调整布局。标题大小按信息层级使用，不因新建页面随意放大。

| 控件 | 已有共同尺度 |
|---|---|
| 带文字按钮，包括图标＋文字 | 最小高度 40 DIP；常规内边距横向 14、纵向 8 DIP；宽度随内容布局 |
| 纯图标按钮 | 32 × 32 DIP；图标 20 × 20 DIP |
| 同组图标间距 | 8 DIP |
| 快捷键键帽 | 22 × 22 DIP；圆角 4、边框 1 DIP；与图标相隔 8 DIP |
| 常规按钮圆角 | 现有模板 7 DIP |
| 图标提示 | 中文提示和辅助名称；沿用 250 ms 初始延迟 |

这些尺度用于同类组件，不把特殊导航、色块、图库或窗口关闭控件强行改成相同尺寸。尺寸使用 DIP；显示大小和实际可点击范围分别核对。

## 3. 页面布局

先明确页面的导航、操作对象、参数内容、预览工具、对象操作和提交操作分别归属哪里，再放置控件。页面标题、页签和内容区不重复表达同一名称。

编辑页面将可滚动内容与固定操作区分开。参数或图库滚动时，预览及应用、取消等必要操作保持可达。错误、未保存提示和恢复入口有稳定位置，不能随转场被隐藏或挤出窗口。

同一窗口内切换首页、捏脸和换装，保持团子的正常预览尺寸与接地基线；参数展开以横向转场为主。纵向时参数放到预览下方独立滚动，保存组仍锚定预览右下。布局变化不靠缩小团子掩盖空间不足。

| 页面 | 应保留的差异 |
|---|---|
| 捏脸 | 参数在右、预览在左；左侧参数页签、右侧动态比较工具 |
| 配饰 | 参数在左、预览在右；对象创建、复制、删除归属配饰工具区 |
| 配饰图库 | 已佩戴与未佩戴分区、四列图片、跨区唯一选中；佩戴与排序保持各自业务合同 |
| 设置 | 壳层内可滚动单列，以宿主确认值和真实保存状态为准 |
| 图片编辑窗口 | 图片画布和参数区分别拥有自身输入；画布滚轮用于缩放 |

最小正式窗口与组件窄宽测试是两个层次。正式窗口下限、布局转折点和支持的 DPI 以实际宿主及各页面合同为准，不将组件在 320 DIP 可布局当成产品正式窗口下限。每页至少核对最小正式窗口、常用横向窗口和纵向窗口。

## 4. 控件状态与操作

同类控件使用共同模板，默认、悬停、按下、选中、键盘焦点及禁用状态必须清晰。选中控件悬停后仍能辨识选中状态；键盘焦点不能只表现为鼠标悬停。禁用状态不显示可执行的假成功反馈。

**局部功能操作优先有图标：排版空间充足时使用图标＋短文字，空间紧凑时使用仅图标。** 创建、复制、删除入口、复位、取消、应用、关闭、收起、排序等常见动作都遵循该规则。文字直接标明动作，按钮外不再重复同一名称。

空间充足指加入短文字后，不挤占团子、素材、参数或必要反馈，不产生溢出或被迫换行，也不需要缩小字号或命中范围。窄窗口和紧凑工具列可切换为纯图标，动作、位置关系、状态及辅助名称保持一致；陌生或易歧义动作仍按下表保留必要文字。

纯图标按钮沿用 32 × 32 DIP、图标 20 × 20 DIP；图标＋文字按钮使用带文字组件的内边距与高度，宽度随内容，不能强塞进 32 DIP 方形。同组间距沿用 8 DIP。主操作通过选中底色、边界和状态突出，不靠加大文字按钮突出。

| 场景 | 默认表达 |
|---|---|
| 编辑与对象工具 | 空间充足用线性图标＋短文字，紧凑布局用仅图标；例如创建加号、复制重叠图形、删除垃圾桶、排序方向箭头 |
| 草稿操作 | 复位回转箭头、取消 X、应用勾；空间充足附“复位／取消／应用”短文字，沿用原操作语义与保存区归属 |
| 页面主导航 | 保留可理解的文字或图标加短文字，沿用已批准导航；不因图标优先自动改版 |
| 参数与内容 | 保留参数标签、单位、数值和必要分组名称，不把内容标签当作按钮一起隐藏 |
| 陌生或易歧义动作 | 保留图标＋短文字或短文字按钮；空间不足时先调整布局，不能为了只留图标而隐藏必要含义 |
| 失败、恢复与破坏性确认 | 保留结果、原因、目标和后果文字；删除入口可为图标，两次确认不能只有图标 |

图标按钮提供中文提示与辅助名称，鼠标悬停和键盘焦点均能获得说明。不要只用省空间作为图标选型依据；动作不易理解时采用上表例外。图标变细不能缩小实际点击范围。

同义动作复用同一图标，不让不同页面重新画出互不一致的版本。图标的朝向、形状、选中状态及名称同时表达当前动作，例如睡眠比较切换为醒来时同步更新图形、可见短文字、提示和辅助名称。解释复杂行为、失败原因或破坏性后果时保留文字。该规则不授权批量替换现有页面按钮。

### 4.1 参数滑条

所有参数滑条采用同一视觉组件，保留各参数的合法范围、单位、步长、方向和默认值。不得统一成 0–100、整数步长或同一个复位值。

本轮样板以 **3 DIP 轨道、12 DIP 圆形滑块、28 DIP 操作高度**为实现起点。经过部分与滑块使用 `HomeAccent`，未经过部分使用 `HomeLine`；悬停与拖动给出轻量反馈，禁用状态保留可辨识轮廓。视觉细度不缩小实际命中区域。

拖动直接映射参数值，不给滑块位置或实际数值加缓动、惯性。指针、键盘和辅助操作应进入同一更新路径。数值输入与滑条值一致；非法输入保留明确反馈，不静默提交无效值。是否提供可编辑数值框按页面需求决定，保留当前捏脸描述值与配饰可编辑数值框的差异。

调整只更新当前预览草稿，应用才提交；取消恢复保存值，复位先进入草稿。页面切换、关闭、隐藏和弹窗取消沿用各自的完整草稿合同。

### 4.2 反馈与破坏性操作

执行结果以真实业务状态为准。宿主或存储失败时，显示原因及可执行的恢复入口；不能用 Toast 或乐观勾选替代真实结果。操作成功而保存失败时，区分已生效的会话状态与尚未保存的状态。

永久删除与草稿应用独立。配饰删除保持两次确认，只提交目标删除，不顺带保存其他草稿；取消删除不提交输入缓冲。通用保存按钮样式不改变这一事务边界。

## 5. 滚动规范

### 5.1 常驻细条

内容确实可滚动时显示细滚动条，平时可见，悬停、键盘焦点和拖动时加深。没有可滚动内容时隐藏或禁用，不能呈现可拖动的假滑块。轨道与内容区保持稳定，状态变化不挤动正文。

本轮样板以 **6 DIP 可见宽度、16 DIP 命中宽度、28 DIP 最短滑块**为实现起点。正常滑块为暖棕 `#B7A28E`，轨道使用 `HomeSoft`，激活使用 `HomeAccent`；滑块长度反映可见内容占比。横向滚动条出现时沿用同一规则。

滚动条的透明命中区域不遮挡相邻按钮、数值或内容。拖动直接跟随指针，不能用缓动掩盖 UI 阻塞。拖动期间离开滑块或命中区域仍保持鼠标捕获与跟随；松手、失焦、关闭、隐藏或取消时终止操作，不遗留输入捕获。

### 5.2 滚轮与嵌套区域

滚轮允许短时平滑衔接：连续输入更新目标位置，反向输入及时响应，不排队补播、不过冲、不在停止后摇摆。样板的过渡设置为 180 ms，正式参数以真实 WPF 测量和人工手感校准；这不是已经验收的生产延迟门槛。

同一滚轮位移不得重复消费。优先滚动鼠标所在的有效区域；内层到达对应边界后，只把未消费的余量交给可滚动祖先。允许一次输入跨越内层边界后由外层承接余量，不能让两层各执行完整位移，也不能吞掉余量。拖动滚动条不转交外层。图片画布保留滚轮缩放，参数拖拽、菜单、文本编辑和模态保留自身输入边界，不触发团子动作。

尊重系统减少动画设置：关闭滚轮缓动和装饰过渡，保留直接滚动、直接拖动及清晰状态。不得为滚动另增物理推进、团子实体或帧 owner。

### 5.3 流畅性与根因

用户反馈所有可滚动页面都明显卡顿，包括拖动侧边滚动条。这是待复现的症状；默认步进、多层滚动及图库缩略图更新是检查方向，不能提前认定根因。

生产修复先对原版测量滚轮、滚动条拖动及参数拖动，区分步进感、输入路由、UI 线程停顿和显示长帧。图库对比冷缓存、重复滚动及不同素材数量。记录输入至显示延迟、真实滚动位置、显示帧间隔和必要的加载耗时，不记录真实窗口内容、输入文本、文件内容或账号信息。

修复后用相同设备与工况复测，保持真实预览、素材和画质。平均 FPS、动画样板和截图不能代替生产页面持续操作的流畅验收。具体实施与门禁见[滚动组件实施计划](planning/2026-10-10-scroll-controls-implementation-plan.md)。

## 6. 新界面的执行清单

设计阶段明确页面主要任务与常用路径，标注本规范采用的布局和组件、允许的业务差异及其理由；样板至少展示常用操作、滚动内容、未保存状态和失败恢复。新增结构或行为先确认设计，再实施。

实现阶段复用共同资源与模板。独立窗口也使用同一资源来源；高对比或主题改变时各窗口一致更新。共享 WPF 资源的抽取属于后续实施，当前源码中的重复主题尚未迁移。

验收按以下清单记录结果：

- [ ] 颜色、字体、图标、尺寸与状态符合共同规则，页面例外可追溯。
- [ ] 常用功能操作空间充足时采用图标＋短文字，紧凑布局采用仅图标；切换不挤压内容、不改变动作含义，图标提示与辅助名称齐全，同义动作一致。
- [ ] 最小正式窗口、横向及纵向布局无裁切；滚动不会带走必要操作或掩盖失败。
- [ ] 鼠标、键盘、辅助操作与焦点恢复一致；页面输入不误触团子动作。
- [ ] 预览、草稿、应用、取消、关闭及保存失败符合真实业务合同。
- [ ] 滚轮、拖动、嵌套边界和图片缩放例外经真实控件验证。
- [ ] 支持范围内的 DPI、高对比和减少动画分别核对，未执行项明确标记。
- [ ] 构建、自动门禁、真实行为、人工观感和 Git 交付分别报告。

截图用于核对静态布局，真实连续操作用于判断手感。测试应能因裁切、错误路由、假保存或拖动迟滞而失败，不能只比较模板或声明属性。

## 7. 本轮交付状态

本轮用户选择了“常驻细条”。浏览器样板已检查滚轮中间位置、反向输入、真实侧边拖动与松手停止、参数键盘更新、减少动画以及窄宽无横向溢出；这些结果只证明样板行为。[常驻细条样板](prototypes/dango-scroll-controls.html)保存已选择的方向。

本轮落地规范与实施计划，生产 WPF 滚动条、参数滑条、公共主题及卡顿修复尚未实施。真实 Windows 卡顿复现、DPI／高对比矩阵和生产人工验收均未验证，本规范不改变已有阶段验收状态。

用户随后明确授权将规范资料合入本地 main；本次合并范围为 AGENTS 入口、界面规范、滚动组件实施计划和常驻细条样板，不包含生产代码、推送、日常安装、部署或 DLL 替换。这一批新产出的界面待批次工作结束后，由用户另行安排统一调整；本次不提前实施该批量调整。
