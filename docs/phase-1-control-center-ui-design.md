# Dango 控制中心 UI 设计

> 状态：已批准设计，尚未授权实施
>
> 日期：2026-09-01
>
> 批准记录：用户于 2026-09-01 明确批准
>
> 适用阶段：Phase 1 桌面生命感原型，并为后续首版扩展保留边界
>
> 前置设计：[Phase 1 桌面生命感原型详细设计](phase-1-desktop-life-prototype-design.md)
>
> 当前实现证据：[P1-002 透明覆盖层宿主验证记录](verification/phase-1-p1-002-overlay-host.md)

## 1. 决策摘要

Dango 增加一个正式的图形化“控制中心”，同时承担两个职责：

1. 在 Phase 1 为用户提供可理解、可操作、可留痕的桌面宿主验收入口。
2. 在后续首版中承载团子、房间、好友、设置和本地状态管理，而不是交付后废弃的测试工具。

控制中心与桌面上的团子场景是两个独立窗口：桌面宿主负责长期、低干扰地显示团子；控制中心是按需打开的普通 WPF 管理窗口。Phase 1 只详细实现本地桌面控制、实验与验收、诊断摘要和应用生命周期。账号、好友、房间等业务页只定义未来导航位置和扩展边界，不显示没有真实能力支撑的入口或假数据。

实现已登记为 `P1-002A — 控制中心壳层与验收入口`，置于 P1-003 之前。设计批准只授权同步实施计划，不自动授权编写 UI 代码，也不改变 P1-003 的既有范围。

## 2. 目标与非目标

### 2.1 目标

- 用户无需阅读 Markdown 或使用命令即可控制显示、隐藏、交互和退出。
- 用户能够从同一界面了解当前宿主、构建、显示器和验收状态。
- 每一项人工验收都有操作说明、预期结果、用户结论和备注。
- 自动门禁、实时观测和人工结论明确分层，不能互相冒充。
- 控制中心以后可以增加正式业务页面，不需要推翻窗口生命周期、导航和状态反馈。
- 不读取、不展示、不导出与验证无关的桌面隐私信息。

### 2.2 非目标

- 本设计不实现账号、好友、房间、聊天、联网或同步。
- 不在控制中心内嵌桌面画面、屏幕录制、窗口列表或实时桌面缩略图。
- 不用 UI 勾选替代真实 Windows 操作；人工结果只能由用户明确确认。
- 不因为增加控制中心而判定 P1-002 通过，也不提前选择 Overlay 或 WorkerW。
- 不引入第三方 UI 框架、主题包、依赖注入框架或数据库。
- 不把开发者压力场景包装成真实多人房间。

## 3. 使用角色与入口

### 3.1 Phase 1 验收者

需要快速确认透明区域穿透、焦点、拖动、托盘、全屏、DPI 和进程回收，并记录哪些项目未执行、通过或失败。

### 3.2 后续普通用户

只需要控制 Dango 的显示、交互、动画强度和退出。实验宿主、测试场景和技术诊断默认不出现。

### 3.3 入口规则

- 托盘菜单首项为“打开 Dango 控制中心”，双击托盘图标执行相同操作。
- 控制中心打开时是普通任务栏窗口，不置顶，不覆盖全屏应用。
- 关闭按钮仅关闭控制中心并让 Dango 继续驻留；首次关闭时明确提示“Dango 仍在托盘运行”。
- “退出 Dango”始终是单独的明确操作，并回收控制中心、桌面宿主、托盘和采样器。
- 再次启动已有实例时，应唤起现有控制中心，而不是静默退出或创建第二个实例。

## 4. 信息架构

Phase 1 只显示四个一级页面：

| 页面 | 当前职责 | 后续演进 |
|---|---|---|
| 概览 | 桌面宿主状态、关键开关、未完成验收、异常提示 | 团子与当前房间摘要 |
| 桌面体验 | 显示、交互、降低动画、宿主模式与安全恢复 | 正式桌面和动画设置 |
| 实验与验收 | 分组清单、操作说明、人工结论和导出 | 默认隐藏，仅开发版或显式开启 |
| 诊断 | 隐私安全的环境、宿主、性能和错误摘要 | 用户支持与故障报告入口 |

“团子”“房间”“好友”“账号”等未来页面不在 Phase 1 以禁用按钮占位。等真实领域能力进入已批准阶段后，再按同一导航容器增加页面，避免造成“功能即将可用”或“已经联网”的误解。

### 5.1 概览

```text
┌────────────────────────────────────────────────────────────────────┐
│ Dango                                                        — □ × │
├───────────────┬────────────────────────────────────────────────────┤
│ ● 概览        │  早上好，团子正在桌面上                              │
│   桌面体验    │                                                    │
│   实验与验收  │  ┌──────────────┐  ┌──────────────┐                │
│   诊断        │  │ 桌面显示  开 │  │ 交互模式  开 │                │
│               │  └──────────────┘  └──────────────┘                │
│               │                                                    │
│               │  当前宿主                                          │
│               │  透明覆盖层 · 正在运行 · 尚未完成人工验收             │
│               │                                                    │
│               │  待你确认  6 项                           [继续验收] │
│               │  输入穿透、焦点、拖动、托盘、全屏、DPI                │
│               │                                                    │
│               │  [隐藏桌面团子]                    [退出 Dango]      │
├───────────────┴────────────────────────────────────────────────────┤
│ 本地运行 · 未连接服务器 · P1-002 Overlay Spike                     │
└────────────────────────────────────────────────────────────────────┘
```

概览只展示用户现在可以行动的信息。状态文案必须同时包含“运行状态”和“验证状态”，例如“正在运行 · 尚未完成人工验收”，不得仅显示容易被理解为方案通过的绿色“正常”。

### 5.2 桌面体验

```text
┌──────────────────────────────────────────────────────────────┐
│ 桌面体验                                                      │
│ 控制团子的本地显示方式，不会读取桌面内容。                       │
│                                                              │
│ 桌面显示                                      [ 开 ]           │
│ 关闭后停止可停止的渲染活动，托盘与控制中心仍保留。               │
│                                                              │
│ 允许与团子互动                                [ 开 ]           │
│ 关闭后团子区域也不应阻挡桌面操作。                              │
│                                                              │
│ 降低动画                                      [不可用]         │
│ 将在 P1-004 接入；当前不显示可操作开关。                         │
│                                                              │
│ 实验宿主                                                      │
│ ● 透明覆盖层   尚未通过验收                                    │
│ ○ WorkerW      尚未实现                                       │
│                                            [查看验收要求]       │
└──────────────────────────────────────────────────────────────┘
```

宿主切换只有在目标宿主已实现、通过最低安全检查且当前没有拖动或恢复操作时才可用。切换失败必须回到上一个安全状态并显示原因，不能只切换单选框外观。

### 5.3 实验与验收

```text
┌────────────────────────────────────────────────────────────────────┐
│ 实验与验收                                                         │
│ 透明覆盖层 / Windows 11 / 2560×1440 / 150%                         │
│                                                                    │
│ 进度  0 / 6 已确认             [新建本次验收] [导出报告]             │
│                                                                    │
│ ▾ 输入与焦点                                                       │
│   透明区域穿透                                  未验证               │
│   操作：在透明区域单击桌面图标、右键并拖出框选。                     │
│   预期：行为与 Dango 未运行时一致。                                 │
│   结果： ( ) 通过  ( ) 失败  ( ) 无法执行                           │
│   备注： [____________________________________________________]    │
│                                                                    │
│ ▸ 拖动与取消                                          0 / 1         │
│ ▸ 托盘与退出                                          0 / 1         │
│ ▸ 全屏与窗口层级                                      0 / 1         │
│ ▸ DPI 与显示器                                        0 / 2         │
│                                                                    │
│ 提示：这里记录的是你的人工结论，不会被标记为自动测试通过。            │
└────────────────────────────────────────────────────────────────────┘
```

验收页以现有验证记录为来源，但 UI 中的每个项目必须有稳定标识，不能依赖显示顺序。一次验收记录至少包含：应用版本、构建标识、宿主模式、OS Build、显示器与 DPI 摘要、开始时间、各项结论、用户备注和结束状态。

验收结果只有四种：

| 状态 | 含义 |
|---|---|
| 未验证 | 尚未由用户执行或没有证据 |
| 人工通过 | 用户执行说明中的操作并明确确认符合预期 |
| 人工失败 | 用户观察到不符合预期的行为，必须允许填写备注 |
| 无法执行 | 当前设备或环境不具备条件，必须填写原因 |

“保存”只保存用户输入，不自动提升阶段状态；“导出报告”生成分层报告，也不自动写回 Git 文档或把候选标记为通过。

### 5.4 诊断

诊断页使用分组键值和状态徽标，不再使用当前一次性消息框：

- 应用：版本、构建类型、资产版本、启动时长。
- 宿主：模式、可见性、交互状态、恢复状态、最后一次安全降级。
- 显示：OS Build、显示器数量、工作区尺寸和 DPI 摘要。
- 性能：只有 P1-005 接入后才显示平均/P95 帧时间、FPS、CPU、工作集和 GPU 观测值。
- 错误：不含敏感请求体的最近异常摘要与发生时间。

每项数据标明“已采集”“未采集”或“当前版本不支持”。未知值显示“未采集”，不得填 `0`、`正常` 或占位成功值。

## 6. 视觉语言

控制中心采用轻量、安静、带少量软萌气质的桌面工具风格，不做重型游戏启动器。

| 元素 | 规则 |
|---|---|
| 窗口 | 建议初始尺寸 960×640，最小 820×560，可调整大小并记住非敏感窗口尺寸 |
| 背景 | 暖白 `#FFF9F3`，内容卡片 `#FFFFFF`，边界 `#E9DED4` |
| 主色 | 杏橙 `#F28C52`，只用于主操作、选中导航和焦点状态 |
| 状态色 | 通过 `#2E8B6D`、警告 `#B7791F`、失败 `#C84A4A`、未验证 `#6B7280` |
| 字体 | 优先系统 UI 字体；中文跟随系统回退，不捆绑新字体 |
| 圆角 | 卡片 12 px、按钮 8 px；不用过度阴影和持续发光 |
| 动效 | 页面切换 120–180 ms 淡入；遵循降低动画和系统动画设置 |

颜色不能作为唯一状态表达。所有状态同时使用图标或文字，例如“● 人工失败”。正文和关键控件在 100%–200% 缩放下不得截断，键盘焦点必须清晰可见。

## 7. 交互与状态规则

### 7.1 命令反馈

- 开关先进入“正在应用”，收到宿主确认后再显示最终状态。
- 超时或失败时恢复原状态，并给出可复制的安全错误摘要。
- 影响桌面输入的操作显示明确后果；退出、重置验收记录等高影响操作需要确认。
- 控制中心不可用时不得影响托盘退出；桌面宿主异常时控制中心仍应可以打开并执行安全隐藏或退出。

### 7.2 能力状态

所有 UI 能力由真实状态驱动：

- `不可用`：当前版本未实现，不渲染为可点击控件。
- `可用`：可以发起操作，但不代表正在生效。
- `应用中`：命令已发出，等待宿主确认。
- `已生效`：宿主返回与目标一致的确认状态。
- `已降级`：发生错误后进入安全隐藏或其他受限状态。

UI 不直接修改 HWND、Shell 句柄或场景状态。它提交应用命令并订阅只读状态快照，宿主层负责验证、执行和确认。

### 7.3 可访问性

- 所有功能可用键盘完成，导航顺序与视觉顺序一致。
- 开关、单选、状态徽标和验收选项提供清晰的自动化名称。
- 不用仅靠悬停显示重要说明；错误信息可选择和复制。
- 支持 200% DPI、Windows 高对比度和系统降低动画偏好。

## 8. 应用结构与职责边界

首个实现继续使用现有 WPF 工具链，不新增项目和第三方 UI 依赖。建议在 `Dango.Desktop` 内按职责组织：

```text
Dango.Desktop/
  AppShell/
    ControlCenter/        普通窗口、导航和页面组合
    Tray/                 托盘入口与应用级命令
  DesktopHost/
    Overlay/              P1-002 覆盖层适配
    WorkerW/              P1-003 未来适配
  Diagnostics/            只读快照、采样与隐私过滤
  Verification/           验收定义、会话、结果与导出
```

- `Dango.Core` 继续不知道 WPF、托盘、窗口、Win32 和验收页面。
- 控制中心不直接引用某个具体宿主窗口；它依赖应用级宿主控制接口和状态快照。
- 托盘与控制中心共享同一组应用命令，不能分别维护两套显示/隐藏状态。
- 验收定义与结果模型独立于具体控件，便于单元测试和 Markdown 导出。
- 未来账号、房间等业务状态来自服务端权威接口，不写进本地验收模型。

第一版优先使用 WPF 自带绑定、资源字典和命令模式。若没有明确重复和测试收益，不为“架构完整”提前引入 MVVM、消息总线或导航框架依赖。

## 9. 本地数据与隐私

### 9.1 本地保存

实现阶段可在 `%LOCALAPPDATA%\Dango` 下保存版本化的本地设置和验收草稿，采用临时文件写入后原子替换，避免异常退出留下半份记录。建议分为：

- `settings.json`：控制中心窗口尺寸、降低动画偏好等非敏感设置。
- `verification/`：用户主动创建的本地验收会话。

账号令牌、密码或未来服务端凭据不得进入这些 JSON；正式认证应使用单独批准的安全存储方案。

### 9.2 禁止采集

控制中心、诊断和验收记录均不得采集：

- 用户名、真实窗口标题、窗口内容和窗口列表；
- 桌面截图、桌面文件名、文件路径和剪贴板；
- 原始键盘输入、完整鼠标轨迹或可还原用户行为的事件流；
- 访问令牌、密码、连接串、真实账号和敏感请求体。

导出必须由用户主动操作，先显示包含字段和保存位置。导出内容只包含环境摘要、Dango 自身状态、验收结论和用户主动填写的备注。

## 10. 验收与证据分层

控制中心中的报告固定分为：

1. **静态门禁**：由构建或测试真实产生；UI 只能显示已导入的结果与时间，不能自行声明通过。
2. **集成门禁**：Phase 1 没有网络或数据库时显示“不适用”，不得显示绿色通过。
3. **实时行为**：记录宿主已启动、恢复事件等可观测事实；可见、穿透和焦点等无法可靠自动判断的项目保持未验证。
4. **人工验收**：用户逐项给出通过、失败或无法执行，并可填写备注。
5. **交付状态**：是否提交、合并、推送和部署来自明确记录，不由运行中的客户端猜测 Git 状态。

报告首页必须同时显示未验证数量和失败数量。只要存在失败或必需项未验证，就不得生成“P1-002 已通过”的总标题。

## 11. 分阶段落地建议

以下工作已同步至 Phase 1 实施计划；用户另行授权开始实现后再逐步执行：

### P1-002A.1 — 控制中心壳层

- 普通 WPF 窗口、导航、托盘打开、关闭到托盘和单实例唤起。
- 接入现有显示/隐藏、退出和 P1-002 只读诊断。
- 先写窗口生命周期、命令状态和重复打开的失败测试。

### P1-002A.2 — 验收会话

- 把现有 P1-002 清单转为稳定、版本化的验收定义。
- 支持人工结果、备注、本地草稿和分层 Markdown 导出。
- 先验证缺项、未知枚举、旧版本记录和隐私字段会被拒绝。

### P1-002A.3 — 视觉与真实桌面验收

- 验证 100%–200% DPI、键盘操作、关闭到托盘和安全退出。
- 用户验收布局、信息密度、状态是否易懂以及是否干扰桌面。
- 完成后仍回到 P1-002 宿主人工清单；控制中心通过不等于宿主通过。

P1-003 后只增加 WorkerW 能力与对应验收定义，不复制一套控制中心。P1-005 通过同一诊断接口增加性能采样和压力场景。

## 12. 设计验收标准

本设计已按以下标准于 2026-09-01 获用户批准：

- 控制中心是长期产品入口，而不是一次性调试窗口。
- Phase 1 只显示真实存在的本地能力，未来业务入口暂不展示。
- 验收页允许人工留痕，但不伪造自动结果或阶段结论。
- 关闭控制中心继续驻留，退出 Dango 明确回收全部本地组件。
- 视觉方向是暖色、轻量、安静的桌面工具，而不是重型游戏启动器。
- 本地诊断和导出遵守隐私红线。
- 获批后先更新 Phase 1 实施计划，再开始任何 UI 代码。

## 13. 明确延期项

- 正式团子形象、装扮预览和资产编辑。
- 登录、账号、好友、房间、权限与邀请流程。
- 自动更新、安装修复和线上故障上报。
- 多语言、完整主题系统和品牌插画资源。
- 面向普通用户的引导流程与实验功能解锁方式。
- 控制中心以外的平台客户端 UI。

这些内容分别属于 Phase 4 或后续设计，不得静默加入 Phase 1 控制中心实现。
