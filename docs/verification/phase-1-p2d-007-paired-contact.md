## 1. 范围与结论

本检查点只验证本地虚构场景中的两个软体环能在同一个 Box2D world 中真实接触，并由唯一共同 `PairedPresentationContactCue` 形成互补横向挤压，取消 cue 后有界分开和收束。它不创建账号、好友、房间或网络连接，也不代表正式贴贴或多人同步功能完成。

新增 paired native session，与已经稳定的单体 soft-body session 隔离。两只团子各自拥有独立运动学核心、动态外圈节点和弹簧；节点只与对方节点及对方的核心碰撞代理接触。托管层每帧传入两个 Core 权威边界换算的锚点；native 只返回双方局部轮廓、真实 contact 数和最大节点速度，不能回写或推动权威锚点。

## 2. 先失败验收

`Box2DPairedContactWorldTests` 首次运行因 `Box2DPairedContactPresentationWorld` 与 `PairedPhysicsPresentationFrame` 不存在而以 `CS0246` 失败。实现后覆盖：

- 共同 cue 的参与者必须与两份输入完全一致，接触法线必须为单位方向；
- 两个软体环共享一个 native world 并产生真实 Box2D contact；
- 双方沿共同法线互补挤压，且返回帧保留两份原始权威边界；
- cue 取消且权威锚点分离后，180 帧内 contact 归零、速度和质心偏移收束；
- 宿主 fallback 立即销毁 paired world，双方进入同一受控 fallback；
- paired 契约不含账号、好友、房间或网络语义。

## 3. 实现边界

- bridge ABI 升至 v6，Box2D 版本继续固定为 3.1.1；新增 `paired_soft_body_create/step/destroy` 三个导出。
- 接触开关只在 cue 状态改变时切换节点碰撞过滤；无接触阶段不每帧唤醒节点。
- cue 只启用这一对参与者的碰撞；形变完全来自双方轮廓节点、对侧核心代理和 Box2D 接触解算，不预先缩短整圈弹簧，也不额外施加相向力。
- 渲染轮廓采样节点圆的外表面，而不是节点中心线；测试按与 WPF 相同的局部坐标比例验证接触面间距，避免不可见碰撞壳已经接触但画面仍留缝。
- paired world 使用共享静态地面、重力和节点地面摩擦；地面 contact 与双体 contact 分开计数。预览的地面线与 native 地面高度一致。
- paired configured create 直接接收 `SoftBodyTuningParameters` 的已验收默认值：宽高、顶部圆度、下半部鼓度、底部平坦度、常态压缩、地面高度、节点质量、弹性、阻尼和接触材料均与 P2D-005 单团子候选一致；双体接触只叠加在该常态轮廓之上。
- paired 节点将物理碰撞半径设为视觉轮廓半径的 10%，渲染仍使用完整视觉半径；这允许轮廓在真实 Box2D contact 下产生明确但有限的视觉重叠，而无需把整只团子压扁来消除碰撞壳缝隙。
- 物理局部坐标与 WPF 实际横向映射比例不同：早期候选的物理轮廓虽已重叠，映射后仍留下 `+1.71 px` 空隙。paired 表现帧现按 cue 强度提供对称接缝补偿，只移动双方渲染位置，不改变权威边界或物理锚点。当前强挤压预览把 cue 从 `0.8` 提高到 `1.0`，并让双方接触锚点再靠近 8 DIPs；稳定接触时实际渲染间距为 `-2.01 px`。
- cue 激活时按节点相对接触法线的位置调整骨架材质：接触侧径向/轮廓弹簧局部柔顺，远侧弹簧加强并施加有上限的横向回形力；cue 取消后弹簧恢复常态参数。
- 托管层把两份权威锚点换算为接触中心两侧的对称物理锚点；预览中的两只团子也同时向中心靠近和分开，避免单侧运动惯性被误认为材质形变。
- `--paired-contact-preview` 使用两只固定虚构标识，按 8 秒确定性时间线执行“分离 → 靠近 → 接触保持 → 释放 → 分离”。
- 预览提供“显示物理骨架”开关，同时显示双方轮廓节点、相邻弹簧、径向弹簧和物理核心。
- `DeformableDangoVisual.BodyFill` 提供可复用体色入口；预览分别使用暖杏色和浅蓝色，便于辨认双方接触边界。
- 预览窗口只显示表现帧和 contact/速度诊断，不读取窗口标题、桌面内容、真实鼠标轨迹或键盘输入。
