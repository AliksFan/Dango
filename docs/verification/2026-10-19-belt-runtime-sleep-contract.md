# 连续外圈 Runtime 与单体休眠候选验证

本文保留严格状态趋势 v1 的历史合同、关闭默认开关的停止点及失败。用户随后选择方向2；当前候选的独立 v2 实现、结果与默认开关状态见[可见形变合同 v2](2026-10-19-belt-visible-deformation-sleep-v2.md)。本文的“当前／默认关闭”均指 v1 停止时快照，不覆盖后续授权，不回写旧 FAIL。

日期：2026-10-19。实现范围为单体、平地、独立 native owner；不覆盖房间、多体、家具、正式安装或功率。默认 `SleepEnabled=false`，休眠尚未完成全部工况验收。

## Runtime 合同

- 唯一长驻线程创建、重配置、推进、读取和释放 native world。生命周期屏障立即使旧 epoch 失效，并等待有限在途 native 调用交还 owner。
- 同一 body epoch 的参数请求只合并尚未开始的完整三元组，保留所有已成功入队快照。成功快照 FIFO 容量 8，持续满 500ms 锁存明确错误；晚到消费者不能撤销已到期失败。
- 快照分别携带生命周期 epoch、编辑会话 body epoch、configuration revision、成功 tick、sequence、实际参数和实际输入。显示旧 FIFO 项不能解除新草稿的保存门。
- 步失败锁存；普通改参不能自动抹去。显式新 body epoch 配置成功可恢复，`LastFailure` 仍保留取证。
- 休眠时 worker 无定时唤醒，不推进求解、不生成假 tick。输入、配置、边界、生命周期和开关变化保留事件序号，入睡判定至 WaitOne 之间的事件不会丢失。醒后重置墙钟调度，不补算睡眠时间。

## 被否定的初始候选与实现错误

初始候选要求 120 稳定 tick、所有 q/真实曲线/核心单步差不超过 `1e-5`、窗口差不超过 `1e-4`，并要求所有广义 v 绝对值不超过 `5e-4`。默认身体 3600 成功 tick 后仍未入睡，v 最大值为 `0.0027795358363925595`。该绝对 v 门为 **FAIL**，后续合同不能改写此结果。

首次 worker 实验还同时存在字段语义错误：把 snapshot[79] 当成剩余冷却时间，使用 `>0` 拒睡。实际 native 创建时赋配置冷却时间，之后每子步增加 elapsed，接受跳跃时归零。短探针默认 tick100/600 的 elapsed 分别为 2.116660/10.449960，grounded=true、contact=3、ramp=0。修正为 `state[79] < state[125]` 才拒睡；125 对应实际 native 配置的 jump cooldown。该修正不改变任何数值阈值或 native 参数。新趋势合同在修正之前的默认／走停不睡失败也保留。

native 源码顺序说明绝对系数 v 不等于整个 tick 的净坐标变化：积分先写 `(q-old)/dt`，地面位置投影仅修 q，随后 Coulomb 接触解再修 v。静止支持可以保留恒定非零 v 残量。不能只检查 COM，也不能清零该残量制造睡眠。

## 新独立 F6a 合同

主 Agent 在收到自然静置 q/v/曲线/核心测量后批准以下独立合同；它替代初始绝对速度候选，保留原候选 FAIL。

- 连续 120 个合法支持状态；真实接地、至少一个接触、完整输入空闲、ramp=0、拖动关闭、实际跳跃冷却已过。
- 全部 36 个 q：逐 tick 差 `<=1e-5`，候选窗口逐分量 max-min 包络 `<=1e-4`。
- 全部 36 个 v：逐 tick 差 `<=5e-4`，候选窗口逐分量 max-min 包络 `<=5e-4`。允许稳定的接触残量，保留原始 v，继承 native 原有限速门。
- 全部 256 点曲线和核心：逐 tick 每轴差 `<=1e-5`，窗口每轴 max-min 包络 `<=1e-4`。窗口门不因某个端点未入睡而扩大。
- 活动输入包括相反键同按；故障、无支撑、空中、内部 q 持续移动、v 随窗口漂移均不得睡眠。

## 实际执行及剩余失败

冻结新门且修复 elapsed 语义后，定向套件 **40/41**：

- 默认真实 native 入睡、完整 numeric snapshot／scaffold／curve／stats 冻结，以及醒后与未睡眠同 state 的下一固定步对照通过。
- 确定性 owner、FIFO、配置版本、保存陈旧回执、在途屏障、输入边沿、判睡至等待精确竞态、正常睡眠无定时轮询、关闭释放等通过；内部 q/完整 v 趋势、空中、无接触、相反输入、未过跳跃冷却、故障反例覆盖。
- 走停 tick2603、跳跃释放 tick491、热编辑 tick436、取消恢复 tick345 入睡并唤醒通过。数值是物理 tick，不能把加速测试墙钟当作真实等待时间。
- **拖动释放 FAIL**：轻量拖动脚本释放后继续 3600 tick，总 tick3914 仍未达到门。末 121 帧真实接地、contact=3、ramp=0、drag=false、elapsed=65.683>配置冷却 .45；q 单步 `2.20551e-6`、v 单步 `1.41388e-7`／窗 `1.69447e-5` 均符合门，但 q 窗 `0.000264525`、curve 窗 `0.000242718` 超过 `1e-4`。核心窗只有 `7.45058e-7`，说明只看核心会误睡，真实形变趋势仍应拒睡。保持失败，未放宽阈值；尚未证明该工况能够节能入睡。
- 真正 wall-clock worker 的 3 秒 CPU A/B 通过：相同默认参数、同自然稳定状态、相同每 8ms 消费循环。开：进程 CPU 0.000ms，native call 0，分配 40904 bytes；关：984.375ms，native call 179，native step 926.563ms，分配 2889432 bytes。满足事先固定的 call=0、关侧至少 120 次、CPU 降至少 50% 门。该实验无 WPF 外观负载，不能代替实际产品 CPU／外观／输入体验验证，也不代表功率测量。

最初完整 Desktop test 命令被既有 NU1903 阻挡；上述定向运行使用 `-p:NuGetAudit=false`，不记作默认审计通过。随后更强原始字节断言＋全部确定性 worker 用例针对性运行 26/26 通过，证据为 `trend-gate/raw-state-and-deterministic.trx`。增加失败末窗诊断后，5 个活动工况的原始字节复验为 4 通过／拖动 1 失败，见 `activity-raw-state-and-drag-window.trx` 和 `activity-drag-release-window.json`；失败没有通过更换断言或放宽门消失。

### 独立延长观察

主 Agent 随后明确授权相同拖动脚本、相同冻结门、释放后最多 12000 tick 的独立长观察；原 3600 tick 失败 case 保持原样。每 120 tick 写一条完整 q/v/curve/core 窗口上界，共 100 条。结果为 **UNSTABLE_AT_CAP**：释放后 12000 tick（总 tick12314）仍未睡；最后 q 窗 `0.000230212243`、curve 窗 `0.00021181256` 仍超过 `1e-4`，v 窗 `1.29196628e-5`、core 窗 `5.66244e-7`。这再次确认严格形变门正确拒睡，但没有建立拖动后节能入睡覆盖。

独立测量测试执行成功只表示完整观测至上限且未出现物理故障，不能写成拖动节能目标通过。证据是 `trend-gate/drag-release-extended-observation.json`（100 个窗口）和独立 `drag-release-extended-observation.trx`。

另补一条生命周期取证修复：在途 Step 返回失败时，即使已被 Pause／Close 使 epoch 失效，也保留旧 epoch 的 `LastFailure`；既不发布旧外观，也不将旧失败锁存为新 epoch 的故障。没有改变成功 tick、native 调用、配置或休眠门。加入该真实反例后的全部 26 项 worker 控制用例通过，证据为 `trend-gate/worker-lifecycle-evidence.trx`。
