## 实际浏览器操作

使用本地临时渲染页和浏览器真实控件操作，不注入事件或修改页面状态。

| 场景 | 实际结果 |
|---|---|
| 平台按钮微调及方向键 | 可见位置改变，保存后退出编辑并清除 dirty |
| 未保存重新打开 | 显示“保存并继续／舍弃并继续／继续布置”；继续保留草稿，舍弃恢复已保存布局 |
| 选择同类家具 | 明确拒绝第二件，保留原家具 |
| 平台改用球 | 待放置时保存禁用；取消保留平台；确认后只有一件球，纵向微调禁用 |
| 边界微调 | 越界拒绝，坐标保持，持续显示具体原因 |
| 移除与取消 | 移除只改变草稿；取消恢复保存的家具 |
| 空布局 | 保存后重新打开仍为空，未误判为加载失败 |
| 场景点击与推荐落位 | 两种落位方式均完成；落位后可微调与保存 |
| 房门保存并离开 | 确认后进入离开界面，返回恢复保存布局 |
| 两种方案切换 | 共享同一家具类型、修改和已保存状态 |
| 1024、736、320 宽度 | 两种方案的控件可见并换行；736/320 检查根与文档 scrollWidth 没有超出 clientWidth |
| 待放置时 resize | 取消 ghost，保留已落位平台与 dirty 状态 |
| 控制台 | 最终本地预览未报告 warn/error |

实际发现并修复两项问题：

1. 侧栏退出编辑后，隐藏目录使场景被自动放入固定窄列。浏览态改为单列，重验保存及跨方案返回后场景占满主体。
2. 320 宽度下，最右侧球覆盖房门中心，点击未触发离开确认。房门作为 UI 控件提升层级，最终两种方案均重验，点击真实打开未保存确认。

原生拖拽通过当前浏览器坐标接口未能完成验证：接口报告 iframe 输入坐标不能安全处理。未据此声明拖拽实时通过；仅完成指针点击、方向键和按钮微调，拖拽逻辑另经上述内存检查。用户评审时仍需实际拖动确认。
