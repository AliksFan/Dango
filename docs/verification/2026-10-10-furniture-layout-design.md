实际发现并修复两项问题：

1. 侧栏退出编辑后，隐藏目录使场景被自动放入固定窄列。浏览态改为单列，重验保存及跨方案返回后场景占满主体。
2. 320 宽度下，最右侧球覆盖房门中心，点击未触发离开确认。房门作为 UI 控件提升层级，最终两种方案均重验，点击真实打开未保存确认。

## 后续可调参数控件稿

用户明确“家具参数”应是后续增加的可调项，例如木平台大小、球大小和弹性。当前稿已移除名称、固定尺寸与行为说明组成的只读参数表，改为按家具类型显示禁用的调节控件：平台显示“大小”，球显示“大小、弹性”。名称只标识当前选择；控件旁明确提示“参数调节后续接入”，只显示小/大、低/高，不把示意位置当作真实参数值。

最终 HTML SHA256：`36F11C11DCAB5A459E7B6E5396E65E2B525C98BBBFAB9EFDCA68F15DE94A0606`，46,369 字节，仓库源与对话预览源一致。

实际浏览器检查发现：增加球的弹性行会改变侧栏布局并触发场景尺寸观察器，取消待放置预览。为参数小组件预留两行最小高度后，平台/球切换稳定；随后从空布局选择家具时，操作行由 0 高变为一行仍触发相同取消。最终仅为参数小组件和操作行预留局部空间，并稍减按钮横向内边距；未固定整段或场景高度，未过滤或禁用真实 resize 的手势取消。空布局操作行的实际高度已从 0 变为 40px，参数控件区为 130px。

最终稿定向检查结果：

- JS 语法、文档相对链接和差异空白检查通过；片段没有文档外壳或网络请求调用。
- 实际浏览器确认平台只有大小控件，球有大小和弹性；两控件均禁用，没有假尺寸或物理效果。
- 桌面空布局选择平台、取消后选择球均稳定保留待放置预览；球推荐落位、横向微调、预览保存及移除后取消恢复均正常。球上下微调仍禁用，待放置时保存禁用。
- 1024 与 320 宽度检查通过：根和文档没有横向溢出；窄屏三段位于场景下方，仓库两个纯图标按钮在同一行并保留无障碍名称。320 宽度下，替换为平台及空布局选择球的待放置预览也稳定。
- 真正调整窗口宽度仍取消待放置预览，保留已落位草稿；局部布局修复没有降低该规则。
