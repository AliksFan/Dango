## 1. 范围与当前结论

本检查点以 Core `ActionStateMachine` 为唯一动作转换规则，新增单团子权威动作控制器和可启停的 Desktop 表现运行时。WorkerW 的 60 Hz 调度只把 Core `SceneSnapshot` 转换为 `PhysicsPresentationInput`；表现帧不能自行触发落地、抓岛或改变 Core 状态。

已接入 `Idle`、`Wander`、`ApproachIsland`、`ClimbUp`、`OnIsland`、`ClimbDown`、`Dragged`、`Falling`、`Landing`、`Reacting`、`Hidden` 和退出语义。手工轨迹负责地面游走、接近岛、爬岛、下岛和全局位置，物理只负责局部形变。拖动保留抓取偏移并限制在工作区；释放后由宿主显式调用 Core 落地命令。WorkerW 内视觉与图标上层窗口消费同一帧，Overlay 仅显示同风格静态 fallback。

实现、自动门禁和真实宿主生命周期检查均已通过。用户在逐轮复验方向控制、摩擦、面向与方向跳、双眼和帽子物理连接、拖动命中、连续下落、猛烈摇晃回正及点击位置局部支点后，于 2026-09-04 确认人工验收通过；P2D-006/B6 标记完成。

## 2. 先失败验收与真实缺陷修正

- Core 定向测试最初以 `CS0246` 失败，因为 `SingleDangoMotionController` 尚不存在；Desktop 定向测试同样因缺少 `SingleDangoMotionRuntime` 失败。
- 动作控制器测试确认 100×100 团子在 800×600 工作区内夹到 `(700,500)`，显式落地点 `(520,580)` 产生 `(470,480,100,100)`，600 个表现帧不能把 `Falling` 擅自变成 `Landing`。
- 首次加入完整全局位移后，真实进程在动作周期内崩溃。Windows `.NET Runtime` 事件 1026 确认：全局位置被累计为局部物理锚点，最终使 `PresentationPoint` 越过 `[-1,1]` 契约并抛出 `ArgumentOutOfRangeException`。
- 修复后 WPF 容器直接跟随 Core 权威位置，物理只保留有界的逐帧局部滞后并自动回中；非有限 native 坐标进入安全 fallback，有限坐标在创建表现点前收敛到契约范围。新增持续跨大距离移动回归测试。
- `SingleDangoMotionRuntime` 的 Stop、宿主丢失和 Dispose 测试确认拥有的物理世界被释放，停止后不能继续 Tick，重启会创建新世界。

## 7. 方向控制增量（2026-09-03）

用户批准方向控制设计与实施细节后，当前 P2D-006 增加以下实现：

- Core 新增无原始键码的 `DirectionalControlIntent`、`Jumping` 状态、低速左右加减速、权威单跳轨迹、禁止二段跳、落地后 450 ms 长按复跳和有界挤压 cue；
- 修复“空中松开后重新按住会排队落地复跳”的缺陷；空中重新按下现在被忽略，不会改变落地后的起跳资格；

- 挤压只变换表现轮廓与挂点，保持表现底边和 Core 权威 bounds/ground contact 不变；
- 失焦、隐藏、交互关闭、WorkerW 失效和退出会清空 held 状态并卸载输入桥；拖动仍走 Core 的 `Falling → ConfirmLanding → Landing` 路径。

## 8. 地面摩擦观感增量（2026-09-03）

首次方向控制人工检查确认基本行为已实现，但左右移动仍有明显滑行感。根因边界为：Core 原固定减速度 `140 DIPs/s²` 使最大速度后继续滑行约 0.39 秒/11 DIPs，同时软体表现存在水平滞后。

用户批准采用“软但能踩住地面”的修正，并要求为未来地毯、地板等不同摩擦表面保留扩展边界。实现结果：

- Core 新增 `GroundSurfaceMotionProfile(surfaceId, frictionCoefficient)`；默认地面系数 `1.0`，安全范围 `0.05–3.0`；
- 默认基础摩擦减速度为 `320 DIPs/s²`，从 `55 DIPs/s` 约 172 ms 停稳；低摩擦与高摩擦表面使用同一输入语义但产生不同停止距离；
- `SingleDangoMotionController.SetGroundSurfaceProfile` 是未来权威接触解析的最小入口。本增量未创建家具系统，也未加入地毯/地板实例；
- Core 输出有界接地摩擦 cue，表现层保持底边不动，仅让上半身在启动时轻微滞后、刹停时轻微前倾并回正；
- Box2D 不决定表面类型、摩擦系数、位置或落地结果。

先失败验收最初因表面配置、Core 摩擦 cue 与表现变换器不存在而编译失败。实现后的定向测试覆盖默认停稳窗口、不同表面系数、安全范围、摩擦 cue 回正和表现底边固定。

## 10. Box2D 物理附件增量（2026-09-04）

用户复验后明确要求眼睛和帽子成为 Box2D 中的独立物体，通过物理连接跟随身体，并要求从左转右存在可见过程。此前眼睛由 `PresentationFacingTransformer` 瞬时偏移，帽子只按当前顶部轮廓计算挂点和切线，没有独立惯性。

实现结果：

- 原生桥 ABI 从 v1 提升到 v2，方向目标进入 `dango_box2d_soft_body_step`，原生帧返回眼睛和帽子的位置与角度；

- 帽子创建独立动态 body，通过两条带局部锚点的阻尼距离关节连接顶部相邻节点，位置和旋转均由 Box2D 求解；
- 转向只修改关节目标长度，附件从旧方向逐步移动到新方向；附件不参与碰撞，不能修改 Core 权威位置、落地或工作区边界；
- 移除表现层瞬时朝向变换器；原生不可用或附件失稳时继续使用手工 fallback，不伪造物理结果。

先失败验收 `NativeAccessoryBodiesTurnThroughDampedConnectionsInsteadOfTeleporting` 首次显示左右目标切换前后眼睛位置完全相同。实现后该测试通过，并覆盖首帧不瞬移、眼睛完成左右位移以及帽子随转向移动。共享 Box2D 测试 9/9 通过，覆盖四种节点/子步组合、确定性重放、持续权威位移和 50 次创建/销毁零泄漏。

## 11. 双眼独立与帽子柔化增量（2026-09-04）

用户复验物理附件候选后指出：两只眼睛应独立计算，使转身后眼距轻微减小；帽子转向仍显僵硬。用户批准正面眼距约 `38 px`、转向约 `34 px`，以及帽子约 `250–350 ms` 的轻微滞后和回摆。

实现结果：

- 原生桥 ABI 从 v2 提升到 v3，单一眼睛输出拆分为左右眼独立位置输出；
- 两只眼睛各自创建动态 body，并分别以三条阻尼距离关节连接左右及顶部身体节点；
- WPF 双眼从共同图层拆成 `LeftEyeLayer` 与 `RightEyeLayer`，分别应用原生位置；眼睛尺寸不变；
- 帽子关节从 `4.2 Hz / 0.78` 调整为 `2.8 Hz / 0.55`，线性阻尼从 `2.6` 降到 `1.5`、角阻尼从 `3.2` 降到 `1.4`，转向目标位移从 `0.025` 增到 `0.05`；
- 既有 `EyeFollow`、`HatFollow`、`HatDamping` 调参继续作用于原生附件输出，没有留下失效参数。

先失败验收因表现帧不存在 `LeftEye/RightEye` 而以 `CS1061` 编译失败。实现后定向验收覆盖双眼独立、转向眼距收缩、两眼渲染层独立，以及帽子首帧不瞬移并逐步到达新方向；共享 Box2D 9/9 继续通过。

## 12. 拖动命中修复（2026-09-04）

## 13. 剧烈拖动回正与连续下落修复（2026-09-04）

拖动命中恢复后，人工验收继续发现两个缺陷：快速大幅摇晃会留下持续可见的轮廓变形；在空中松开鼠标后，团子由固定等待直接确认地面位置，表现为瞬移落地。

先失败验收得到以下证据：

- `ReleasedDragFallsContinuouslyBeforeLanding` 首次失败，释放后第一个固定步的 Y 坐标完全不变；
- `ViolentDragShakingReturnsToAStableRestShape` 以 240 帧大幅交替拖动注入能量，释放 1 秒后相对正常轮廓的最大点误差约 `0.0179`，未达到回正门槛。

修复结果：

- Core 在拖动释放后以有界重力和最大下落速度逐帧推进 `Falling`，到达工作区地面时才进入 `Landing`；WorkerW 不再用固定 `260 ms` 计时器直接确认地面；
- 原生桥 ABI 从 v3 提升到 v4，增加拖动恢复 cue；它逐帧衰减轮廓与附件残余速度，并把轮廓平滑拉回当前目标形态，不修改 Core 权威位置；
- 第一版只在松手首帧触发恢复。用户复验确认连续下落自然，但指出停止摇晃、仍按住鼠标时不会主动回正。后续实现把快速拖动与静止按住分开：位置变化时保持拖动形变，位置静止时每帧恢复；松手后在 `Falling` 中继续恢复最多 `750 ms`，进入 `Landing` 时立即让位给落地回弹；
