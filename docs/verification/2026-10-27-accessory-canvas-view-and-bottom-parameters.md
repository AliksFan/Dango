# 配饰画布视图、底部参数与细调空白修复

2026-10-28更正：用户明确“全显示图层”只指图层Tab；本文的底部参数布局已退役，当前恢复右下三Tab，见[最新核对记录](2026-10-28-accessory-inspector-tabs-and-rename.md)。画布视图修复保持。

日期：2026-10-27。工作分支 `codex/accessory-editor-rig`，HEAD `51caf0e` 的既有未提交实现继续修改。用户反馈：平移／缩放只有图案变化、右下空白应交给图层、有用参数转到底部、展开形变细调后骨架页变空白。

## 复现与根因

- 旧棋盘只设置背景class，没有读取zoomView变换；zoomView又将平移和缩小限制在文档边界。旧打包资源上新视图检查2项失败：fit状态手掌不能平移，缩放后棋盘和骨架坐标不一致。
- 在1104×668浏览器视口，选中真实组后展开细调，旧布局判为高度溢出，将整个`group_fields`搬入一个关闭的顶部details；实测`fine=true`、参数`visible=false`，不是数据丢失。旧资源上两项底部／细调反例失败。

## 改动

- `canvas-view.js`接入现有Dango自有zoomView，统一手掌、点击缩放、顶部缩放和滚轮入口。主canvas作为固定工作区，图像、有限棋盘和SVG使用同一视图；完整清屏、按文档边界裁剪，保留文档外工作区留白。
- `vendor/src/js/libs/zoomView.js`原本就是Dango自有替代实现，本次解除错误的边界限制、保留有限缩放范围和单一变换owner。`skeleton-editor.js`只接入该视图，不改共享关节或物理解算。
- `editor-layout.js`、`canvas-layout.css`将原图层和骨架参数控件移入独立底部dock，默认收起；右侧两个图标选择底部参数页，右下图层／组列表始终保留完整可用高度。细调展开不再搬家；退役顶部参数搬迁逻辑、旧206px固定数值区高度与相关样式。
- 底部不改变现有控件事件、数值合同、导出、编辑序列或历史。右侧无滚动、对象超出容量分页；底部超长内容采用细滚动条。沿用桌面规范v0.1第2–6节，最新页面差异同步至UI合同。
