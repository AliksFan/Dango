# 胖侧外围回弹微调：有限通过、完整下落失败

日期：2026-10-11。按用户批准的[最小修正计划](../planning/2026-10-11-landing-build-recovery-validation-plan.md)实施并验证。新 `landing-build-v4-recovery-preview` 只把胖端外围频率系数 `.70→.72`，默认和瘦侧、初始圆形及其它物性精确不变。有限恢复及默认胖端外形保护通过，随后 S1 出现新的短时横移门禁失败，已硬停止；本候选不能作为完整验证通过的预设交付。

## 实现与静态／预检结果

`LandingBuildMapping.cs` 新增明确 RecoveryPreview 表，旧 A／B／C／v3 保留。`LandingBuildRecoveryVerification.cs` 实现有限复验和 S1；`Program.cs` 增加专用入口、错误新参数位置／数量返回2，不进入旧GUI路径。原 `LandingBuildStretchMatrixVerification` 只增加接受表参数的内部完整性 helper；原一参校验仍固定 v3，旧门槛及命令不变。没有修改共享单 trial 轨迹、求解器、native、生产宿主或存储。

Release 有限工具与 S1 工具构建均零警告、零错误。旧映射／合成效果配置检查8/8，新配置检查1/1（覆盖3大小×3柔软度×全部101整数体型）通过。后者核对只允许外围频率变化、默认／瘦侧精确不变和预设插值，不冒充物理验证。

实际预检拒绝均返回2且未创建目标报告：错误正式DLL、错误原下落报告、缺失DLL路径、裸新flag、篡改原失败trial的预览、S1错误正式DLL。已有输出返回2，原`preview.json`哈希不变。审查发现的 S1 原恢复来源校验缺口、入口库路径异常返回码和裸flag问题，已在运行S1前修正；S1从实际旧运动报告计算SHA并深比较原失败，不能仅相信预览声明。

两次构建的实际程序集和源码清单分别保留在`preview-source.json`／`s1-source.json`，独立审查已核对PortablePDB源SHA与各清单一致。S1导入较早有限报告时保留其实际程序集哈希，不伪称两次工具二进制相同。

## S1 新失败与精确复现

S1计划45组，实际记录32个唯一组合：28精确复用、3新完整通过、1新失败；剩余13组未执行。28复用为原v3默认／瘦侧27组及本轮新默认胖端1组，独立审查与各来源完整深比较无差异。3新完整下落均3,600帧，失败581帧，共11,381新帧；报告计入复用共112,181健康／绘制帧。尚未完成每个大小全部组合，空效果失败列表不能解释成效果判据通过。

失败为**大小100／柔软度100／胖0，第581帧**：`ShortSettling`，原481～600短时窗累计跨度`0.003014800138771534`，原门槛为`<0.003`。当时已采集101短窗样本，没有均值窗样本及第600帧检查点。全部581帧健康、合法绘制，没有native停止或穿地。顶层completed=true表示受控收口，outcome=`hard-failure-stop`，不表示45组完成。

使用报告绑定的同一S1程序集、native、配置、轨迹定点重跑：除墙钟耗时外14字段全部相同，`reproduced=true`、差异为空。独立轴跨度诊断同配置运行至原第581帧，最后完整原生快照及最大跨度均与失败trial精确相同。它使用原`MaterialSession.Step`和`LandingBuildFrameValidator.Observe`，没有安装探针或修改求解器；原v3同组合仅补充至原第600帧的基线诊断，不运行新矩阵阶段。

触发失败的是**向左慢移**。新观测窗核心X由−0.00135058350861073到−0.00436538364738226，在scale190约0.573像素；实际样条宽、高跨度分别约0.192／0.119像素。第481与581帧速度约0.00563／0.00266，均低于原0.03停稳速度门槛。小速度不能替代累计位移门槛。上述像素量仅代表这个短窗，未测本组合后续总变化或长时趋稳；不能据此扩大用户此前仅默认正向甩后慢形变的已知差异。

单字段微调在同原生模块下使该短窗从通过变成失败，证明该预设产生新的稳定性回归。尚未证明外围频率如何通过节点接触、约束或松弛机制导致慢移，不写成已定位的求解器根因，也不继续扫描其它系数。
