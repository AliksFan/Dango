# DIY 配饰第四轮修订验证

日期：2026-10-08。分支 `codex/accessory-diy`，起点 `5bc3215`。本轮依据[设计第 13 节](../planning/2026-10-07-accessory-diy-design.md)实施；用户人工验收尚未完成。[第三轮](2026-10-08-accessory-ui-v3.md)和[第二轮](2026-10-08-accessory-ui-refinement.md)的失败及未验证项继续保留。

## 范围与实现

- 图层及排序改为“团子前／团子后／上移／下移”四个图标，保留选中反馈、工具提示和辅助名称；排序继续使用已佩戴同层／未佩戴库规则。
- 删除参数内容区“图像与位置／柔性与连接／旋转与重力”三个重复标题，左侧导航名称保留。
- 图片保存上限提高到最长边 4096、16,000,000 总像素和 32 MiB。超限源图从原始解码帧等比缩小并规范化编码；真实图片编辑窗口与参数区显示原／最终尺寸、文件大小和“图片已压缩”。源文件不修改，通知不写入清单 Schema。
- 源读取另有 64 MiB、最长边 16384、64,000,000 像素及单像素面 256 MiB 边界；解码前检查 PNG 结构、CRC、IDAT 展开长度及透明描述，剥离非必要元数据。极大或损坏源图明确拒绝，存储图片仍严格遵守保存边界。
- 草稿累计预算为 128,000,000 像素／256 MiB PNG，同图去重。内置纹理从 64 提高到 512 像素，保留 ID、逻辑尺寸和支点；图库缩略图覆盖实际 DPI 下的 48 DIP，并在 DPI 切换时刷新缓存。
- 持续 A／D 的修复先复现，保留真实身体、完整眼帽步态、配饰柔性、低跳、固定纵向镜头与唯一帧 owner。已复用普通窗口的位置插值和整体实体投影；视觉抖动等待本轮人工确认，原性能门禁仍未通过。

主要文件为 [编辑面板](../../src/Dango.Desktop/Accessories/AccessoryEditorPanel.cs)、[图片资产](../../src/Dango.Desktop/Accessories/AccessoryImageAsset.cs)、[图片编辑窗口](../../src/Dango.Desktop/Accessories/AccessoryImageEditorWindow.cs)、[本地会话](../../src/Dango.Desktop/Accessories/AccessorySettingsSession.cs)、[内置纹理](../../src/Dango.Desktop/Accessories/BuiltinAccessoryImages.cs)、[预览接线](../../src/Dango.Desktop/AppShell/ControlCenter/ProductHomeView.Accessories.cs)，以及 Shape／Face／Hat／Gait 的输出等价计算优化。

## 根因与保留的失败

旧候选真实 WPF 窗口使用一件柔性叶芽、150% DPI：持续 D 八秒约 47.493 应用帧／秒，A 约 50.183；native 约 60 步／秒，按住意图未丢失。同一成功帧的 BodyPath 重建两次，60/60 样本触发重复绘制反例。修复为单次 `DangoHostFrameBinding.Apply`，读取同一轮廓后平移身体、帽子和前后配饰保持接地，不再预画一遍。

隐藏旧帽计算的中间实验未通过 59 应用帧／秒门槛，且逐帧对照发现 `Gait=null`：步态几何依赖帽子姿态。该实验已完整撤回；正式候选保留帽子和步态。随后采用不可变边数据缓存、Hat workspace 复用及正零 fit 缓存、Gait 最小平方距离只求一次平方根；所有采样、阈值、搜索次数和原距离运算保留。

独立 PNG 反例首轮 22 项中 18 失败／4 通过；中间一项夹具使用 Fastest deflate，使随机源膨胀超出 64 MiB，改为 NoCompression 后实际处于 32–64 MiB，未放宽限制。最终图片专项 66/66，完整编辑与资产集成 132/132，含 Adam7、1-bit palette/tRNS 和 RGBA16 正例。

完整候选首轮较宽回归 615 项：585 通过、14 失败、16 跳过，保留 `ui-v4-functional-r2.trx`。六项图库检查仍假设缩略图最多 48 像素，修订为严格覆盖当前 DPI 的 48 DIP；新增 4096×4096 光栅夹具超出 16,000,000 像素，改为合法 4096×3906，保存上限未改变。四项 GaitSample 和一项 Porch 旧能力反例需要指定原 00FF 模块；隔离提供该模块后全类及反例共 8/8。

Face recovery 的 Wardrobe 高度门禁观察到 298→301.333 DIP。独立旧 Desktop DLL 同条件复现完全相同的失败，Close 分支通过，确认属于已有基线差异；本轮不改写该门槛或顺带处理布局。16 项跳过属于需要真实前台鼠标／捕获环境的既有门禁，不能写成通过。

宽回归中的真实八件光栅 p95 为 16.70 ms；后续独占性能首轮仍为 17.85 ms，超过原 16 ms 门槛。持续移动独占首轮 D 为 57.452、A 为 55.770 应用帧／秒，均低于 59。原失败保存，需继续修复后验证；不以反复重测选择绿色结果。

随后完整像素等价优化及 Gait 结构体复制／内联优化集成：功能 489/489、零跳过，含原独立 930 帧对照和新增五组完整光栅像素哈希。下一次正式性能仍为 4/6：D 58.119、真实八件绘制 p95 16.29 ms，仍不算通过，证据名称 `ui-v4-isolated-performance-final.trx` 保留其实际红灯。

新增像素优化保持三个双线性舍入步骤：四邻域完全相同直接返回原像素，其他邻域用等价的 unchecked uint 环表达式减少整数乘法。独立逐通道 oracle、20,000 个混合／边界样本、六种 alpha 的全部 256×256 分数，以及非方形／非对称 DPI／4096×3906 的完整像素哈希均一致。原算法的五组哈希先捕获保存，最终测试强制断言，未使用当前输出回填基线。

一次带临时插桩的真实运行诊断定位到 Gait 最小清距和 Contains；该诊断使用独立旧 UI／纹理，且 observer 自身增加开销，不能替代完整产品帧率。成本前后有明显变化，但旧 Create 的 JIT trace 同样出现 FullOpts，不能把单个编译属性认定为该变化的根因。后续光栅 trace 则直接发现 RasterBand 首版为 Instrumented Tier0，每像素调用 Sample 并有 profile／patchpoint，只出现后续 OSR 版本；直接优化编译的候选去除这些调用，仍须实际完整候选验收。临时插桩全部撤除，调度时钟、帧计数、预热时长和门槛保持。

r8 集成光栅直接优化编译与步态清距保守下界：全眼轮廓盒覆盖全部实际采样点，线段盒使用 Start 与实际计算的 Start+Delta；有限域内扩边，域外和非有限输入执行原算式，仅下界严格大于当前最小时跳过投影。新增反例覆盖端点浮点抵消、相邻浮点严格比较、退化段、非有限与 NaN 传播、真实眼轮廓及不可见／单眼／闭眼路径。当前 runtime 的独立精确对照通过，不称为全平台形式证明。

统一 r8 功能门禁 59/59、零跳过；随后独占性能仍为 3/6：D 53.866、A 46.072 应用帧／秒，真实八件 p95 17.51 ms，4096×3906 等效 150% DPI p95 16.91 ms。A 同时观察到 133 个按住意图丢失帧；尚需记录焦点／窗口激活时间线，不能把它直接归因于物理步进或更改失焦清理规则。原失败 `ui-v4-r8-isolated-performance.trx` 和完整 JSON 保留，继续定位完整帧与光栅成本。

后续光栅增量通过弱引用身份缓存共享同一冻结 BitmapSource 的只读像素，非冻结来源仍独立快照；网格 raster 顶点按原减法及乘法顺序预计算，UV 和索引形成当前工作的数组快照。纹理读取成功后才发布源身份、尺寸及像素状态。根任务重新构建后 18/18、零跳过，包含五组原完整画面哈希、双线性逐通道 oracle、可变纹理快照隔离和两组 48 帧回放的最终八个 bitmap 哈希。离线成本下降不代表真实窗口门禁已通过，且共享纹理收益仅适用于相同冻结源引用。

完整 r8 UI 的一次临时分段诊断记录焦点和各求解阶段；观察代码明显改变冷启动成本，其 FPS 不作为验收。未插桩的独立 Hat 冷过程 JIT trace 确认 Evaluate 先进入 Instrumented Tier0 再进入 Tier1。随后只对该拟合内核添加直接优化编译属性，原算式、320 段扫描、搜索及排序不变；原子方法增量在根任务按原 LF 换行集成，产品 Git blob 与交付补丁目标一致。主树 23/23、零跳过，含完整 930 帧旧二进制对照和真实进程重启。

共享纹理与 Hat 编译增量的独占性能为 5/6：真实八件动态柔性图片 p95 9.54 ms，4096×3906 等效 150% DPI p95 9.30 ms，四组等效绘制均通过；持续移动仍失败，D 46.749／A 54.113。D 的 374 个应用帧中 371 个按住意图为空，不能作为有效持续移动性能通过证据，原红灯继续保留。

测试随后增加每回调的既有调度时间结构、当前任务窗口激活与焦点事件记录，并增加连续前台条件，帧定义与门槛未修改。用户配合保持前台后的唯一采样没有失焦或意图丢失，D 56.479／A 57.875，仍未过 59：D 有 466 个回调、452 次应用、480 个 native 步进，14 个真实零步批次；A 有 470 个回调、463 次应用、480 个步进，7 个零步批次。当前时钟以墙钟余量补齐物理时间，多步仅显示末帧；物理 60 步不能推定显示 60 帧。显示回调本身亦不足 59，未发现充分依据修改时钟、计数或门槛，继续检查 UI 的重复显示工作。

显示绑定反例确认旧外置帽子在 30 个真实配饰帧中发生 60 次 Visibility DP 变化：先显示／更新、随后再被配饰层隐藏。R12 仅在配饰启用、Canvas 宿主及 runtime 定制实体条件同时成立时保持该旧视觉隐藏并跳过其外置显示更新；runtime 完整 Hat、Gait、身体和八件动态网格仍推进。关闭配饰或取消兼容预览后，同次绑定恢复当前帽型、尺寸、姿态和步态。独立反例及相关回归 21/21，隐藏控件的 WorkerW 检查不冒充新 Wallpaper 实时验收。

眼睛节点反例在旧实现第二个有效帧失败：左右眼逐帧移除并新建 Path。候选保留两个节点，仅进入／退出编译眼睛模式时更换父子关系，几何和颜色仍逐帧更新。原 XAML 眼睛实例、fallback 与隐藏恢复路径保留；局部初验 4/4。随后补入不可见眼睛、隐藏帧、关闭附件及脱离视觉树时颜色变化的恢复检查，与 R12 统一验证 34/34、零跳过，包含原 930 帧独立二进制轨迹对照。这些显示开销修正不能代替正式持续移动性能门禁。

显示开销修正后唯一持续移动采样 `ui-v4-display-work-foreground-performance-r1.trx` 仍失败：D 56.471 应用帧／秒，Loop／Apply p95 降为 6.566／1.216 ms；A 55.519，且 316 个按住意图丢失帧。完整 JSON 保留于 `accessory-held-movement-v4/32a6bf2924654d90ac65838cba88078c/held-movement.json`，不能称为通过或有效 A 持续移动验收。

R13 已复用既有插值及成功步数／余量呈现时钟，使用新增内层 `LiveEntityLayer` 的共同变换移动身体、旧帽及前后配饰；外层 Canvas 保持固定，避免相机变换反馈到视口测量。团子和水平相机使用同一显示位置；接地时只插值 X，保留每个成功帧的实际轮廓接地修正，离地时插值 XY，纵向相机始终固定。零步回调只更新投影，不重建身体／网格／位图，不增加物理或应用计数。重复回调不推进，多步批次使用完整时间跨度；隐藏、停止、放置、失败、时间不连续与退出清除旧样本。身体支点仍通过 WPF 反变换映射。真实低跳、无限水平、唯一 owner 和全部配饰保持。

独立新增呈现边界最终 8/8；独立相关回归实际 82 项通过，另 6 个旧缩略图检查仍使用 48px，已用旧程序集确认，root 的 DPI 检查早已更新。本次 root 集成 85/86，全部八项呈现检查通过；480×800 保存按钮检查未落盘，隔离重跑两种尺寸 2/2 通过。该夹具未绑定实时场景，不执行 R13 路径；原失败缺少保存错误状态，不能推定竞态或改写为全部通过。真实进程保存／重启／来源图片移动与单实例边界 12/12 通过。尚未做 R13 持续移动 FPS 采样；本轮视觉抖动仍待用户实际确认，历史性能红灯保留。
