## 两处裁切与修复

用户提供的正式版局部图片显示头部水平缺块、帽盖状残片和底部水平切口。仅比较当前 WPF 视觉树与当前窗口区域的旧检查无法发现相邻帧错位，也没有验证控件内部的布局裁切。

第一处是透明桌宠窗口逐帧调用 `SetWindowRgn`：UI 线程同步更新的形状区域会裁剪 WPF 异步呈现的图像。相邻真实帧的机制检查中，下一份窗口区域切掉了前一份图像的 122/7079 个内部像素，旧实现失败。该检查建模上一帧仍在呈现的状态，不是桌面合成视频或确切呈现时序记录。修复保留准备期的空区域，首个健康帧准备完成后清除额外区域，之后由 Windows 分层窗口的图像 alpha 同时决定可见轮廓与透明处原生命中；不再逐帧维护另一份形状遮罩。依据：[Windows 分层窗口的零 alpha 命中规则](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#layered-windows)。

用户复验第一版完整产品候选后确认上方显示正常，但报告空中向下拖仍有平底，随后正常退出。第二处因此继续保持未完成，未将第一版标记为整体修复通过。

第二处是身体 `GaitBodyLayer` 的 Grid 布局限制。一个被 Belt 渲染器接受、核心仍在内部的轮廓延伸到 120 DIP 模板下方时，几何内部点 `(60,135)` 的实际渲染 alpha 为 0。该单测在第一处修复后仍失败。改用不约束 Path 自然尺寸的 Canvas 后，下方内部点完整绘制；根控件的 160×120 坐标模板、几何映射、输入策略和物理参数不变。三组真实物理轨迹的缓慢空中下拖检查没有单独复现此切口；合法越界轮廓单测负责直接覆盖布局缺陷，完整产品的后续人工复验负责确认实际症状。

第二版完整产品候选复验时，用户明确确认“平底消失，上方和配饰也正常”，并确认已正常退出候选版。本轮人工通过仅覆盖报告的拖动显示缺陷，不扩展为全部 DPI、多屏、长时运行或跨进程输入验收。

## 改动范围

- [透明桌宠窗口](../../src/Dango.Desktop/AppShell/Rooms/DesktopPetDangoWindow.cs)：首个健康帧启用图像 alpha，退役逐帧路径和配饰包围框区域。
- [Win32 边界](../../src/Dango.Desktop/DesktopHost/Win32/NativeMethods.DesktopPet.cs)：保留准备期隐藏与失败边界，删除不再消费的多边形区域拼接实现。
- [身体绘制层](../../src/Dango.Desktop/Rendering/Dango/DeformableDangoVisual.xaml)：Grid 改为 Canvas，允许接受的轮廓超出模板槽位。
- [桌宠集成回归](../../tests/Dango.Desktop.Tests/AppShell/DesktopPetAccessoryIntegrationTests.cs)：使用正式 `ProductPhysicsComposition` 的 Belt 运行时，覆盖相邻帧裁切、前后配饰、连续提起与空中下拖；比较实际像素和原始几何。
- [原生输入回归](../../tests/Dango.Desktop.Tests/AppShell/DesktopPetRoomNativeInputTests.cs)：检查旧位置确实腾空且 Windows 实际命中下层应用，同时保持拖动、当前身体命中、捕获释放和焦点断言。
- [越界轮廓回归](../../tests/Dango.Desktop.Tests/Rendering/DangoOverflowRenderingTests.cs)：验证身体槽位下方的真实内部像素可见，而非仅检查 `ClipToBounds` 声明。

原生输入检查的首次对照中，未改 main 的 6 项通过，第一处修复有 2 项停在核心须抬升 100 world units 的前置条件。没有改物理参数或降低该距离门槛；测试改为直接等待其业务目标——旧身体接触点已离开当前身体，且实际原生命中下方应用，并新增拖动仍有效的断言。原始失败、main 对照和最终结果均保留，没有将失败归为 main 已有失败。
