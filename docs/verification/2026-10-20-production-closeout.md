# 新身体正式接线与合并收口

日期：2026-10-20。分支 `codex/belt-page-completion`，从已交付的 `b2a024b` 收口。用户已经明确“接入已验收”；随后要求记录过度隔离问题，把本分支接到正式启动和构建、整理到可合并标准。范围见[本轮计划与必要性判断](../planning/2026-10-20-production-closeout.md)。

## 实际改动

- 普通无参数启动默认连续身体。首页、实时捏脸、配饰与门廊沿用已验收 worker／presenter；普通房及桌宠沿用现有框架的 room runtime。首页不预先初始化房间第二个本人，入房继续执行暂停屏障、真实存档准入、配置和显示确认。
- 退役本分支新增的 `--belt-body-review`、专用模块参数与启动脚本，不再维护新身体的产品开关。通用 `--data-root <绝对目录>` 只改变存储位置及该目录的实例身份；默认路径与旧本地安装验收事件身份兼容。Win32 尾点／空格、大小写和末尾分隔符归一后共用同一实例。
- 普通 `dotnet build/publish` 自动从当前 native 源码生成两个模块；DLL 和源／产物清单作为 Content 进入应用、项目引用与发布输出。WPF 临时项目不重复构建。正式发布不要求旧 module 路径；已有安装管理器新增真实源码身份，保留旧包合同，不执行安装。
- 设置页按当前所在场景读取与恢复身体／房间。审查发现托盘未选房时的恢复回调会绕过正常入口，现由 Host 同时拒绝未选房、交接和目录准备状态，托盘未选房时禁用对应动作；已选房恢复不改变。
- 木平台 `-707／-605` 修复已集成 `71c1302`。在原预算内寻找被未决单元遮住的穿入见证；入口法向采用原允许壳一致的禁止区域；集合路径共用既有解析候选定位。最终整步连续证书、完整回滚和原门限不变，材料／步态／平台几何不改。详见[原生根因与正负验证](../../artifacts/belt-platform-merge-fix/verification.md)。

首次正式 Host 测试把独立门廊的旧单门断言误用于真实目录：新目录会导入原本地普通房，不能断言触发旧 `LocalRoomRequested` 或新建空门。保留两份 27 通过／1 失败 TRX，恢复独立门廊夹具的专用门动作检查；新增 Schema 组仍通过真 Host 完成实际默认接线。早期门廊位置断言还将导航后的物理移动算作坐标错误，改为同步检查交接原点公式，未修改物理或放宽容差。传递输出遗漏曾造成 DLL 缺失，修复 Content 后普通构建实际供给测试；原失败 TRX 保留。

路径审查提出的“尾点／空格将产生另一目录身份”经 Windows 当前 .NET 实测并不成立：`GetFullPath` 已作归一。定向反例先拒绝断言失败，随后改为检查相同路径与实例身份，保留失败 `data-root-paths-final.trx`，不新增多余路径门槛。初期两个所谓 CLI 漏项实际属于 `Dango.JointReview`，并非 Desktop 参数；配饰绑定也不触发 world 初始化，两项误报均核实后未改产品。
