本次人工确认覆盖所呈现的隔离单体动态体验及本计划操作清单，不推断用户逐条执行了全部测试步骤，也不把自动故障注入记作人工操作。关闭窗口/子进程回收尚无现场关闭证据；评审进程仍保留。人工通过不等于多体、左右墙、承重、正式宿主或整个开发阶段通过，不授权替换正式 DLL 或进行 Git 交付。

前提：用户已接受[隔离静态外形评审](phase-1-dango-ground-contact-evaluation.md)中的候选 4 轮廓。此次只推进单体真实动态评审，不重复要求静态轮廓达到旧物理空间筛查值，不把用户接受推广至未展示的形变。

## 范围与排除项

检查静置休眠、A/D 水平施力、S 下压、W 接地起跳、鼠标拖动与释放、失焦释放输入，以及显式重置。保留 16 节点、核心、既有满意参数、最高节点抓取、现有 WPF 映射、全部几何/速度/能量门禁及异常锁存。

本次不实现左右墙、数量面板、双体/三体承重、网络同步或正式宿主接入；不替换 ABI 13/DLL，不写个人设置，不提交、合并、推送或发布。碰撞唤醒和支撑移除继续保留原生证据，但不称为本窗口已经验证的多体功能。

## 最小接入设计

1. 复用 `dango_self_sleep_tests.c` 的 `configuration`、候选 4、`tick`、整 rig 休眠资格和故障锁存。新增明确的交互诊断入口，与现有测试命令分离；缺省仍不启用交互模式。
2. 在独立子进程中持有唯一真实 Box2D world。由 WPF 通过本地标准输入/输出交换有界消息，无监听端口。子进程只处理此诊断场景；结束或父进程关闭时通过 EOF/退出命令释放 world 并退出。
3. 每个步进请求固定推进 1/60 秒，携带 A/D/S/W、拖动目标和抓取状态。当前测试辅助函数把抓取目标固定为 `x-1,0`，需为交互入口增加独立显式目标适配，默认关闭，不能误把测试目标当鼠标坐标。消息字段须有限、在限定范围内且数量正确；非法消息不得推进。
4. 返回原生节点、核心位置、真实 awake 数、休眠资格、步号和故障状态。UI 不自行计算“已休眠”，不补间虚构碰撞或播放预录数据。只允许一个未完成请求，避免并发 world 步进；窗口卡顿时限制积压并显示实际模拟时间，不以无限补帧隐藏性能问题。
5. 复用独立评审工具和现有 `DangoStreamGeometryFactory`，按原 72/58 横纵比例定位真实身体，绘制与物理地面一致的参考线。默认参数不变；放大是整场景等比显示，不改变物理大小。
6. 仅在评审窗口有焦点时处理按键和鼠标，不使用全局键盘钩子。鼠标按下抓最高节点、捕获鼠标，移动传入实际物理目标；松开、失焦或失去捕获时清除输入，W 忽略系统重复按键，避免粘键与自动连续跳跃。
7. 非法几何/非有限状态保持错误锁存；停止自动推进并显示失败，不自动重生。只有用户按明确的“重置本次试验”才能销毁该 world、按相同参数重建；不能静默重置掩盖故障。

这是隔离验证通道，不是正式客户端架构或新的生产 ABI。后续生产接入须另行设计生命周期和多体接口，不能把诊断进程协议直接当作正式同步协议。

## 先定义失败，再实现

| 验证 | 失败条件 / 要求 |
|---|---|
| 协议与生命周期 | 非有限/越界/缺失字段被拒绝且不推进；退出释放 world；重置仅显式触发；不会启动第二个 world |
| 静置 | 默认场景在原资格条件下自然入睡；awake=0/17；不得提前冻结渲染冒充休眠 |
| A/D/S/W | 输入真实唤醒；水平位移、下压、起跳符合既有方向；释放后在 6000 帧内重新达到资格 |
| 鼠标 | 首次抓最高节点；目标来自实际鼠标映射；松开及失焦后不继续施力；释放后重新休眠 |
| 锁存 | 已失败的 world 不继续伪造正常帧，不接受普通输入作为恢复；显式重置另计试验 |
| 显示映射 | 核心/皮肤/地面同一坐标变换，比例不失真；实际状态与画面一致 |
| 人工 | 用户确认静置、唤醒、下压、跳跃及拖放手感可接受；真实窗口运行不由进程响应状态替代验收 |

实施顺序：先原生交互协议和进程级自动测试，再 WPF 输入适配和坐标测试，复跑受影响原生运动序列及渲染回归，最后启动明确命名的隔离动态窗口。只在静态和进程级门禁通过后交人工操作；失败记录必须保留。

## 人工操作清单

1. 不操作，观察自然落地、静置与真实休眠状态；首次默认预计数十秒，不强制加速入睡。
2. A/D 移动后松开，S 下压后松开，W 起跳后落地，分别观察唤醒及恢复。
3. 鼠标抓取、移动、释放；拖动中切换窗口，确认失焦不会持续牵拉。
4. 检查已接受轮廓在动态形变中是否仍自然；指出不满意动作与部位。
5. 关闭窗口退出本次验证；关闭不代表批准，验收意见仍在 Codex 中明确给出。

## 实施与验证结果

已实现 `dango_dynamic_review_protocol.h` 与原生 `interactive-review` 入口，以及独立评审工具的 `DynamicSession`、`DynamicWindow`、`DynamicVerification`。采用有界标准输入/输出，单次固定 1/60 秒；只有一个未完成请求，最多补 4 帧，使用实际模拟时间显示状态。诊断模式不读取缓存干预环境变量；旧测试默认路径不变。动态窗口不复制或使用候选生产 DLL，而是启动唯一原生测试子进程。

进程级自动验证通过：

- 非有限、越界、缺字段、超长行及非法跳跃值被拒绝，首个合法请求仍为第 1 帧。
- 第 2086 帧自然入睡（约 34.77 秒），之后 120 帧所有节点和核心坐标严格不变、awake=0/17。此入口与先前模拟入口第一步不同，使用本入口实际测量帧号，不修改资格门槛。
- A/D 两向真实位移及释放再休眠；W 起跳高度约 0.06505 后落地再休眠；S 下压及释放再休眠。
- 鼠标初次选取最高节点，整个拖动保持该编号；真实目标坐标产生位移，释放后 selected=-1 并重新休眠。
- 仅测试模式开放的故障注入可验证错误锁存，普通输入不能推进或恢复；显式重置返回新的第 1 帧。退出响应 `bye 0`，原生 world 分配差值为零。

WPF 离屏检查使用此次进程返回的真实休眠帧，不是静态评审快照：验证鼠标坐标/地面逆变换，以及失焦处理所复用的输入清理函数；生成 `dynamic-review-render.png`，代理查看确认轮廓与地面位置、比例、文字正常。此项不等于真实鼠标事件、前后台切换或屏幕观感已验收。
