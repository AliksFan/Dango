# 帽子轨道临时分配优化方案

日期：2026-09-21。状态：用户在“确认该方案后进入实施”的明确提议后回复“通过”，本方案与实施已获授权；按下述顺序执行，性能与人工验收尚未通过。

起点：`codex/performance-stability` / `75de095`，本轮开始时工作区干净。依据：[时钟修复验证报告](verification/2026-09-21-host-clock-scheduling-repair.md)。本方案只处理已定位热点，不代表上一批性能门禁通过。

## 1. 证据与目标

完整60秒独立诊断中，`HatTrackSolver.FitRaw` 出现在66.7%的托管执行样本中，关联约96.3%的GC分配采样估计量；实际进程托管分配率约320.52MB/秒。采样包含探针开销；这些比例不是进程CPU百分比，也不是精确逐对象字节。

源码存在两种不必要的结果构造：

1. `HatTrackSolver.Create` 扫描321个位置，仅使用`FitRaw`是否为空，却为试算构造完整姿态及多组数组。
2. `HatPlacementSolver` 的定位、两侧各160步边界查找和`AvailableLift`只消费姿态标量，却通过公开`track.Fit`取得包含接触样本的完整结果。

目标是保持几何与视觉结果，减少这些热路径上的临时分配和计算。实际CPU/帧率改善必须重测，不能由采样占比预先承诺。

## 2. 最小改动

产品文件限于`HatTrackSolver.cs`和`HatPlacementSolver.cs`，允许增加小型内部值类型/缓冲辅助类型。`HatMotionController`保留现有重映射、20次搜索、速度、弹性、取消和恢复规则，只通过下层求解器获得优化。

- 共享求值内核分为“只判合法”“返回标量”“构造完整公开结果”三种用途，避免复制一套几何算法。仅判合法和标量路径不构造`HatContactPose`及无消费者的`ContactSamples`/`FittingSamples`。
- `CreateGeometryGuide`合法性扫描保留弧长、角度、投影覆盖和严格单调等全部拒绝条件；只有证明后续计算不会再影响合法性时，才可停止在最后一个判定处。严格贴面扫描仍执行完整接触范围、间隙和穿入门禁。不能用guide规则替代strict规则。
- `HatPlacementSolver`通过内部标量入口取得Center/Angle等结果；两侧各160步查找仍检查校准后位置/角度的有限性与边界，`AvailableLift`保留原计算。
- 固定的小尺寸工作区可用栈空间；动态工作区优先在一次扫描内复用，容量覆盖65个接触点及全部内部顶点，必要时使用现有.NET数组池短期独占租借并在`finally`归还。工作区在扫描外层取得，不在321次循环内反复`stackalloc`。不得使用未同步的共享可变工作区或跨帧几何缓存。
- 公开`Fit`仍返回完整独立结果；接触点和拟合点按原顺序复制到结果自有存储，后续调用不能覆盖先前结果，也不能将池内存暴露给调用方。

保持321点扫描、最近零点合法组件选择及相同距离时按Min排序、65/9点采样规则、两侧160步边界查找、求值/排序语义、接触宽度、所有阈值及strict/guide区别。稳定排序中相等键的次序必须保留；不把残差门禁改写成代数上看似等价但浮点求值不同的公式。不得调整物理步长、姿态参数、眼帽样式、打盹、宿主时钟或原生DLL；不引入依赖或后台计算线程。

## 3. 先建立能失败的验收

先从`75de095`冻结测试专用旧实现/确定性输出作参考，参考实现不进入产品。不得只将新实现与自己的内部包装比较。复用既有几何、原生校准及嵌入位置用例，再补关键反例。

| 门禁 | 必须断言 |
|---|---|
| 几何等价 | 平顶、弯曲/非对称、窄冠、轮廓起点轮换、变形、区间端点及相邻浮点值、非法输入；新旧null判定、合法区间、Center/Angle/S/宽度/间隙/穿入、接触点与拟合点数量/次序一致。保留现有数值容差，不因优化放宽；拒绝/接受结果必须完全一致。不能仅沿用“接触点数量至少33”的宽松断言。 |
| strict/guide分离 | 保留“strict拒绝但嵌入guide可接受”的真实反例；不能因快路径跳过严格贴面或校准后的边界条件。 |
| 所有权和复用 | 保存一次公开Fit结果，再执行不同位置/形状的求值，旧数组内容不变；独立及并行求值无工作区串扰，失败路径归还租借资源。 |
| 运动回归 | 既有帽子滑动、嵌入根部、重映射、脉冲/释放、窄冠失效恢复、原生形变用例保持通过；不以单张几何结果替代动态序列。 |
| 分配回归 | JIT及缓冲预热后，内部判定/标量求值循环不产生按调用次数增长的堆分配；旧实现必须触发这一反例。另测完整Create/Remap循环的每次分配并与同输入旧实现比较，允许必要的solver和公开结果构造。计数测试不使用噪声较大的墙钟耗时作为单元门禁。 |
| 真实效果 | 相同保护库、单团子、Release候选，分别测Wallpaper/Window；预热≥60秒，每个参与资源判定的状态≥180秒，轻采样与EventPipe分开。继续使用空闲CPU≤1%、工作集≤250MB、普通活动CPU≤5%、60FPS目标及无异常丢时要求。 |

实现顺序：先冻结参考并证明反例可失败 → 求值/结果构造分离 → 接入标量调用和缓冲复用 → 定向回归与分配对照 → 最终候选全量相关门禁、隔离发布和两个宿主短测。

## 4. 真实验证与停止点

复用已修正的schema 2探针。观察中发生人工隐藏/最小化时，保留原始证据并将连续可见观察判为中断；受影响的完整观察需要另开新运行，不能删除隐藏样本或拼接成连续通过。隐藏恢复循环、持续隐藏/恢复和退出仍分别验收。

若几何/运动出现差异、复用影响旧结果、局部故障范围变化，停止并定位，不降低精度。若局部分配显著减少但真实CPU/帧率仍不达标，记录剩余热点，不扩大到脸部、物理或渲染后端重写。

只有两个宿主短测和完整性门禁合格，才对同一最终候选启动真实60分钟观察，再从项目候选开展人工眼帽观感验收。既有旧DLL缺失导出继续单列；不更换库制造全绿。

本方案按[实施计划](phase-1-hat-track-allocation-plan.md)进入实施。日常安装更新、合并main、推送和部署不在本方案范围内；临时产物与既有证据保留。
