# Dango Phase 1 Box2D 视觉软体实施计划

> 状态：Approved
>
> 日期：2026-09-03
>
> 批准日期：2026-09-03

> 已批准设计：[ADR 0005](adr/0005-box2d-visual-soft-body-presentation.md)

> 阶段任务：P1-004 单团子生命感最小纵切；为 P1-005 性能基线准备诊断入口

## 1. 目标

在不改变 Core/服务端权威结果的前提下，把已批准的 A 极简团子、手工动作语义与 Box2D 真实二维物理组合成可运行的 Windows 桌面纵切：团子具有连续柔软轮廓、自然落地回弹、独立眼睛与帽子，并能在物理不可用、降低动画或异常时安全回退到手工关键姿势。

本计划在用户批准前只用于审查，不授权安装构建工具、引入 Box2D 源码或二进制、修改运行时代码、合并分支或发布验收包。

## 2. 已确认基线

- `phase/1-desktop-life-prototype` 当前核对 HEAD 为 `1ea0885`，P1-003/C3 已完成自动门禁、Windows 11 Build 26100 实时验证和用户人工验收。
- 当前阶段路线采用原生分层 WorkerW 候选，保留 Overlay 回退；P1-007 才形成最终宿主 ADR。
- 动画预生产分支 `feat/p1-004-animation-preproduction` 当前 HEAD 为 `b412930`，A0–A4 已完成，包含 A 极简视觉、项目 skill、资产预检以及 `Idle`、`Landing`、`ClimbUp` 静态动作样本。
- 当前视觉硬约束：无脚/腿/爪/手臂、无嘴、无腮红、无阴影、无描边、无光照/渐变/纹理；身体纯色、眼睛和帽子独立。
- 当前 Core 只表达权威状态、逻辑位置、动作 clip、语义锚点与简化碰撞；当前资产 Schema 尚无软体拓扑、物理参数或动态挂点。
- Box2D 依赖、P/Invoke、动态轮廓和真实动画性能均未验证。

实施开始时必须重新核对这些事实。阶段分支或资产契约变化时，先更新本计划，不得用本文覆盖新代码。

## 3. 范围与排除项

### 3.1 包含

- 从最新 Phase 1 分支建立独立 P1-004 实施分支并安全集成已批准动画预生产成果。
- 完成 AP-005 所需手工动作/fallback 候选包和最小资产契约变更提案。
- 对官方 Box2D 固定版本、源码/构建来源、MIT 许可证、native ABI 和 self-contained 发布方式做可失败 Spike。
- 在 `Dango.Desktop` 内建立不泄漏 Box2D 类型的 Physics Presentation Adapter。
- 单团子软体环、固定步长、形变限制、睡眠、异常熔断和确定性容差测试。
- WPF `StreamGeometry` 动态纯色身体、独立眼睛与帽子挂点。
- `Idle`、`Wander`、`ClimbUp/Down`、`Dragged/Falling/Landing`、`Reacting` 和 `Hidden` 的单团子纵切。
- 双团子贴贴的本地技术场景，只验证接触、挤压和成对约束，不实现好友、房间或网络。
- 为 P1-005 准备 1/6/12 只场景与帧时间诊断钩子；正式性能结论仍留在 P1-005。

### 3.2 不包含

- 让 Box2D 决定 Core 位置、登岛、落地、拖动结果、权限或服务端状态。
- 上传或逐帧同步节点、顶点、速度、冲量、弹簧或轮廓数据。
- Phase 2 房间同步、好友、情侣、正式贴贴、群体动作或离线睡眠。
- Godot、SkiaSharp、Direct2D、LiquidFun、第三方 .NET Box2D 移植或第二套长期渲染器。
- 正式美术、完整捏脸 UI、颜色/帽子最终数量、嘴、腮红、四肢、阴影、光照或材质。
- `win-arm64`、移动端、macOS、Linux 或公网部署。
- 合并到阶段分支/`main`、推送、发布标签、安装器或正式发布。

## 5. 目标架构

```text
Dango.Core SceneSnapshot / Action State / semantic contacts
                          |
                          v
            PhysicsPresentationController
             |         |          |
             |         |          `-- authored pose / fallback sampler
             |         `-- InteractionDirector (presentation cues only)
             `-- IPhysics2DWorld
                        |
                        v
                Box2D C API adapter
                        |
                        v
          soft-body ring vertices + attachment frames
                        |
                        v
       WPF DeformableDangoVisual / StreamGeometry
              | body | eyes | hat |
```

### 5.1 模块职责

| 模块 | 职责 | 禁止承担 |
|---|---|---|
| Core Scene | 权威状态、位置、动作结果、逻辑碰撞和语义锚点 | Box2D 句柄、物理顶点、WPF 类型 |
| Presentation Contract | 将快照转换为动作/接触 cue，定义 fallback 和诊断结果 | 改写 Core、决定业务结果 |
| Box2D Adapter | native 生命周期、世界步进、软体环和接触采样 | 桌面 HWND、WPF 控件、网络同步 |
| Interaction Director | 为落地、抓边、拖动和双体场景生成有界表现约束 | 成为第二套状态机或碰撞权威 |
| WPF Visual | 根据采样点绘制纯色轮廓并放置眼睛/帽子 | 直接调用服务端或裁定动作 |
| Diagnostics | 记录步进、帧时间、fallback 和异常计数 | 读取窗口标题、桌面文件或用户输入内容 |

首轮不新增独立项目；先在 `Dango.Desktop` 内以目录和接口隔离。只有 native adapter 无法在不污染 WPF/宿主的情况下独立测试时，才提出拆分项目的计划变更。

## 6. 物理模型候选

每只团子的候选 rig：

- 一个不参与外部碰撞的运动学核心锚点，平滑跟随 Core 权威姿态；
- 12 与 16 个外圈动态节点作为比较候选，不预先固定胜者；
- 相邻节点使用距离弹簧维持周长，节点与核心使用径向弹簧恢复轮廓；
- 必要时增加有限交叉约束或角度限制防止翻面，但不建立通用网格/骨骼系统；
- 外部接触使用专用 category/mask；同一团子内部节点默认不自碰撞；
- 地面、岛边和另一个团子的表现代理来自 Core 语义接触，不反向决定 Core 结果；
- 固定步长首轮候选为 60 Hz，并比较 2/4 子步；掉帧时限制最大补步，禁止追赶形成长时间卡顿；
- 形变、面积变化、质心视觉偏移、节点速度和总能量均设硬上限；实际数值由 Spike 证据选择。

轮廓由节点按稳定顺序采样，以周期 Catmull–Rom 或等价平滑方法转换为 WPF Bézier/`StreamGeometry`。算法必须避免自交、翻面和尖刺；不能通过阴影或渐变掩盖形变缺陷。

眼睛使用身体局部归一化坐标或局部三角插值挂点，允许受限位移/旋转但不跟随极端拉伸。帽子使用顶部节点计算的位置和切线方向，可附加单自由度旋转弹簧，默认没有碰撞体。

## 7. 运行、同步与降级状态

### 7.1 固定步长

- 累加真实时间并以固定 `dt` 步进；单帧补步有上限，超出部分记入诊断并丢弃，不通过无限补算追赶。
- 同一 `win-x64` 构建、初始条件、cue、种子和固定步长在测试容差内重复；不承诺跨 CPU 逐浮点一致。
- 渲染使用上一/当前采样插值，插值不能写回物理世界或 Core。

### 7.2 生命周期

- 创建：只有可见团子进入需要物理表现的状态时创建实例。
- 休眠：能量低于阈值且无新 cue 时允许 Box2D 休眠；低频眨眼不唤醒身体物理。
- 隐藏/宿主失效：立即停止调度并释放 native 实例，不保留后台模拟。
- 恢复：从当前 Core 权威姿态重新初始化，不高速补播离线物理帧。

### 7.3 fallback

以下任一条件立即切换手工关键姿势：native 加载/ABI/版本失败、非有限数、节点顺序翻转、形变或补步超限、连续异常、降低动画开启，或渲染器无法消费有效轮廓。

fallback 必须保留动作事件、最终姿态、眼睛表情和帽子；不得用隐藏角色掩盖普通物理错误。fallback 原因只记录受控错误码和计数，不写异常内存、桌面内容或输入数据。

## 8. 任务顺序与失败验收

### P2D-000 — 最新基线与资产集成预检

**目标**

在新 P1-004 Worktree 中核对最新阶段 HEAD、P1-003/C3、动画分支提交、Core/资产差异和文件所有权，形成可审查的集成差异。

**先失败验收**

- 阶段分支不是已验收 P1-003 后继、工作区不干净或出现重叠未提交文件时停止。
- Core 状态、资产 Schema、逻辑画布或宿主接口与动画参考不兼容时，不直接合并；先更新设计/映射。
- 集成后必须保留阶段分支的 P1-003 验证与原生分层实现，不能被旧文件覆盖。

**完成条件**

- 记录最新 HEAD、动画输入提交、差异和集成方式；
- 全解决方案基线格式、构建和测试通过；
- 没有开始 Box2D 接入。

### P2D-001 — AP-005 手工动作与 fallback 候选包

**目标**

先补齐 `Wander`、`ApproachIsland`、`OnIsland`、`ClimbDown`、`Dragged`、`Falling` 和 `Reacting` 的手工动作语义与分层 fallback，形成不会默认加载的候选资产包。

**先失败验收**

- 每个 Core 状态必须有 clip 或明确的 `Hidden` 处理；缺失映射失败。
- 图层、挂点、事件、fallback、来源或透明 PNG 不完整时失败。
- 身体/眼睛/帽子烘焙、嘴/腮红/阴影、脚状轮廓、渐变或未知来源均失败。
- 当前 Schema 无法表达物理 profile 时，只新增最小版本化字段提案；不得把参数塞入无关字段。

**完成条件**

- AP-005/A5 资产结构门禁通过；
- 手工姿势可独立承担无物理运行；
- 视觉观感仍标记为候选，未提升为 WPF 或人工体验通过。

### P2D-002 — Box2D 获取、构建与加载 Spike

**目标**

验证官方固定版本的来源、MIT 许可证、x64 native 构建、最小 C API、P/Invoke ABI、发布复制和进程回收，再决定依赖以源码还是固定构建产物进入仓库。

**先失败验收**

- 先写 native loader 测试：DLL 缺失、架构错误、ABI/版本不符必须得到受控失败和 fallback，不能导致进程崩溃。
- 干净 checkout 无法按文档构建，或 self-contained 发布物需要运行时联网下载时失败。
- 许可证、tag/commit、源码/二进制哈希和修改记录不完整时失败。
- native world/body/joint 未全部销毁或重复创建/销毁不稳定时失败。

**停止点**

任一项无法在小型 adapter 内解决，停止并提交依赖证据；不得改用未经评估的 .NET 移植、复制未知 DLL 或把下载写进应用启动流程。

**完成条件**

- 一个不渲染的 create/step/destroy 探针通过；
- `win-x64` self-contained 从独立目录成功加载固定版本；
- 来源、许可证、构建命令、哈希和发布布局可审查。

### P2D-003 — 表现契约与隔离边界

**目标**

先用 fake physics world 定义 Core 快照到表现 cue、轮廓输出、挂点、诊断和 fallback 的接口，再接真实 Box2D adapter。

**先失败验收**

- 物理输出修改 Core 快照、状态机或逻辑落点的测试必须失败。
- `Dango.Core` 或 Desktop Host 引用 Box2D/native 类型时架构测试失败。
- `Hidden`、降低动画、宿主失效和 dispose 后继续 step 时测试失败。
- 双体技术 cue 只能表达参与者与视觉接触，不得创建房间/好友语义。

**完成条件**

- fake 与 native adapter 共享最小接口；
- 宿主、Core、物理和 WPF 渲染边界可分别测试；
- 不引入新的通用 DI/消息总线框架。

### P2D-004 — 单团子软体环稳定性

**目标**

在无 WPF 的固定步长测试中建立运动学核心、节点环、相邻/径向弹簧、接地代理、休眠和异常熔断。

**先失败验收**

- 长时间空闲、落地冲量、拖动、时间尖峰和重复初始化均不得产生非有限数、节点翻转或无界能量。
- 物理质心/轮廓超出 Core 权威范围时必须被限制或 fallback，不能移动 Core。
- 相同输入在同一构建重复采样必须在批准容差内一致。
- 12/16 节点与 2/4 子步必须用同一输入比较，不凭预览主观选择性能方案。

**停止点**

若 Box2D 关节软体无法同时做到可控轮廓、稳定衰减和合理节点数，停止并保留复现；不在 P1-004 内扩展为自研 FEM、流体或通用网格引擎。

### P2D-005 — WPF 动态轮廓与分层挂点

**目标**

用 `StreamGeometry` 绘制纯色闭合身体，并把眼睛、帽子和手工姿势 fallback 接入同一视觉组件。

**先失败验收**

- 自交、翻面、尖刺、脚状凸起、描边/渐变/阴影、眼睛过度拉伸、帽子漂移或透明区域脏边均失败。
- 无效轮廓必须切 fallback，不能把异常点传给 WPF 导致宿主崩溃。
- 渲染组件不得直接 step Box2D；调度和采样由 controller 统一管理。
- 关闭物理与降低动画后，手工姿势必须独立可见且事件语义一致。

**真实检查**

- 在普通 WPF 验证窗口先看单团子，再接已验收 WorkerW；
- 分别检查静止、落地、拖动和帽子晃动；
- 用户确认无脚轮廓、柔软、可爱且不过度果冻化。

### P2D-006 — P1-004 单团子动作纵切

**目标**

以 Core 状态机和手工关键姿势为语义主线，将物理 cue 接入 `Idle`、移动、爬岛、下岛、点击/抚摸、拖动、下落、落地、隐藏和退出。

**先失败验收**

- 每个状态的允许/拒绝转换、取消点、落地点和 fallback 有测试。
- `landed`、`island-grabbed` 等事件不能由 Box2D 接触回调自行触发权威转换。
- 拖动跨岛边、屏幕/显示器边缘后的最终位置必须来自 Core。
- 隐藏、切换宿主、Explorer 失效和退出必须停止物理调度并释放 native 资源。

**真实验证**

- 原生分层 WorkerW 完成完整动作清单；Overlay 只做安全 fallback 兼容检查，不重复提升为同等人工验收。
- 真实桌面记录输入、焦点、图标层切换、动作连续性与残留进程。

### P2D-007 — 双体接触技术证明

**目标**

在本地虚构场景中验证两个软体环的真实接触、共同 cue、互补挤压与释放。它不是正式贴贴功能。

**先失败验收**

- 双方独立决定接触对象、接触方向或最终位置时失败。
- 物理碰撞将核心锚点推离权威位置、产生持续争抢/抖动或明显穿模时失败。
- 删除任一参与者、取消 cue 或切 fallback 后必须有界收束并释放约束。
- 测试不得创建账号、好友、房间、网络连接或声称同步完成。

### P2D-008 — 诊断、性能预检与 P1-004 验收

**目标**

建立 P1-004 验收记录和供 P1-005 使用的统一采样入口，取得单团子门禁与 1/6/12 只初步基线。

**自动门禁**

- 格式、Release 构建、Core/Desktop 全部测试和 `win-x64` self-contained 发布通过；
- native 缺失/错误版本、异常形变、fallback、生命周期和隐私负向测试通过；
- 发布目录包含固定 native 依赖和许可证，且 `--smoke-test` 不残留进程；
- `git diff --check` 通过。

**性能与人工边界**

- 一只空闲团子 CPU 不高于 1%，工作集不高于 250 MB；一只普通活动团子 CPU 不高于 5%，目标 60 FPS；降低动画目标 30 FPS。
- 平均/P95 帧时间、physics step、补步丢弃、fallback、CPU、GPU 和工作集记录实际设备、构建与采样窗口。
- 6/12 只只形成设备相关预检；正式压力结论属于 P1-005。
- 用户单独验收重量、柔软、可爱、安静、眼睛/帽子稳定性和长期干扰程度。
- 自动测试、单次录像或静态截图不得替代真实桌面与人工验收。
