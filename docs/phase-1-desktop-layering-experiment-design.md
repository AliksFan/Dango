# Phase 1 桌面对象分层功能试验设计

> 状态：已批准、已实施并完成人工验收
>
> 日期：2026-09-02
>
> 验收日期：2026-09-03
>
> 适用范围：P1-003 WorkerW/Shell 宿主的增量可行性试验
>
> 决策属性：仅验证技术能力与交互取舍，不构成最终产品规则

## 1. 背景

P1-003 的两阶段原生宿主已经在 Windows 11 Build 26100 上取得以下人工证据：

- Dango 能切换到 WorkerW/Shell 动态桌面宿主；
- 浅蓝桌面背景、占位团子和悬空岛可见；
- 桌面快捷方式、空白区域框选和右键可正常使用；
- 通过位于桌面图标层前方、只覆盖团子矩形的透明输入代理，团子可以拖动。

当前原型仍把团子、悬空岛和后续家具视为同一渲染层，无法验证不同对象位于桌面图标之前或之后的体验。用户希望先用功能试验判断这种分层是否值得成为正式产品规则。

## 2. 试验目标

本试验验证三个独立能力：

1. 普通家具可以逐件选择位于桌面图标之上或之下；
2. 团子可以选择位于桌面图标之上或之下；
3. 悬空岛作为特殊家具，可以悬浮于普通应用和任务栏之上，但在真正的全屏前台窗口出现时临时隐藏。

层级选择保存在本机，Dango 重启后恢复生效。试验结果用于后续产品设计，不预先承诺最终保留所有选项。

## 3. 明确不做

- 不实现完整家具编辑器、家具资产库、房间或多人家具同步；
- 不把本地层级偏好写入服务端或房间间共享状态；
- 不读取窗口标题、进程名、窗口内容、桌面文件或图标名称来判断游戏和视频；
- 不承诺识别应用类型，只判断窗口是否形成全屏占用；
- 不在本试验中实现 P1-004 正式团子动画、攀爬或家具动作；
- 不改变团子、房间和家具在产品设计基线中的唯一性与服务端权威规则。

## 4. 对象与层级模型

### 4.1 层级定义

| 层级 | 相对位置 | 用途 |
|---|---|---|
| `BelowDesktopIcons` | WorkerW 壁纸层之上、`SHELLDLL_DefView` 之下 | 背景、下层团子、下层普通家具 |
| `AboveDesktopIcons` | `SHELLDLL_DefView` 之上、普通应用窗口之下 | 上层团子、上层普通家具 |
| `AlwaysOnTopExceptFullscreen` | 普通应用和任务栏之上；全屏前台窗口出现时隐藏 | 特殊家具“悬空岛” |

“图标之上”只表示高于桌面图标，不表示高于普通应用。普通家具和团子不得使用系统级 Topmost。

### 4.2 试验对象

- **团子**：一个现有占位团子，提供“图标之上 / 图标之下”选择；
- **普通家具**：新增一个视觉上容易区分的占位软垫，提供独立的“图标之上 / 图标之下”选择；
- **悬空岛**：保留现有占位岛，固定使用“所有界面之上（全屏时隐藏）”试验模式，不与普通家具共用图标层开关。

普通家具按稳定的本地对象 ID 保存选择。本次只有一个占位软垫，但数据结构不得把设置写死为单个全局家具开关。

## 5. 输入优先级

### 5.1 团子位于图标之上

- 团子矩形接收点击和拖动；
- 团子以外的代理区域不拦截输入；
- 桌面快捷方式、空白区框选和右键保持可用；
- 团子若遮住图标，团子优先接收该重叠区域的输入。

### 5.2 团子位于图标之下

- 桌面图标命中优先于团子；
- 若指针位置命中桌面图标，点击、双击和拖动必须交给桌面；
- 若指针位于团子上且没有命中桌面图标，透明输入代理允许拖动团子；
- 团子与图标重叠的部分可能暂时无法拖动，用户需要从未重叠部分拖走；这是已接受的试验取舍。

图标命中只查询系统桌面列表控件在给定坐标是否存在项目，不读取、记录或持久化图标文本、文件路径及内容。查询失败时安全退化为“桌面优先”，不得为了维持团子交互而吞掉未知桌面输入。

### 5.3 普通家具与悬空岛

- 普通家具本轮只验证显示层级，不实现拖动；
- 悬空岛本轮只验证 Topmost 与全屏隐藏，不拦截鼠标；
- 后续若需要家具交互，必须另行设计输入区域和桌面优先级，不能直接复用团子规则。

## 6. 全屏避让

### 6.1 判定

悬空岛不识别“游戏”或“视频”的业务语义。客户端只使用必要的 Win32 几何和可见性信息判断：

1. 获取当前前台窗口；
2. 排除 Dango 自身窗口、桌面 Shell 和无效/不可见窗口；
3. 获取该窗口所在显示器的完整边界；
4. 当前台窗口可见边界覆盖完整显示器边界时，视为全屏；
5. 普通最大化窗口若只覆盖扣除任务栏后的工作区，不视为全屏。

不读取或记录窗口标题、进程名、窗口内容。独占全屏若由系统自然遮挡 Dango，也视为符合“不覆盖全屏内容”的结果。

### 6.2 行为

- 进入全屏：悬空岛在短暂防抖后隐藏，不抢焦点；
- 离开全屏：悬空岛恢复到原位置和原显示器；
- 快速切换窗口：重复事件幂等，不创建重复窗口或计时器；
- 判定异常：悬空岛安全隐藏，控制中心保留本地诊断状态。

## 7. 宿主结构

```text
普通应用 / 任务栏
└─ 悬空岛 Topmost 透明覆盖窗口（全屏时隐藏）

Progman
├─ 上层对象宿主（团子或普通家具，非 Topmost）
├─ SHELLDLL_DefView（桌面图标）
├─ 下层对象宿主（背景、团子或普通家具）
└─ WorkerW 壁纸层
```

实现保持对象场景与 Win32 句柄分离：对象只声明本地层级枚举，宿主协调器负责把对象投影到对应渲染表面。不得把 `HWND`、Shell 类名或 `SetWindowPos` 调用泄漏到场景模型。

团子跨层时必须保持同一个逻辑对象和同一坐标，不能复制成两个同时可见、可交互的团子。切换过程先建立目标表面并确认可见，再移除旧表面；失败时恢复旧层，不显示重复对象。

## 8. 设置与持久化

控制中心“桌面体验”页增加“对象层级（实验）”卡片：

- 团子：`图标之下` / `图标之上`；
- 普通家具列表：每件家具独立选择 `图标之下` / `图标之上`；
- 悬空岛：只读显示 `所有界面之上；全屏时隐藏`；
- 明确标注“实验设置，规则可能调整”。

建议默认值：

- 团子：`BelowDesktopIcons`；
- 普通家具：`BelowDesktopIcons`；
- 悬空岛：`AlwaysOnTopExceptFullscreen`。

设置保存到 `%LOCALAPPDATA%\Dango\settings.json`，使用带版本号的数据结构和临时文件原子替换。仅保存对象 ID 与层级枚举，不保存桌面图标、前台窗口或鼠标轨迹。未知枚举或损坏文件回退到上述默认值并显示非阻断提示。

示意结构：

```json
{
  "schemaVersion": 1,
  "desktopLayeringExperiment": {
    "dangoLayer": "BelowDesktopIcons",
    "furnitureLayers": {
      "prototype-cushion": "BelowDesktopIcons"
    }
  }
}
```

## 9. 状态切换与失败恢复

1. 用户修改层级选项；
2. 设置服务先验证枚举和对象 ID；
3. 宿主协调器创建或复用目标层表面；
4. 将逻辑对象投影到目标层并保持统一坐标；
5. 确认可见且句柄有效后移除旧层投影；
6. 原子保存设置；
7. 任一步失败则恢复旧层和旧设置，并在控制中心显示安全错误。

Explorer 重启后，三个层分别重新发现宿主并恢复；恢复期间不置顶错误窗口、不无限重试。悬空岛覆盖窗口不依赖 WorkerW 句柄，但仍随应用统一隐藏和退出。

## 10. 先定义的失败验收

### 10.1 自动验收

- 同一对象不能同时属于两个可见层；
- 团子跨层后逻辑 ID 和坐标不变；
- 每件普通家具的层级设置互不覆盖；
- 设置重启后恢复，损坏或未知值回退默认；
- 下层团子命中桌面图标时返回“桌面优先”；图标查询失败也返回“桌面优先”；
- 上层团子命中时可拖动，代理外区域不阻断桌面；
- 普通家具宿主不是 Topmost；
- 悬空岛窗口为 Topmost，但全屏状态下隐藏；
- 最大化到工作区不误判为全屏，覆盖完整显示器时判定为全屏；
- 全屏检测不读取窗口标题、进程名或内容；
- Explorer 句柄失效后有界恢复，失败时安全隐藏。

### 10.2 Windows 实时验收

1. 分别把团子置于图标上层和下层，确认视觉顺序；
2. 下层团子与图标重叠时，点击、双击和拖动图标优先；从团子未重叠部分仍可拖走；
3. 上层团子遮住图标时团子可拖动，团子外桌面操作正常；
4. 分别切换占位软垫到图标上层和下层，确认其设置不改变团子层级；
5. 普通窗口和任务栏前确认悬空岛保持最上层；
6. 播放真正全屏视频、运行全屏游戏或使用等价全屏窗口，确认悬空岛隐藏；退出全屏后恢复；
7. 重启 Dango，确认团子与软垫层级选择保留；
8. 重启 Explorer，确认对象不重复、桌面操作和退出仍正常；
9. 在高 DPI 环境复验对象位置、代理命中和跨层坐标。

## 11. 通过与停止条件

本试验只有在自动门禁和关键 Windows 实时验收均通过后，才能说明“双桌面层 + 特殊 Topmost 岛”技术上可行。它仍不自动成为最终产品规则。

出现以下任一情况时停止继续堆叠补丁，回到宿主设计评估：

- 图标优先必须依赖读取图标名称、文件路径或其他私人内容；
- 上层对象导致桌面点击、框选或右键出现不可接受干扰；
- 悬空岛无法稳定避让全屏内容；
- 跨层会复制对象、丢失坐标或破坏后续同步模型；
- Explorer 恢复需要无界轮询或持续置顶错误窗口。

## 12. 与现有基线的关系

- `docs/product-design-v0.1.md` 中“交互式桌面壁纸/桌面背景层”和“少量特殊家具”仍是批准基线；
- 本文仅细化待原型验证的承载方式、输入干扰和悬浮岛空间关系；
- 本试验已经作为 P1-003 的受控增量实施，并于 2026-09-03 完成人工验收；
- 当前结论仅确认技术可行性，在用户形成后续产品决策前不修改产品设计基线；
- 若试验结果被采纳为正式规则，再单独更新产品设计、阶段计划和对应 ADR。
