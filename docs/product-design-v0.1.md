## 2. 桌宠房间与共同房间

### 2.1 表现形式

房间分为桌宠房间与共同房间两种空间，单人能力与在线共享规则分别定义：

- **桌宠房间**本质上是单机房间，后续支持双人联机。完整真实房间环境强制显示在壁纸层，同一团子绘制在独立透明上层，可位于普通／最大化应用上方；两表面共享一个房间物理世界、一套坐标映射和一个物理 owner。首阶段支持点击、Shift＋左键轻抚和拖动；松手后按重力落回同一房间地面，应用窗口暂不参与碰撞。主屏单屏、既有外观和稳定初始视角为首阶段边界，不新增窗口边缘平台、全局玩法键盘或跨重启房间存档。单人可在本地独立运行，无需账号、服务端准入或第二席；双人连接、裁定与权限接入另行设计。真实桌面始终属于本机，不共享给对方。
- **共同房间**是不接触真实桌面的独立多人活动空间。电脑默认打开新的独立场景窗口，也可在壁纸层呈现完整独立场景；壁纸层只是宿主，不让该场景与真实桌面交互。后续手机端可在应用内进入同一共同房间。

Windows 首版先验证电脑端体验；既有壁纸宿主仅作能力参考，不证明本次分层设计已可用。桌宠房单人进入须等房间环境与独立团子的同次新健康帧均实际呈现、映射一致后，才收起来源并开放目标输入；只有一个表面成功不算入房成功。正式在线入房另须服务端确认。失败与恢复入口不能随转场一起消失。此前悬浮岛与桌面平台线条构想暂缓，须另行设计和验证，不能作为当前房间机制的默认前提。

### 2.2 同一个团子、同一个房间

- 每只团子拥有唯一身份，同时最多属于一个有效房间；无房间是合法状态，不代表团子身份删除，也不因不同电脑或手机显示而被复制。
- 单人桌宠房是一个本地逻辑房间，两种显示表面不复制房间或团子。未来在线会话中，不同设备是同一共享房间的不同视图。
- 单人桌宠房的位置、朝向、表情、动作和互动结果由本地运行时维护；在线会话中，经同步设计确认的部分才属于共享状态。

### 2.3 共享与本地边界

以下为在线房间的共享范围，不是单人首阶段的联网要求：

- 团子的房间、相对位置、朝向、表情和动作。
- 团子之间的靠近、贴贴、碰撞和群体互动。
- 家具的位置和可交互状态。
- 点击、抚摸和拖动所产生的团子反应。
- 哪位用户发起了一次共享互动。

以下内容只属于本地电脑：

- 真实软件窗口及其标题、内容和位置。
- 本地鼠标原始轨迹和键盘输入内容。
- 桌面文件、图标及其他私人系统信息。
- 只为本地操作反馈服务的光标效果和选中框。

后续本地环境互动可以触发团子行为，在线会话仅共享经设计确认的抽象动作结果。例如“围观工作”若另案获批，其他用户只能看到动作和抽象小键盘图标，不能看到软件或输入内容。本段不授权单人首阶段读取工作应用输入；真实窗口平台及其跨电脑支撑差异仍需独立设计。

### 2.4 多分辨率一致性

房间使用与具体像素无关的统一坐标。共同房间在电脑视口中保持同一逻辑布局，后续手机客户端交付后也按同一布局适配手机视口；桌宠房间环境、团子和鼠标逆变换共用 Room→Desktop 映射到本机安全区域，不能各自缩放或另造屏幕底边地面。首阶段限主屏单屏，显示配置变化须结束拖动并安全恢复；跨屏迁移另案验证。未来双人不得用本机窗口几何改变房间权威位置或权限，窗口平台的本地支撑差异仍需设计。首个同步原型至少验证两种分辨率；超宽屏、系统缩放、多显示器和桌面平台映射列入后续专项验证。

## 3. 核心对象与规则

本节账号、访客席位、共享容量和服务端归属属于正式在线产品规则；本地单人桌宠首阶段不要求注册，不生成虚构准入或在线占位。后续双人接入与本地身份、存档的关系仍需专项设计，不能直接将单人会话认作正式在线房间。

### 3.1 用户

- 用户拥有账号、好友关系、房间权限和一只主要团子。
- 注册后自动拥有一个桌宠房间；它不占主动创建房间的额度，且不可解散。拥有房间不代表每次离房或启动都自动进入。
- 用户可以额外创建最多 3 个有效共同房间。
- 服务端保存团子的零或一个有效当前房间；登录和重连不得生成新团子或自动复制到上次房间。无房时再次启动停留首页，不自动进入桌宠房或旧公共房。手机不能显示桌宠房间，只能显示简要归属状态并手动将团子迁往共同房间。

### 3.2 团子

- 一名用户首版拥有一只主要团子。
- 团子拥有唯一身份，不因进入不同房间而被复制。
- 首版基础外观分开设计自身捏脸与帽子换装；自身捏脸提供身体／眼睛纯色及眼睛大小、椭圆度、高度和眼距调节。基础长相可保存，眨眼、开心、困倦和睡眠等运行时表情在其上组合；设计确认不代表生产实现已完成。
- 团子 DIY 分批实现：多人前先做基础外观轻量版；多人同步与碰撞原型稳定后，再提供安全、有界的真实大小、身体形状与柔软度调节；完整创建与编辑流程在后续整合。
- 自由绘画并上传团子形象属于后续企划。
- 团子没有饥饿、清洁、疾病或死亡压力。
- 团子可以自主发呆、移动、睡觉、靠近其他团子并触发简单社交动作。

### 3.3 房间

每个房间至少包含唯一身份、名称、类型、房主、成员/访客权限、容量、家具或场景布局，以及当前团子的共享状态。桌宠房间固定为私密；用户主动创建的共同房间在创建时选择私密或公共，首版不直接互转类型。

#### 桌宠房间

- 每个账号自动拥有一间，不可解散或转让；只有电脑客户端可显示和进入。
- 房主加一名由房主邀请、对方接受的**固定长期访客**。好友或情侣身份本身不自动获得第二席，访客也不能把权限转授他人。
- 房主离线不影响访客进入。两个成员席位分别保留；容量按归属本房的团子计，**最多 2 只，离线睡眠也计入**，不按连接数计。
- 在房间内正式下线的团子留在原处睡觉；成员将团子迁到别的房间时，旧位置立即移除。
- 两名成员各自在本机电脑桌面观察共享团子，不共享任何一方的真实桌面内容。

#### 私密共同房间

- 已接受定向好友邀请的长期成员才能进入；房主不在线也可使用。
- 默认 6 个成员席位，可设 1–12 个，房主和可管理成员均占席。成员暂时去了别的房间，席位仍保留。
- 成员在房间内正式下线时，团子可以留在房间睡觉，占其席位。电脑可进入独立场景；后续手机客户端交付后，手机也可进入同一房间。

#### 公共共同房间

- 默认同时容纳 6 只团子，可设 1–12 只；按当前在场团子计，不为仅持码者预留位置。
- 登录用户持有效房间码或定向链接可申请进入；没有全网广场或随机匹配。持码者仅是临时访客，没有长期席位或管理权。
- 离线团子不在公共房间留宿；正式下线时释放占位并进入**无房间状态**，不自动进入桌宠房。电脑可进入独立场景；后续手机客户端交付后，手机也可进入同一房间。
- 房主可重置房间码并封禁指定账号；被移出但未封禁者仍可用有效码再次申请进入。

### 3.4 房间创建额度

- 每名用户最多同时拥有 3 个未解散的主动创建共同房间。
- 默认桌宠房间不计入这 3 个额度。
- 被软删除的房间立即释放创建额度。
- 恢复房间时重新检查额度；额度已满时必须先解散其他主动创建房间。
- 不能通过转移房主绕过额度，房主转移规则不进入首版。

### 3.5 房间解散与恢复

- 默认桌宠房间不能解散。
- 只有房主可以解散主动创建的共同房间。
- 解散是高影响操作，需要明确展示后果并二次确认。
- 解散后房间立即停止进入和互动，并进入 7 天恢复期。
- 房间内所有在线及睡眠团子进入**无房间状态**；团子身份保留，不自动进入桌宠房或已恢复的房间。
- 公共房间码在解散时失效，恢复后由房主重新生成。
- 7 天内房主可以恢复房间，但必须重新满足创建额度。
- 7 天后永久删除房间权限、家具布局和剩余状态；永久删除不可恢复。

解散与团子迁移必须作为一个完整操作执行，不能出现房间已解散但团子仍指向该房间的状态。

### 3.6 无房间状态与离线

- 不提供“家”的概念、设置或强制归处。账号仍拥有不可解散的桌宠房间及其房主席位，但用户可以选择不用桌宠房。
- 团子在桌宠房间或私密共同房间正常正式下线时留在原处睡觉。公共共同房间正式下线，或团子被移出／封禁、失去当前房间权限、所在共同房间解散时，原子释放当前占位并进入无房间状态，不在桌宠房生成睡眠形象。
- 短暂断线先保留原房间状态和名额，超过容错时间才按正式下线处理。后续手机客户端只可看见桌宠房间的简要归属状态，不能进入或呈现该房间；手机用户可手动将团子迁往共同房间。
- 所有迁移和清空归属由服务端裁定。进入失败不主动改变最新权威归属，可保留原房或无房；并发撤权后不能恢复已失效的旧房。一个账号的多个设备不能让团子同时占据两个房间。

### 3.7 好友与权限

- 首版包含好友系统，通过邀请码或等价的定向方式添加熟人。
- 添加好友需要双方确认。
- 桌宠房主只能授予一名好友固定长期访客席位；私密共同房间的定向邀请须由受邀者接受。
- 好友身份不自动授予所有房间权限。
- 被撤销权限的用户不能再次进入；实际归属该房间的团子（包括睡眠团子）立即进入无房间状态，旧命令被拒绝。若团子已在另一有效房间，只撤销目标房的资格，不清空其另一房间归属。
- 共同房间角色保持精简：房主、可管理成员、访客。可管理成员可邀请/移除普通访客和移出当前公共访客；只有房主可改上限、授予管理身份、封禁或解散。房间管理权不授予控制他人团子的权利。

### 3.8 情侣关系

- 每名用户同时只能与一人建立情侣关系。
- 建立和解除关系都需要明确流程；建立需要双方确认。
- 首版提供轻量情侣标记和一至两种专属贴贴动作。
- 情侣身份不自动授予全部房间权限，也不排斥普通好友进入多人房间。
- 共同小窝、纪念日、情侣任务和关系数值不进入首版。

## 4. 核心体验流程

4.1–4.5 描述正式在线闭环；单人桌宠首阶段从现有首页经门廊进入本地场景，沿用已保存外观，不引入注册、邀请或服务器。共同入口与返回见 4.6。

### 4.1 初次使用

1. 用户注册并创建主要团子。
2. 系统创建该用户自己的桌宠房间，团子初始属于此房间。
3. 用户选择有限的预设外观。
4. Windows 用户在本机桌面看到团子；后续手机用户可从共同房间入口把团子迁入可玩的共同房间。
5. 系统引导用户完成点击、抚摸和拖动。

### 4.2 好友相遇

1. 用户通过邀请码添加好友。
2. 房主创建共同房间并发出邀请，或邀请一名好友占用自己的桌宠房间第二席。
3. 好友接受后带着自己的团子进入；进入成功时团子从原房间移出。
4. 所有支持该房间类型的客户端看到相同的逻辑位置、家具和动作；桌宠房间的真实桌面仅在本机显示。
5. 团子自主靠近、打招呼或贴贴。
6. 下次上线时客户端读取团子的当前权威房间；手机若发现团子在桌宠房间，仅显示归属状态，用户可手动进入共同房间。

当前归属为无房间时，首页只展示自身团子预览，桌面不出现房间团子；用户手动打开门廊选择房间并重新准入。

### 4.3 多人共处

1. 私密共同房间成员或持码进入公共共同房间的用户，带着团子进入同一房间，直至达到对应席位或在场上限。
2. 团子根据距离、空闲状态和关系选择双人或群体动作。
3. 系统保留发呆、独处和小群体互动，避免所有团子持续挤在一起。
4. 房间状态由服务端统一裁定，所有客户端显示同一结果。

### 4.4 下线

- 桌宠房间或私密共同房间：团子留在原位置附近睡觉并占名额。
- 公共共同房间：释放占位并进入无房间状态，不回桌宠房睡觉。
- 短暂断线先保留位置，超过容错时间才按正式下线处理。

### 4.5 解散房间

1. 房主发起解散并查看影响范围。
2. 房主完成二次确认。
3. 房间冻结，所有实际归属该房的在线及睡眠团子进入无房间状态。
4. 房间进入 7 天恢复期并释放创建额度。
5. 恢复时重新检查额度，团子不自动回迁；超期后永久删除。

### 4.6 门廊、入房与回门廊换房

- 首页按 W 收起编辑界面并进入二维横向门廊；镜头跟随团子，落地房门沿后墙排列，不改为三维第三人称。
- 正式在线目录只展示服务端允许本人查看的入口，不提供全网列表。看到门不等于准入成功；进入仍逐次验权、验房型和验容量。本地单人桌宠入口走本地显示就绪，不伪造服务端确认。
- 普通房窗口左上角“小门＋房门”为主返回入口，窗口有焦点且无输入控件／弹窗消费按键时也可用 Esc。桌宠房通过独立团子层右键或托盘的“房门”返回，共同房壁纸层沿用自身菜单／托盘；不捕获全局 Esc。
- 桌宠房环境与团子作为同一个场景隐藏、恢复和返回；隐藏暂停物理与输入并保持会话内位置，恢复重新核对双表面首帧，不能遗留孤立团子或透明拦截窗。点击团子不抢工作应用键盘焦点，团子可交互轮廓之外的区域穿透。
- 回门廊收起房间画面并恢复控制界面；在线会话保留当前权威归属及连接，不视为正式下线或强制退出。选中门也不迁移，只有新房准入成功才换房。无房时不显示“返回原房”。
- 房间窗口 × 仅隐藏画面，不离房、不下线、不解散；托盘仍能打开门廊或恢复画面。
- 转场失败、失焦或隐藏必须清空当前按键意图；门廊移动不发送到仍保留归属的原房间。

## 5. 首版功能范围

### 5.1 必须形成闭环

以下为完整首版目标，不是本次单人桌宠设计的实施授权；当前增量范围以 2026-10-07 分层设计为准。

- Windows 客户端安装、启动、隐藏和退出。
- 账号注册、登录和基础个人资料。
- 一只团子的创建与有限外观选择。
- 团子 DIY：在可回退的默认外观基础上调节纯色与基础眼睛参数，帽子作为独立换装部分，并分批提供有界的真实大小、身体体型与柔软度。
- 2026-10-07 换装修订：帽子扩展为无官方分类的 DIY 配饰；透明 PNG 导入、图片缩放旋转、可调图片支点／身体附着点、多件前后分层与层内排序、统一图片柔软度、独立连接／旋转／重力参数及本地显式保存重载已获批准。配饰不碰撞、不向身体施加反作用；配饰间挂接、区块色相与区域材料编辑为后续候选。详细合同见[配饰设计](planning/2026-10-07-accessory-diy-design.md)与[实施计划](planning/2026-10-07-accessory-diy-plan.md)。实施候选尚待人工验收，不关闭身体物理 DIY、多人或跨平台阶段。
- 2026-10-09 配饰账号保存方向已确认：已佩戴图片与完整穿搭参数随团子保存；本地佩戴自由，上传可私有保存，审核通过后才向其他玩家展示，含私密房间。图片按内容去重，账号权限独立，额度、引用回收及审核撤销分别管理；具体执行待细化，未实施账号资产上传或恢复。见[配饰账号保存设计](planning/2026-10-09-accessory-cloud-storage-design.md)。
- 2026-10-09 家具范围收口：先做项目提供的预设家具，自定义家具制作模块暂缓。外观图片、碰撞区与行为独立定义；第一批单件静态平台与独立单人验收窗口设计及本地实施已获批准，见[官方家具方向与小样方案](planning/2026-10-09-official-furniture-design.md)和[实施计划](planning/2026-10-09-static-platform-implementation-plan.md)。独立小样已完成编码，自动门禁与本机真实输入检查通过，规定的运行观察通过；原造型比例回归修复后，用户对 r6 窗口回复“通过”，本批独立单人小样已验收，见[验证记录](verification/2026-10-09-static-platform-prototype.md)；最终房间类型及摆放保存仍待确定。
- 2026-10-10 家具摆放方向确认：用户选择独立窗口里的本地单人场景，并大致通过微调／参数／仓库三段侧栏、仓库两列图标；要求继续简洁与部分按钮图标化。官方家具后续可调参数包括平台大小、球大小／弹性，首个真实增量先完成空布局或单默认尺寸平台的摆放与本地初始布局保存，参数调节与球布局后置。当前仅准备[实施计划](planning/2026-10-10-official-furniture-layout-implementation-plan.md)，未开始产品编码或持久化／物理集成验收；不接账号、云或正式在线房间。
- 默认桌宠房间，电脑桌面呈现，房主加一名固定长期访客，最多两只团子且离线睡眠占位。
- 共同房间以独立场景呈现，不与真实桌面互动；电脑端先实现，手机端依后续平台阶段交付。
- 创建最多 3 个共同房间，设置私密/公共类型和默认 6、最高 12 人上限。
- 房间邀请、长期权限、解散和 7 天恢复。
- 添加好友。
- 进入、离开、跨房迁移与从服务端恢复当前权威房间。
- 多人团子位置与动作同步。
- 自动靠近、普通贴贴和少量群体互动。
- 点击、抚摸、拖动及共享反馈。
- 桌宠房间和私密共同房间正常离线睡眠；公共正式下线与被迫离房进入无房间状态。
- 唯一情侣关系、轻量标记和专属贴贴动作。
- 静音、降低动画和临时隐藏。

### 5.2 团子 DIY 参数边界

正式 DIY 不直接暴露当前物理诊断面板的全部数值，而使用用户能理解的名称、预览、默认值和恢复入口。

2026-09-22 用户确认以下分批方向，详见[行走自然感与 DIY 路线](planning/2026-09-22-gait-and-customization-roadmap.md)。这是范围和排期决定，具体参数、设计与实施计划仍需逐批确定：

- **基础外观，先做轻量版**：原路线为有限纯色、帽子、基础眼睛大小和眼型预设；2026-10-05 修订为自身身体／眼睛 RGB 与四个连续眼睛滑块，帽子独立换装。基础长相与动态表情分开，调整后仍能眨眼、开心和睡眠；替代此前“眼睛不作为固定捏脸部件”的限制。
- **真实大小与体型，后续开放**：身体尺寸、宽高、顶部圆度、下半部鼓度、底部平坦度和常态压缩等候选。真实大小需匹配碰撞和承重，不能只改变图像缩放。
- **柔软性格，先预设后滑条**：将整体恢复弹性、外圈轮廓弹性、阻尼和回弹体感组合为“软糯／标准／紧实”等安全预设，具体映射待验证；多人同步与碰撞原型稳定后再开放，有限滑条需通过组合安全验证。

基础外观先具备最小保存和恢复默认能力；完整创建团子、编辑器与预设管理在后续内容整合阶段完成。

2026-10-05 用户确认[自身捏脸交互](planning/2026-10-05-dango-face-design.md)：身体与眼睛完整 RGB（含黑色和同色），眼睛以大小、椭圆度、高度、眼距四个连续滑块取代离散预设；帽子另行设计。保留现有 Windows 默认长相，生产坐标按旧默认校准，不直接套用示意身体比例。[实施计划](planning/2026-10-05-dango-face-implementation-plan.md)已授权实施，本地 Windows 候选已接通整套预览／取消／默认／显式 Schema 3 保存、兼容保护和隔离重启，见[实现验证](verification/2026-10-05-face-implementation.md)。

2026-10-06 用户确认当前候选观感，并要求归档此前对话设计：[首页与自身外观编辑](planning/2026-10-06-home-and-appearance-design.md)确定上 W 门、左 A 换装、右 D 捏脸及键帽；捏脸右侧面板向左展开，换装反向；三态原尺寸、共用接地高度与阴影，纵向参数独立滚动，保存图标靠团子右下。最新[验收记录](verification/2026-10-05-home-icons-and-ground-shadow.md)分别列自动、Native、150% 实窗与人工状态；100%／125% 及其它显示器未验证，未关闭整个 Windows 阶段。帽子候选评审、换装内容、身体物理 DIY 和多人外观同步仍独立；未合并 main、推送或更新日常安装。

2026-10-06 后续交付更新：上方候选状态保留原人工确认时的快照；用户随后授权只合捏脸，普通房依赖剥离后已将自身捏脸／首页源码合入本地 main，重新验证 370/370、零跳过，见[独立整合记录](verification/2026-10-06-face-only-local-main-integration.md)。这不改变房间领域规则，不接通普通房、多人或新换装内容；未推送、安装或部署，原专项未验证项保留。

以下仍属于引擎和安全配置，不进入用户 DIY：地面高度、节点碰撞半径、摩擦/接触求解细节、节点数量、物理子步、固定步长、核心跟随速度、形变熔断、质心/速度/面积阈值。下落高度和撞击速度属于动作表现，是否形成独立“动作性格”需后续设计，不与身体 DIY 静默绑定。

DIY 配置必须版本化、校验并可恢复默认；其他客户端同步的是受支持的团子外观/柔软度配置或预设标识，不同步逐帧节点、弹簧、速度或碰撞结果。旧客户端或性能降级模式必须得到接近的安全预设，而不是加载失败或显示不同身份的团子。

### 5.3 首版不做

- Android、iOS、macOS 或跨端客户端。
- 面向陌生人的公开广场和随机匹配。
- 公共聊天、私聊、语音和图片消息。
- 自由绘画、上传自制团子及审核系统。
- AI 对话、长期记忆和生成式角色行为。
- 饥饿、清洁、疾病、死亡等重养成数值。
- 纪念日、情侣日记、相册和关系任务。
- 复杂家具编辑器、交易或经济系统。
- 团子攀爬任意真实应用窗口。
- 房主转移和复杂组织权限。
- 允许其他用户读取本地窗口、桌面文件或输入内容。

## 6. 首版动作需求

- 基础：待机、呼吸、眨眼、移动、转向、睡眠、醒来。
- 桌宠空间：在本机桌面安全区域移动与停驻；悬浮岛、窗口线条平台及相关动作留待独立设计。
- 用户互动：被点击、被抚摸、被拖动、落地恢复。
- 普通社交：靠近、观察、打招呼、贴贴、一起睡或围坐。
- 多人社交：加入小群体、短暂停留后散开。
- 情侣专属：一至两种差异明确但不过度排他的贴贴动作。

### 6.1 行走自然感增量

2026-09-22 确认优先制作步态小样：先做轻微“压缩 → 舒展 → 放松”和起步/收步姿态过渡，保持贴地，随实际移动调整表现，眼睛和帽子协调跟随，停止后平滑恢复。首个候选不改变碰撞体、硬度或真实位移规则，具体方式与数值在小样设计时确定。

真实行走快慢节奏与最小多人移动规则共同设计，因为它会改变碰撞、停止距离和边缘余量；共享节奏由服务端裁定，各客户端不得独立随机变速。动作表现不逐帧上传。具体批次与验收方向见[行走自然感与 DIY 路线](planning/2026-09-22-gait-and-customization-roadmap.md)。

## 7. 待原型验证

1. **Windows 房间呈现**：验证壁纸层完整桌宠房环境＋独立上层团子的同一实体、坐标、单 owner 和双表面联合就绪，普通／最大化应用前台互动、透明轮廓穿透及焦点保持；共同房默认独立窗口及可选壁纸层完整场景另按对应范围验证。
2. **双电脑桌宠映射**：验证同一逻辑房间在不同本机桌面、安全区域和分辨率下的空间关系；窗口线条平台另案设计。
3. **严格同步观感**：验证不同分辨率和网络延迟下的拖动、贴贴和群体动作。
4. **多人自动互动调度**：避免动作抢占、持续贴贴或部分团子长期被冷落。
5. **输入与工作干扰**：验证点击区域、输入穿透、任务栏和桌面图标兼容性。
6. **公共共同房间入场体验**：验证房间码/定向链接、满员、封禁与重置后的清晰反馈，不提供广场或随机匹配。
7. **共同房间容量观感**：以默认 6、最高 12 作为首版基线，验证私密成员席位与公共在场人数的不同规则。

## 8. 建议验证顺序

2026-09-30 排期补充：以下 A→B→C→D 是原建议顺序。Phase 2A 已完成 B 的同机最小纵切并获用户人工认可，但 B 的正式双机验证仍未完成；用户要求先完成完整可用的 Windows UI（创作编辑器后置），再安排正式双机验收。因此 C 的账号/社交能力与 D 的相关界面可能先于 B 的双机门禁推进，具体交叉范围、实现顺序和验收仍须另行设计与批准。该排期调整本身不批准正式房间或账号实施；随后获批的房间产品规则以上文 2026-10-02 修订为准，也不把 B 或完整 Phase 2 判为已验收，详见[排期记录](planning/2026-09-30-ui-before-dual-machine-note.md)。

### 阶段 A：桌面生命感

- 单机、无账号、无服务器。
- 一只团子和本机桌面安全区域。
- 移动、点击、拖动、隐藏和输入穿透；悬浮岛专项暂缓。

### 阶段 B：同一房间同步

- 两个 Windows 客户端连接一个临时房间。
- 同步两只团子的位置、拖动和一个贴贴动作。
- 使用不同分辨率验证同一空间感。

### 阶段 C：社交闭环

- 账号、好友邀请、桌宠固定访客、共同房间权限和权威房间恢复。
- 至少三只团子进入同一房间。
- 桌宠与私密共同房间睡眠、公共正式下线及被迫离房的无房间状态，以及共同房间解散与恢复。

### 阶段 D：首版完善

- 有限外观、家具、基础动作和情侣动作。
- 完善断线恢复、设置、隐私提示和错误状态。
- 进行小范围熟人测试。

原建议要求阶段 A 和 B 通过前不投入大量美术资产、完整账号系统或正式后端建设；当前顺序调整允许在详细设计及实施范围另行获批后，先于双机验收实施 UI 所需的账号/后端能力，不以同机纵切代替 B 的双机验收，也不据此提前投入大量美术资产。

## 9. 产品验收标准

- 不打开传统游戏窗口也能持续看到团子生活在桌面中。
- 团子能自然地在本机桌面安全区域活动；悬浮岛不作为当前验收前提。
- 两名及以上用户看到一致的房间、位置和动作。
- 一名用户拖动或抚摸团子时，其他在线用户看到同一次互动。
- 无人操作时，团子会自然社交，也保留适量独处行为。
- 桌宠房间、私密共同房间、公共共同房间下线和短暂断线分别得到正确处理。
- 房间权限能够阻止未授权用户进入。
- 房间解散、恢复和超期删除不会留下悬空团子；被迫离房者进入合法无房间状态，恢复或启动不自动入房。
- 一只团子不会因跨房间、多设备或重连而同时出现在两处；手机不能进入桌宠房间。
- 用户可以降低或隐藏桌宠干扰。
- 没有重养成、聊天和 AI 时，测试者仍能理解“我们的团子正在一起陪伴”。

## 10. 尚未确认

- 最终渲染后端与桌面承载细节；客户端基础技术栈已由 [ADR 0001](adr/0001-windows-client-foundation.md) 批准。
- 桌宠房间本地平台识别、位置差容忍与失效处理，须单独满足隐私约束。
- 他人团子互动的同意与限频细则。
- 情侣关系解除后的冷却期或重新建立规则。
- 原型和首版的具体日历时间线。
