> 状态：已实施并通过自动门禁；真实桌面矩阵与人工验收待完成

## 1. 目标与实施结论

本增量把本地桌面宿主从当前 `Overlay` / `WorkerW` 两个试验候选收敛为两个正式显示模式：

- `Wallpaper`：默认模式，由已验证的 WorkerW/Shell 宿主承载；
- `Window`：标准 WPF 独立窗口，由用户显式选择，也作为 WorkerW 不可用时的可选恢复路径。

最终运行时枚举、设置、控制中心和诊断只允许 `Wallpaper` 与 `Window`。透明覆盖层不再作为用户选项、自动回退或隐藏的第三条运行路径。历史设计、验证记录和 Git 历史继续保留，避免改写 P1-002 已经发生的证据。

实施必须先让 `Window` 独立通过最低安全门禁，再切换默认值、迁移设置和删除 Overlay。任何中间提交都不得形成“控制中心已移除 Overlay，但 Window 尚不可用”的不可恢复版本。

## 2. 当前基线与前置条件

### 2.1 已核对的当前结构

当前阶段基线 `1ea0885` 具有以下结构：

- `DangoApplicationHost` 同时创建 `OverlayWindow` 和 `WorkerWWindow`，启动时先显示 Overlay；
- `DesktopHostCoordinator` 在 `Overlay` 与 `WorkerW` 间迁移可见性和交互状态，WorkerW 激活失败时回滚到 Overlay；
- `ApplicationCommandController` 通过宿主确认结果后才报告设置已应用；
- `WorkerWWindow` 负责 Shell 发现、有界恢复、图标上下层、输入代理和安全隐藏；
- `ControlCenterWindowSettingsStore` 使用版本化、原子写入的 `settings.json`，当前 Schema 只覆盖控制中心尺寸和桌面分层试验设置；
- Overlay 命中和拖动类型仍被 WorkerW 上层对象复用，不能直接按目录整体删除。

P2D-006 脏工作树还加入了单团子 Core 动作与 `SingleDangoMotionRuntime`。其生命周期测试已经要求 Stop、宿主丢失和 Dispose 释放所拥有的物理世界，但方向控制和最终动作观感仍在收口。

### 2.2 强制前置条件

本任务不得从当前旧阶段基线直接编码，也不得与当前 P2D-006 脏工作树并行修改宿主、控制中心或动作控制器。开始实施前必须同时满足：

1. 方向控制/P2D-006 已完成可失败测试、WorkerW 接入和人工验收，形成可引用的安全提交；
2. 该提交及其依赖已集成到最新 Phase 1 基线，工作区无未归属修改；
3. 从该集成点创建独立分支 `feat/p1-006-window-mode-host-cutover` 和独立 Worktree；
4. 重新核对 `AGENTS.md`、上位设计、阶段计划、HEAD、状态以及所有相关 Worktree；
5. 明确本分支独占宿主协调器、场景窗口、控制中心宿主设置、设置迁移和对应测试文件。

若 P2D-006 尚未形成安全基线，或其 Core/物理生命周期仍会在 WorkerW 切换时丢失状态、重复 Tick 或泄漏 native 世界，本任务保持阻塞，不复制未提交代码绕过集成顺序。

## 3. 范围与排除项

### 3.1 本次包含

- 标准、可移动、可缩放、可最小化的 WPF 场景窗口；
- `Wallpaper` / `Window` 正式模式契约和 WorkerW 默认值；
- 单一 Core 实体跨宿主的位置映射、调度暂停和物理世界重建；
- 普通窗口关闭到隐藏、重新显示、最小化和恢复生命周期；
- WorkerW 失效后的安全隐藏、显式重试和显式切换窗口入口；
- 控制中心正式设置、确认状态、诊断文案和桌面图标层级的条件显示；
- `settings.json` 版本升级、旧 Overlay 值迁移、损坏与未知值处理；
- DPI、多显示器、显示器移除、Explorer 重启和重复事件幂等；
- Overlay 运行实现、入口和仅属于 Overlay 的当前测试退役；
- 自动门禁、真实 Windows 验收、人工观感和交付证据分层。

### 3.2 本次不包含

- 改写方向键/WASD、跳跃、挤压或走动语义；
- 新增自主行为、多人同步、服务端输入、房间或账号能力；
- 新渲染后端、新物理引擎、安装器、自动更新或公网部署；
- 将 Window 变成无边框、透明、穿透、Topmost 或桌面伪装窗口；
- 自动弹出 Window、自动抢焦点或在宿主失败时替用户改写显示模式；
- 删除 P1-002 历史设计、历史验证记录或历史提交；
- 把静态门禁、进程存活或自动化点击称为真实桌面与人工验收完成。

## 4. 最终模式与职责契约

### 4.1 枚举与命名

运行代码使用语义枚举：

```text
DesktopDisplayMode
├─ Wallpaper
└─ Window
```

`Wallpaper` 是产品语义；WorkerW 是该模式当前的 Windows 技术实现。控制中心显示“壁纸层”，诊断可额外显示“WorkerW 已挂载”或恢复状态。不得继续把 `WorkerW` 暴露为面向用户的长期枚举名。

`Overlay` 只允许出现在迁移读取器、历史验证文档和 Git 历史中。迁移完成后的写入模型、运行时分支、UI 自动化 ID 和新测试数据不得再生成 `Overlay`。

### 4.2 模块职责

| 模块 | 职责 | 不得承担 |
|---|---|---|
| Core 场景/动作控制器 | 唯一团子实体、权威动作状态、逻辑位置、边界裁定 | WPF 窗口、HWND、WorkerW、DPI 和物理节点 |
| 表现运行时 | 从 Core 快照创建并推进一个物理世界，输出局部轮廓 | 决定宿主模式、创建第二个 Core 实体、补播停机帧 |
| `Wallpaper` 适配器 | Shell 挂载、Explorer 恢复、桌面层级、输入代理、渲染表面 | 自动打开 Window、持久化模式 |
| `Window` 适配器 | 标准 WPF 窗口、焦点、尺寸位置、可见性与渲染表面 | 模拟桌面层、Topmost、透明穿透 |
| 宿主协调器 | 串行化切换、暂停输入/调度、坐标映射、回滚和状态快照 | 修改 Core 业务语义或由 UI 外观推断成功 |
| 设置服务 | 读取、验证、迁移、原子保存最后确认的设置 | 在目标宿主未确认前保存请求值 |
| 控制中心/托盘 | 提交命令、显示观测状态、提供显式恢复操作 | 直接操作 HWND、安装输入桥、自动弹窗 |

## 5. 普通 WPF 独立窗口

### 5.1 窗口属性

`Window` 模式新增独立的场景顶层窗口，最低契约为：

- WPF 标准系统标题栏和边框；`ResizeMode=CanResize`；
- 有任务栏入口，可最小化、最大化和通过系统窗口菜单移动；
- `Topmost=false`，不使用 `AllowsTransparency`，不设置点击穿透；
- 初始客户区建议 `800 × 600 DIPs`，最小 `480 × 360 DIPs`；
- 窗口内容复用 WorkerW 使用的场景组合和动态团子视觉，不复制第二套动作/物理实现；
- 场景背景使用明确的不透明产品色，普通应用遮挡和 Alt+Tab 可见是正常结果；
- 场景窗口不承载控制中心设置或退出确认，避免窗口与应用生命周期耦合。

不得从当前 `OverlayWindow.xaml` 改名后保留透明、无边框或 ToolWindow 行为。可复用的拖动、命中和视觉组合必须先移动到中性模块，再由 `Wallpaper` 与 `Window` 适配器引用。

### 5.2 窗口生命周期

- 用户点击场景窗口关闭按钮时，拦截本次关闭并执行“隐藏场景”；不切回 Wallpaper，不退出 Dango；
- 托盘和控制中心仍运行，当前持久化模式仍是 `Window`，可从“显示团子”重新打开同一场景；
- 最小化、隐藏或完全遮蔽时停止可停止的帧调度并释放物理世界；恢复时从当前 Core 快照创建新世界；
- 窗口恢复不得按离开时长推进若干物理步，也不得重放期间积压的按键或动作帧；
- 只有应用级“退出 Dango”执行真实 Close/Dispose，按确定顺序回收输入、计时器、物理世界、场景窗口、控制中心和托盘；
- 重复关闭、重复显示、最小化/恢复抖动必须幂等，不创建重复窗口或重复计时器。

### 5.3 尺寸与位置

窗口移动和缩放使用 DIPs。持久化前把窗口中心相对于所在显示器工作区归一化，并保存经验证的宽高；不保存桌面内容、窗口标题或鼠标轨迹。

恢复顺序为：

1. 按不含用户内容的显示器键匹配原显示器；
2. 匹配失败时选择当前主显示器；
3. 使用当前显示器 DPI 把保存的 DIPs 还原为逻辑尺寸；
4. 用归一化中心计算位置；
5. 把标题栏和最小可操作区域夹入当前工作区；
6. 非有限数、越界尺寸或未知显示器数据回退到居中的默认尺寸。

显示器键只允许使用系统设备标识的最小必要形式，不保存显示器友好名称、序列号或其他可关联个人设备的信息。

## 6. 单一实体与宿主切换事务

### 6.1 坐标归一化

宿主切换只转移一个 Core 实体。以团子权威边界中心为基准，源可用区域为 `S`，目标可用区域为 `T`：

```text
u = clamp((centerX - S.left) / S.width,  0, 1)
v = clamp((centerY - S.top)  / S.height, 0, 1)

targetCenterX = T.left + u × T.width
targetCenterY = T.top  + v × T.height
```

源区域和目标区域都使用各自显示器的逻辑工作区，不混用物理像素。目标边界由 Core 的现有夹紧规则收敛，保证团子完整位于目标安全区域。零尺寸、非有限 DPI、已移除显示器或无法取得工作区时，切换失败并保持原宿主；不得猜测坐标后声明成功。

岛和家具使用与团子一致的场景坐标变换，不为每个宿主保存一套互相漂移的位置。桌面图标上下层只影响 Wallpaper 的投影，不改变 Core 坐标。

### 6.2 切换步骤

所有切换经单一异步门串行执行，按以下顺序：

1. 读取当前确认状态；目标与当前模式相同则幂等返回；
2. 拒绝拖动中、Shell 恢复中或已有切换进行中的请求，并返回可公开的安全原因；
3. 暂停键盘输入桥、窗口预览键和宿主 Tick，清空四键按住状态；
4. 从唯一 Core 控制器取得一次权威场景快照和源逻辑工作区；
5. 计算目标工作区及归一化位置，并由 Core 夹紧得到待应用快照；
6. Stop 并 Dispose 当前 `SingleDangoMotionRuntime` 所拥有的物理世界；确认不存在活动 Tick；
7. 在不可见状态创建或准备目标宿主表面；
8. 隐藏源表面，针对同一 Core 实体创建一个新的物理世界，以最新权威快照作为第 0 帧；
9. 显示目标表面并核对模式、可见性、交互、句柄/窗口状态和唯一运行时；
10. 目标确认后才关闭不再需要的源表面资源、恢复目标输入并原子保存模式；
11. 发布新的只读状态快照，控制中心从“正在应用”进入“已生效”。

切换间隔只影响墙钟，不影响物理步进。新物理世界从第 0 帧开始，固定步长计数重新建立；不得用切换耗时计算补帧数量。

### 6.3 失败回滚

目标准备、映射、物理创建、显示或确认任一步失败时：

1. 停止并释放目标输入、计时器、物理世界和表面；
2. 使用切换前的同一 Core 快照和源工作区重新创建源物理世界；
3. 只在源宿主确认可见后恢复输入；
4. 保持持久化模式为切换前值，并报告经过隐私过滤的失败原因。

若源宿主也无法恢复，则进入统一 `SafeHidden`：无场景窗口、无输入桥、无 Tick、无 native 物理世界，控制中心和托盘继续可用。安全隐藏不是第三种显示模式，也不得写入设置枚举。

### 6.4 切换不变量

- 任意时刻只有一个 Core 团子实体；
- 任意时刻最多一个活动物理世界和一个活动 Tick 源；
- 任意时刻最多一个可交互场景表面；
- 目标未确认前，设置和 UI 不显示新模式已生效；
- 切换、回滚和恢复均不补播离线帧；
- 拖动捕获、键盘按住状态和输入代理不得跨宿主延续；
- 诊断不得输出异常正文、按键、窗口标题或桌面内容。

## 7. Wallpaper 默认与失败恢复

### 7.1 默认规则

- 全新安装、设置文件不存在、旧设置无宿主字段或宿主字段损坏时，期望模式为 `Wallpaper`；
- 有效且已确认保存的 `Window` 选择在重启后继续使用，不被“默认 Wallpaper”覆盖；
- 应用启动先创建控制中心/托盘所需的应用壳，再尝试启动期望宿主，确保宿主失败后仍有恢复入口。

### 7.2 WorkerW 失败

WorkerW 初次挂载失败、Explorer 句柄失效或有界重试耗尽时必须：

- 立即关闭 Wallpaper 输入、调度和物理世界；
- 隐藏所有 WorkerW 子表面、图标上层对象窗口与悬空岛窗口；
- 保持期望模式为 `Wallpaper`，状态标记为安全隐藏并记录可公开错误码；
- 控制中心显示“壁纸层不可用，团子已安全隐藏”，提供“重试壁纸层”和“切换到窗口模式”；
- 不自动显示、激活或置前 Window，不用 MessageBox 抢焦点；
- 用户显式选择 Window 且目标确认后，才保存 `Window`。

Explorer 恢复沿用有界重试和幂等原则。Window 模式运行时不启动 WorkerW 恢复计时器，Explorer 重启不得影响 Window 场景。

## 8. 设置 Schema 与迁移

### 8.1 新设置模型

沿用 `%LOCALAPPDATA%\Dango\settings.json` 和临时文件原子替换，把 Schema 升级为明确的新版本。建议逻辑结构为：

```json
{
  "schemaVersion": 2,
  "displayMode": "Wallpaper",
  "sceneWindow": {
    "width": 800,
    "height": 600,
    "monitorKey": "DISPLAY1",
    "normalizedCenterX": 0.5,
    "normalizedCenterY": 0.5
  },
  "desktopLayering": {
    "dangoLayer": "BelowDesktopIcons",
    "furnitureLayers": {
      "prototype-cushion": "BelowDesktopIcons"
    }
  }
}
```

实际实现可保留控制中心自身尺寸字段，但必须把“控制中心窗口设置”和“场景/宿主设置”职责分开，不能继续用一个只为控制中心命名的 record 承担全部产品设置。

### 8.2 迁移表

| 输入 | 迁移结果 | 用户可见结果 |
|---|---|---|
| 文件不存在 | Schema 2 + `Wallpaper` + 安全默认 | 正常尝试 Wallpaper |
| 当前 Schema 1，无宿主字段 | 保留合法控制中心尺寸和桌面分层，补 `Wallpaper` | 无阻断提示 |
| 旧值 `WorkerW` | 映射为 `Wallpaper` | 无阻断提示 |
| 旧值 `Overlay` | 映射为 `Wallpaper` | 可显示一次“旧显示模式已更新”提示 |
| 有效 `Window` | 保留 `Window` 与合法窗口布局 | 正常恢复 Window |
| 未知模式/未知 Schema/损坏 JSON | 不猜测旧业务值，使用内存安全默认 | 非阻断提示，原文件不被半写覆盖 |
| 合法模式但窗口布局无效 | 保留模式，窗口布局回退居中默认 | 非阻断提示 |

迁移分两阶段：先纯函数读取旧模型并产生候选新模型；宿主确认启动后再原子写入。若旧 Overlay 映射到 Wallpaper 但 WorkerW 当时不可用，保持安全隐藏并提示选择 Window，不能把“已完成文件迁移”表述成“Wallpaper 已运行”。

未知字段继续拒绝或经显式版本迁移处理，避免悄悄吞掉未来设置。所有测试使用临时目录和虚构数据，不修改真实用户设置。

## 9. 控制中心与托盘改造

“桌面体验”页把“实验宿主”改为正式“显示模式”：

```text
显示模式
● 壁纸层（默认）
○ 普通窗口

允许与团子互动                         [开/关]

团子与桌面图标层级（仅壁纸层）
● 图标之下
○ 图标之上
```

- 删除 Overlay 选项及其自动化 ID、文案、状态徽标和回退提示；
- `Wallpaper` / `Window` 单选项只有在命令确认后才改变最终选中状态；
- Window 模式隐藏或禁用桌面图标层级卡，并说明该设置只对壁纸层生效；原值保留，切回 Wallpaper 后恢复；
- Window 隐藏后“显示团子”重新显示场景窗口；“关闭场景”只隐藏，不改模式；
- Wallpaper 安全隐藏时显示恢复卡片，不弹出 Window；
- 诊断同时显示期望模式、确认模式、可见性、恢复状态、当前显示器/DPI 摘要、活动物理世界计数和最后安全错误码；
- 托盘“显示/隐藏”继续复用应用级命令，不维护第二套状态；退出仍是单独确认操作。

控制中心设计中关于“候选宿主”和旧 P1-002 线框属于历史批准上下文。本增量在实现提交中同步当前阶段计划与必要的界面说明，但不得把历史验证内容改写为新模式证据。

## 11. 先失败验收

实施每个增量先加入能够失败的测试，确认红灯原因确实是能力尚未实现，再写实现使其通过。禁止通过字符串存在性测试替代可调用的状态与生命周期契约；只有 XAML/Win32 属性无法直接实例化时才保留最小结构检查。

### 11.1 W0：基线与隔离

- 当前分支起点包含已集成的方向控制/P2D-006 安全提交；
- 源工作区干净，相关宿主/控制中心文件没有其他执行者所有权；
- 已记录 Core/物理生命周期现状和真实 WorkerW 验收基线；
- 不满足任一项时停止，不开始 Window 编码。

### 11.2 W1：Window 最低宿主门禁

先失败测试至少覆盖：

- Window 是标准顶层 WPF 窗口：可调整大小、有任务栏入口、非 Topmost、非透明穿透；
- 默认/最小尺寸和非法尺寸夹紧；
- Show/Hide/重复 Show 幂等，只存在一个场景窗口；
- 用户关闭按钮只隐藏场景，应用壳、控制中心和托盘仍存活；
- 最小化或隐藏停止 Tick 并 Dispose 物理世界；恢复只创建一个新世界；
- Window 使用 P2D-006 的同一 Core 快照、同一视觉和同一物理参数契约；
- Window 自身焦点之外不接收方向控制，关闭/最小化清空按住状态。

只有 W1 自动门禁通过并完成一次真实 Windows 的显示、缩放、最小化、关闭到隐藏和恢复检查，才能进入设置迁移与 Overlay 删除。

### 11.3 W2：切换事务与单一性

先失败测试至少覆盖：

- Wallpaper → Window → Wallpaper 后 Core 实体 ID、动作状态和权威快照来源不变；
- 归一化中心在不同比例工作区中映射正确并由 Core 夹紧；
- 100%、125%、150%、200% DPI 不混用物理像素与 DIPs；
- 切换前停止并释放旧物理世界，目标只创建一个新世界；
- 切换耗时不会生成补帧，目标收到的是当前快照第 0 帧；
- 切换时清除按键、鼠标捕获和输入代理；
- 拖动中、恢复中和并发第二次切换会被拒绝或串行，不产生双表面；
- 目标确认失败会从同一快照重建源宿主；源也失败时进入无 Tick/无世界的安全隐藏；
- 模式只在目标确认后保存，回滚不污染持久化值。

测试替身必须能计数 Start/Stop/Dispose、活动世界数、可见表面数和 Tick 次数，才能证明不存在重复运行时。

### 11.4 W3：默认值、迁移与控制中心

先失败测试至少覆盖：

- 无设置、Schema 1、`WorkerW` 和 `Overlay` 均迁移到 `Wallpaper`；
- 有效 `Window` 保留，未知模式、未知 Schema、损坏 JSON 使用安全默认并返回可显示提示；
- 非有限、越界窗口尺寸与坐标回退到当前工作区；显示器移除后窗口仍可见；
- 原子写入失败保留最后一份完整文件；
- UI 最终只枚举 Wallpaper/Window，Overlay 自动化 ID 和命令入口不存在；
- 切换中、成功、失败、安全隐藏分别显示观测状态；
- Window 模式下桌面图标层级不可编辑，切回 Wallpaper 后原值仍在；
- WorkerW 失败只安全隐藏并呈现显式按钮，不创建、显示或激活 Window；
- 重试 Wallpaper 成功不改变用户保存的其他设置。

### 11.5 W4：Overlay 删除门禁

- 生产程序集不再引用 `DesktopHost/Overlay` 或 `DesktopHostMode.Overlay`；
- 当前运行时测试、验证定义和测试夹具不再把 Overlay 当有效模式；
- 迁移读取器可识别旧字符串，但新序列化结果永远不会写出 `Overlay`；
- 中性命中/拖动测试继续覆盖零尺寸、非有限几何、失焦取消和桌面输入优先；
- 历史 Markdown 链接仍有效，P1-002 证据未删除或改写。

## 12. DPI、多显示器与系统恢复矩阵

### 12.1 自动矩阵

| 场景 | 必须证明 |
|---|---|
| 100% → 200% DPI 映射 | 团子中心归一化位置稳定，尺寸使用 DIPs，命中使用正确转换 |
| 16:9 → 4:3 工作区 | Core 夹紧后团子完整可见，不产生非有限坐标 |
| 副屏在主屏左侧/上方 | 允许负物理坐标，不误判为非法逻辑位置 |
| 目标显示器移除 | Window 回主屏可见区；Wallpaper 重新取得有效桌面目标 |
| 主显示器切换 | 下次恢复按当前拓扑重新映射，不复用过期像素边界 |
| Explorer 句柄失效 | Wallpaper 停输入、Tick 和物理世界后有界恢复 |
| Explorer 重复通知 | 不重复创建宿主、计时器、输入代理或物理世界 |
| Window 模式下 Explorer 重启 | Window 持续可用，不启动 Wallpaper 恢复流程 |
| 睡眠/唤醒、锁定/解锁 | 不补帧；从 Core 快照重建一个世界 |

### 12.2 真实 Windows 验收

使用 Release/self-contained 产物，至少完成：

1. 清空测试专用设置，确认首次启动选择 Wallpaper；
2. Wallpaper 中验证团子可见、方向控制基线、拖动、图标上下层和桌面输入；
3. 切换到 Window，确认标准标题栏、任务栏入口、移动、缩放、最小化/恢复和普通应用遮挡；
4. Window 中复验方向控制、拖动、下落/落地、视觉和物理参数一致；
5. Wallpaper ↔ Window 往返至少三次，观察团子唯一、位置合理、无状态重放、无闪退和无重复进程；
6. 点击 Window 关闭按钮，确认只隐藏场景；从托盘和控制中心分别重新显示；
7. 在 Wallpaper 中重启 Explorer，确认有界恢复；人为让恢复失败时只安全隐藏，控制中心仍可显式切换 Window；
8. 在 Window 运行时重启 Explorer，确认 Window 不受影响；
9. 在 100% 和当前高 DPI 环境复验两模式；若有双屏，覆盖异 DPI、负坐标、跨屏和拔除/禁用副屏；
10. 重启 Dango，确认最后确认的模式与窗口布局恢复，旧 Overlay 测试设置正确迁移；
11. 验证任务栏、开始菜单、Alt+Tab、普通最大化窗口和真正全屏应用无异常抢焦点或置顶；
12. 明确退出后确认 Dango 窗口、输入桥、计时器和进程全部回收。

自动 UI 操作只能证明控件和宿主确认链路，不替代第 2–11 项的视觉、焦点、桌面干扰和观感判断。

## 14. 停止条件与风险

出现以下任一情况时停止堆叠补丁并回到设计/架构评估：

- Window 必须复制 Core 控制器、动作状态机或物理实现才能工作；
- 切换无法保证最多一个活动物理世界或一个 Tick 源；
- 回滚必须恢复 Overlay 才能保证应用可退出；
- DPI/多屏映射需要读取窗口标题、桌面文件或其他非必要个人信息；
- Explorer 恢复需要无界轮询、自动弹窗或持续抢焦点；
- Window 关闭无法与应用退出可靠区分；
- 设置迁移会覆盖无法解析的真实文件，或未确认宿主就保存成功状态；
- 删除 Overlay 会同时删除 WorkerW 仍依赖且尚未中性化的输入安全门禁；
- P2D-006 集成点发生变化，导致本计划关于 Core 快照或物理生命周期的假设失效。

主要已知风险是当前 Overlay 类型被 WorkerW 复用、设置 Store 职责混合、WorkerW 恢复与表现运行时生命周期尚未由统一协调器拥有。实施应先建立可观测计数和事务边界，再做目录/枚举清理，避免以搜索结果“没有 Overlay”代替运行时安全。
