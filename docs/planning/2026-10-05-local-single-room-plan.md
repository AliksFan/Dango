# 本地普通房分批实施与验收计划（实施中）

## 当前授权更新

### 人工评审修订

用户要求移除房间顶部常驻操作栏，改为 Esc 打开全窗半透明蒙版和中央菜单；Esc 再次按下收起，回门廊须使用明确菜单动作。菜单期间清输入并阻断玩法、拖动和滚轮，保留最小窗控与拖动区域。

进入普通房后控制中心仍可独立打开，不借此返回门廊或重启 Home 帧 owner。首页隐藏团子及捏脸、换装入口，显示用户指定文案“团子去玩拉！回来才能换衣服哦”；明确返回门廊／首页后恢复。隐藏房间仍保持外出状态，独立打开的控制中心保留。

用户补充壁纸玩法本轮同时支持 A/D、S、空格与鼠标拖动、抚摸。抚摸复用现有 Shift+左键手势。壁纸资格改为桌面 Shell 前台，所有显示器没有可见且未最小化／未 cloaked 的非 Shell 最大化或全屏窗口；鼠标另需背景资格，排除图标、任务栏、菜单和其他应用。Windows 没有应用焦点以实际桌面 Shell 前台表达，空句柄继续拒绝。规则比只排除全屏严格，副屏最大化也阻断。事件和应用命令时均复核，失格清输入，迟到输入不补播，不记录窗口内容或输入历史。

实施顺序：先定位真实资格失败点，随后修订窗口菜单及控制中心；共享 driver 增加统一逆投影指针玩法；壁纸键盘／鼠标桥接与资格更新接入同一个 driver。分别执行 UI／状态回归、native 指针集成及真实 Shell 门禁；无法建立真实桌面焦点或缺少实体输入的项目明确记未验证。Git 合并、推送、日常安装和部署权限不变。

用户于 2026-10-05 明确回复“通过，开始产品实现”。本次授权涵盖普通房窗口与壁纸两种呈现、两层初始环境、普通滚轮视距及 L1–L3 产品闭环；下方“未授权实施／壁纸另行授权”等文字保留为批准前历史，不再限制本轮已批准范围。正式服务端准入、多人、数据持久化、main 合并、远端推送与日常安装仍未授权。

实施分支从设计提交 `14e7a14` 建立；并行相机与壁纸输入各使用独立工作树，由唯一集成负责人整合应用、导航和帧 owner。首版采用隐藏清输入并暂停、仅保留本次运行的呈现和视距选择；重启从首页开始，不新增磁盘房间存档。家具、地形编辑、场景门、网络和新依赖不在范围内。L1–L3 当前为实施／验证中，未标记人工验收通过。

本轮产品实现、实际门禁及人工待验项集中记录于[产品实现验证](../verification/2026-10-05-local-room-product.md)。本地候选与产品人工验收、main 合并和日常安装分别记录，不用候选自动测试关闭正式房间阶段。

## 4. 验证顺序与用户评审脚本

先跑受影响的本地合同／几何／输入测试，再跑可使用明确隔离候选模块的 Desktop/Physics 集成；记录实际选中、通过、失败和未执行项。不要为本增量放宽旧失败。L2/L3 在真实 Windows 候选中验证首帧、物理、焦点／前台输入、托盘和故障恢复，才进入人工验收。

人工验收走完整链：从首页 W 到门廊 → 进两层初始房间 → 核对纯色后景、连续平坦地面及同源接触线 → A/D 走到两侧、S、跳跃、待机 → 房门和 Esc 返回 → 再进房按住 D 时 × → 松键 → 托盘恢复确认不续跑 → 托盘房门确认回门廊 → 模拟打不开并重试。再核对首页三档尺寸、同屏 DPI 与减少动画。原型只是视觉和状态示意，不能代替这条真实链。

在获准的呈现模式中另验滚轮：窗口前台且指针在场景时双向调视距、选择三档后继续调中间倍率；窗口失焦／指针离开场景／菜单或UI滚动优先时不调视距。壁纸接入另获准后，分别核对桌面Shell前台可用、普通应用前台否决、主屏／副屏全屏独立否决、图标／任务栏／菜单／指针下其他应用否决及250ms停顿／失焦／切宿主不继承旧滚轮量；事件发生后到应用前条件变坏也不能生效。浏览器中的前台／全屏状态开关及100px近似刻度只是示意，不代替真实Windows判定或原生120刻度。

每批报告分开列出：静态门禁、native／WPF 集成、实时行为、人工验收、Git／安装／推送／部署。用户尚未人工确认时不得标“已验收”。批间若修改上述合同或结果，重跑对应门禁；无新风险不机械扩大测试范围。
