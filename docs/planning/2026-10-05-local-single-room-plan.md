# 本地普通房分批实施与验收计划（待确认）

日期：2026-10-05。依据[小晴间设计提案](2026-10-05-local-single-room-design.md)。状态：设计／计划评审中；**没有授权生产编码或宣布任一实施批通过**。这是一条本地呈现增量，正式 [D0–D2／E2–E4](2026-10-04-room-entry-implementation-plan.md) 的业务依赖及未完成状态保留。

## 1. 开工前条件

1. 用户确认房间视觉、空间、固定镜头及隐藏暂停方案；确认首版不新增家具碰撞、房内位置存档和重启恢复。
2. 用户另行授权实施批次；届时重新核对 main、HEAD、状态、工作树与文件重叠。以本地已合入 E1 的基线建立独立实施工作树，不复制旧多人树或未提交草案。
3. 先定义能够失败的门禁，再实现使其通过。本地可以使用现有隔离候选 native 作为明确来源的验证输入；**不覆盖受保护旧 DLL 或修改发布 hash 门禁**。
4. 启动真实 Windows 评审窗口只在实施／验证授权内进行，使用隔离配置与产物；不更新安装、不关闭已有产品进程。

## 3. 能在错误实现下失败的验收

| 门禁 | 必须满足的结果 | 必败反例／检验办法 | 证据层 |
|---|---|---|---|
| 同实体 | 全程 session/runtime/entity 标识或对象引用保持；世界可 rehost，实体不得新建。 | 用工厂计数及共享引用核对连续进入／返回／隐藏恢复；故意另建 runtime/团子应失败。 | 合同＋native 集成 |
| 单 owner | 任一时刻 active 帧 driver ≤1；交接可短暂为 0；源仍可见也不得自行抢回。 | 同时启动源／目标 scheduler，源被暂停后触发可见性／布局刷新；双推进计数必失败。 | 合同＋真实 WPF 调度 |
| 清输入／优先级 | 手动优先；交接、隐藏、失焦清 D/S/Space 等；恢复不补播按键或隐藏时间。 | 按住 D 或 S 切场景/隐藏后释放，再恢复；手动 intent 为 None，未重按不得延续隐藏前的手动移动／挤压。已有自主漫步允许正常发生；位移断言在受控待机测试策略下执行。注入旧 owner/旧代际命令不得生效。 | 合同＋局部 Windows 输入 |
| 固定投影／边界 | 同源物理地面和投影；左右限制真实，缩放不改世界；往返恢复门廊边界／相机。 | 跑到两边并继续按键，跳跃后实际落地；反复缩放和往返不能越界/穿地/NaN。画边框但不配置物理应失败。 | 几何合同＋native 实时 |
| 首帧凭据 | 目标宿主、本次 attempt、同 runtime、有效视口、表面对齐、有效身体帧已应用且呈现完成；无 fallback/错误。 | `Show()` 成功但无帧、0 尺寸、旧 `LastFrame`、旧 attempt、只有背景、异常路径的 `CallbackCompleted` 都不得隐藏主界面。 | 合同＋真实 WPF；人工看真实窗口 |
| 失败可恢复 | 入房、房间→门廊、×后恢复均覆盖准备失败、激活失败、首帧超时：保有可操作重试／返回入口，失败目标释放 owner，源或恢复界面可操作；重试能正常成功。 | 对三个方向各阶段注入 rehost/无帧/激活/超时故障，检查最终 owner 与可见入口；等待期间取消再发送迟到 ready，不得隐藏或覆盖后续状态。恢复房间不能直接使用旧 ready。 | 合同＋WPF 故障注入 |
| 去重 | 连按 W／双击／托盘并发只产生一次有效进入和一个新房窗。 | 保留窗口工厂计数与 attempt 历史；迟到失败不得干扰后来的成功。 | 合同＋真实 UI |
| 返回 | 顶部房门／场景门／局部 Esc／托盘房门回到门廊相应入口；命令只交接一次。 | 复用旧 `ShowControlCenter` 会回首页，应失败；双触发不能重建 runtime。 | 合同＋真实 Windows |
| 局部键盘 | 只有房窗有焦点且输入／弹窗未消费时 Esc 返回；A/D/S/Space 同样服从输入优先级。 | 外部窗口 Esc、房内文本输入／模态先消费 Esc、失焦按键不得离房或驱动物理；禁止全局 hook。 | 输入路由合同＋Windows 前台验证 |
| 隐藏／托盘 | × 隐藏而不退出；无 active owner；托盘恢复同一本地房间，或明确进入门廊。 | × 错误 Dispose session/退出、托盘只开首页、隐藏后台推进、恢复积压动作／第二实体均应失败。 | 合同＋Windows 实时 |
| 既有行为 | 首页 D左捏脸/A右换装/S/Space/W；门廊 A/D/S/Space/W/Esc；门 124×194、净空96；三档尺寸及当前同屏 DPI 保持。 | 修改键位为方向键、门被改回旧间距、首页团子不原地、预设尺寸或编辑动作改变应失败。 | 受影响回归＋人工 |
| 本地边界 | 清楚显示本地单人；本地进房不调用正式 ConfirmAdmission，不造权威快照、网络或数据库。 | 产品路径下监测权威适配器调用计数应为0；审查禁止创建伪业务 DTO／固定票据。正式旧合同类保持其真实语义。 | 静态范围审查＋合同 |

L2 必须先验证暂存宿主的实际渲染条件：现有帧循环依赖可见性，不能把目标完全隐藏后无限等待 ready。可采用不抢焦点的临时展示／层级暂存，源界面始终保有取消入口；具体方式由真实 WPF 结果决定。WPF 回调证据不自动等于 OS 合成画面已被用户看见，仍需截图及人工确认无黑屏／闪现。参考首帧超时 3 秒仅为可控验证起点，不是性能承诺。

## 4. 验证顺序与用户评审脚本

先跑受影响的本地合同／几何／输入测试，再跑可使用明确隔离候选模块的 Desktop/Physics 集成；记录实际选中、通过、失败和未执行项。不要为本增量放宽旧失败。L2/L3 在真实 Windows 候选中验证首帧、物理、焦点／前台输入、托盘和故障恢复，才进入人工验收。

人工验收走完整链：从首页 W 到门廊 → 进小晴间 → A/D 走到两侧、S、跳跃、待机 → 房门和 Esc 返回 → 再进房按住 D 时 × → 松键 → 托盘恢复确认不续跑 → 托盘房门确认回门廊 → 模拟打不开并重试。再核对首页三档尺寸、同屏 DPI 与减少动画。原型只是视觉和状态示意，不能代替这条真实链。

每批报告分开列出：静态门禁、native／WPF 集成、实时行为、人工验收、Git／安装／推送／部署。用户尚未人工确认时不得标“已验收”。批间若修改上述合同或结果，重跑对应门禁；无新风险不机械扩大测试范围。
