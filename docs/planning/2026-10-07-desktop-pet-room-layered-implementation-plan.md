## 2. 交接约定

新增桌宠宿主提供 `Scene`、`Bind(driver)`、`Show(attempt, screen)`、`ConfirmReady(attempt)`、`StopInput()`、`Hide()`、`Dispose()`，以及同次双面真正呈现后的 `HealthyFrameReady(attempt)` 和返回／隐藏／控制中心／恢复／宿主失效事件。宿主只消费帧；驱动保留唯一 scheduler，桌宠模式开启物理拖动。背景与上层使用同一映射，不建立第二 runtime。

驱动的单面健康事件不直接完成桌宠交接；只有宿主联合确认背景和上层新帧后才能完成。代际更换、捕获丢失、隐藏或返回清空手势，迟到回调无效。系统桌面／显示配置失效时关闭不完整两层并释放输入，保留托盘／门廊恢复入口。

## 3. 验证顺序与交付边界

1. 编译与文档／差异静态检查；执行新映射、门禁和手势测试及受影响普通房、门廊与首页回归。
2. 使用隔离物理模块执行原生双层真实宿主检查，验证 WorkerW 亲子关系、上层样式、透明命中、实际首帧、单 owner、真实物理拖动和完整生命周期。
3. 使用自有虚构普通／最大化应用检查前台键盘焦点保持、轮廓外穿透与捕获，截图只渲染自身视觉树；无法执行的行为明确列为未验证。
4. 启动隔离桌宠候选供用户操作：门廊桌宠房门→真实环境在壁纸→普通应用前台点击／轻抚／拖动→松手重力→透明处操作应用→隐藏恢复→房门回门廊。

只有用户完成实际体验确认后才可标记人工功能验收；本轮自动测试不关闭完整 Windows、多人或正式房间阶段。结束时记录候选进程及隔离设置／构建产物，保留日常版本。
