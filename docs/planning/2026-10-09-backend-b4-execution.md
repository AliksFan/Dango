# B4 准入、租约与正式通知实施细化

日期：2026-10-09。依据已批准邮箱首期 B4；授权包括实现、静态验证与本地提交，新的数据库迁移和虚构写入待精确数据计划批准。B5 客户端界面、逐帧运动、原生物理适配、好友及桌宠第二席不在本批。

## 事务与协议选择

- 保持 `PetRoomState` 唯一归属。进入／离开比较来源与归属版本，接管再比较租约与控制代际。纯心跳不改变房间版本或发送事件。
- `Room.Version` 同时排序可见房间领域变化，沿用 audit／outbox 的房间版本唯一约束。配置更新可能与在线变化冲突，调用者读取新快照后重新决定；无需新增第二套事件序号。
- B4 租约／控制请求收据绑定账号、会话、实例及规范化请求摘要，保存有限确认 JSON；公共码／房主管理仍允许同账号新合法会话重放。同请求不同用途或参数冲突。公共码只保存 SHA256 摘要和恢复代际绑定的 Data Protection 密文，收据、通知和日志不含原码。服务端生成 32 随机字节；有效期默认 24 小时，允许 1–168 小时。
- 公共准入代际独立于配置／在线版本，重置只影响今后准入。公共房主可直接进入本人房间；访客须有效码且未被封禁。私密／桌宠首期只允许房主，桌宠只接收 desktop 设备。
- 设备实例使用非空 GUID；desktop／mobile 类型固定于服务端租约。最多 8 个有效设备；登录和租约期限独立，心跳建议 10 秒，租约 30 秒。Hub 重新绑定使旧 transport 无效，短断线只移除传输登记。
- 控制方失效但观察方有效：保留在线归属，清控制资格并提高代际，必须显式接管。全部租约失效：桌宠／私密保留睡眠归属，公共清空归属。attach／snapshot 必须裁定到期，不能等待 worker 后才能满足业务规则。
- 统一锁序：actor email、User、Session，排序 owner quota 键，排序来源与目标 Room，PetState，排序 Lease。预读来源在锁后重验，改变则回滚清 tracker 并最多重试三次；系统维护不得在房锁后补凭据锁。
- B3 解散／到期必须同事务清控制、终止租约、撤销码；恢复不能恢复码或迁回占位。封禁房间 A 的用户时，只清其仍属于 A 的归属，不能损坏当前房间 B。

## 正式传输与资源边界

- 正式 Hub 与匿名原型独立，身份每命令重新检查。仅提供租约 attach／心跳／接管／离开与个人／房间快照，客户端动画仍为本地呈现。
- outbox 同事务捕获最多 32 个受影响账号 ID，允许删除房间后发送本人刷新提示。通知仅含事件 ID、房间 ID、版本和类型；不直接向 SignalR 房间组广播。
- 每个收件人以当前凭据、房间、归属和租约重新检查，并在有界发送期间保持共同事务 gate，防止权限检查后撤权先提交的竞争。重复通知可接受，快照恢复漏发。
- 传输登记最多 128 总连接、每账号 8；消息与调用频率有界。租约／outbox worker 默认关闭，需显式环境开关。集成测试只调用新造 Pet／事件范围，不能启用全库后台扫描。

## 五项门禁

| 质量 | 必须能够失败的证据 |
|---|---|
| 正确性 | 非法／超大／未知输入、手机桌宠访问、旧来源／控制版本、到期未扫的 attach 与快照、码重置与封禁 |
| 一致性 | 独立连接争最后席、迁移锁序、解散／封禁与进入竞争、提交前故障回滚、请求精确重放、观察方存活时控制失效 |
| 安全性 | 跨账号直接调用、撤销 Cookie／会话、旧 transport、逐收件人撤权与发送竞争、秘密不入审计／outbox |
| 可靠性 | 新宿主恢复持久状态、通知漏发与重复、发送后记录失败；进程异常中断及真实备份还原未执行时明确保留未验证 |
| 扩展性 | 设备／连接／频率／快照席数／批次上限，必要索引，前向迁移与 pending-model 检查；不以本地测试承诺生产容量 |

## 所有权与交付

根代理拥有共享协议、模型／迁移、B3 兼容、HTTP／Hub／通知、执行和数据计划。两个干净且已附着的隔离 worktree 分别实现准入租约快照和公共码管理；禁止改共享模型或同时写根分支。实现审查后先运行无数据库门禁，再形成精确 B4 数据操作计划。main、远端、日常安装及受保护 DLL 保持原有授权边界。
