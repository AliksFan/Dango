## 交付边界

新增安装器 `eng/install-desktop-entry.ps1`，并在安装根生成 `tools/Manage-Dango.ps1`、`install-state.json`、`Rollback.lnk` 与桌面 `Dango.lnk`。继续使用现有 `eng/publish-desktop-entry.ps1` 生成内部候选；不改候选应用行为、设置 Schema、native/DLL 内容、网络、启动项或发布流程。

## 先行失败验证

1. 为版本 ID、清单、文件、两 DLL、哈希、许可、`settingsContract` 及五份受控设置源文件的 `settingsSourceHashes` 建立独立校验函数与测试夹具。
2. 写入负例：篡改文件或哈希、缺少任一 DLL/许可、清单不匹配、复用契约字符串但设置源合同哈希不同、状态指向缺失版本、首装回退、运行中实例、任一用户快捷方式冲突。
3. 证明任一负例不会改动已有 `install-state.json`、`current`、`previous`、设置或快捷方式。

## 实施步骤

1. 明确发布包中构建标识、清单、两 DLL、许可、设置契约及五份受控设置源文件的 LF 标准化合同哈希读取位置；它只证明本地可信发布链中的源合同不变，不读取真实用户设置或验证任意第三方二进制字段。
2. 实现版本目录复制到安装根 `.staging-<guid>`、完整校验、最终 rename 至不可变 `versions/<commit12>-<manifesthash12>`；`versions/` 只容纳完整候选，失败 `.staging-*` 保留并不写状态。
3. 实现状态读取、临时文件写入和同目录 rename；对缺失、损坏、未校验目标和不一致的 `current`/`previous` 明确失败。
4. 安装管理脚本，实现 `Status`、`Start`、`Activate`、`Rollback`。实例检测必须区分当前目标版本与另一版本，且绝不停止进程。
5. 在复制或激活前预检桌面 `Dango.lnk`（隐藏控制台）与安装根 `Rollback.lnk`，以 `-StageOnly` 预置候选、创建两快捷方式，最后才激活；任一冲突均拒绝覆盖非本安装器所有的快捷方式或用户文件且不切换状态。
6. 实现 `-StageOnly`、`-InstallRoot`、`-ShortcutPath`，使自动验证在隔离目录完成，默认模式才使用固定根和桌面路径。
7. 补充使用说明、运行自动验证，并在隔离根做首装、更新、切换、回退和设置保留的真实脚本流程。

## 验收标准

| 场景 | 必须观察到的结果 |
|---|---|
| 首装 | 写入 `current`，没有 `previous`，默认不启动程序。 |
| `-StageOnly` | 版本和工具到位，状态不切换。 |
| 更新 | 校验完成且用户退出旧程序后，`current` 指向新版本、`previous` 指向旧版本。 |
| 运行中冲突 | 不结束程序，不把另一版本说成新版本已启动，状态不被错误切换。 |
| 回退 | 仅在旧版完整且设置契约兼容时交换版本；不自动启动。 |
| 设置保留 | `%LOCALAPPDATA%\Dango\settings.json` 的 Schema 4 及既有字段保持原样，不发生回拷。 |
| 失败输入 | 已有状态、快捷方式与用户文件不被覆盖；失败产物和旧版本保留。 |

## 验证与交付状态

自动测试必须先证明上述负例可失败，再通过正例。脚本集成验证与人工桌面快捷方式验收分别记录；不把构建或隔离脚本通过写成既有桌面体验的人工验收。

当前已授权阶段允许创建本地提交；本计划不含合并到 `main`、推送、部署、发布标签或删除。旧 DLL 缺少导出是已知失败；第二种 DPI 与长期稳定性在本批结束后仍须标记未验证。
