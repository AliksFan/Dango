## 1. 本轮确定的范围

用户确认使用 miniPaint，在统一编辑器中编辑图片、图片连接点、形变方式和配饰参数；一张完整图片可以绑定多个骨节，无需把每一节切成独立图片或图层。新制作方式收为刚性与骨架柔性，重力影响保留。

用户随后明确：已有柔性配饰不需要考虑继承成本。因此本次替换旧整图柔性，不保留旧弯曲／应变场兼容模式，不安排旧柔性转骨架或效果迁移工程。该指令不授权清空、删除或覆盖用户已有存档。

首批提供单条、不分叉的链，保持初始曲线并响应实际移动、重力和回弹。手动抠图与简单绘图纳入本批；AI 自动抠图、主动摇尾动画、分叉骨架、局部材质笔刷、配饰互挂、碰撞、自碰撞、三维扭转、云同步和分享后置。新功能直接接入正式编辑与显示链，不另做会话演示或独立产品预览入口。

本文中的模块拆分、资源预算冻结和版本化保存是为已确认方向补齐的工程合同，不是已实现事实。miniPaint／WebView2 精确版本、构建散列、求解参数与性能预算由 E0 验证后记录；缺少这些证据不能宣布依赖或性能门禁通过。最初文档准备不授予实施权限；后续用户已单独授权本地生产实施与验证，未授权安装、main 合并、推送或部署。

## 3. 统一编辑与草稿流程

1. 从正式配饰页创建或编辑一件配饰。选择器只允许用户显式选择本地静态 PNG／JPEG，按真实文件头、帧数与资源边界验证，不能仅看扩展名。
2. 选图成功建立未应用的创作草稿，随后进入编辑窗口。未完成抠图或成品导出的草稿可保留源画布，但要显示“待完成”，禁止将其当作已保存配饰；资源记入源工程预算。
3. 在同一窗口编辑图像、根部连接点、刚性／骨架柔性、骨架及全部参数。团子身体附着点仍在真实团子预览中选取，也提供数值入口；图片上的根部与身体上的附着位置分别存储。
4. 编辑器中的真实试摆读取当前编辑快照，由现有 Dango 预览宿主推进。编辑期间的快照只影响暂时预览；模态取消完整还原进入模态前的图片、骨架及参数，不能提前替换外层草稿。
5. 确认时导出并校验成品与工程，把完整结果一次放入外层配饰草稿，不写正式清单。已存在配饰保留稳定条目 ID；图片和工程以新的不可变资产替换引用。
6. 配饰页“应用”校验整套草稿并保存。任何待完成项都须明确列出并提供继续编辑入口，不能静默跳过；保存失败保留草稿。“取消”及现有离开边界恢复最近已保存快照。

保留现有两层取消区别：新建时图片窗口取消，仍保留进入该窗口前的新草稿项；外层取消才撤销未应用的新项。选择器取消不建项，过期编辑回调不能写回已切换／关闭的会话。永久删除继续两次确认，只提交目标删除，不顺带提交其他草稿；未保存项删除只移除草稿。

## 4. 图片编辑与坐标合同

miniPaint 本地定制版提供画笔、橡皮、填充、文字、基础图层、魔棒选区去背景、透明区域恢复、裁剪、旋转、翻转和撤销／重做。恢复工具须保留本次编辑需要的未擦除像素；不能用填白冒充恢复透明蒙版。隐藏 URL 导入、云打开／保存、打印、远程字体和其他本期未接入操作。

绘图图层描述外观，骨节描述运动，两者数量独立。运行时使用合成的一张成品 PNG；编辑工程保留受支持的图层，重开后可以继续修改。工程中的图像引用改为受控内部资产 ID，不保存原文件路径、外部 URL 或非必要元数据；外部编辑工程导入不在首批范围。

根部和链控制点以**当前输出画布**的归一化坐标保存，允许位于透明区域；不自动裁除透明边。图像像素旋转／翻转／裁剪属于图像编辑，按同一变换更新根部、控制点和绑定数据。查看缩放／平移只改变视图。配饰尺寸和基础角度只改变佩戴造型，不重采样工程。

撤销／重做包含图像与相关坐标的一致快照。裁剪会移除根部或部分链时，提示结果并将该编辑标为待重新定位／绑定，允许撤销或修正，禁止静默夹到边界。应用前必须消除失效结构。自动缩小成品仍保留归一化位置，并将实际输出尺寸与工程显示一致化，不能每次打开重复缩小。

## 5. 骨架与参数

根部是图片支点，也是链的首点；其余点沿图片从根部到末端排列。添加、移动、删除控制点后，更新初始曲线、骨长和基础绑定。首期没有分叉、拓扑闭环或隐藏身体挂点；零长度、非有限坐标和超过预算的结构明确拒绝。

一张图生成纹理网格，每个顶点由相邻骨段的规范化权重共同驱动。弯曲时颜色、透明边缘和花纹随网格连续变化，骨节与网格编辑标记不进入成品 PNG。绑定处理折返和相邻段歧义，不以最近像素距离宣称所有图片都能正确自动绑定；无法得到有效绑定时提示调整中心线，不能显示成功后使用坏权重。具体采样、权重算法与拓扑预算在 E0 冻结。

| 参数归属 | 语义 |
|---|---|
| 刚性／骨架柔性 | 唯一的内部形变选择。刚性保持图内相对位置；骨架柔性仅运行骨架求解，不叠加旧整图场 |
| 尺寸、基础角度、图片根部、身体附着点 | 同一配饰的造型与连接配置，随草稿、复制、应用和重载 |
| 连接强度、连接最大行程 | 决定整件根部相对身体挂点的有界弹性；不代替骨节弯曲 |
| 朝向锁定、整体旋转阻尼、整体回正、整体最大摆角 | 控制根部整体朝向。锁定优先，锁定不等于锁死内部骨节 |
| 重力影响 | 每件可调，0 关闭。刚性可影响连接位移与整体转动；骨架可产生逐段下垂，仍受连接／锁定／恢复约束 |
| 骨架柔软度、骨架阻尼、骨架恢复 | 分别控制内部易弯程度、回摆衰减和向初始曲线恢复；标签与整体旋转参数明确区分 |

已有共同参数的范围和默认值在无语义冲突时沿用；新骨架参数的量纲、端点与默认值由 E0 以可失败测试冻结，不能把旧整图柔软度系数直接视为新系数。骨架柔软度 0 保持内部初始形状，但不关闭已允许的整体运动；重力 0 不关闭惯性。重力不能对同一骨段重复累计，连接、整体旋转与局部骨架的耦合要在力／位移归属测试中验证。

旧 `AllowFolding` 和整图 `MaxDeformationPercent` 不直接复制为同名骨架开关。新链以骨长、弯曲、速度和位移约束保持有界；节点和蒙皮可在二维画面中重叠，不宣称有厚度或自碰撞。旧径向连接行程仍是根部连接参数，与内部约束独立。模式切换保留图片和根部；有效链数据可暂存以便切回，但只允许当前模式生效。

## 6. 运行时与正式接线

沿用 `AccessoryMeshFrame` 的不可变顶点／UV／三角形输出和 `AccessoryMeshVisual` 绘制边界，必要时对合同做最小扩展；不能承诺旧固定 8×8 拓扑可直接满足长链。新增轻量 managed 链式约束求解，优先验证长度约束、初始弯曲恢复和阻尼的 PBD／XPBD 路线。每次从当前身体成功步的真实挂点变化获得运动激励，不能用按键或固定循环动画冒充自然跟随。

| 接入方 | 推进合同 |
|---|---|
| `BeltBodyAppearancePresenter`，首页／外观编辑／配饰／门廊 | 消费 Belt owner 的 `Tick/Seconds`；同 tick 最多推进一次；静态刷新只重建呈现 |
| `AccessorySceneController` 与 `StackedDangoSceneRuntime`，房间／桌宠 | 在既有成功身体步中推进；其他宿主只读当前帧；保持实体、代际与坐标映射 |
| WebView2／miniPaint | 只发编辑操作与版本化快照，不建立第二个身体或配饰物理 timer |

按现有 owner 进行有界子步。重复／回退 tick 不追加积分，过大时间间隔重建稳定状态，不追算隐藏时段。配置或骨架拓扑变化重置受影响实例的动态状态，刚性／骨架切换不残留速度；同拓扑纯显示刷新不推进时间。暂停／恢复、隐藏、失败、移除、实体代际和换宿主的状态保留／重建规则必须分别测试。

配饰只读取身体和挂点，不新增碰撞体，不向团子、家具或 native 世界施力，不扩展身体拖拽／命中范围。普通启动与正式 build/publish 接入新路；旧图片窗口、旧材质场以及失效入口、测试夹具与诊断一起按消费者清单退役，不长期留配置开关。刚性根部连接、角度与当前支持的图层／图库功能继续复用。

## 7. 数据格式与提交

新清单采用 Schema 2，建议文件名 `accessories-v2.json`；每件保存稳定 ID、名称、PNG 资产 ID、可编辑工程 ID／工程版本、输出尺寸、形变方式、根部、身体附着点、链的静止结构和参数、佩戴／层次／排序。速度、当前变形网格和浏览器对象不持久化；绑定派生数据若缓存，须带算法版本并能由源结构重建。

可编辑工程与 PNG 各有内容散列及受控相对引用；外部来源先完成必要的元数据清理。修改副本产生新的不可变工程／图片引用，不联动原件。直接保存 miniPaint 任意内部 JSON 不是稳定产品合同：Dango 包装工程格式、校验引用与版本，限定可重开工具集，并保留可验证的 PNG 成品。

提交顺序为：校验全套草稿 → 写入并校验引用到的不可变工程／图片 → 原子替换新清单 → 更新保存快照。清单是唯一提交点；某文件先写成功不能报告整件保存成功。提交前复核清单修订，外部改动时拒绝覆盖并保留草稿。结果不确定时重新读取提交快照确认；保存失败保留旧清单和草稿，未引用文件作为残留记录，不自动垃圾回收。新格式坏清单、未来版本与单资产损坏继续采用明确隔离／写保护，不能过滤损坏条目后顺带提交删除。

本批不加载或转换 Schema 1 的旧柔性效果，也不安排旧库迁移。若只有旧清单，界面明确“发现旧版配饰库，本版未载入”，原文件与图片保留；用户可以创建新草稿，并通过显式应用建立独立的新格式清单。旧图片可由用户重新选择为素材；没有迁移成功或兼容还原提示。新格式存在后以它为准，未来／损坏的新清单不能回退成空库覆盖。此安排不执行重置、批量迁移、备份删除或原资产清理。

## 8. 源图、成品与资源边界

| 对象 | 限制与处理 |
|---|---|
| 源 PNG／JPEG | 大于 0、文件最多 64 MiB、最长边 16384、总像素 64,000,000、单解码像素面 256 MiB；解码前后分别验证，允许不透明，不支持动画／多帧 |
| 最终静态 PNG | 最长边 4096、总像素 16,000,000、文件 32 MiB；包含可见及透明／半透明像素，不能全透明或完全不透明；规范化去元数据，不改源文件 |
| 超出成品上限的有效素材 | 有界读入后等比例缩小／重编码，显示原／最终尺寸和压缩结果；已存成品仍严格校验，不在加载时偷偷缩图 |
| 未应用的成品 PNG | 沿用同图去重后的 128,000,000 像素／256 MiB 累计预算；同时佩戴最多 8 件 |
| 工程、图层与源草稿 | 必须独立计入源像素、编码字节、撤销历史和峰值内存，不借未完成状态绕过限额；数值由 E0 冻结 |
| 骨架与消息 | 节点数、网格顶点／三角数、绑定权重、消息／分块总量、操作超时与最大子步数须有硬上界，E0 未冻结不得接入无界输入 |

成品像素改为透明的校验发生在成品阶段，不能复用旧导入检查把待抠图源提前拒绝。图片、工程和骨架资源不足时保持当前结果，显示具体失败及可重试入口，不静默降低画质、删层或减少骨节。

## 9. WebView2、依赖与隐私

miniPaint 以固定 commit、受控本地资源和 Dango 自有扩展打包，普通启动不访问其在线站点或 CDN；编辑输入、工程和成品不上传。只使用已核对许可的本地／系统字体及素材。保留 MIT 文本、版权和实际 bundle 内各项第三方声明；许可证核查覆盖真实依赖锁定和静态素材，不能仅凭项目根 MIT 认定整个包已完成核查。

WebView2 使用受控本地来源与最小消息桥；验证来源、协议版本、编辑会话 ID、请求 ID、长度和数据形状。浏览器不接收本机任意路径或文件系统对象，文件选择与正式写盘由 native 宿主负责。拒绝外部导航、弹窗、下载、远程资源和未授权权限；日志只记录必要的错误类型与匿名计数，不记录原图、输入文本、工程或源路径。

新合同至少表达 `Open/Preview/Confirm/Cancel/Error` 的输入、输出、失败、超时和关闭生命周期。PNG、工程、骨架及参数必须属于同一编辑修订号；关闭、取消、切条目后的迟到消息丢弃，不能部分提交。native 对导出内容重新验证，不能相信网页宣称的尺寸或散列。

WebView2 Runtime 的 Evergreen／Fixed 分发方案、SDK 版本和更新维护方案由 E0 结合体积与官方再分发规则确定。运行时缺失／过旧、初始化失败、网页进程退出时保留草稿，显示原因、重试和取消；不自动下载／安装 Runtime，不隐式启动旧编辑器充当回退。离线编辑要求和 Runtime 安装前置分别报告。

## 11. 验收与文档交付

验收编号供实施计划引用：

- **C1 图片编辑闭环**：不透明源可进入编辑；手动去背景、绘图与图层真实改变像素；重开工程仍可编辑，PNG 与工程修订一致。
- **C2 坐标与草稿**：根部、身体附着点、整图多骨节、裁剪／翻转／撤重、查看缩放和输出缩小一致；两层取消、失效结果和待完成项不能误保存。
- **C3 骨架机制**：刚性距离保持、骨架存在相对弯曲；骨长有界、静止曲线恢复、柔软度／阻尼／重力的独立反例成立，不运行旧整图场。
- **C4 成功帧与宿主**：各正式入口覆盖唯一推进、真实运动激励、实体／暂停／隐藏／换宿主；身体及家具对照轨迹、步数和输入范围不变。
- **C5 存储与权限边界**：工程／PNG／清单的故障注入、旧／未来／坏格式、单图损坏、复制独立、独立删除、重启、源移除与编辑桥拒绝路径可验证。
- **C6 分发与交互**：普通启动、标准 build/publish 有本地资源与许可；离线及 Runtime 失败路径真实；Windows 实际绘制、输入、1／8 件活动负载和人工观感分别记录。

最初设计交付为本文、实施计划、ADR 和必要索引更新，当时没有实施或新增依赖。后续获授权的 E0–E4 实现、依赖和验证按独立记录更新；本设计不能取代验证结果。正式编辑窗口、双运行链接线和旧路退役已有实现及验证，完整交互和人工验收仍未完成；没有安装 Runtime、迁移用户存档、main 合并、远端推送或发布。
