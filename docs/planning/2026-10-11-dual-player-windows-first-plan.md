# 双人推进顺序修订：Windows 先行，Linux 部署前验收

日期：2026-10-11。状态：用户对 Windows 先行建议明确回复“可以，按照这集计划继续”，批准本修订及下一 Windows 隔离呈现增量。改变平台门禁顺序，保留原物理、呈现、安全出生与权限要求，不追认 Linux 通过。

## 1. 决策和阶段边界

原 P1 将 Linux 与 Windows 技术准入同时前置。提前核查原生模块可以降低返工，但 Docker 环境阻断不应继续阻塞不依赖 Linux 的 Windows 工作。采用 Windows 物理／呈现 → 后端条件具备后的 Windows 正式接线与双客户端 → Linux 部署准备与平台验收的顺序。

- P1-W：Windows 双体物理、健康 world 续接／丢失 world 安全出生、低频语义驱动真实 WPF 呈现。现有正常与反例证据保留；实际窗口、持续运行及人工分别报告。
- P1-L：严格同源 Linux 构建／加载／步进／恢复／回收及错误 profile、资源边界，移至 Linux 服务部署准备之前。当前仍未验证，Docker 排障仍停止。
- P2–P5-W：P1-W 满足且后端联合基线具备后，沿用正式身份、逐次授权、持久生命周期、Windows 接线和双客户端门禁推进。Linux缺口不阻断这些Windows范围任务，不能宣称Linux服务器可用。正式服务、数据库和资源仍需各自精确计划，本增量不操作它们。
- Linux 正式部署／验收前必须完成 P1-L 与后端部署、数据库、恢复、TLS 和运维门禁；不能以 Windows 结果或脚本存在替代。

替代方案：继续把全部平台作为P2前置会维持环境阻塞；删除Linux门禁会隐瞒部署风险，均不采用。main合入、推送、安装和生产DLL替换仍各自授权。

## 2. W0–W4：下一窄增量

W0：本计划先本地提交，更新阶段计划、P0合同及物理ADR的现行顺序。历史失败和原批次报告保留。

W1：新增独立 `eng/tools/Dango.SemanticPresentationReview` WPF工具，不改变生产窗口／solver／参数／ABI。输入仅为已有R1的push、stack、withdraw三份60Hz实际authority trace，各完整600步，模块SHA `59EC861EE748BA93E661D058EEBD01D3E8A04ABF9D24F0376BACB4D98015B6DC`。载入前检查来源报告、完整轨迹和模块匹配，分别记录文件SHA。仅按20Hz发布中立语义，每个实例拥有自己的sampler、replica、native world、adapter和visual，不能复制一份局部结果。

W2：在30／60／144Hz显示调度组合下完成600相邻固定步。复用真实`DeformableDangoVisual`，从其已应用的WPF BodyPath几何和到scene的实际transform独立采样128点。保留`.98`、quadratic B-spline、水平`.9`、竖直`58/60`及160×120控件。曲线原点(80,66)，gait=null。实际中心各轴误差≤`1e-5 p`、侵入比≤`.031`、支撑正gap≤`.008 p`；共同采样中心一致，撤支撑后幸存local entity不重建，旧visual／支撑清除。三种布局离屏渲染留图，不冒充前台或OS DPI验收。

W3：错误原点（Top减60）、共用replica、fallback、撤支撑后残留visual必须实际退出1且指定oracle失败。结果写独立新证据目录，记录模块／trace前后hash、PID／退出、native分配前后。保留错误输入与失败证据，不改变门槛。

W4：打开同一候选的隔离实时窗口供人工观察；推挤／堆叠／撤支撑切换、暂停与重放使用同一管线。实际可见回调／新帧、失败停止及正常关闭／释放单列，不宣称联网、正式多人或双机通过。600秒持续观察和人工门禁单独保留，不自动要求用户占用电脑补完。P1-W未全部通过前不宣布准入或开始正式接线。
