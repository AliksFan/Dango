## 2. 用户体验与数值建议

| 行为 | 触发与表现 | 完成与验收观察 |
|---|---|---|
| 自然眨眼 | 可待机时随机等待 4–8 秒，双眼同眨一次；沿用 `Blink.Default(Both)` 的 40/10/80 ms | 130 ms 结束，固定步取整误差最多一步；不抖帽、不下压身体、不连续双眨 |
| 偶尔张望 | 可待机时随机等待 15–25 秒，等概率看左或右；`SetGaze(Both, ±0.4, 0)`，目标水平偏移约 2 DIP | 从首次成功消费命令起保持 1 秒，然后 Release 本批双眼 Gaze；沿用现有弹簧回正，不强制瞬移 |

张望 1 秒包含平滑转入过程，不另加一段瞬移到位或更长停留。建议自动断言：保持开始 300 ms 后，在对称稳定夹具里双眼相对无张望对照的水平偏移为目标方向 1.8–2.2 DIP；释放后 300 ms 内相对对照偏移绝对值不超过 0.2 DIP。实际几何仍受现有脸部裁剪约束，不扩大眼睛可移动范围。

每次间隔分别均匀抽取整数毫秒 `[4000,8000]`、`[15000,25000]`，方向左右各半。只在需要新间隔/方向时抽样，不逐帧重抽；生产使用进程内随机源，测试注入确定序列。随机种子、倒计时和方向不保存到设置。

不要求每次左右交替：允许偶尔重复同一方向，避免机械表演。保留已验收的方向面向 7/5.25 DIP、跳跃纵向眼动、1.35 倍帽子及物理跟随；本批只借用既有 Blink/Gaze 命令。

## 3. 什么情况下可以待机

“无人操作”仅指**没有正在操作这只团子的输入**，不读取系统全局空闲时间、不监听其他应用打字、不记录真实鼠标轨迹。

建议入口条件全部成立：

1. Product 宿主实际可见、运行中、允许交互；实体、代际、物理帧和该实体附件健康。
2. 没有有效按压候选、物理拖动、方向/跳跃/下压控制；该实体的手动点击/抚摸反馈和 300/1000 ms 冷却均结束。
3. 该实体连续至少 500 ms 的成功物理步满足 `IsGrounded`，且相邻成功帧的核心速度 `sqrt(vx²+vy²) ≤ 0.15`（现有物理世界单位/秒）。首次无前帧时尚不合格；无穷/NaN 数据不合格。只读 `CoreX/CoreY`，不修改物理参数或增添物理步。

稳定条件的理由：现有 `SetGaze` 同时指定 X 和 Y，`Y=0` 会覆盖默认跳跃纵向眼动。0.15 与现有纵向眼动死区一致；落地并稳定后才张望，离地或移动的首个成功步应在附件消费前释放，避免覆盖跳跃。本批两个行为共用此条件，减少动作重叠。

身体自然抖动若持续达不到稳定条件，应在实施时先用真实静置物理帧验证并报告，不暗调阈值或改物理来让测试通过。这是需要实测的设计参数，而非已经证实适合所有场景的结论。

Window 未获得焦点、Wallpaper 非桌面前台时，**可见且稳定的团子仍可安静待机**，这是日常陪伴的主要使用场景；它不接纳新手势、不激活窗口、不改变桌面前台策略。失焦事件终结当时正在发生的行为和输入，随后重新等待；不能因为后台状态每帧取消而永远无法待机。隐藏、最小化、宿主安全隐藏时则完全停止本批调度。

建议沿用“允许交互”作为本批启用条件：关闭时连同这两项自主眼睛动作暂停，开启后重新等待；不宣称这能减少所有身体/帽子动效，也不新增含糊的“低动效”设置。

## 4. 调度、时钟和有限状态

每实体仅保留代际、上一成功核心位置、稳定时间、两个下次触发时刻、当前自主动作及其成功步期限。它不是通用行为树，也不把待机写入原身体动作状态机。

- 所有等待、稳定确认、保持与结束只使用共享 runtime 的**成功物理固定步**；一次 Step 对应一次调度和一次附件消费。失败帧、重复观察 UI 帧、诊断查询、暂停和不可见时间均不增加计时。
- 初次可见、用户操作结束、失焦取消后、切宿主、DPI/坐标映射变化或恢复时，先重新取得连续 500 ms 稳定状态，再从零抽取 4–8 秒和 15–25 秒的等待。不立即表演，不保留隐藏前即将到期的行为。
- 稳定待机时两个倒计时并行推进，包括自主动作播放期间。每个成功步至多接纳一个新自主动作；两动作不叠加，前一个结束后至少留 500 ms 无自主动作间隔。
- 同一步两者均到期时，张望优先，眨眼丢弃并重新抽取等待。某个到期请求遇到已有自主动作、500 ms 间隔或附件 Busy 时，也丢弃并重抽，不排队、重试或延长当前动作。未到期的另一倒计时保留。
- 动作接纳后，为该动作重新抽取下次等待；下一次触发间隔按接纳点计算。拒绝也重新抽取该项，绝不因“仍到期”在后续每帧提交。
- 失去任一入口条件时取消当前自主动作，并丢弃两个倒计时；重新满足条件后走完整稳定确认和等待。手动 300/1000 ms 限频规则保持不变，自主动作用独立等待，不占用手动冷却。

上述规则保证：只要持续可见、稳定且无人操作，就能按大致频率看到两种行为；繁忙或被打断时频率只会降低，不会积攒后补播。

## 5. 输入优先、命令归属与取消

优先关系：生命周期/故障 → 团子直接操作及物理运动 → 自主待机。

### 5.1 手动输入接管

按下命中团子且主机条件有效时就撤销该实体的自主行为，而不是等到松手眨眼、16 DIP 抚摸成立或 3 DIP 起拖后才撤销。按住不动、Shift 候选及手动冷却期间也不启动自主行为。捕获失败同样丢弃旧自主计划并重新等待，但不得创建多余抓取。

共享 `LightInteractionSession` 需把“候选占用/释放”通过窄接口告知 runtime，覆盖 Window 与 WorkerW WPF/proxy/overlay；不能只看 `IsDragging`。转换拖动仍沿用上一批清候选、释放旧捕获、BeginPhysicalDrag 同步取消、复核并重捕获的流程。重复清理、旧会话结束不能清除新会话的占用。

对外的手动反馈提交边界也应确保自主命令已让出，防止绕过宿主的直接 `TryReact` 遇到自动 Blink 被误判 Busy。必须先取消自主占用、再提交手动命令；手动反馈的代际和冷却校验不放宽。新自主任务不能通过取消手动反馈给自己腾通道。

### 5.2 独立低优先级所有权

现有 `AttachmentSceneController` 每实体只有一个 preview token，Product 手动反馈也复用它。**不把自主与手动的 Blink/Gaze 放在同一 token 上**：这样会出现自动 Blink 挡住点击，或晚到 Release 清掉新手动命令的风险。

建议每个实体/附件代际只注册一次独立自主 token，复用现有 router 的低优先级 `RegisterAction`（priority 1）；既有手动/评审 token 保持 priority 2。自主有独立序号，不每次动作注册 token，不改 router 仲裁规则，也不建立通用动作总线。DeveloperReview 不启动自主调度。

结束或取消只释放自主 token 所拥有的双眼 Blink 或 Gaze，绝不 `Release(All)`，不释放手动 EyePose、Gaze 或帽子。自然眨眼完成沿用既有事件结束；张望满 1 秒后在下一次附件消费前 Release，期限误差不超过一个固定步。旧代际的到期事件不得向当前实体提交。

### 5.3 生命周期

| 情况 | 本批行为 |
|---|---|
| 手动 Down、方向/跳跃/下压输入、身体离地或不稳定 | 撤销自主占用；直接操作立即走旧路径；稳定后重新等待 |
| 正常手动 Up、取消、捕获失败 | 清对应候选占用；自主不立刻恢复，等手动反馈/冷却结束及稳定确认 |
| Esc、意外失捕获、失焦/桌面前台切换 | 取消当时自主行为和旧计划；可见后台随后仍可重新待机。Esc 只沿用现有局部输入检查，不新加全局钩子 |
| 隐藏、最小化、交互关闭、切宿主、DPI/映射变化、退出 | 健康状态先 Release 自主命令，再暂停/拆宿主；清期限及旧会话。恢复从完整新等待开始 |
| 物理故障或该实体附件故障 | 丢弃本地计划并冻结；不走会抛健康异常的公共提交路径补 Release；显式恢复重建代际和附件 ledger |
| 健康取消/到期 Release 被拒绝 | 锁存可见错误，禁止继续自主计划；沿用显式“恢复团子”，不能静默保留凝视或无限重试 |
| 重置、删除、重新初始化 | 销毁旧自主 token/序号/期限/稳定采样，新实体重新等待；不改其他实体反馈或选中项 |

释放后的眼睛只进行既有弹簧回自然状态；禁止为清除表情偷偷重置全部眼帽、推进额外物理步或修改身体位置。

## 8. 项目窗口与人工验收

实施后沿用已确认的项目输出普通 Product 启动，不默认 ZIP，不用评审模式代替。启动前核对当前实例与候选路径；需替换正在运行的实例时明确目标，不把第二次启动唤醒旧程序当作候选已启动。

人工建议连续观察至少 90 秒：自然眨眼不过密，张望轻微且会回正，身体和帽子没有新增动作；在两种自主行为期间分别短点、Shift 轻抚、拖动、方向控制与跳跃，确认操作立即接管且原观感保持。

分别验证 Window 与 Wallpaper 图标上/下层级，尤其在其他应用前台工作时仍能看见安静待机但不抢焦点；隐藏/最小化/禁用/切宿主恢复后等待完整新间隔。可用两种 DPI 与安全故障夹具逐项记录，不能用总体观感认可推定全矩阵通过。
