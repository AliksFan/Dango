# 新身体分支：正式接线与合并收口

日期：2026-10-20。起点 `b2a024b`，在现有 `codex/belt-page-completion` 分支收口。用户已确认“接入已验收”，随后明确要求记录过度隔离问题、与正式启动／构建对接，并把本分支整理到可合并标准。目录整理和规则建设由用户在合并后的新分支安排；本轮不提前执行，不修改 AGENTS.md，不合 main、推送、安装或部署。

## 记录的问题与后续边界

临时验收模式逐渐留在生产项目，导致已验收功能与普通启动／发布路径分叉。当前快照普通 App 有 13 种 review／preview 模式：main 原有 12 种，本分支增加新身体 1 种。新身体绑定只由 `--belt-body-review` 选择，房间模块还需额外参数；普通启动和发布仍沿旧物理。首页／门廊因此同时维护旧 LiveScene 和新 BeltBody 的接线。

只读审计还发现 `SingleDangoMotionRuntime`、`DragGrabPointMapper`、`DangoBodyColorPolicy` 和 `DeterministicFakePhysicsWorld` 目前只找到测试调用。最后一个文件中的 `AuthoredPoseSampler` 仍服务真实回退，不能整文件删除。单体编辑 worker、房间 owner 及共用 `dango_belt.c` 的两个模块分别承担实际职责，不能按名称或数量直接合并／删除。

这些目录与历史模式的全面收敛记录为**合并后待办**：确认消费者、迁出纯样板／测试类型、退役已被正式功能替代的接线、再建立统一工作规则。本轮只消除新身体产品上线所需的当前分叉，不新建验收框架。

## 本轮设计与实施

1. 普通产品启动默认使用新身体：首页／捏脸／配饰／门廊由已有单体 worker 和 presenter 承载；普通房／桌宠由现有房间 runtime 承载新 room 模块。房间在明确入房时初始化，首页不同时启动第二个本人。
2. 删除本分支新增的新身体专用启动模式和配置门控。通用 `--data-root <目录>` 只改变设置与存档位置，不改变物理、页面或业务；实例身份随显式数据根区分。既有本地安装验收参数保留其数据保护及兼容用途。其它历史 review 工具不在本轮广泛迁移。
3. 普通构建／发布自动构建并携带 `dango_belt_product.dll` 和 `dango_belt_room.dll`，不依赖手工复制 ignored 产物或本机绝对路径。更新现有发布清单和源契约，保留旧契约供旧包管理，不将新语义冒充旧包兼容。
4. 修复木平台跳跃后连续证书 `-707／-605` 的已复现首因，保留旧失败并增加定向反例及受影响回归；不改材料、步态、穿透容差或保护预算。
5. 校验旧外观格式读取不写盘、成功显示后显式应用才迁移、失败保护、配饰及房间保存。仅针对正式接线影响补验证，不重做整个 F1～F7。

界面继续沿《[桌面界面规范 v0.1](../desktop-ui-design-v0.1.md)》第 2～6 节和现有页面合同，本轮不重新设计布局／主题。记录用户已有的接入验收，不外推为新发布接线、平台修复、完整性能／Windows／多人验收。

## 可合并标准

- 正式默认启动及通用数据根覆盖使用同一产品行为；旧新身体验收参数不能静默回落读取日常存档。
- 普通构建／发布中两个模块实际存在、版本能力及源／产物身份可核查；安装器清单检查通过；不替换受保护 DLL 或日常安装。
- 平台最小失败有根因修复和相应反例；剩余未知问题准确记录，不用重复绿灯关闭历史失败。
- 受影响自动／后台集成检查完成，本轮需要的前台复测另按 AGENTS.md 第 4 节申请；用户已有接入验收与新增验证分别记录。
- 工作区、差异、文档和本地提交清楚，main 原有 AGENTS 修改保留。合并、推送和安装的授权分别处理。

## 历史门槛的本阶段必要性

按用户此前“即使需要，也不一定要放在本阶段修”的要求重新判断：木平台故障直接使正常跳跃停机，已复现、有确定根因，属于本轮必须修复项。旧 Schema1 保存单次间歇失败尚无具体异常／根因，已有有界调查和 1319 次数据执行未复现，本轮也不修改保存器；保留 UNKNOWN 与下次失败应收集的诊断，不继续盲目复跑，也不把根因查明作为本次启动接线的前置。此项是调整阶段顺序，不等于修复或将风险写成用户已明确接受。旧收口记录中的前置条款由本次必要性判断替代。

完整 Windows、其它 DPI、多屏、59 FPS 和多人矩阵继续属于各自阶段。本轮覆盖新的默认入口、产物、旧数据实际显示与显式保存、受影响房间及已知平台故障；不以扩大历史门槛延长当前收口。
