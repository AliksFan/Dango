# 本地与联网体验及普通房编辑决策

记录日期：2026-10-15。产品方向和编辑规则于 2026-10-13 确认；2026-10-15 补充本地收口范围、断网游玩和新建房间要求。本文记录用户已确认的决定；生产实现、服务端裁定和实时验收按后续批次分别推进。

## 1. 本地与联网定位

本地模式在网络较差、没有网络、服务器尚未完成或服务故障时，提供完整的单人陪伴与创作体验。联网增加账号双向同步、好友和共享房间能力。单人互动、外观和配饰编辑、本地保存不以账号连接成功为前提，普通房家具编辑另按第3节资格处理。

用户原意为“本地的设置／团子都要可以同步到帐号上，同时云端的数据在连接时也要可以同步到本地”。同步失败保留本地成果，准确表达本地保存与云端同步各自的结果。

账号内容、共享房间状态和本机环境分别处理，不新增“个人空间”房型：

| 数据 | 已确认的边界 |
|---|---|
| 团子外观、配饰及必要图片、穿搭方案、个人偏好 | 作为账号内容支持本地与云端双向同步；某项功能尚未实现，不因列入同步范围而自动进入首批实施 |
| 普通房布局 | 按房间身份和编辑资格处理；已开放多人房的布局受在线房间裁定，不能作为普通账号设置直接覆盖 |
| 窗口位置、显示器选择、DPI等设备设置 | 保留在本机，不跟随账号跨设备覆盖 |
| 真实桌面、应用内容、原始输入、剪贴板等私人环境 | 不进入账号或房间同步 |

同一项内容在本地和云端分别修改时，保留双方版本，只对冲突项让用户选择；不以客户端时间简单覆盖，也不因一项冲突回滚全部无冲突内容。首次关联账号同样保护已有本地和云端内容。具体对象粒度和身份关联流程在同步契约中细化。

## 2. 房间机制沿用现有基线

“普通房”在正式产品规则中对应共同房间，分私密和公共；桌宠房间是另一种房型。联网与本地是使用状态，不据此新增房型。正式在线规则见[产品基线第3节](../product-design-v0.1.md#3-核心对象与规则)。

| 项目 | 保留的规则 |
|---|---|
| 桌宠房 | 每账号一间，房主加一名固定长期访客，最多两只；离线睡眠占位，房主离线不取消访客资格 |
| 私密普通房 | 默认6席，可设1–12席；接受邀请取得长期成员资格，离开或睡眠不等于空出成员席位 |
| 公共普通房 | 默认6只，可设1–12只；凭有效码或链接申请进入，没有长期席位，正式下线进入无房间状态 |
| 创建额度 | 统一最多3间未解散普通房；桌宠房不占额度，私密／公共首版不直接互换 |
| 解散与恢复 | 普通房解散后释放创建额度，保留7天恢复期；恢复重新检查额度，团子不自动回迁 |
| 团子身份 | 一名用户一只主要团子，同时最多一个正式有效房间归属；无房间是合法状态 |
| 视图与下线 | 隐藏、回门廊不等于正式下线；短断线与超过容错时间的正式下线分开处理 |

本地已有单人普通房实现不能冒充上述正式账号、权限、成员、额度和归属机制已经接入。

## 3. 普通房家具编辑资格

用户最后明确：“锁定布局时联网可编辑，不是永远锁定。”因此锁定的是已开放多人房的离线编辑资格。

| 普通房状态 | 离线编辑 | 联网编辑 |
|---|---|---|
| 上限1只，且只有房主本人有进入资格 | 允许 | 允许，仍核对编辑权限与房间状态 |
| 多人容量，但从未发出邀请、从未开放他人入场 | 允许 | 允许，仍核对编辑权限与房间状态 |
| 已发出邀请，或已启用房间码、链接等对外入场方式 | 禁止，只能进入单人游玩 | 允许有编辑权限者实时编辑，经服务端裁定 |
| 桌宠房 | 当前没有家具接入，暂不纳入本规则 | 同左 |

资格按房间开放状态判断，不能仅数当前在线团子。邀请尚未接受也已触发开放；成员离开、下线、睡眠或撤回既有邀请，不使多人房回到“从未开放”。公共房上限1只仍可能接纳持码访客，必须同时满足仅房主可进入，才适用第一行。改变上限不能绕过其他人的资格和实际占位。

不新增离线布局草稿、重连预览发布或自动回放离线家具操作的产品功能。现有家具单次操作的预览／确认／取消，以及捏脸、配饰的未应用编辑状态继续沿用，不受本决定取消。

## 4. 联网编辑与本地同步

联网添加／移动家具仍沿用[实时家具编辑规则](2026-10-10-live-furniture-editing-design.md)：确认前保留原家具，确认时依据最新房间状态、真实碰撞轮廓、边界和其他家具复核。其他团子进入目标位置时拒绝确认，保留原家具和当前操作预览，不通过同步自动挪开团子。

删除支撑家具按实际变化清除接触和支撑，团子自然下落；不重建团子或重置全房位置、速度来应用布局。家具权限、手套限制和共享写入仍由服务端裁定。

允许离线编辑的房间先保存真实本地布局；开放邀请或公共入场前必须完成当前布局同步。重连后复核服务器最新开放状态和版本，旧离线写入不能覆盖已开放的共享布局。另一设备先行开放或修改时，保留冲突数据供选择，不能绕过已变化的编辑资格。

## 5. 断网游玩与新建普通房

多人房断网后保留单人陪伴和本地可编辑内容，重新连接时先确认当前在线归属。用户补充：“可以进去游玩，但家具只读，另外可以创建新房间。”

- 缓存的已开放普通房可作为本地单人游玩场景，家具只读。单人运行不代表仍与其他用户同步，不把缓存的其他团子呈现为实时在线角色。
- 本地游玩不新建服务端归属或占位；移动、碰撞和球的运行态不能在重连后当成在线房间结果回放。
- 本地允许新建普通房。统一最多3间未解散普通房，满额需先解散一间；不新增本地专属房型或独立创建额度。
- 本地新建房在首次对外开放前可编辑，布局先在本地保存。未来关联账号时核对房间身份、额度和版本，不因本地新建而假报云端已创建。

离线只能根据本机已知目录校验额度，不能证明另一设备没有创建房间。后续同步须处理目录合并和额度冲突，保留已有内容，不自动删除或覆盖任一房间；异常处理的具体交互见需求草案待定项。

## 6. 取舍与后果

| 选择 | 理由与后果 |
|---|---|
| 完整本地体验，联网增加同步与社交 | 服务故障不阻碍基本陪伴和创作；本地保存与云端确认需要独立状态 |
| 已开放多人房禁止离线编辑 | 消除离线布局直接碰撞其他在线团子的情形；家具编辑需等连接恢复 |
| 已开放多人房仍可联网编辑 | 保留实时布置能力；最新碰撞检查、权限和并发裁定仍须实现 |
| 不增加离线草稿功能 | 减少房间副本、发布和整房合并的操作负担；单次操作预览继续保留 |
| 统一3间额度 | 沿用既有房间规则；多设备离线创建可能在同步时发生额度冲突 |
| 保留双方冲突版本 | 保护用户成果；不能把“选用本地”当作绕过房间权限或额度的授权 |

此前讨论的“个人空间布局自动双向同步”“离线编辑多人房并重连发布草稿”“多人房一旦开放永久禁止编辑”均不作为现行方案。

## 7. 本轮收口范围

2026-10-15 用户确认：先整理现有单人功能的完整闭环，双向同步先定义契约；补齐普通房与桌宠房退出、重启后的内容保存和恢复要求，启动是否自动入房单独决策。本地新建普通房及统一额度作为本轮新增需求列入设计。

后续入口为[本地模式收口需求草案](2026-10-15-local-mode-closeout-requirements.md)。首批不自动包含穿搭方案管理、配饰分享包、手机、好友系统、新物理功能、服务部署或数据库操作。新物理接入与其准入验证继续由原任务负责。

后续“本地房间目录＋每房存档”已在独立任务分支推进，见[具体设计](2026-10-15-local-room-catalog-save-design.md)。允许本分支设计工作，并在具体设计及批次获批后修改、验证和本地提交；不据此授权真实账号同步、日常存档操作、持久资源删除、合入main、推送、安装、部署或替换生产DLL。

## 8. 本地目录任务的恢复选择

2026-10-15 用户在本地目录任务明确确认：

- 首页启动，记住上次选择的房间，进入仍由用户主动操作。
- 每房保存团子的安全逻辑位置及本机镜头模式、视距和手动视角；位置失效回安全出生点。速度、抓取、跳跃过程及睡眠阶段不作为重启存档，镜头不随账号跨设备覆盖。
- 纯本地、未关联账号的普通房经二次确认解散后立即释放额度，7天内可恢复；恢复重新检查额度，不自动入房。到期关闭常规恢复入口，底层存档保留，不自动删除。

用户随后要求将这些功能入口全部放入门廊场景。新建、解散、恢复与房间选择的入口归属门廊场景对象；必要表单和二次确认可在场景内临时浮层完成。具体房门／空门位／恢复标牌方案见具体设计第7节，不新增常驻目录管理侧栏。

纯本地房的到期保留是本轮明确例外；正式在线房间的解散、服务器额度和过期清理仍由服务端裁定。本机离线计时不能宣称可信在线时间。上述选择与场景入口方向已确认，目录结构、兼容协议、具体界面和实施分批仍以具体设计审批为准。
