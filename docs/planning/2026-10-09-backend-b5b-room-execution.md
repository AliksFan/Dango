# B5B Windows 房间目录与管理

承接已批准 B5 和居中浮层选择。B5A 真实 HTTPS→PostgreSQL 5／5 已通过；本增量接入既有 B3 房间管理合同，保留本地单人入口。当前允许代码、静态验证与本地提交。新的虚构房间写入、解散和恢复按独立数据计划另行授权。

## 范围与流程

- 门廊在线目录与账号“我的房间”入口共用暖色居中浮层；未登录先进入账号，登录后可以管理房间，配置来源确认只约束后续在线进入。
- 本人有效／已解散目录按游标每页 20 项读取；详情重新读取，不把原操作回执当作当前房间状态。
- 创建私密／公共共同房，默认 6 席，范围 1–12，最多 3 间由服务器裁定；类型创建后不可修改。默认桌宠房固定 2 席，不可解散。
- 修改带期望版本；解散先阅读后果，再第二次明确确认。恢复重新检查 7 天和额度，不迁回团子或复活公共码。
- 每次写入保存原请求 ID、目标、版本和正文；断线、取消或响应不可信时保持待核对状态，只能显式继续原请求。关闭再打开同一会话仍保留；成功回执后重新读详情。进程退出后的请求恢复本增量未实现，不能宣称崩溃后自动对账。
- 版本冲突终止旧尝试，重新读取后由用户再次决定；会话／账号变化清除目录与原绑定，旧响应不得发布。正式客户端共用账号 Cookie、串行传输与新 CSRF。
- 本增量不提供场景进入、Hub、租约、公共码界面、好友或配饰上传；管理成功不表示在线呈现成功。

## 文件所有权与集成

独立 room-client 工作树负责正式传输及静态反例；room-view 负责 `RoomPanelView` 与 STA 反例；room-tests 负责真实 HTTPS 用例、独立 B5B runner 与精确数据计划。根工作树负责房间编排、账号／首页／host 路由与集成。依次 cherry-pick 局部提交，不改 main、日常安装或受保护 DLL。

## 五项可验证门禁

| 项目 | 本增量证据与边界 |
|---|---|
| 正确性 | 201 创建、合法名称／容量、严格响应形状与分页；受控异常响应、错误输入、默认桌宠保护、解散确认 STA 反例 |
| 一致性 | 原请求键与正文保持、迟到结果隔离、CAS 冲突显式重读；真实丢响应、独立客户端并发和数据库关系检查另行执行 |
| 安全性 | 固定 HTTPS、身份绑定、新 CSRF、归属逐次服务端检查、外部响应有界；真实跨账号拒绝与旧会话另行执行 |
| 可靠性 | 关闭／断服仍可本地，未知写不报成功；已有备份还原门禁不被客户端测试替代；进程级请求日志与人工桌面未验证 |
| 扩展性 | 页大小 20、传输最多 50、目录读体有界、单 UI 请求与清理；不引入无界刷新、轮询或分布式设施 |

静态门禁、集成门禁、真实 Windows 操作与人工验收分别记录。未授权前不启动 PostgreSQL／HTTPS fixture，不写 WinCred；不删除已有数据或资源。
