# 第一批正式桌面入口整合：实施计划

> 日期：2026-09-17；状态：用户确认[详细设计](2026-09-17-desktop-entry-integration-design.md)后，已在独立分支按本计划实施，并获用户本批人工验收通过确认。后续默认直接从项目打开验收窗口，不再默认提供整个压缩包；下文保留原计划和验收要求。实际完成及专项未验证项见[实施记录](../verification/2026-09-17-desktop-entry-integration.md)。
> 目标：一个普通入口运行已认可身体/眼帽，支持现有操作、基础设置/帽型保存、故障恢复和完整分发候选。
> 不覆盖点击/抚摸、自主生活、岛物理、低动效、联网或整个 Phase 1 收口。

## 1. 实施前边界

用户在审阅具体设计与本计划后回复“确认设计”；承接此前确认后实施的约定，进入下列第一批步骤。该授权不扩展到后续批次、合并、推送或部署。

实施不能从本规划工作树的 `0610355` 补造缺失桌面代码。建议从已核实开发检查点 `72199ef` 建立独立 `codex/` 任务分支/worktree；不修改原 `feat/p1-004-box2d-soft-body` 工作树，也不搬入它保留的 1 处 CMake 差异和 25 个历史实验源码。若实施时 HEAD 已变化，先比较相关文件与新证据，不机械覆盖。

本批只新增/修改必要托管桌面、测试、发布脚本和对应记录。原生算法、默认物理参数、受保护 DLL 字节、旧预览及证据目录不动；不调用会覆盖旧 DLL 的构建脚本。不新建服务器、业务端口、数据库、付费资源或网络模块。

## 2. 增量与文件所有权

一个实现者负责 AppShell/runtime/设置的连续接线；审计和验收准备可并行只读，避免多个执行者同时修改相同生命周期代码。每一增量先建立能区分错误实现的验收，再实现并运行受影响验证。

| 步骤 | 主要文件/模块（开发基线相对路径） | 具体交付 | 前置和停止条件 |
|---|---|---|---|
| E0 基线与输入 | Git/worktree；Desktop/Core/Physics 测试；库和历史证据清单 | 新工作树、保护清单、明确模块输入、可重复的基线命令与结果 | 缺少真实夹具/库则说明未验证，不能用 fake 替代并报通过；新失败先定位 |
| E1 启动模式与附件接线 | `App.xaml.cs`、`AppShell/DangoApplicationHost.cs`、`Rendering/Dango/StackedDangoSceneRuntime.cs`；必要的宿主状态接线/启动结果类型 | 普通新眼帽、评审UI独立、受校验帽型状态接口；标定一次且释放；未初始化/失败时控制中心可用；本步不写首次引导字段 | E0；不改眼帽数学/native；不能产生双world、双step、空引用或悄悄回旧机制 |
| E2 基础设置 Schema 4 | `AppShell/ControlCenter/ControlCenterWindowSettingsStore.cs`；AppShell保存协调；对应测试 | 迁移及新字段；两退出路径统一保存；迁移/恢复先备份、失败保护原文件；保存失败可见 | E1契约已明确；未开控制中心也不丢字段；本步提供introSeen存储，E3才接首次展示流程 |
| E3 正式控制中心 | `AppShell/ControlCenter/ControlCenterWindow.xaml`、`.xaml.cs`、`ApplicationCommandController.cs`；必要窄能力接口 | 普通单人导航、帽型/基础设置、首次说明；隐藏开发功能但保留帮助/诊断；reset/exit真实反馈 | E1/E2；未实现能力不展示可操作按钮，review功能不删 |
| E4 完整普通分发候选 | `src/Dango.Desktop/Dango.Desktop.csproj`；建议新增 `eng/publish-desktop-entry.ps1` 及相对路径包清单 | 全新输出、显式已验收模块、两库哈希、许可证、普通exe与清单；不自动启动 | E1–E3；缺库/错哈希/已有输出失败；不重建native，不复制个人设置 |
| E5 集成与真实验收 | `tests/Dango.Desktop.Tests` 中入口/设置/渲染/宿主测试；新验收记录 | 自动结果、两宿主普通入口实测、人工认可、遗留问题与候选包身份 | 全部测试结果如实保留；旧导出失败未完成契约评审时不得标全绿正式交付 |

本表新增类型和脚本名为建议，不表示已存在。优先复用已有接口、store 和写入器，不增加 UI 框架、消息总线或第三方依赖。

E1只建立安全的启动/状态链，不提前读写尚未存在的Schema4引导字段；E2完成字段与统一保存后，E3接入概览展示确认和 `introSeen` 的持久化。E2明确由保存协调器控制备份/恢复权限，原子写入器只负责单文件写入，不自行决定覆盖损坏或未来版本文件。

## 3. 必须能失败的验收用例

| ID | 用例与判定 | 必须被识别的错误实现 | 增量 |
|---|---|---|---|
| ENTRY-01 | 普通启动启用新附件，打开控制中心没有评审面板；review仍有自己的实例/设置/面板 | 普通模式直接等同 `--eye-hat-review` 或附件开关触发实验窗口 | E1/E3 |
| ENTRY-02 | 首次默认Wallpaper、一只、键盘关闭/方向键、叶芽；旧有效偏好优先；旧Schema3骨架true在Product中仍关闭且兼容值保留 | review默认污染普通入口；旧骨架无条件应用；保存时丢失兼容值 | E1/E2 |
| ENTRY-03 | 标定240步仅一次，临时world释放后创建实际world；换帽/Show/模式切换不再标定 | 两个同时活跃world；每帧/每次打开设置都重建 | E1 |
| ENTRY-04 | 缺/错模块及标定失败明确Unavailable；概览/诊断/重试/退出无空引用；失败无活跃world，重试成功仅一个且状态刷新 | 异常穿出启动；catch后空runtime导致UI崩溃；静默旧表现或重试叠加world | E1 |
| ENTRY-05 | Window↔Wallpaper和隐藏/恢复保持同一ID/world；物理每固定步一次，眼帽暂停/恢复连续 | 双计时器重复Step、恢复补算隐藏时间、失焦后仍按住 | E1/E5 |
| SETTINGS-01 | Schema1/2/3迁4保留全部既有有效偏好；缺新字段得到明确默认 | 迁移丢失旧位置/键盘/图层；缺字段导致整份文件作废 | E2 |
| SETTINGS-02 | 换帽经命令校验后两宿主同值，退出/重启恢复；打开/未打开控制中心两种保存路径一致 | 只改一个窗口、只改review变量、某条退出路径重写默认帽型 | E2/E3 |
| SETTINGS-03 | 模拟写入拒绝/中断：旧文件完整，UI显示已应用未保存，重试保存不重放动作 | 静默Debug错误；写半份JSON；重试触发多次宿主切换 | E2 |
| SETTINGS-04 | 未来schema/损坏文件使用安全默认，退出不覆盖原字节；显式恢复先备份；备份失败继续保护且可不保存退出 | 启动失败后自动覆盖；备份失败仍改原文件；错误使应用无法退出 | E2 |
| SETTINGS-05 | 仅偏好/帽型等稳定字段入库；恢复团子不清设置；临时隐藏不导致下次找不到入口 | 存储键鼠历史/节点/句柄/token；reset清全档；持久化按住键 | E2/E3 |
| UI-01 | 正式无多体增删/骨架/参数/验收页；review保留；普通帮助/诊断与退出可达 | 只改文字仍暴露危险控制；删除review功能；把诊断一并藏死 | E3 |
| LIFE-01 | 场景/控制中心关闭为隐藏；再次启动激活原实例；显式退出释放输入、计时器、world和托盘 | 关一个窗退出整个应用；两个普通实例；退出残留捕获/后台循环 | E3/E5 |
| PACKAGE-01 | 全新输出打包无需源树artifacts；用户包包含两个指定哈希库和许可证；普通加载来自包内 | 开发机DLL搜索偶然成功、缺新库照样产包、包内是不同库 | E4 |
| PACKAGE-02 | 缺输入/错哈希/已有输出拒绝；前后源库哈希相同；包清单无本机路径/用户设置 | 发布重建覆盖旧库、清空旧产物、把个人settings打进包 | E4 |

核心自动回归继续覆盖1/2/3体每例900步的新表现/旧表现/直接模块对照、稳定ID、暂停/重置/移除与compiled双宿主绑定。并非重新要求在本轮规划时执行；实施时使用明确模块夹具，证明本批只改变接入和显示配置，不改变身体轨迹。

测试应断言外部可观察结果与资源计数/帧序号，不仅检查新方法是否被调用。完整Suite仍运行并保留唯一历史失败，不能用筛选绕过它后称全绿。已有长测被排除的事实必须明示；本批没有物理算法变化时按风险运行必要回归，不无理由重复全部历史长测。

## 4. 候选发布流程与验证命令

实施时脚本建议接收 `-RunName` 与 `-PhysicsModulePath`。路径只在本机解析，不写进源码或包清单。新输出建议位于 `artifacts/desktop-entry/<RunName>/`，构建/测试/包/证据分目录。

脚本的顺序：校验参数与输入哈希 → 拒绝已有输出 → Release self-contained publish到新目录 → 校验包内新旧DLL、许可证和文件清单 → 返回exe/清单/日志位置。默认只构建，不启动，不kill进程，不删除或重建旧目录。

主要命令类别（具体夹具路径与结果目录由E0确定，不把以下当已运行记录）：

```powershell
dotnet format .\Dango.slnx --verify-no-changes --no-restore
dotnet build .\Dango.slnx -c Release
dotnet test .\tests\Dango.Core.Tests\Dango.Core.Tests.csproj -c Release
dotnet test .\tests\Dango.Desktop.Tests\Dango.Desktop.Tests.csproj -c Release
dotnet test .\tests\Dango.Physics.Tests\Dango.Physics.Tests.csproj -c Release --filter 'FullyQualifiedName!~DangoPhysicsStabilityTests'
```

这些命令需使用本次独立artifacts/结果目录、必要restore和明确模块/历史夹具来源后再执行；不能把缺fixture当产品故障，也不能把跳过全部native路径当有效验证。正式包使用 `-r win-x64 --self-contained true` 并显式传 `DangoPhysicsModulePath`，发布成功后再运行包内已有 smoke；smoke只证明Dispatcher启动退出，不替代场景/库加载。

旧 `--box2d-native-probe` 检查的是旧库，不能作为新模块加载证据。新模块需要由普通入口真实初始化、包内模块实际加载路径/哈希与控制中心状态共同证明；在报告中分开静态文件校验与实时模块加载。

## 5. 普通入口人工清单

使用获授权的隔离Windows测试用户/桌面环境，包内无参数启动。两种宿主各执行，至少覆盖当前125%与另一种缩放/分辨率；设备/配置不足记未验证，不自动调整用户日常桌面设置。

1. 首次启动一只团子，观察身体、眼形、面向、跳跃眼动与帽子；不出现眼帽评审面板或数量控制。
2. 拖放、释放、移动、下压、跳跃；失焦/Esc/隐藏后无输入残留。对照已认可手感，不凭测试绿灯代替视觉确认。
3. 选择三种帽型，Window/Wallpaper一致；正常退出重启后保留帽型、键盘、图层与窗口偏好。
4. Window↔Wallpaper往返至少3次，隐藏/恢复至少3次；不重生、不增加团子、不漂移抓点、不出现帽子跳变。
5. 验证图标之上/之下、空白输入穿透、真实桌面图标、焦点、任务栏；普通场景窗口关闭只隐藏。
6. 再次普通启动只唤醒已有控制中心；场景隐藏时仍可找回；退出后检查本次精确进程与资源，不停止其他预览。
7. 在虚构设置副本/隔离环境验证旧schema、损坏/未来schema、无写权限；真实显示保存失败，原文件保留，重试后恢复。
8. 通过独立包副本注入缺/错库，验证Unavailable与恢复入口；不操作受保护源库。WorkerW故障与Explorer恢复按既有矩阵执行，未实测项单列。

该清单是本批人工认可，不自动覆盖完整Phase1的长期驻留、所有系统/硬件矩阵、1/6/12性能与后续动作/岛。正式默认的新组合需要用户明确确认。
