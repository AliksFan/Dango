# 团子自身捏脸设计

日期：2026-10-05。状态：设计候选。用户明确捏脸只关乎团子本身，帽子作为另一部分单独设计。本轮沿用已认可的颜色规则，提出基础眼型与眼睛大小的交互示意；候选数量、尺寸、界面及保存扩展待评审。没有实施眼型、大小或生产捏脸界面。

## 1. 目标与本轮范围

在现有“我的团子”首页编辑区改变团子自身长相，让用户能预览、取消、应用及恢复默认，同时保留同一团子的真实活动和动态表情。

本轮设计包含身体颜色、眼睛颜色、有限基础眼型与双眼统一大小。帽子、服装、配饰属于独立换装部分；帽子另见[独立选择设计](2026-10-05-hat-selection-design.md)。不把帽子控制项放入捏脸，也不因取消捏脸而重置帽子。真实大小、身体形状与柔软度继续留给后续有界物理 DIY；本轮不添加嘴巴、眼距、单眼编辑、绘制或上传。

范围依据[已批准路线](2026-09-22-gait-and-customization-roadmap.md)与[产品 DIY 边界](../product-design-v0.1.md#52-团子-diy-参数边界)。用户本次纠正约束帽子归属，其余具体候选不写成已批准参数。

## 2. 当前实现事实

- [首页](../../src/Dango.Desktop/AppShell/ControlCenter/ProductHomeView.xaml)已有右侧编辑区，身体色只有内存预览，眼型与“应用”仍未开发。
- [独立颜色成果](2026-10-05-appearance-consolidation.md)本轮整理了身体／眼睛 RGB、草稿与颜色 Schema 2；未与首页接线。
- 当前 `EyeShape` 描述眨眼、开心、困倦和睡眠等动态表现，不能直接把全部枚举当成可保存的基础眼型。
- [FaceLayoutSolver](../../src/Dango.Desktop/Physics/Presentation/Attachments/FaceLayoutSolver.cs)的基础尺寸与间距目前固定。已有注视、间距、尺寸、闭眼与隐藏的安全退让；新的眼型和大小需要进入安全求解，不能只缩放最终图画。
- [AttachmentMotionController](../../src/Dango.Desktop/Physics/Presentation/Attachments/AttachmentMotionController.cs)无动态眼睛指令时回到 Round。长期调用 `SetEyes` 会占用睡眠／表情通道，不能据此实现基础眼型。

## 3. 界面候选

沿用首页结构：左侧团子预览，右侧捏脸编辑区。“颜色”和“眼睛”两个局部页签；切换页签保留同一草稿，不自动保存，也不改变实体、位置或物理参数。帽子入口由后续换装设计承担。

颜色页分别显示身体与眼睛的当前色块和只读 Hex，使用系统调色盘选择 RGB；身体保留既有三个快捷色。选择确认只更新草稿；取消系统调色盘保持原值。完整 RGB、黑色和同色合法，不自动改善对比度。

眼睛页提出以下候选；用缩略图配短名称，不把开心或睡眠作为永久眼型：

| 基础眼型候选 | 睁眼轮廓 | 与表情的关系 |
|---|---|---|
| 圆眼 | 沿用当前默认比例 | 默认长相，仍可眨眼与睡眠 |
| 纵椭圆 | 相对圆眼收窄宽度 | 动态闭合与注视继续组合 |
| 横椭圆 | 相对圆眼收窄高度 | 保持可辨识的睁眼／闭眼区别 |

眼睛大小先提出“小／标准／大”三档，双眼使用同档。示意暂用 0.85／1／1.15 相对倍率，纵／横椭圆暂用 0.8 的对应轴比例；这些只用于比较设计，不是经真实求解验证的安全数值。最终比例需覆盖每种轮廓、表情、注视和身体受压组合。

预览区提供一次性“眨眼”和“睡眠／醒来”比较，不保存表情、不改变产品中的自动行为。真实实现使用既有 runtime 动态状态；示意仅用页面形状演示，不作为软体、WPF 或安全布局证据。

底部提供“恢复默认”“取消”“应用”。恢复默认只是草稿变化；取消回到最近已应用的整套自身外观；应用成功后才成为已保存值。关闭编辑区、去设置／门廊、隐藏或退出时取消未应用草稿，清理临时比较状态；后续集成需检查现有转场与输入顺序。按钮或调色盘有焦点时消费自己的操作，不能同时触发移动、跳跃或 W 进门。

## 4. 草稿、保存与故障

区分已保存自身外观、编辑草稿、逐帧动态表情三个层次。草稿在同一预览实体上展示，不能创建第二个 runtime，也不能用旧模拟帧掩盖故障。动态表情结束后回到当前基础眼型；取消草稿后回到已保存基础眼型。

| 操作 | 预览与草稿 | 本地保存 |
|---|---|---|
| 选色／眼型／大小 | 对应项即时预览，其他项保留 | 不写 |
| 切换颜色／眼睛页签 | 保留草稿与同一实体 | 不写 |
| 恢复默认 | 全部自身项进入默认草稿；帽子不变 | 不写 |
| 取消／关闭编辑／隐藏 | 回到已保存自身外观，临时表情清理 | 不写 |
| 应用成功 | 整套草稿成为已保存外观 | 原子保存受支持的自身配置 |
| 应用失败 | 保留草稿和最近已保存值，允许重试或取消 | 原文件保持完整，不标已保存 |
| 文件损坏／未知版本 | 安全默认并提示保护状态 | 普通应用不能覆盖；显式备份恢复 |

当前整理的颜色 Schema 2 不包含眼型／大小，本轮不向它偷偷添加字段。后续实现建议另行批准外观 Schema 3，保存现有身体／眼睛 Hex、稳定眼型标识和大小档位标识；旧 Schema 1／2只读使用默认圆眼／标准大小，用户显式应用时才升级。旧版软件遇新 Schema 时沿用保护与回退，不能覆盖未知版本。

眼型／大小不存在当前生产文件里。上述升级方案仍是候选，不能提前写盘或声称已经完成重启恢复；需要专门的兼容与回退验收。帽子现有设置路径不在本轮重构，未来换装的跨文件保存规则另行设计。正式多人仅同步受支持的版本化配置，服务端校验；本轮不扩展协议或宣称外观已同步。

## 5. 实施顺序候选与文件所有权

1. 本轮先完成独立旧颜色模块整理与聚焦验证，提供捏脸示意供评审。
2. 界面确认后，再制定基础眼型／大小契约和安全布局计划，以必败反例锁定动态组合与兼容行为。
3. 颜色与自身草稿接线、首页 UI 和 runtime 输入由一名集成负责人处理，避开普通房并行修改同文件；眼型与大小按小批独立验证。
4. 在隔离 Windows 候选验收自身外观全闭环后，再单独安排合入、安装或共享交付。

不修改 native、碰撞、软硬度、移动、房间状态或主设置 Schema；不以此次设计批准后续实现、迁移或发布。帽子独立设计不在上述批次中混入。

## 6. 可失败的验收

- RGB 原值在草稿、文本与保存一致；黑色和同色均不被拒绝、钳制或反色。低对比是用户选择，不作为失败。
- 每种基础眼型 × 大小均能眨眼、自然闭眼和睡眠，醒后回到所选长相；不能长期锁住动态 `EyeShape`。
- 极端注视、压缩、跳跃与安全退让不使眼睛越出有效脸部、交换左右或产生非法数值。临时缩小／闭眼不改已保存大小。
- 预览、页签与表情比较不写文件；取消同时回滚身体、眼睛、基础眼型和大小，帽子状态不变。
- 原子保存、备份、升级或未知字段失败不丢旧文件，不把失败草稿标成已保存；重试和取消仍可用。
- 首页、门廊和后续普通房保持同一实体、同一外观；外观编辑事件不主动调用 Tick 或额外推进物理，既有唯一帧驱动继续负责活动；不重建实体、不新增帧 owner，旧回调失效。
- 输入焦点、关闭、隐藏、托盘恢复、三档首页布局与减少动画不回归；实际 WPF/native、磁盘重启和人工观感分别记录。

[交互示意源](../prototypes/dango-face-design.html)的“应用”仅在页面比较草稿与已应用值，聊天恢复状态也仅服务示意；不访问生产设置、外观文件或网络。示意检查不能替代上述真实功能验收。
