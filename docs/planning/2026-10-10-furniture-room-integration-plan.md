# 家具编辑接入主程序普通房计划

日期：2026-10-10。状态：**用户已批准并授权 I0–I4 本地实施。I0–I3 已实现，本地实现提交 `776ed4b`，最终 Release 回归 235/235 通过；I4 真实产品 50 次往返及独立进程恢复已完成。用户明确结束持续观察以使用电脑，600 秒观察和人工验收仍待完成。** 详见[实施与验证记录](../verification/2026-10-10-ordinary-room-furniture-implementation.md)。

本轮将已验收的木平台布置能力接到主程序普通房。玩家从门廊面向本地普通房门按 E 进入布置，或在房内通过 Esc 菜单进入；编辑时继续使用房间里的同一只团子和物理世界。此处的主程序普通房是现有本地单人运行场景，正式在线房间的准入、账号归属与多人裁定保持后续阶段。

## 范围与来源

首轮只提供空布局或一件默认木平台、选择与拖动预览、方向微调、确认添加或移动、直接删除、本人手套、右键拖动视角和逐操作本地保存。侧栏保留微调、后续参数、两列家具缩略图仓库三部分；本轮不开放大小或弹性调节。用户在实施中明确仓库展示实际家具图片，操作工具继续使用图标，后续家具也沿用缩略图内容项。

桌宠房、普通房壁纸呈现、皮球与多家具组合、新圆形身体、玩家 PNG、自定义家具、账号云存档、多人编辑及跨玩家手套不进入本轮。已验收的界面方向直接复用，不重新设计家具编辑器。

- 主程序代码基线为 `f10121b`。本轮开始时本地 main 位于该提交，交付前复核已由另一项任务推进到 `2acb532`，新增内容仅为 AGENTS 规则、桌面界面规范、滚动控件计划与原型，生产代码未变。普通房已通过既有窗口人工验收，房间运行事实以现有代码及[普通房计划](2026-10-05-local-single-room-plan.md)为准。
- 家具来源为 `codex/furniture-layout-live@06c367f`，实现提交为 `956ec56`；其通过范围是独立单人验收窗口，见[实施记录](../verification/2026-10-10-live-furniture-layout-implementation.md)。
- 交互规则沿用[实时编辑设计](2026-10-10-live-furniture-editing-design.md)及[入口设计](2026-10-10-official-furniture-layout-design.md#用户指定的布置入口)。独立试窗的几何和存档合同见[C0](2026-10-10-live-furniture-c0-contract.md)，不能直接作为普通房的几何合同。
- 实施获批后，已从家具来源建立独立 `codex/furniture-room-integration` 接入分支与 Worktree，并纳入批准的主线界面规范。保留两份已验收来源；共享入口、运行时与构建由唯一集成人整合，协作者按明确文件所有权实施。

界面采用 `main@2acb532` 的 `docs/desktop-ui-design-v0.1.md` v0.1：第 2 节暖白与棕色细强调、共同字体及语义资源；第 3 节固定必要操作与三段侧栏；第 4 节线性图标、中文提示、辅助名称及焦点/禁用状态；第 5 节在确有滚动内容时采用常驻细条与正确滚轮消费；第 6 节核对正式窗口尺寸、DPI、高对比和减少动画。共同 WPF 资源尚未迁移，接入只复用现有可用资源与所需最小组件，不借此批量改版。页面差异是已批准的实时逐操作提交、取消仅撤当前预览、平台直接删除，以及房内滚轮镜头；不套用外观编辑的整份草稿或配饰删除的两次确认。

## 已核实的接入约束

| 当前事实 | 接入要求 |
|---|---|
| `FurnitureLayoutSceneSession` 构造器自行 Create world、Add 团子，并设置固定试窗边界 | 不能直接嵌入该 session 或打开原试窗；提取提交协调逻辑，接到现有 `DesktopPhysicsScene` 持有的世界 |
| `DangoApplicationHost.LocalRoom` 的普通房、门廊与桌宠复用 session/runtime，`HostFrameScheduler` 管理唯一帧 owner | 编辑只切操作层；不得新增物理 timer、世界、实体或隐藏 Step |
| `LocalRoomSceneView` 的普通房逻辑尺寸为 2160×360，真实左右边界各缩进 24；地面视觉上沿抬高 10 | 保留房间、碰撞地面和镜头；布局采用房间坐标，不能套用试窗 X `[-8,8]` 或把视觉地面当碰撞面 |
| `DesktopPhysicsScene.ToWorld/ToHost` 使用当前 origin；现有基准身体映射为横向 80、纵向 60 | 固定房间内的坐标合同，显式转换到 native；相机、DPI、窗口大小及换场 origin 不写进布局 |
| `RehostSelectedEntityAt` 需要 TranslateHorizontal，而 native 在平台存在时拒绝该操作 | 跨场景前必须在唯一 owner 边界卸载普通房平台；源场景恢复也须恢复正确布局 |
| 门廊现有 W 用于互动，房内 Esc 已打开菜单 | 新增 E 家具请求，保留 W；Esc 菜单增加布置动作，Esc 不直接进入编辑 |
| 试窗 schema 1 固定 `local-single-window` 与 `static-platform-p-v1` | 主程序使用专用场景标识、坐标和几何版本及文件命名空间；旧试窗文件保留，不隐式迁移 |
| 家具候选与主程序眼帽、步态、已佩戴配饰的实际组合尚未验收 | 能力检测和真实组合验证是接入门禁，不能只凭试窗通过启用入口 |

## 房间入口与编辑行为

门廊 E 针对当前可交互的本地普通房门提出布置请求。首次进入复用正常入房和健康首帧交接，只有目标房间、布局和真实团子都就绪后才打开侧栏。进入失败保留可操作的返回或重试入口；重复按键、失焦和迟到回调不能打开错误房间的编辑层。已有 W 入房行为保持。

房内 Esc 仍打开或收起房间菜单，菜单加入一个带名称与提示的家具图标。选中后关闭菜单并打开布置层。已在房间的团子不迁出、不自动挪位、不重建；身份、原生身体、速度、物理步和外观运行状态保持连续。

家具预览不参与真实碰撞。添加或移动只有确认后才提交，在物理步边界按最新身体形状复核；穿入时保留原家具和预览，正常相切允许。删除已选平台直接提交，清除旧支撑，让团子自然掉落。文件与 native 的提交顺序及结果不明处理沿用已验收合同，不把文件已保存等同于当前房间已应用。

本人手套操作同一团子，复用已验收的速度、拉力和释放限制，并通过普通房实际碰撞验证。方向键只微调预览，A/D、S、Space 在场景焦点下控制本人团子；图标、按钮和文本输入不穿透为跳跃或提交。右键拖动编辑视角，退出编辑恢复进入前的镜头模式与视距；镜头变化不得改家具逻辑坐标或真实地面。

Esc 先由控件或下拉处理；场景手势或未确认预览存在时，先取消该手势或预览，其后沿原菜单语义处理。退出图标结束编辑并释放抓取，不回滚已发布操作。失焦、捕获丢失、切工具、隐藏与 DPI 变化都清持续输入和抓取。进入编辑不持续暂停房内物理；故障停止和隐藏继续遵循现有运行规则。

## 本地房间身份与保存

本轮只有一个主程序本地普通房，使用显式、稳定的本地房间 key 和独立布局文件。未来账号及在线房间采用独立身份命名空间；本地 key 不作为服务器 roomId，不声明布局跟随账号或跨机器恢复。

可编辑判断至少包括本地普通房上下文、正确房间目标、健康运行时、唯一 owner、完整 Furniture ABI 1 和有效可写的布局状态。门可见、登录状态、访客或管理角色、`localRoomSelected` 都不能单独授予编辑能力。桌宠及在线入口不建立本地家具预览或修改文件。未来在线权限由服务端另行接入。

正式普通房的布局合同在第一批冻结：采用稳定房间逻辑坐标，锚点以房间内 X 与距真实地面的高度表示，再经固定房间映射转换当前 native origin，保留现有房间大小、默认平台尺寸与材质。2160×360 是逻辑 Surface；绘制与鼠标逆变换须共同使用实际 `LocalGroundY/GroundY` 及 `NeutralBodyGroundOffset` 的对齐，不能把 360 永久当真实地面，或将保存锚点直接当 native 坐标。根据现有入房点及身体包络设置固定出生保护区，避免重入时平台遮挡团子；保护区以外，确认必须检查当前真实身体。保护区不得跟随相机，也不得为适配存档临时移动团子。

新布局记录明确的场景、坐标、几何和预设版本、平台实例、锚点、layoutVersion 与 operationId。保留 64 KiB、有限值、0/1 件、严格字段、坏文件保护、独占 lease、原子文件替换和重复请求规则。具体版本号在第一批冻结，不改写旧试窗 schema 的含义。布局不保存团子运动、相机、手套或运行 token。

仅缺家具可选能力且确认布局为空时，普通房可沿原玩法进入，布置入口明确不可用，不写布局或演示假的碰撞。已有非空布局而不能真实载入家具时，阻止目标房间就绪，保留返回与重试，不进入无平台的空房冒充恢复成功。坏文件、暂时不可读、版本不支持和另一进程争用时保留原件并禁用写入；不能覆盖为空布局。临时文件不参与启动加载。

## 换场景与故障恢复

同一普通房的编辑开关不走房间 handoff。隐藏或最小化沿原有策略保留当前平台和会话；恢复时不重复创建平台、实体或 owner，不补算隐藏时间。

回门廊、回首页或进入桌宠前，先完成正在提交操作的结果核对，再取消未确认预览和抓取，在 owner 边界卸载普通房真实平台并读取一致帧确认，然后执行既有换场。卸载只改变运行绑定，不写布局、不增加文件版本、不删除存档。

重入普通房按正常入房规则转换坐标、设置边界并载入已提交布局，在健康目标首帧前确认家具与团子来自同一世界。换场失败恢复源场景时也恢复源布局绑定；不能恢复一个只有团子的空房副本，或让平台留在门廊、首页、桌宠。恢复无法可靠确认时进入明确故障状态，不继续损坏的物理世界。

## 验收与交付

自动验证覆盖受影响 Core、Desktop、Physics、native、真实文件与进程重启；在已有试窗门禁之外增加主程序世界、坐标、入口和往返反例。真实候选必须使用主程序导航与 `LocalRoomWindow`，原 JointReview 窗口不能替代接入验收。

Windows 验收逐项覆盖门廊 E、房内 Esc、预览确认、实时拒绝、接触删除、本人手套、右键镜头、输入焦点、×隐藏/托盘恢复、回门廊/重入和重启恢复；100% 与 150% DPI 或对应设备矩阵、高对比和减少动画分别记录。至少 50 次编辑开关与往返循环、10 分钟有效运行观察，并记录提交耗时、资源回收和已有性能门禁。新状态绘制频率不冒充应用 composition FPS；既有 59 FPS 门禁独立，不因家具观察通过而关闭。

最终启动隔离主程序候选供用户在实际普通房验收。无法执行的真实输入、设备或性能项标记未验证；静态、集成、实时、人工及 Git 状态分别记录。计划批准后可在本轮范围内实现、验证和创建本地提交；合并 main、推送、部署、日常安装更新、生产 DLL 替换及删除数据或 Worktree 仍需单独授权。

本计划最初交付时仅包含方案；随后用户“开始实现”授权本轮 I0–I4 编码、隔离构建、验证与真实普通房候选窗口。实现分支为 `codex/furniture-room-integration`，基线 `4765435e` 已包含家具来源与批准的主线界面规范。原独立窗口的人工通过记录保持原范围，不能替代本轮主程序验收。
