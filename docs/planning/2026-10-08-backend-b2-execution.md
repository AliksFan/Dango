# B2 团子配置关联与本地存档

状态：用户“继续”授权，实施中、未验收。承接邮箱首期设计的 B2，不扩大到 B3 房间管理、B4 正式准入或 B5 登录／选择界面。

## 数据合同与范围

服务端 `GET /api/v1/me/pet` 只返回本人 UserId、稳定 PetId、配置版本和七字段 Schema 3；`PATCH /api/v1/me/pet/configuration` 只接收 expectedVersion 与 configuration。身份来自有效会话，输入不能指定他人／Pet／房间；写事务重新检查账号和会话，仅修改配置及版本，不改变房间、成员、坐标、睡眠或控制代际。读取持久配置也严格校验，不自动建 Pet 或用默认外观覆盖异常值。复用 B0 的 configuration_version，不需要新迁移。

客户端首次关联／重新选择前读取云端与本地，选择之前不覆盖。覆盖本地或 PATCH 之前将两份原数据持久归档：本地原字节与是否缺文件、规范配置，云端原配置／版本、服务端来源、UserId 与 PetId；不保存 Cookie、密码、继续秘密。归档失败阻止选择；仅本机归档，不承诺设备丢失后恢复旧云端。接口／编排与 UI 分开，B5 再呈现选择。

响应丢失只以原 expectedVersion 重试；409 后读取当前快照。语义匹配时只确认当前状态达目标，不认定原请求成功；不同则保留两份数据和冲突，不自动改版本覆盖。归档或本地保存中断时原文件保留，重启不自动重新 PATCH。

本地房间独立 Schema 1，保存普通房／桌宠房的本地 ID、类型、固定现有模板、逻辑位置和相机模式／缩放／手动位置，不保存动作、速度、拖动、句柄、屏幕内容或输入历史。房间位置与在线归属独立。启动不要求服务器；恢复位置越界使用明确安全入场位置，不恢复瞬时动作。存档损坏／未知版本保护原文件，错误明确可重试，写失败继续本次游玩。

## 所有权与执行

根拥有 Protocol 数据合同、根配置、桌面宿主／相机接入、文件转换、基线和集成。复用已附加且干净的独立 Worktree，分别创建 B2 分支：服务器 Pet 用例与数据库／HTTP测试；独立本地文件／房间存档模块与故障门禁；正式 Pet HTTP 与配置选择编排／归档及测试。先提交共享合同，然后开始模块写入，不同时修改同一分支。

## 能失败的验收

- 同版本两个独立连接只允许一个配置变更；提交前故障／会话撤销／到期均回滚；PetId 和完整房间状态不变。
- 非本人／伪造字段、未知 Schema／字段、异常参数／大小拒绝；云端损坏不回填默认值。
- 两份原数据先落盘，归档失败／本地磁盘失败／外部文件变化／账号或服务端变化均不误覆盖；丢响应及其他设备抢先更新均保留冲突。
- 本地存档往返、损坏／未知版本／旧文件保护、原子写中断、离线加载；保存有限稳定数据，不发任何位置网络请求。
- 接入现有普通房和桌宠房的实际停止／重启路径；自动门禁不能代替 Windows 人工显示验收，保留原 DLL。

数据验证仅复用先前明确批准的独立 `run20261008b0`／`dango_backend_b0` 与虚构账号，B2 无迁移／重置／删除／恢复，不使用实际本地用户存档；测试文件在独立忽略目录。实例按既有精确工具启动／停止，保留所有数据。真实 SMTP、灾备恢复、main、推送、部署、安装和 DLL 替换仍不包含。
