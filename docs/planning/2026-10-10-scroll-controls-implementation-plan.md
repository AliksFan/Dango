# 桌面滚动与参数滑条实施计划

日期：2026-10-10。状态：规范阶段的实施计划，生产实施待授权。依据：[桌面界面规范](../desktop-ui-design-v0.1.md)。

用户要求所有可滚动页面更顺滑，侧边滚动条与参数滑条更细、符合现有配色，并已选择“常驻细条”。浏览器样板是外观与手感起点，真实 Windows 页面卡顿尚未复现；不得直接宣布动画可以解决拖动卡顿。

## 1. 实施范围

在获准生产实施后，统一桌面功能页面的滚动条与参数滑条，处理真实卡顿的最小根因。首页、捏脸／配饰参数、配饰图库、设置及图片编辑参数区使用共同资源；图片画布保留滚轮缩放，房间游戏镜头保留现有输入合同。

不改变物理、配饰材料映射、参数范围、草稿事务、数据库或同步功能。共享主题只抽取本任务需要的控件资源，不连带重做全部页面。保留日常安装、用户设置和正式 DLL，验证使用隔离设置及候选输出。

## 2. 顺序与停止点

### S0 复现并记录原版

先在原候选真实窗口分别观察滚轮、拖动滚动条、拖动参数滑条。记录设备、系统缩放、窗口尺寸、页签与素材数量；图库分别检查首次滚动和重复滚动，预览静止与运动分别观察。

用必要的临时诊断记录输入至显示延迟、滚动位置、显示长帧、UI Dispatcher 长任务和缩略图读盘／解码耗时。仅记录匿名性能指标，不记录原始个人输入、图片内容、桌面或凭据。区分默认滚轮步进与真实 UI 阻塞，检查嵌套区域是否吞输入。

停止点：不能复现用户描述时，报告具体已试工况和缺少的复现条件；不猜根因，不通过改测试或加动画掩盖问题。

### S1 共同控件和输入行为

在现有能力内建立共同 WPF 资源与模板，给首页和独立配饰窗口使用同一来源。视觉从常驻细条样板起步：滚动条可见 6 DIP／命中 16 DIP，参数轨道 3 DIP／圆形滑块 12 DIP，状态使用既有暖棕资源。数值均需正式控件校准。

滚轮使用有界平滑目标更新，反向及时响应；滚动条与参数拖动直接映射，释放即停。保留系统减少动画、高对比、鼠标捕获、键盘和辅助操作。滑条值经相同草稿路径更新，不给真实参数加缓动。

嵌套区域优先由最近可滚动容器消费位移，到边界后只把未消费余量交给祖先，同一位移不重复执行。图片画布缩放、菜单及编辑控件的自身输入优先。主题实现不得改变现有帧 owner 或物理推进。

### S2 按根因修复卡顿

仅处理 S0 有证据的瓶颈。如果证明同步图片处理阻塞 UI，才调整其缓存或工作调度；如果证明输入路由错误，才修路由。保持原素材、透明画布、预览行为和画质，不通过减少内容或停止预览降低负载。

停止点：缺少证据证明改动对应原症状时，不扩展重构范围。共享主题与性能修复分别可审查。

### S3 验证与人工验收

先跑受影响的控件、布局和草稿回归，再在同设备同工况复测真实输入与性能。报告原始延迟分布、长帧及卡顿出现条件，性能阈值在 S0 明确设备与工况后确定，不预填已通过结论。

按最小正式窗口、常用横向与纵向窗口检查固定操作区、标签、数值和滚动范围。DPI、高对比、减少动画、快速反向、拖出窗口和失焦分别验证；缺少设备或权限的项标记未验证。

用户在候选真实窗口中确认滚动手感和控件观感后，才标记对应人工验收通过。样板、截图、构建及局部自动检查不替代该确认。

## 3. 能失败的门禁

| 门禁 | 必须捕获的错误 |
|---|---|
| 滚轮平滑及停止 | 没有中间位置、迟到补播、过冲、反向后仍继续原方向 |
| 直接拖动 | 显示位置滞后于指针、指针离开细条就中断、松手后继续移动、松手／失焦后仍持有捕获 |
| 嵌套边界 | 两层重复消费同一位移、内层尚可滚动却提前转交、到边界后吞掉未消费余量 |
| 输入例外 | 图片画布滚轮变成页面滚动、编辑输入触发团子动作 |
| 参数真实结果 | 滑条或辅助状态已改变而草稿未改变，应用重载／取消结果错误 |
| 主题状态与布局 | 独立窗口颜色漂移、选中悬停丢失、命中区覆盖内容、最小窗口裁切 |
| 减少动画与高对比 | 关闭动画后仍缓动、焦点或滑块不可辨识 |
| 原症状性能 | 同工况仍出现原长帧／阻塞，或靠减少素材、预览、画质伪造改善 |

门禁使用真实输入路径和显示位置，不能只断言模板中存在某个资源或调用 `ScrollToBottom`。旧版证据、失败反例与修复后结果分别保存，不改写旧记录。

## 4. 当前状态

S0–S3 均尚未执行。已完成的是用户方向选择、浏览器组件样板和规范／计划落地。生产修改、生产人工验收、提交、合并、推送、安装、部署和 DLL 操作按各自授权及实际结果报告；本计划不自动授权这些操作。
