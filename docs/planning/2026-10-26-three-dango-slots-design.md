# 3 个团子栏位与首页选择专项设计

日期：2026-10-26。状态：**设计草案，待审阅；尚未修改生产行为或执行存档迁移。**

本轮任务是核实单团子实现，形成可供实施依据的栏位设计。用户已允许推进栏位功能，以下“已确定”来自本专项交接；“建议”是本轮提出的具体规则，不能当成已经批准的设计或已经实现的功能。设计确认后再制定可验证的实施计划。

## 1. 目标、授权与范围

### 1.1 已确定的目标

- 每人固定 3 个栏位，可以逐只创建，最多保存 3 只独立团子，不要求一次建满。
- 同时最多 1 只实际出场；从首页选择。首页预览、当前选择、场景实际出场是不同状态。
- 每只具有稳定身份；名字、基础外观、当前穿戴及已有个体资料相互隔离。改名、捏脸、换装不改变身份。
- 创建使用“草稿 → 确认保存并占栏”；取消不占栏，不改变原选择。建议创建成功后选中新团子并留在首页。
- 主路径为：首页选 A → A 出场 → 返回首页并收回 A → 选 B → B 出场。不能留下两只出场，也不能把选中变化报告成实际出场切换成功。
- 未出场团子保留资料、暂停自主活动，没有未使用惩罚。素材库及穿搭资源可共享，当前穿戴逐只保存；本机显示与操作设置不变成个体性格。
- 旧用户完整承接当前团子到一个栏位，另外两栏为空；保留原存档，不复制成三只。
- 删除、重建、恢复策略未确定。本专项本轮不删除、重置真实资料，也不增加归档或隐藏栏位。

### 1.2 明确排除

不涉及本地 AI／小模型、性格或情绪计算、习惯学习、行为动作、桌面活动空间、窗口互动、家具或其他桌宠体验设计；不读取原对话的混合讨论文档来扩展范围。

不增加房间额度或容量，不做账号、多设备或多人同步实施。仅在第 9 节记录多身份对未来房间归属的必要约束。不借本专项迁移配饰编辑器、物理内核或全局主题。

本轮允许只读核查及专项文档、本地文档提交；不合入 `main`、推送、部署、修改日常安装或日常存档。

## 3. 建议的身份与数据归属

### 3.1 栏位不等于身份

建议以随机生成、持久保存的 `DangoId` 作为团子身份，不采用名字、栏位序号、列表下标或物理实体序号。栏位仅有固定位置 1、2、3，每项为空或引用一个 DangoId；同一个身份不能占两个栏位，身份记录与已占栏位一一对应，不保留第四只隐藏团子。

名字建议为 1–24 个 Unicode 文本元素，首尾空白去除，拒绝空名、控制字符及换行；允许重名，界面以头像、栏位位置和明确选中态区分。改名只改变显示名，不重建身份。新草稿默认名为对应位置的“团子 1／2／3”，旧档承接建议名为“团子”，均可改名；这些是新默认规则，不是旧档已有名字的事实。

本地数据根代表当前本地资料集合，不伪造账号身份。现有房间 `ProfileId` 继续表示房间目录的本地主体，原值不变；不得把它改成当前 DangoId，也不为每只复制房间目录。未来账号映射另案确认。

### 3.2 归属表

| 数据 | 建议归属与规则 |
|---|---|
| 名字、身体／眼睛颜色、眼睛布局、已有身体大小／柔软度／落地体型及物理模型版本 | DangoId；沿用现有合法范围、版本校验和真实预览确认，不新增参数 |
| 当前穿戴、图层和排序、每件的尺寸／角度／附着及现有物理参数 | DangoId；A 应用换装不改变 B 的已保存配置 |
| 配饰图片与可复用资源条目 | 资料集合共享；同一图片可以被多只引用，资源 ID 不能当成团子 ID |
| 已有未佩戴配饰及其编辑参数 | 迁移时完整保留为共享资源模板；旧团子同时保留其原有逐项参数，不能只迁移正在穿的部分 |
| 房间目录、房主／权限、房间额度、家具布局 | 维持既有主体／RoomId 归属，不随选择切换或按团子复制 |
| 普通房恢复位置 | 设备＋RoomId＋DangoId；只恢复该团子的安全落点，仍按当前身体轮廓和布局复核 |
| 房间相机、窗口位置、显示模式、DPI、辅助与操作设置 | 设备／设备＋RoomId；切换团子不复制或重置，也不作为性格 |
| 当前首页选择 | 本机导航偏好，引用现有 DangoId；不表示入房或云端归属 |
| 当前实际出场与转场 token | 仅运行会话；不能用上次选中或旧检查点推断重启后已经出场 |
| 按键、拖动、速度、临时表情比较、当前物理节点等 | 活动会话；切换时释放，不能写入另一只的资料 |

尚未实现的个体状态只要求未来设计明确归属，不新增性格、情绪、成长、活动计时、惩罚等占位字段。

### 3.3 共享资源与独立穿戴的最小分离

不能给每只简单复用同一个可变 `AccessorySettingsSession`，也不能仅复制整份库三次来宣称共享。

建议把现有条目分成“共享模板”与“团子穿戴快照”：模板保留条目 ID、名称、图片引用及现有起始参数；穿戴快照保留模板引用和这只团子的完整参数／图片引用。新团子默认无穿戴，选择共享模板时才把参数复制进自己的草稿。已有团子未佩戴条目的个体参数也保留，避免脱下再穿丢失调整。

对某只调整尺寸、支点、图层、排序、柔软度等只改它的草稿；应用仅提交它的配置。更换图片产生新的内容引用，已保存的其他团子继续引用原图，不能以可变模板更新隐式改穿戴。图库使用当前团子的“已佩戴／未佩戴”分组，不显示另一只的穿戴为当前穿戴。

导入及取消维持现有资源预算和草稿合同。共享模板删除仍是配饰模块的独立操作，沿用原两次确认；若删除会使另一只保存的配置失效，则拒绝并用文字指出被引用，不进行级联脱下或清空。本专项不扩展素材清理；仍被引用的图片必须保留。此处仅定义多身份兼容边界，具体适配需列入后续实施计划。

## 4. 首页与编辑流程建议

### 4.1 首页布局

建议在顶部导航下方、中央预览舞台以外，放置一行 3 个紧凑头像位。三个位置始终可见，不横向滚动，不把它们当成三只运行中的实体。

```text
 Dango                                      设置等现有导航
                [头像 · 团子 1 ✓] [头像 · 团子 2] [+ 创建]

                         现有入场入口
                换装       中央正常预览       捏脸
                             当前名字  改名
                  选中／保存失败等必要反馈
```

这只是结构示意，不是 WPF 已验证布局。建议头像 40 DIP、单项宽 80–96 DIP、间距 8 DIP；名字单行省略，完整名字在提示与辅助名称中可读。空位用线性加号＋“创建”。卡片是对象选择控件，不强套 32 DIP 动作按钮；局部改名用图标＋短文字，紧凑时才用图标。已选中项用棕色细边界及可辨识勾选状态，选中不能只靠颜色。

头像由已保存基础外观和穿戴静态生成，草稿不提前写入头像；缩略图失败用中性占位并保留名字／选择入口，不能换成别只头像。头像缓存键至少包含 DangoId 与配置修订；缓存不是档案真相，不增加三套动画／物理循环。

同一宿主尺寸下：首页、捏脸、换装继续使用相同正常预览尺度和接地基线；头像行在三态中预留同样高度，编辑时保持位置并禁用切换／创建，显示当前对象。不能通过缩小团子、改变身体大小参数或挪动阴影腾空间。纵向参数独立滚动，应用／取消仍在团子右下，必要失败反馈和返回动作不滚走。短窗口优先使用原有合理溢出路径，正式尺寸下必须实测控件可达。

以正式宿主的 1080p 横向、1440p 横向、纵向预设及实际支持的最小窗口为验收对象；源码预设的横向物理像素目标、纵向逻辑下限和持久设置校验下限含义不同，不能只读 XAML 的初始 MinWidth 就当正式下限。实施时依据 [ControlCenterWindowSettingsStore](../../src/Dango.Desktop/AppShell/ControlCenter/ControlCenterWindowSettingsStore.cs) 与 [窗口宿主](../../src/Dango.Desktop/AppShell/ControlCenter/ControlCenterWindow.xaml.cs) 冻结测试矩阵。

### 4.2 首页各状态

| 状态 | 展示与可执行动作 |
|---|---|
| 没有团子 | 3 个空位；中央显示简短创建引导，无默认真实团子，捏脸／换装／入场禁用 |
| 已选择、没有出场 | 当前保存版本在中央预览；可改名、捏脸、换装、从既有入口进门廊 |
| 正在准备选择 | 原选择保留，候选项显示准备中；重复操作不产生第二份提交；失败仍落在原选择 |
| 创建或编辑中 | 头像行保留位置，切换／创建禁用；编辑区明确当前名字，原有草稿操作可达 |
| 有团子在场景（含隐藏／最小化） | 首页保留“某某在房间中”及真实恢复／返回入口；头像可显示但不允许切换、创建或改名／编辑，不再建立中央活动预览 |
| 保存结果待核对或资料受保护 | 必要文字和重新读取入口固定可见；阻止会改变当前身份／资料的动作，不把安全默认值保存成旧团子 |

这里选择“场景在运行时先返回再选择”的方案。暂不提供在外出首页排队选择 B、自动收回 A 或一键热替换，以免新增未获批的跨场景切换语义。

### 4.3 创建

1. 只有没有实际出场、没有转场／待核对写入时可点空位。记住原 SelectedDangoId 与目标空栏位，生成本次创建操作 ID 及草稿 DangoId。
2. 建议复用现有捏脸控件作为“创建”子模式：名字＋已实现基础外观，默认外观起步、无穿戴，不复制当前团子。中央显示草稿，原选择仍未提交；不允许入房。换装在创建保存后使用既有入口，避免在创建事务中改共享素材库。
3. “创建”按钮必须保留文字；它提交完整创建草稿，而不是执行普通编辑的“应用”。身体配置必须先经当前草稿、当前预览版本的真实确认；单纯写按钮可点击不能越过此门禁。
4. 确认时重新校验栏位仍空、总数不超过 3、名字和参数合法。身份记录、占栏与选中一起提交；确认写入成功后，头像才出现，选中新团子并留首页。
5. 明确未提交：保留可重试草稿，原选择和空栏不变；取消、Esc、关闭、隐藏或离开创建模式均丢弃未提交草稿，恢复原选择，不保存半只团子。不为取消的草稿建立常驻运行时或归档。
6. 写入结果不确定：不能当作取消成功、创建失败或再次生成另一只，进入第 7 节核对路径；仅确认“未提交”后才允许正常丢弃或重试。确认已提交则按同一次创建成功处理，不重复占栏。

创建已核实提交后，退出创建模式或绑定正常首页预览仍可能失败。此时明确显示“已创建，预览暂不可用”：新身份、占栏和持久选择均保留，禁止入场，提供重试该对象预览／返回安全页；不能落回未提交取消分支、偷偷恢复旧选择、删除新身份或再执行创建。正常首页预览恢复不应再次写入身份资料。

### 4.4 改名、捏脸与换装

改名建议使用首页当前名字旁的轻量编辑区，确认后只更新名字；取消保留旧名。失败保留输入并显示原因，身份不变。

进入捏脸或换装时捕获 DangoId、当前资料修订和会话 generation。参数请求、比较结果、弹窗回调及应用都验证该对象仍是本次编辑对象；不能只查询“现在选中的下标”后写回。不同对象的会话不能共享可变 Saved／Draft 状态。

保持原合同：参数即时预览，显式应用后才保存；复位只改当前草稿；取消、收起、离开或隐藏丢弃未应用内容并恢复当前对象已保存版本。编辑中不切换栏位，用户先应用或按现有取消路径回首页；不新增每只长期挂起草稿。正常写失败保留这只的草稿，可重试或明确取消；结果未知先核对，不能把未知提交当普通草稿取消。

保持设备焦点规则：普通选择按钮执行后焦点回预览；命名输入、参数、弹窗保留输入，不能触发团子移动或进门。切换清空旧按键／指针捕获；后台回调不激活窗口或抢别的应用焦点。头像控件遵守第 4.3 节现有控制中心焦点策略，辅助操作通过明确的选择动作完成，不另加数字键或占用游戏方向键。

## 5. 选择、预览与实际出场生命周期

### 5.1 三种状态及不变量

建议明确区分：

- `SelectedDangoId`：首页已完成选择的对象，可为空；本机持久导航偏好。
- `PreviewTarget`：已选择团子的已保存／编辑草稿，或创建草稿；临时状态，不能当作已出场。
- `ActiveDangoId`：实际交给门廊／房间活动会话的对象，最多一个。隐藏、最小化或只打开控制中心时仍然占用，不能视为空闲。

门廊沿用入场导航预览，不算第二个房间实体，但同样锁住该 DangoId；只能回到可选择的首页后换对象。转场准备中的目标尚未提交为成功出场，仍必须锁住对象并计入唯一会话约束。

核心不变量：可选择首页没有仍在运行或接收输入的房间实体／残余输入 owner；场景活动或转场锁存在时不改变 SelectedDangoId；所有场景参数来自锁定身份的已保存版本；非活动团子没有后台自主活动推进；头像和普通首页预览不形成第二只实际出场团子。已停止的可复用运行时对象可以保留，不为选择动作强制重建整个物理宿主。

不改变物理模块帧 owner、线程和生命周期。栏位协调者只发装配／暂停／解绑请求并等待确认，不能通过布局、刷新、选择事件自行推进物理。

### 5.2 首页 A → 首页 B 的选择事务

1. 确认目前处于可选择首页；无编辑草稿、活动／隐藏房间、门廊、转场及待核对保存。
2. 用当前目录修订读取 B 的名字、外观、穿戴及所需素材；验证身份和引用。先保留 A 的选中态，显示“正在准备 B”，不乐观换成 B 的名字配 A 的模型。
3. 清空 A 的输入和临时比较，暂停 A 预览；在既有预览 owner 内准备 B，不增加并发 owner。回调验证 DangoId、资料修订与操作 generation。
4. B 真实预览准备成功后保存选择偏好。明确保存成功才同时公布 B 的名字、勾选态、中央预览和操作目标。选中 B 的反馈只表示首页选择完成，未入房。
5. B 加载／预览／选择保存明确失败：回到 A；A 无法恢复时显示预览故障并禁用入场，SelectedDangoId 仍为 A，不拿 B 或默认团子冒充成功。无原选择时回到无可用选择状态。
6. 选择写入结果未知：先暂停选择和入场，按第 7 节核对实际持久选择；核对前不宣布 A／B 任一切换成功。

重新选择已选项是幂等无操作；快速重复点击由同一协调入口串行处理，转场中不排队自动切到下一只。被取消或过期的异步回调不能恢复 A、覆盖 B 或把新草稿写入旧身份。

### 5.3 A 出场 → 返回首页 → B 出场

```text
可选择首页(A)
    → 门廊(A，锁定) → 准备入房(A) → 房间活动／隐藏(A)
    → 既有返回房门(A，锁定)
    → 回首页并完成收回确认(A，无活动房间 owner)
    → 可选择首页(B) → 门廊(B，锁定) → 准备入房(B) → 房间活动(B)
```

“返回首页并收回”建议复用既有回房门与门廊回首页路径，不更改房门菜单、Esc 或托盘已有含义。必须确认旧房间停止输入／推进、释放呈现及家具绑定，门廊安全交接结束，首页准备完成后，才释放身份锁并允许选 B。开控制中心、隐藏窗口和进入设置不等于完成收回；普通房解除绑定失败时保留 A 的锁和真实错误。

入房时捕获 `(DangoId, SavedRevision, RoomId, generation)`。准备阶段只使用该对象已保存配置，当前对象无法确认则拒绝；沿用目标场景健康首帧及桌宠双表面就绪门禁，确认后才报告实际出场成功、开放输入并收起来源。不能仅看 `Show` 或在首页标记选中就报告成功。

为保持单一正式路径，现有门廊与房间装配入口统一接收锁定身份的不可变快照，不允许仍有入口从全局单团子字段装配。

### 5.4 失败恢复矩阵

| 失败点 | 保留状态与恢复动作 | 禁止结果 |
|---|---|---|
| 创建已提交、正常首页预览绑定失败 | 新团子已创建并占栏、选择仍为新身份；显示预览故障并禁用入场，可重试预览 | 假称取消未占栏、自动改回旧选择或再次创建 |
| B 资料或必需配置校验失败 | A 的持久选择不变；展示 B 不可用并允许返回／重读 | 用 A 外观显示 B 名字，自动覆盖 B 为默认值 |
| 单张配饰缩略图／图片不可显示 | 沿用现有隔离与警告，保留参数及引用；明确显示缺图。只有确认是可降级素材错误才继续，未知配置版本不得按缺图降级 | 静默删除穿戴、把默认图写回原配置 |
| 收回 A 时解绑或停止确认失败 | A 保持活动或故障锁；保留恢复 A、重试返回入口 | 解锁 B 并让两只同时运行 |
| A 检查点明确未保存、但停止和解绑已确认 | 保留旧落点并提示“位置未保存”；可继续回首页。资料保存和停止确认不是同一结果 | 把停止成功冒充检查点已保存 |
| 检查点写入结果未知／写任务未结束 | 核对或等待所属任务完成；必要时保留故障锁，不让后续 B 写入旧任务目标 | 旧 A 保存回调写到 B 名下 |
| B 入房／健康首帧失败 | B 仍为首页当前选择，实际出场未成功；退回安全首页／门廊或明确故障状态，保留重试入口 | 自动换回 A 出场、自动复制团子、宣称 B 已入房 |
| 快速操作、超时、过期回调 | generation 失效后忽略；当前已提交身份和 owner 不变 | 旧成功帧给新身份解锁，旧失败解绑新场景 |
| 进程崩溃或正常退出后重启 | 从最后已提交资料与选择回首页；没有实际出场，手动进门廊 | 按上次选择自动生成房间实体，后台补算未选中团子的活动 |

## 6. 保存结构与旧档承接建议

### 6.1 存储边界

建议本地先采用一个版本化的团子目录文档，容纳固定 3 栏映射、最多 3 个个体记录、共享配饰模板、当前本机选择和操作修订信息；图片继续内容寻址存放。单个文档可使创建的“身份＋占栏＋选中”成为一次发布，不引入数据库或跨文件分布式事务。

建议相对路径为 `dangos/roster.json`；确切序列化类型与版本号在实施计划中冻结，不擅改现有外观和配饰内部版本。目录至少包含：

| 必要内容 | 用途 |
|---|---|
| SchemaVersion、Revision、LastOperationId | 格式校验、预期版本写入、结果不确定时核对同一次操作 |
| 固定长度 3 的栏位映射 | 限定容量，禁止重复 ID、越界及悬空记录 |
| 每个 DangoId 的名字、已保存外观与穿戴参数 | 个体资料，不能混入运行节点或未应用草稿 |
| 共享配饰资源模板及现有素材引用 | 保留原库，支持独立穿戴；沿用现有资源上限 |
| SelectedDangoId | 本机偏好；必须为空或指向已占栏位。存在团子而引用失效时显示目录错误，不静默改存档 |
| 已完成旧档承接的来源摘要／身份映射 | 防止重试复制旧团子；不记录真实内容、账号或绝对路径 |

名字、外观应用和换装应用仍是各自明确操作；即使存于同一目录文档，也只能用当前快照合并目标字段，不顺带提交另一组未应用草稿。写入通过统一仓储串行／加锁、校验预期修订，以临时文件写入、刷新、校验和原子发布完成；不能只把原来的全局路径换个目录就绕过校验。

素材资产先完成验证和可读性确认，最后发布引用它的目录；失败后未引用的临时资产不构成已创建团子。不得为此次切换删除仍被任何保存配置引用的图片。

首次初始化也必须有持久的保护顺序：确认无新目录、无初始化意图或发布记录后，先写入并核实初始化意图（操作 ID、目标身份映射／空目录、候选摘要及来源摘要），再发布目录；意图是保护记录，完成后仍保留。纯新用户的空目录与旧用户承接走同一协议，空目录核实可用后才允许第一次创建。只要已有初始化意图／发布记录而目录缺失，不论标记是否写成“完成”，都进入保护／待核对状态，不能按新用户重新初始化或重新导入。

若意图与已存在目录的操作及内容一致，可核实并完成同一次初始化；意图冲突、目录不匹配或目录缺失且无法证明提交结果时，保留现场，只提供重读和明确故障说明，后续恢复须明确目标。中断发生在意图已写、目录尚未发布时，也不能为了继续使用而猜测重建。不得留下“目录已用过、但还没有任何持久保护记录”的时间窗；这项规则同时覆盖新用户与旧档承接，而非只保护迁移用户。

### 6.2 旧用户承接

建议首次在候选明确数据根启用新模型时，执行可重试的一次承接；后续实际启用必须先通过隔离副本验证，不能在本轮操作日常存档。

1. 新目录未发布时，检查已知旧文件的存在、版本与保护状态。存在旧 `appearance.json`／`accessories.json`，或存在旧设置且需从中承接兼容帽型时，视为旧资料；不能因未手动保存过外观就将原默认团子丢掉。纯新数据根不自动创建团子，初始 3 空栏。
2. 读取现有受支持迁移结果，但保留全部原文件。完整承接旧外观的现有参数、模型版本、配饰库（含未佩戴项）及穿戴状态到栏位 1 的单一 DangoId；另外两栏为空，选中栏位 1。不把读取错误后的安全默认值当作成功迁移。旧设置中与兼容帽型无关的设备字段不复制进团子。
3. 原格式需要真实身体预览再升级时，保留该要求与原版本来源。若新模型无法安全保存该旧表示，必须停在待承接状态并说明原因，不静默应用默认身体或提前宣称完整承接。
4. 按第 6.1 节先持久记录承接操作 ID、固定 DangoId 和来源相对路径／哈希，再发布完整目录；可核实的重试复用同一身份，未知结果保护。发布前复核来源未变化；变了则保留现场并重新核对，不能拼接两个时刻的外观与穿戴。
5. 发布后读取校验栏位、选择、全部资料及素材引用。新程序正常写入改走新目录，旧外观／配饰文件只作只读来源保留；不双写两个权威存档。已有房间目录及 `ProfileId`、RoomId、布局文件原样保留。
6. 旧格式普通房恢复点仅允许首次归属到承接的旧 DangoId；其他新团子不能继承该落点。采用独立的身份恢复点路径／版本承接，旧文件保留。相机属于设备＋房间，可沿用。
7. 新目录一旦发布，以新目录为准；保留首次发布前已持久化的初始化意图／承接保护记录。目录之后缺失、损坏或版本过新时进入保护状态，不能再把旧文件导入成“新第一只”。来源备份不是第四个可操作栏位，也不提供归档入口。

旧客户端回退只读得懂旧文件；其修改不会自动合并到新目录。实施与交付必须说明版本并存边界，检测到旧来源变化时告警并保护，不循环导入、不反向覆盖旧格式。本专项不设计全自动降级或双向兼容同步。

### 6.3 普通房恢复点

现有 `RoomResumeDocument` 合并保存位置与相机，只有房间所有者身份，必须在接入多团子前处理，不能把它直接应用于每个新选择。

建议将落点保存改为设备＋RoomId＋DangoId 作用域，携带对应外观／几何兼容信息，沿用布局版本和当前身体轮廓校验。相机继续设备＋RoomId 一份；两个文件各自报告保存结果，不把部分成功伪装为全部成功。不承诺保存每帧形变、速度或休眠求解器状态。

首次 B 入房没有 B 的恢复点时，使用既有安全入场位置；既有落点因身体或布局变化失效时也走真实安全回退。A 的记录保留，仅在 A 再次进入该房间时读取。家具和共享房间状态不因 A 换 B 重建；球等既有重入规则继续由房间模块负责。

所有异步检查点任务在捕获时固定 RoomId、DangoId、布局版本和操作 token；后续回调只更新对应对象的保存状态。收回时等待必要任务核对，不能在执行时查当前选择再决定保存目标。

## 7. 明确提交、失败与结果未知

建议仓储统一返回以下三种业务结果，并保持原件保护：

| 结果 | 上层行为 |
|---|---|
| 已提交并核实 | 发布新 Saved、栏位和选择；更新头像、反馈和允许动作 |
| 明确未提交 | 原文件与 Saved 不变；当前草稿可重试或取消；创建不占栏，选择仍是原对象 |
| 结果未知 | 保留操作 ID、前后修订及候选摘要；锁住相关写入、选择和入场，读取并核对，不显示成功或重新创建 |

未知核对读到同一操作、候选修订及合法完整内容时按成功处理；确认仍是前一版本且没有该操作时才允许原操作重试／取消；读到另一合法新修订则报冲突并重载，不覆盖；无法确认则继续保护并提供重读／返回安全页入口。仅靠“抛异常”无法判断原子替换是否已经生效。

损坏、重复字段／身份、超过容量、悬空引用、未来版本和已发布目录丢失不得自动恢复成空目录或默认三只。可以展示最后已确认的只读资料和错误；没有可信数据时显示不可用，不假造成功预览。备份后的恢复、重建或重置涉及用户资料，须另行明确目标与授权，本专项不自动调用旧全局“备份并恢复默认”按钮覆盖整份多团子目录。

正常应用失败保留可用草稿；进程重启只恢复已提交资料，不承诺草稿跨重启恢复。重试与取消按钮文案必须区分“未提交”与“待核对”，遵循界面规范第 4.2 节。

## 8. 产品接入与旧路边界

按[开发工作流 v0.1 第 13 节](../development-workflow-v0.1.md#13-产品接入与结构维护)提出以下建议，具体代码拆分待设计确认后制定计划：

- 应用壳层集中装配团子仓储、当前对象会话和出场协调；首页仅展示快照／发命令。必要合同包括创建、选择、保存、收回、入场的输入、结果及生命周期，不为每个类强加接口。
- 复用外观／配饰现有校验和渲染数据类型，把储存目标和草稿所属身份显式传入。现有 `BindAppearance` 一次性绑定及全局只读 Host 字段不适合直接用于切换，需正式适配消费者；不能仅换 UI 后继续写全局单对象文件。
- 必须接通普通启动 → 新／旧资料加载 → 3 栏首页 → 创建／选择 → 捏脸／换装应用 → 门廊 → 普通房／桌宠房 → 回首页 → 换另一只 → 重启。实验入口与假成功状态不算接入。
- 新目录成为权威后，旧全局存储正常写路退役，仅保留明确的只读迁移来源。评审入口若仍有单对象用例，须隔离测试数据并说明其兼容合同，不能与正式产品争用日常资料。
- 不合入其他未提交专项，不依赖配饰新编辑器尚未合入的候选。若之后基线先集成该功能，应对新版本数据做兼容核对，而非在本轮自行复制实现或降级参数。

## 9. 重要取舍、待定事项与未来约束

| 事项 | 本轮建议与理由 | 替代方案／后果 |
|---|---|---|
| 选择位置 | 首页单行 3 头像位，编辑中禁用且保持占位 | 侧栏／大卡片占用正常预览空间；另开管理页增加简单切换路径 |
| 创建后落点 | 保存成功后选中新团子，留首页；不自动入房 | 保持原选择会让新对象的下一步不清晰；自动出场增加失败链 |
| 场景运行时切换 | 显示实际出场者，先沿原路径收回再切换 | 热替换需处理在途输入、家具绑定和首帧回滚，超出最小路径 |
| 删除／重建／恢复 | **待业务决定；建议第一批不提供入口**，满 3 栏后仍可编辑但不可创建。不得把编辑成默认外观当成新身份 | 永久删除涉及误删；软删除涉及占栏、期限、恢复容量及引用；无限归档变相增加栏位，均不自行实施 |
| 新目录保存 | 小规模本地资料采用单文档原子发布，图片外置；保留目标字段事务边界 | 每只分散多个文件需要额外协调创建／选中；引入数据库不符合目前最小充分实现 |
| 未出场状态 | 冻结个体活动，仅保留已有资料 | 离线补算或未使用扣分会新增机制，已排除 |

删除策略可以后置而不阻塞 0→1→2→3 的首批路径；若用户要求第一批可腾空栏位，须先补充删除目标、是否可恢复、期限、引用处理和旧身份再利用规则后批准，不能直接做清空按钮。恢复存档故障与恢复被删团子是两件事。

未来在线接入必须重新确认：用户级房间额度／角色／邀请仍归用户，不能每个 DangoId 额外获得一份；每只团子的零或一个有效房间、以及每人最多一只出场须由服务端一起裁定，客户端选择不能释放权威占位；旧在线睡眠团子是否要迁出、如何释放席位再换另一只，仍需独立决定。本地“收回”不代表修改服务端归属。本专项不把 3 栏解释成桌宠房新增三席，也不承诺多设备分别出场。

设计获批后只同步产品基线中单团子数量、身份／流程的受影响条款及必要导航；不将提案或本地实现写成账号同步、正式房间或阶段验收事实。当前文档不直接改写这些基线。

## 10. 可失败验收标准

以下全部是**后续实施的验收要求，本轮未执行功能验证**。使用虚构名字、隔离 `--data-root` 和合成／授权副本，不读写日常存档。测试必须断言对象、文件与实际 owner，不能仅检查按钮可点击或提示文字。

| 编号／层级 | 场景与通过条件 | 必须能抓到的错误 |
|---|---|---|
| A1 静态／存储 | 0／1／2／3 栏目录合法；第 4 只、重复 ID、悬空引用、未知版本、坏文件均拒绝且原件字节保留 | 隐藏第 4 只、自动清空重建、按名字合并身份 |
| A2 存储／集成 | 创建 A 后创建 B，分别取消及模拟写入失败；身份＋占栏＋选择全部提交或全部保持旧值 | 取消占栏、失败后先选中、双击多创建 |
| A3 故障注入 | 原子替换前失败／替换后确认前失败／重启重读，按操作 ID 核对，不重复创建或误报成功 | 异常一律未提交、重复生成 DangoId |
| A3a 集成／真实预览 | 创建已核实保存后，注入正常首页预览绑定失败；身份、占栏和选择仍在，重启一致，恢复预览不重复创建 | 将显示失败当创建取消、自动回旧选择、保存第二只 |
| A4 集成／重启 | A、B 使用明显不同名字、身体／眼睛参数和同素材的不同穿戴参数；反复切换、改名、捏脸、换装并重启逐项一致，ID 不变 | 数据串用、重名覆写、全局穿戴泄漏 |
| A5 集成 | A 草稿未应用时切页／收起／隐藏；槽位禁用；取消后再选 B，B 不获得 A 草稿；旧调色／身体确认回调被拒绝 | 延迟回调写到当前下标、草稿误保存 |
| A6 迁移／重启 | 受支持旧外观／配饰、未佩戴项、兼容帽型、房间目录／布局及恢复点承接；只出现 1 只，重试身份不变，旧文件哈希保持 | 只迁移已穿物品、克隆三只、改 ProfileId 或房间数 |
| A7 迁移失败 | 旧文件损坏／过新／来源变化／发布标记存在但目录丢失，停在保护状态；不得导入安全默认值 | 误认新用户、覆盖原件或再次导入 |
| A7a 初始化故障 | 新用户与旧用户分别在意图写入前后、目录发布前后及确认前中断；有意图但目录缺失时保护，有合法匹配目录时核对；不重新初始化 | 仅检查最终已发布标记、空目录首创漏保护、重试换身份 |
| A8 集成／真实场景 | A 出场，打开控制中心、隐藏／最小化时不能选 B；真正收回至首页后可选 B；每个时刻最多 1 个活动身份，预览／房间 owner 合同不变 | 控制中心一开就解锁、两个实体或两个帧 owner |
| A9 故障／真实场景 | 收回解绑失败、B 入房失败、首帧超时、桌宠仅一表面成功、过期回调均不报告出场成功；恢复入口始终可达 | Show 即成功、错身份解锁、失败隐藏错误页 |
| A10 存储／真实房间 | A、B 在同普通房保存不同合法落点；B 首入不读 A 的落点，B 体型改变后重验安全；相机／家具共享且不复制。延迟 A 检查点仍写 A | 仅以 RoomId 恢复、旧异步写入归 B、换人重建房间 |
| A11 资源／集成 | 同素材两只穿戴不同；改图／改参数只影响目标，另一只保存参数与图片引用不变；被其他团子引用的删除被拒绝 | 可变共享条目改坏另一只、级联删除 |
| A12 正式启动／重启 | 普通产品入口跑通第 8 节完整路径；无团子不出现假默认实体；重启只到首页，其他团子无后台活动或未使用惩罚 | 只在测试入口可用、自动进房或额外后台实例 |

界面逐项验收映射：

| 规范引用 | 本专项验收 |
