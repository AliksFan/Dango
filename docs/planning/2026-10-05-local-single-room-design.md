# 首个可用本地普通房：两层初始房间（设计修订）

日期：2026-10-05。用户已回复“通过”，确认**连续平坦地面层（碰撞前景）与纯色墙面层（无碰撞后景）**及普通房窗口／壁纸的视角方案，并补充普通滚轮调视距要求。本修订记录该设计批准及输入补充，替代之前的窗景／植物／日光装饰建议。隐藏策略、位置／恢复建议与实施计划仍待各自确认；当前只授权设计、必要只读代码核对和交互示意，未授权生产编码，不将 D0–D2 或 E2–E4 标为完成。

## 1. 基线与范围

已只读确认本地 `main@e2f4037ea2e56a222d41a5cd3085b21cee220565` 干净，门廊初版及门距修订已获确认，见[本地整合记录](../verification/2026-10-05-porch-local-main-integration.md)。本设计树显式从该提交建立；不从远端旧 main、team-integration 或 Phase 2A 开始。没有构建、启动房间服务、替换 native 或更新日常安装。

目标：首页 → 既有二维门廊 → **本地单人普通房新独立窗口** → 同一只真实团子活动 → 回门廊。常驻短标记“本地 · 单人”；进门是本机场景切换，不是准入成功，不属于多人免权限模式。未来桌宠房继续遵循壁纸层规则，无房不自动强制进入桌宠房。

不包含账号、权限、目录服务、联网、多人、持久化、家具编辑器、完整美术包、建房／邀请／好友页面、UGC、手机端或新物理引擎。首页与门廊行为继承[已批准入口设计](2026-10-04-room-entry-and-no-room-design.md)，本提案不重做它们。

## 2. 初始空间：墙面层＋连续地面层

采用二维侧视。环境只包含两层：

- **墙面层**：团子和地面后方的纯色墙，无碰撞，不阻挡移动或跳跃。首版用纯色填充表达。
- **地面层**：一条贯穿房间宽度的连续平坦地面，无台阶和缺口；其上沿就是唯一物理碰撞表面。呈现为连续平面，复用现有连续地面碰撞。

团子在这两层环境之上呈现，房门等窗口／托盘UI独立于环境。用户的参照只用于说明两层结构，不据此确定像素画风或引入地形编辑、放置／拆除、采集、生成、动态层修改及新地形引擎。

| 项目 | 拟定设计及理由 |
|---|---|
| 窗口 | 初始外框 **960 × 600 DIP**，最小 **640 × 420 DIP**，支持调整尺寸；非置顶、有任务栏入口。圆角 14 DIP、无系统边框、紧凑 36–40 DIP 标题栏。房间尺寸独立于首页三档物理像素预设；不重写预设或 DPI 策略。 |
| 标题栏 | 左上“小门＋房门”为返回入口；中间弱化“初始房间”；右侧“本地 · 单人”和 ×。保留拖动、边缘缩放和键盘可访问性，不增加常驻设置侧栏。 |
| 世界与镜头 | 使用固定逻辑世界，具体宽高仍为待调参建议。墙面层、地面层和团子共用世界投影。已通过的[视角方案](2026-10-05-room-view-mechanism-proposal.md)采用标准／近景／全景快捷入口、必要横向跟随及普通滚轮调视距，替代上一版“始终固定镜头”建议；门廊相机不重做。 |
| 地面与边界 | 连续地面的单一上沿对应物理碰撞表面；取消旧后墙／前景双地面视觉深度。左右仅保留不可见安全碰撞边界，不新增可见侧墙。物理地面与画面上沿须同源。 |
| 团子比例 | 标准视距候选目标为中性身体可见宽 **150–165 DIP（待真实调参验证）**，不再按每次窗口宽百分比自动放大。现有 `160 × 120` 是控件／帧包围框，不是可见身体宽。整个场景统一等比投影，保留现有软体参数、外观／帽子与实体；具体视角规则见独立提案。 |
| 美术与装饰 | 纯色墙面与连续地面。首版不设计家具、风景、窗景、植物、日光、场景门或装饰命中区。默认色仅为示意，可在视觉评审中调整。 |
| 最少交互 | 真实 A／D 走动、S 轻压、空格跳跃；左右安全边界和地面落地。返回只通过顶部房门、局部Esc或托盘；房内W暂不新增用途。 |
| 滚轮视距 | 普通滚轮向上拉近、向下拉远，无须Ctrl；保留三档快捷入口，允许档间倍率。首轮建议每标准刻度调整标准倍率的10个百分点，范围为当前全景至近景130%，同时受高度安全上限约束。窗口仅本房前台且指针位于场景时响应；壁纸仅桌面Shell前台、所有显示器均无可见全屏应用且指针位于目标显示器可交互背景时响应。UI滚动、图标、任务栏、菜单和指针下其他应用优先；每次事件和实际应用前复核，判定不明不响应。完整规则见视角方案。 |
| 待机 | 复用自主漫步、眨眼、左右看、打盹，手动操作优先。没有单独核实呼吸动画，不把自然物理回弹称为新增呼吸功能。 |

地面纯色从同一投影上沿向下填满视口，并横向延展到可见边缘，避免在全景或壁纸中画成悬浮矩形带；填色延展不扩大物理活动范围或增加碰撞面。

两层区分环境职责，但首版只需要连续地面和纯色背景。保持最简单的充分实现，不为以后可能编辑地形提前搭建完整资源、地形存储或生成系统。

## 3. 进门、返回与隐藏

门廊增加一个明确标记“本地单人”的本地入口描述。它与未来服务端目录分开，不伪造四门夹具为正式目录；其门宽 124、高 194、相邻净空 96 DIP 的已确认布局规则保持。靠近后 W 或点击入口进入，重复 W／点击只接受一次。

进门以目标画面实际就绪为准：源门廊先清输入、暂停自己的帧 owner，保留最后画面和取消／返回能力；目标宿主在受控暂存状态生成并应用有效首帧。确认当前进入代际、同一 runtime、目标表面、有效尺寸、有效身体帧和实际呈现后，才隐藏主控制界面并开放房间输入。`Show()` 返回、`Loaded`、单独 `ContentRendered`、旧 `LastFrame` 或任意 `CallbackCompleted` 均不能独自证明就绪。

首帧失败、无有效视口、物理错误或超时：释放目标 owner，清输入，恢复门廊表面／owner；界面提供“重试／回门廊”，不黑屏、不无限等待、不显示静态团子冒充成功。等待期间取消后，迟到的就绪信号必须失效。暂存方式及超时数值留给 L2 的真实 WPF 验证，不承诺完全隐藏窗口仍能渲染。

返回由左上房门、局部 Esc 或托盘“房门”走同一命令。场景内不保留门装饰或旧命中区。仅房间有焦点且输入控件／弹窗没有消费按键时响应 Esc；不注册全局键盘钩子。返回先清输入、暂停房间，再交回门廊；目标门廊有效画面准备完成后收起房间。返回失败时保留房间的可操作恢复入口，释放失败目标 owner，并可重试。约 320 ms 柔和转场，减少动画时跳过位移动画。回到进入这间房的门前，继续既有门廊导航；不强制回桌宠房、不误回首页。

× 只隐藏窗口，保留这次本地房间选择，不退出应用。**推荐隐藏期间暂停运行时、释放 owner**；恢复不追赶隐藏的时间，不重放旧输入。恢复也使用本次代际和目标有效首帧合同；恢复失败仍保留可操作的重试／房门入口，清理失败目标 owner，不能留在不可见死路。托盘首项随状态为“恢复房间／恢复画面”，第二项“房门”；现有设置／诊断／退出入口保持其真实语义。应用退出仍由既有明确退出命令完成。

### 待确认建议，不自动纳入实施

- 隐藏暂停是本轮推荐行为，需随设计确认；失焦仅清手动输入，窗口仍可见时可继续已有待机。
- **家具及风景装饰当前不设计**，仅交付纯色墙面／连续平坦地面这两个环境层；用户已明确该范围。
- **首版每次进房落在地面上的安全出生点**（按身体实际足迹和左右安全边界确定，具体位置待调参）。不新增房内跨往返位置保存；× 恢复可继续当前内存里的物理状态，因为未销毁会话，但这不是位置存档功能。
- **不新增重启恢复／自动进房**：重启沿用既有首页承接；房间布局、位置和选择均不新写持久化数据。正式账号房间恢复仍属 D0–D2。

## 4. 本地会话与未来权威接缝

现有 `RoomNavigationCoordinator.ConfirmAdmission` 明确要求外部确认，当前 `PorchSceneView.CanEnterRoom` 恒为 false。不得调用假确认、伪造 `AuthorityRoomSnapshot`、借 Phase 2A 临时票据实现本地房。

建议新增一个很小的本机场景呈现协调器与新的独立 `LocalRoomSceneWindow/View`。命名／API 均为建议，实施时以最简单充分结构为准：协调器只拥有当前视图、进入代际、目标宿主和帧就绪状态；场景描述只包含本地入口名、背景、地面／边界及出生点，不含权限、账号、容量或服务器归属。未来正式适配器先取得真实权威确认，再调用宿主准备／显示边界；本地模式不会自行成为授权策略。

复用唯一 `DesktopSceneSession`、`StackedDangoSceneRuntime` 和现有团子实体；`HostFrameScheduler` 保持唯一驱动门禁。任意交接允许短暂零 owner，禁止两个 owner。只将场景表面和实体位置交接给目标；不创建新团子，不设新逐帧循环，不用控制器位置改写掩盖真实物理边界。

只读代码事实：

- `DangoApplicationHost.cs:47–74,171` 创建并共享 session/runtime。
- `HostFrameScheduler.cs:105–142` 拒绝重复驱动并释放 owner；257 行 `CallbackCompleted` 在失败时也会触发，不能当 ready。
- `StackedDangoSceneRuntime.cs:363,404–440,487,529` 已有停止、边界、安全放置、手动优先及清输入能力。
- `ProductHomeView.LiveScene.cs:24,54–88` 已有释放，恢复需新增受控接缝；保持源窗口可见时不能靠 `IsVisible` 自动重新抢 owner。
- `DangoApplicationHost.cs:100–105` 的 `ShowControlCenter` 会回首页；房门需要明确“打开门廊”的路径。
- `DangoTrayIcon.cs:26` 当前菜单和双击回控制中心，尚无新房间恢复入口。

这些是当前代码事实，不是新房间已实现的证据。后续按[独立分批计划](2026-10-05-local-single-room-plan.md)执行。
