# 房间视角机制提案

日期：2026-10-05。状态：**待用户评审，仅设计**。以干净本地 `main@e2f4037` 和设计分支 `codex/local-room-design@2b7eb64` 为依据。本轮未修改生产代码、构建／启动产品、变更DLL或接入服务。

用户明确范围：**只设计普通房的窗口和壁纸层两种呈现**。本方案通过后，替代[上一版提案](2026-10-05-local-single-room-design.md)中“始终固定单屏”和“按窗口宽占比确定身体大小”的建议，其余房间美术、往返、单实体／owner及首帧约束继续待评审，不视为已批准。

## 1. 默认：标准视距，保持舒适观看尺寸

二维房间的“视距”表示整套场景的观看倍率，不使用三维相机距离／FOV。每个视距同时缩放背景、门、地面、团子、帽子和命中区域；不改变实体大小、物理参数、世界边界、位置、速度或跳跃强度。

默认“标准”：在参考窗口下，中性静止身体的可见宽度候选目标约 **150–165 DIP**。此数值是待真实视觉验证的目标，不是现有帧包围框宽度。首次校准后固定基准倍率，不根据每帧变形、轻压、帽子大小或当前窗口宽度重算。窗口变宽时看到更多房间，团子不会跟着窗口无限变大。

初版推荐三档，直接可选，不新增自由拖镜头或复杂相机面板：

| 视距 | 规则 | 使用场景 |
|---|---|---|
| **标准（默认）** | 固定基准倍率；参考中性身体约150–165 DIP。 | 日常活动，软体和表情清楚，留有走动空间。 |
| **近景** | 约标准 **130%**，目标约195–215 DIP；受跳跃／帽子顶部安全空间限制。 | 看表情和变形，镜头随自己团子横向移动。 |
| **全景** | 按当前可用视口等比容纳整间房，不高于标准倍率。 | 看整间房／找入口；小窗口里团子允许变小，大屏不强行放大整间房填满屏幕。 |

全景保证完整，标准保证舒适尺寸，两者在窄窗里不能同时满足。近景的130%为调参起点。标准／近景共用顶部安全倍率上限：参考最小640×420 DIP窗口应保证标准完整；若任务栏、系统安全区或更矮视口使顶部空间不足，降低实际观看倍率，并在菜单标出“受窗口高度限制”及实际比例。不能降低真实跳跃高度或按跳跃逐帧变焦。

连续倍率滑杆／Ctrl+滚轮可在三档确认后追加，本轮推荐先不做：三档已经覆盖默认、看近和看全，尤其壁纸层无需新增滚轮截获机制。

## 2. 镜头：看得全时固定，看不全时跟随

- 如果所选倍率能容纳整间房，横向居中、镜头固定；宽屏余下区域由安静后景／留白承接，不增加可走物理世界，不拉伸美术。
- 如果放大或窄窗造成裁切，镜头只跟随**自己的团子**，先保留约画面40%–60%的缓冲区，走出缓冲区后再平滑跟随；到两侧夹紧房间边界。
- 镜头依据稳定的物理核心位置，不按每帧软体外轮廓宽度或帽子动画追踪；不能轻压一下镜头就抽动。
- 竖直镜头固定，地面锚定在底部安全线。跳跃只让团子向上，镜头不随跳跃上下摇晃。安全空间包含中性身体、当前帽子及可达跳跃高度。
- 切换视距围绕自己的团子／地面落点过渡，边界夹紧可能产生必要水平位移；约140–200ms柔和插值只是候选调参。减少动画时直接到新视角；不改变物理或补播时间。
- 全景不跟随；不加入旋转、纵向漫游、鼠标自由拖镜头、自动追其他团子或第三人称模式。门廊原相机及首页预设不在本次调整范围。

## 3. 窗口和壁纸层的操作

| 场景 | 默认／调整入口 | 窗口尺寸与输入边界 |
|---|---|---|
| **普通房独立窗口** | 标准；标题栏新增一个小“视角”入口，展开三档，选择后收起。 | 拉大／缩小窗口只改变可见范围，全景会重新适配。控件获焦点时消费自身按键；仍按既定A/D/S/Space和局部Esc。视角控件应为原生可键盘操作菜单。 |
| **普通房壁纸层** | 标准；团子右键“视角”子菜单和托盘“视角”提供同三档。 | 呈现完整的小晴间背景与同一房间世界，应用窗口在其前方。没有普通窗标题栏；无需进入截获全局输入的调整模式。其他应用的滚轮、按键、Esc均不能改视角或返回。 |

普通房切换窗口／壁纸层只是宿主与本地视角变更，不是换房。仍使用同一session/runtime/entity，清输入、暂停原owner、目标有效首帧后交接。托盘房门、恢复与×语义不改。

首次仍默认独立窗口。窗口的房间菜单提供“显示方式：窗口／壁纸”；壁纸层通过托盘同一项切回窗口。视距是其中独立的三档选择，不随“换一种呈现”重置已有偏好。

推荐在本次运行内，窗口与壁纸各自保留最后选择的三档，首次均为标准；×恢复同一选择。切到新宿主根据其DPI／可用面积重新计算投影，不拷贝旧屏幕像素偏移。**首版不新增磁盘视角偏好存储、房内位置存档或重启自动进房**；后续可另加仅本地显示偏好，仍与权威归属分开。

普通房壁纸层当前仅作为设计范围；这次先做普通房窗口的实现排期不自动扩大为壁纸实现授权。壁纸层的游戏键盘输入尚未接通；未来若提供A/D等，必须单独验证严格前台／交互入口，不能因设计了视角菜单就宣称可直接玩。

## 4. 显示器、DPI与异常恢复

只在一个选定显示器内呈现一间房，不跨混合DPI显示器拼接，也不每块屏复制一只团子。目标屏与任务栏的系统几何可用于安全区；不读取真实窗口内容、桌面文件、图标、输入记录或剪贴板。

普通房壁纸画面铺完整个目标屏的背景；活动地面和返回／托盘交互避开任务栏安全区。标准倍率以DIP校准，设备像素按该屏DPI换算。超宽屏仍保持标准身体观看尺寸，房间居中并延展后景；竖屏／小视口进入横向跟随，不改房间布局。全景保持等比，允许留白，不强行铺满或裁掉边界。

跨屏、DPI变化／热插拔：先取消拖动和当前按键，更新视口、正逆投影与命中区域；保留逻辑位置及同一实体。目标屏消失时保持可操作恢复入口，提示选择可用屏／窗口；不擅自跨屏复制或改变房间。

壁纸挂接／首帧失败，保留当前可操作源呈现，必要时恢复主界面，并提供“重试／用窗口打开／房门”。从已显示窗口切到壁纸时，失败恢复原窗口；控制界面此前可能已隐藏，不能把“始终保留主界面”当作唯一恢复路径。**推荐用户明确选择“用窗口打开”后**，准备同一普通房窗口，有效首帧完成后再交接。当前既有壁纸失败策略为安全隐藏并让用户明确选择Window，不改为突然抢焦点的自动窗口。继续失败仍保留恢复入口；迟到就绪必须失效。

## 5. 最小技术边界与当前事实

建议新增轻量房间投影对象：固定逻辑世界、基准倍率、三档视距、相机位置，以及世界↔视口的正／逆矩阵。具体命名不是已批准API。窗口和壁纸消费同一场景描述；相机调整不调用`AttachSurface`重新映射房间，不通过`SetViewport`改物理活动区域。

普通房在进入／真正切场景时才配置固定物理表面、地面与左右墙；改变视距、窗口尺寸或DPI只更新呈现。漫步参考采用明确的房间活动世界宽，避免视距改变自主漫步距离。既有门廊／桌宠的参考语义不顺带重写。

所有显示bounds先投影再换算设备像素；鼠标命中／拖动依次设备像素→DIP→逆投影到世界。身体、帽子、装饰与命中不允许各算一套scale。拖动期间切视距先取消输入／释放捕获，避免拖拽目标瞬移。

只读事实：

- `PorchSceneView.cs:61,110` 和`PorchCameraController.cs:27`已有统一投影与只移动相机的思路，但没有完整三档视距或逆映射API。
- 旧`DangoSceneWindow.xaml.cs:237,358` resize会将宿主尺寸送入session；`DesktopSceneSession.cs:118`会重新映射位置。这是旧场景行为，不能复制为新房纯相机缩放。
- `WorkerWSurfaceCoordinateMapper.cs:7`只转换DPI；旧WorkerW proxy还需接入新投影和逆映射。
- `WorkerWWindow.xaml.cs:477,495`实际是**不透明**淡蓝背景；只有旧宿主能力，尚不是本方案的完整房间场景。`783`行的游戏输入标记为false，不能宣称已具备壁纸房内键盘。
- 产品基线的不同设备统一逻辑布局及局部返回规则保持；当前代码现状与目标设计分别描述。

## 6. 通过前必须能失败的反例

1. 标准视距下窗口从960拉宽到2400 DIP，团子成倍变大；或全景在小窗为维持身体大小裁掉房间边缘。
2. S轻压／帽子动画触发自动变焦；标准或近景下因视口高度不足裁掉跳跃／帽子，或镜头上下追跳跃。
3. 改视距／resize／DPI导致世界位置、速度、物理边界、实体或跳跃强度变化；漫步距离跟着zoom变。
4. 门、地面、身体、帽子、命中区域缩放不一致；近景点击／拖动落到错误世界位置。
5. 壁纸层截获其他应用的滚轮／Esc；菜单消费按键后同时触发玩法。
6. 切宿主出现两owner／两团子；沿用旧ready提前隐藏主界面；挂接失败突然自动弹窗抢焦点。
7. 视角切换或屏幕变化后旧拖动继续生效；屏幕消失后失去重试／窗口／房门入口。

本轮只验证交互示意和文档。真正的native／WPF投影、WorkerW挂接、输入命中、跨屏DPI、两端一致性和人工视觉需后续实施验证。旧DLL／发布hash、前台鼠标、历史Physics夹具和M7边界继续保留。
