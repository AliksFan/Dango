# 桌宠房使用真实桌面与单一虚拟桌面显示设计

## 1. 目标与授权边界

用户本轮明确要求：删除桌宠房的壁纸，以电脑桌面作为团子的房间；Win＋Tab 切换多个 Windows 虚拟桌面时，团子只能在其中一个桌面显示。

这更新了 [2026-10-07 分层设计](2026-10-07-desktop-pet-room-layered-design.md)中“完整真实房间固定在壁纸层”的方向。用户随后明确回复“确认，按此设计开始实施”，实施范围见[本轮计划](2026-10-29-desktop-room-single-desktop-plan.md)。本轮不更新旧设计的历史验收结论，不把设计批准当作功能已经交付。

本任务从当时本地 main 的独立任务工作树开展。原工作区既有修改保留；用户随后明确授权本地 main 合并，不推送、不更新安装，不操作保存数据。

## 2. 实施前基线（历史）

- `DesktopPetRoomHost.Show` 创建 WorkerW 宿主与不透明 `WallpaperSource`，并把 `LocalRoomSceneView` 放入其中；背景不是系统壁纸文件，而是应用绘制的墙面与地面。
- `DesktopPetDangoWindow` 单独绘制身体、帽子和配饰，窗口透明、不激活、不显示任务栏按钮并置顶。
- `NativeMethods.DesktopPet` 目前没有处理 Windows 虚拟桌面归属；不能仅凭这一点断言所有 Windows 版本的具体根因，跨桌面表现仍需真实复现。
- 场景布局、像素换算、健康帧确认及故障恢复目前依赖壁纸表面。只删背景颜色或墙面绘制不足以退役这条依赖。

主要依据：[桌宠房宿主](../../src/Dango.Desktop/AppShell/Rooms/DesktopPetRoomHost.cs)、[场景视图](../../src/Dango.Desktop/AppShell/Rooms/LocalRoomSceneView.cs)、[团子窗口](../../src/Dango.Desktop/AppShell/Rooms/DesktopPetDangoWindow.cs)、[原生窗口操作](../../src/Dango.Desktop/DesktopHost/Win32/NativeMethods.DesktopPet.cs)。

## 3. 推荐行为

### 3.1 桌面就是房间

1. 桌宠房不再绘制墙纸、墙面、地板、边界材质或其它整屏房间背景，直接露出用户原有 Windows 桌面；不修改系统壁纸设置或删除图片文件。
2. 保留同一只团子的身体、眼睛、帽子和配饰，沿用当前大小、透明空白穿透、不抢焦点、普通及最大化应用上方互动。
3. 主屏可用区域继续作为活动范围，避开任务栏；沿用当前安全区域映射、点击、Shift＋左键轻抚和拖动。松手仍受重力作用，落至当前主屏可用区域底边对应的地面，不画地面线。
4. 普通房的墙面、地面和可选壁纸宿主沿用原合同。本次不接入应用窗口碰撞、跨屏活动、新家具或自动行为。

2026-10-29 用户再次明确：桌宠房不要求 Explorer 桌面或团子窗口拥有焦点，只处理自身鼠标行为，不接管方向键。普通／最大化软件在前台时，命中团子仍应允许点击、轻抚、拖动与右键菜单；虚拟桌面归属、健康帧及透明轮廓边界继续有效。Windows 桌面服务查询不得在同步鼠标／窗口消息内执行。

### 3.2 只属于一个 Windows 虚拟桌面

| 场景 | 推荐规则 |
|---|---|
| 进入桌宠房 | 以本次进入时所在的 Windows 虚拟桌面作为所属桌面；只有一只实体、一套运行时 |
| 切换到其它桌面 | 不显示团子，不接受其点击／轻抚／拖动，不把团子迁往新桌面 |
| 切回所属桌面 | 恢复同一只团子及保留的位置；重新确认健康帧后开放互动 |
| 切换发生在拖动或菜单期间 | 取消手势、释放捕获、关闭团子菜单、清除输入，不在别的桌面补播 |
| 手动暂时隐藏与恢复 | 保持本次所属桌面；在其它桌面触发恢复也不把团子带过去，切回所属桌面才显示 |
| 想换到另一个桌面 | 返回门廊后，在目标桌面重新进入桌宠房 |
| 所属桌面被 Windows 删除 | 跟随 Windows 对自有窗口的实际迁移结果，重新验证唯一归属；无法确认则收起并提供重试，不退回所有桌面显示 |
| 退出应用后重新进入 | 重新选择本次进入所在桌面；不新增跨重启虚拟桌面标识存储 |

建议非所属桌面期间暂停桌宠物理推进并保留会话状态，返回后从当前状态继续，不追赶离开时间。区分“因桌面切换暂不可见”“用户手动隐藏”“宿主故障”，不能让一次桌面切换误触发故障退出或自动重新入房。

### 3.3 显示大小（同日追加批准）

用户追加“增加一个调整团子显示大小的功能”，并确认：设置中增加“桌宠大小”滑条，范围 50%–200%、默认 100%，整数百分比，即时预览并保存本机。身体、帽子与配饰按同一投影缩放，鼠标命中及活动边界同步适配；保留当前物理身体参数。100% 对应本轮之前的默认显示大小。

该偏好单独保存为 `desktop-pet-display.json`，避免向严格旧版主设置格式添加未知字段。保存失败保留当前预览和旧保存值，在原位置显示真实状态及重试；非法／未知文件保护原件。调整时先结束拖动，按新安全区域修正必要的位置与碰撞范围，暂停／隐藏状态也保留比例，恢复时重新校验健康帧。沿用界面规范第 4.1 节参数滑条及第 6 节验证要求，不改变普通房相机或捏脸身体尺寸。

缩放后的完整绘制包络包括身体、帽子及真实配饰网格。使用共同显示平移把可容纳的包络保持在安全区，显示画布、鼠标逆变换、手势 guard 与拖动限制使用同一偏移；包络回到安全区域后偏移归零。物理高度和地面不随这个显示偏移移动。尺寸超出整个安全区时居中保留可见部分，用户可缩小；不假称超过屏幕容量的装扮可以完整显示。

## 4. 技术与失败边界

- 桌宠房退役 WorkerW 房间背景和双表面成功前置；将健康帧、布局和坐标换算改为依托团子宿主与共享映射。不得留下仅用于假装双表面成功的空壁纸窗口，也不得直接绕过真实呈现确认。
- 物理 owner 仍只有一个，复用既有帧驱动和同一实体；返回、隐藏及失败清理继续走正式导航／恢复链。
- 虚拟桌面归属由 Windows 宿主边界集中管理。实施前核对公开 Windows API 的适用范围，验证透明工具窗及其自有 owner 的真实归属；不能靠取消置顶破坏应用上方显示，也不能只改 WPF `Visibility` 就宣称解决。
- 实施选择“始终隐藏的普通 owner → 1×1 全透明普通 anchor → 团子工具窗”。公开 `IVirtualDesktopManager` 只查询 anchor，并持续核对两层自有 owner 关系；不查询没有独立 app-view 的工具窗，不枚举或移动其它应用。后台原生试验确认，在当前 Windows 上 `ITaskbarList.DeleteTab` 会把 anchor 的 app-view 一并移除、令归属变成空 GUID，故已退役该尝试；单纯 `HwndSource` 还会剥除所需 layered 样式，最终 owner 使用项目既有的 `Forms.NativeWindow` 边界。采用标准隐藏 owner 关系保留可查询归属，真实 Win＋Tab／任务栏观感仍待人工验收。
- 查询／关联失败时停止输入并保留来源或托盘重试入口；不静默变成每个桌面可见。明确区分首次进入失败与运行期间失去桌面归属。
- 只处理 Dango 自有窗口所需的临时桌面归属及屏幕几何；不读取桌面内容、外部应用内容、桌面名称或输入历史，不保存／上传虚拟桌面标识，不引入账号、网络或数据库操作。

替代方案：只把背景改透明会保留无必要的 WorkerW 依赖及旧双表面合同；每次切桌面都把团子移动过去仍会让所有桌面看到它。两者均不符合本轮目标。

## 5. 界面规范与验收

适用 [桌面界面设计规范 v0.1](../desktop-ui-design-v0.1.md) 第 2、4、6 节。透明桌宠表面按业务要求直接显示系统桌面；保留的操作／恢复控件沿用共同资源、清晰状态和必要短文字，不新增独立主题或设置页。没有新增滚动容器，滚动条及全局控件迁移不纳入本次。

实施后的必要验收项：

1. 普通启动进入桌宠房可见真实桌面，无应用绘制的墙面／地面；系统壁纸设置不变。普通房背景回归通过。
2. 至少两个真实 Windows 虚拟桌面来回切换，只有所属桌面显示团子；Win＋Tab 预览及实际桌面均核对，无残留身体、配饰或团子菜单。
3. 切换桌面、切换期间释放鼠标、手动隐藏恢复、所属桌面删除和重新进入不复制实体，不遗留捕获／输入，不误判为壁纸故障；不可见期间暂停且不补播。
4. 原有点击／轻抚／拖动、重力落地、配饰完整绘制、透明处穿透、原应用焦点、普通及最大化应用上方显示仍有效。
5. 进入／恢复前确认本次新健康帧及正确归属；失败时来源或托盘可恢复，不以旧壁纸健康字段或旧代际回调放行。
6. 自动验证覆盖状态转换、单 owner、归属失败、旧代际拒绝及正式导航集成；真实呈现、Win＋Tab 和输入验证须另获屏幕使用授权。未执行项明确标为未验证，构建或模拟结果不能代替真实 Windows 验收。

设计确认后才同步产品基线与当前实施状态；后续实施保留历史验收记录，按开发工作流第 13 节迁移消费者并退役桌宠旧壁纸路径。
