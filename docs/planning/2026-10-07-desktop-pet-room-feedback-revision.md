# 桌宠房间体验修订

日期：2026-10-07，候选更新：2026-10-08。状态：体验修订候选已实现并打开，大小／边界与功能回归通过；性能门禁和消失根因仍开放，人工验收未完成。结果见[修订验证](../verification/2026-10-07-desktop-pet-room-feedback.md)。

依据：[分层设计](2026-10-07-desktop-pet-room-layered-design.md)及用户本轮确认。保留一个真实物理世界、壁纸环境和独立上层团子；只修订当前单人候选，不包含联机、窗口平台、安装更新、合并或推送。

## 已确认的体验调整

- 默认统一投影为上一候选的 1.4 倍，房间视野随之缩小，仍以世界中心居中。身体、帽子、环境及输入逆映射共同缩放。
- 主屏可用区域为活动边界，只排除任务栏；取消原额外 16 DIP 边距和地面下方 48 DIP 留白。物理横向范围、游走范围和拖动夹取跟随新视野，真实地面高度保持不变。
- 桌宠房间不绘制左右边界虚线或排除区斜纹，保留真实墙面与地面。普通房显示及物理规则保留。
- 实际绘制身体与随身外观需要在可用区域内；输入目标夹取不能代替真实足迹验证。

## 两项故障的定位边界

用户观察到拖动或松手时房间和团子同时消失，托盘仍在。旧候选进程尚存，双层 HWND 已消失；当前可确认是房间双面退出，尚未确定触发原因。需用自有真实宿主及受控鼠标平台复现，核对宿主失败原因、帧一致性、原生捕获与唯一 owner；人为发送显示失效消息只证明恢复入口，不能证明本次根因。

拖动不顺滑需测量静置、直接驱动拖动、手势桥拖动三组。检查真实新帧间隔、呈现耗时、输入到呈现延迟、长间隔与物理丢步。重复布局／原生窗口更新、队列竞争和固定步进显示均是待验证假设。仅依据实测做最小修复，不改变真实物理参数、删除透明轮廓或放宽健康门禁来换取通过。

实施定位：贴工作区底边后，原生输入回归的点击和 Shift 轻抚四行失败；两面仍健康，输入目标却被原顶节点拖动夹取向上移动约 40 world units。夹取因此下沉到已由真实 controller 判定的 Begin／MovePhysicalDrag，点击和轻抚保持原始接触点，hook 的轻抚资格也核对原始点。保留 8 world 竖向阈值、有限极值、取消锁存、时间戳水位及四边实际足迹门禁。

第二轮性能分段测量确认拖动卡顿主要在 Window 的定位／尺寸阶段：受控直接拖动约 29.0 新帧／秒，该阶段 p50 24.93 ms、p95 40.26 ms；手势桥拖动约 30.5 新帧／秒、p95 39.19 ms。绑定、两次布局和真实 region 各自中位数均不超过约 1.1 ms。探针第一轮的 Input 优先级 feeder 有呈现饥饿，bridge admission 又未扣 WPF 的整数点量化；修订测量为 Normal feeder 及自有 HWND 逆映射的严格消费关联，预算不降低。

最终选择固定主屏可用区域的独立透明窗口，Show 后定位一次；同一真实团子在内部按共享投影移动，region 继续逐帧取身体／帽子轮廓。相较逐帧移动小窗口，这移除实测约 25 ms 的原生定位瓶颈，但扩大透明 backing surface；不得因此取消真实轮廓或穿透门禁。最终静置／direct／bridge 为 56.51／55.20／56.79 新帧／秒，拖动 Apply p95 为 3.40／3.55 ms；59 FPS 与部分停顿门禁仍失败，不降低预算或修改物理。实际鼠标顺滑度仍需用户验收。

故障诊断仅覆盖一个最新本地报告，保存固定失败原因、原生消息／错误码、健康及捕获布尔值、scheduler 聚合计数和 UTC；不保存坐标、鼠标轨迹、外部窗口内容或异常消息。报告写入失败不得阻止原有严格退出与恢复。此项用于下一次真实操作回查，不能标记消失根因已经解决。

## 实施与验收

1. 新尺寸／边界合同先在旧实现上运行并取得失败证据，再修订共享映射、物理横向边界与环境绘制。
2. 使用真实 session/runtime/driver/双层 HWND，仅将受控手势输入平台注入测试；复现拖动／松手失败后修根因。
3. 串行执行实时与性能检查，避免桌面捕获竞争。保存汇总性能和受控失败原因，不保存真实鼠标轨迹、外部窗口或桌面内容。
4. 执行受影响普通房、入口、手势、足迹、生命周期门禁并核对受保护 DLL。生成新隔离候选，保留上一包供回查。
5. 用户实际拖动确认流畅度、大小和房间观感后才记录人工验收；自动检查与构建不能替代此项。
