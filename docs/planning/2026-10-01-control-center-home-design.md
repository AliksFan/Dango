# Dango 控制中心首页与后续页面设计

> 日期：2026-10-01。状态：已认可的交互方向整理为实施与验收约束；后续账号、房间和完整编辑器仍需各自的详细设计与授权。
>
> 实施基线：`main` 的 `89bacb5`。Phase 2A 多人小样及基础外观工作分别留在其他工作树；本批不接线它们的未整合代码。

## 1. 已核实的边界

- 控制中心和桌面团子是两个独立窗口。关闭控制中心后，桌面团子与托盘继续运行；“退出 Dango”是独立操作。
- 当前正式程序有真实的本地桌面显示、交互、帽型、宿主模式、键盘、恢复、诊断与设置保存能力；`main` 没有正式账号、好友、房间和同步入口。
- Phase 2A 已有隔离的同机多人小样，M7 双机人工验收未完成。小样不能充当正式账号或房间。
- 基础外观工作树包含尚未整合的改动；其预览与保存能力不能由本批正式 UI 预先宣称可用。
- 已认可的 2026-09-24 可点击布局原型仅用于交互讨论；其中的颜色切换、页面数据与房间状态不代表产品功能。

## 2. 页面结构与视觉规则

目标导航的主入口是“我的团子 / 一起玩”，登录、好友、设置处于辅助位置。顶栏固定，不随主体动画移动。控制中心保持简约、少字、轻盈；桌面团子始终由独立宿主窗口显示。

| 页面 | 用户能完成的事 | 开放条件 |
|---|---|---|
| 我的团子首页 | 看见真实本地运行状态，显示或隐藏桌面团子，进入已有桌面设置、帮助与诊断 | 本批 |
| 捏脸、换装 | 看当前真实外观、选择受支持选项、明确应用/保存/恢复；失败时保留上次有效状态 | 外观能力整合并有保存与恢复证据后 |
| 一起玩 | 查看真实连接和当前房间，进入加入/创建/邀请等流程 | 正式身份、权限、房间服务与失败处理就绪后 |
| 登录与账号 | 注册、登录、注销、资料与连接状态 | 鉴权、凭证安全和持久化设计获批并实施后 |
| 好友 | 邀请、双方确认、查看关系和授权入口 | 服务端好友与房间权限闭环后 |
| 设置 | 本地桌面显示、交互、宿主、键盘、诊断；声音、动画和账号项按真实能力逐项增加 | 本批先复用已有本地能力 |
| 创建房间 | 类型、人数、邀请与权限、创建结果和重试 | 服务端配额、授权、事务和持久化就绪后 |
| 自绘/导入帽子或皮肤 | 创作、预览、提交、审核和房间成员可见 | 后续独立设计；当前标为“未开发” |

未开放的页面不在正式运行产品中以可点击或禁用的假入口占位。阶段推进时才加入对应导航；顶栏的“我的团子 / 一起玩”两主入口是最终布局契约，不表示本批已开放多人能力。

### 2.1 团子首页的已认可交互

完整外观能力开放后，首页默认居中显示团子，只有“捏脸 / 换装”两个入口，详细选项收起。点任一入口时，团子与两个入口作为整体水平左移，选项从右侧滑入；团子区与选项区始终左右并排，窄窗口也不改成上下布局。切换入口保持展开布局。再次点击当前入口、点击收起或按 Escape，选项收起，主体归中。顶栏位置固定。

动画只是位置和透明度过渡，不驱动外观或保存状态。系统要求减少动画时立即切换布局，不播放位移或入场动画。窄窗口保留两列，通过缩小留白、约束宽度和区域内滚动保证控件可达；焦点、键盘操作与可见提示须与鼠标等价。收起后焦点返回触发展开的入口。

本批只有首页与设置导航，不播放首页布局动画，因此不受系统减少动画设置影响；EDIT-01/02 的动画和键盘状态机要等真实外观编辑能力接入时实现。

本批首页使用简化团子图形作为装饰，不称为实时外观预览；旁边的显示状态、错误与操作结果来自实际宿主。正式外观预览须接入有效配置，不能用装饰图形冒充已保存外观。

### 2.2 后续流程的一致规则

- 登录页先交代账号状态，再提供注册/登录；错误展示可重试且不回显凭证。返回首页保留本地桌面能力。
- 捏脸与换装共用“预览 → 应用/保存 → 成功或失败 → 恢复默认”的框架。选项按能力分批出现；无真实选项时不显示编辑按钮。
- 设置按“桌面与团子 / 声音与动画 / 账号 / 帮助与诊断”分组。尚未实现的声音、降低动画和账号设置不露出操作开关。
- 一起玩先展示真实连接及房间状态。创建房间、加入和好友邀请从此进入，失败不能显示成功房间或成员。房间额度和权限以服务端判断为准。
- 创建房间至少区分私人/公共、允许人数和邀请/授权结果；最多三个主动创建房间、默认个人房间不计入额度。未获批的公开发现入口和审核规则不在此定案。
- 自绘或导入的帽子、皮肤若进入未来房间共享展示，必须先通过审核；未通过审核的资产不能作为其他成员可见的正式装扮。审核主体、申诉、撤回和旧客户端回退由后续独立设计决定。

页面层级建议为“我的团子 → 捏脸/换装”和“一起玩 → 当前房间/好友 → 创建或加入”。登录属于全局身份入口；设置、帮助与诊断属于辅助入口。登录、编辑和创建房间都至少区分初始、提交中、成功、失败四种状态；返回上一层保留未提交输入的处理方式、凭证存放与审核责任要在各自详细设计中确定。当前本地设置仍由已有本地设置会话负责，未来房间和身份写入由服务端裁定。

## 3. 本批实施范围与顺序

1. 在独立工作树保留 DeveloperReview 的旧清单和导航。正式 Product 模式改为固定顶栏，将“我的团子”作为首页主入口，“设置”“帮助与诊断”作为辅助入口。
2. 首页去掉阶段术语和长段操作说明；中央团子图形仅作装饰，真实显示/交互/宿主与错误状态继续从现有命令控制器读取。显示/隐藏、进入设置、恢复、诊断及退出均复用现有命令。
3. 维持设置保存、控制中心关闭后托盘驻留、重复启动唤起首页、高对比度和现有评审模式行为。首页不引入独立设置文件、网络请求、数据库、额外进程或新依赖。
4. 账号、好友、一起玩、创建房间与完整捏脸/换装先停留在本文和独立交互原型。后续按业务闭环分别设计、验收和集成。自绘/导入及审核标记未开发。

选择复用现有控制中心窗口，可保持单实例、托盘和保存责任不变。另建平行主窗口会重复这些生命周期；直接把 Phase 2A 同机小样包装成产品页则无法满足身份、持久化和授权要求。

## 4. 能失败的验收

| 编号 | 操作与应见结果 | 明确失败例 |
|---|---|---|
| HOME-01 | 普通入口打开固定顶栏首页；团子图形居中，字数精简，状态来自实际宿主 | 仍默认展示旧侧栏或大段说明；把装饰图形称为实时预览 |
| HOME-02 | 显示/隐藏后宿主状态、按钮文案与实际桌面同步；命令失败显示原因 | 仅按钮变色或文案改变，桌面团子未变 |
| HOME-03 | 设置、帮助、首页往返后顶栏保持原位，已有本地开关和诊断仍可操作 | 导航漂移、设置消失或返回时新建第二个宿主 |
| HOME-04 | 关闭控制中心后托盘和桌面仍在；托盘/重复启动唤回首页；退出回收进程 | 关闭按钮直接退出，或重复启动产生第二只团子 |
| HOME-05 | 在最小窗口、键盘、高对比度下，顶栏和必要按钮可达且焦点可见 | 控件裁切、焦点不可见、退出不可达 |
| HOME-06 | Product 模式无账号、好友、房间、捏脸/换装假入口；DeveloperReview 仍可进入原验收页 | 产品中可点击到静态房间；评审清单被删除 |
| EDIT-01（后续） | 默认收起；展开时主体整体左移、右侧面板滑入且始终左右并排；收起归中 | 窄窗口改上下排；仅团子移动、入口留在原位 |
| EDIT-02（后续） | 顶栏固定；Escape/当前入口/收起按钮均可收起并返回焦点；减少动画时无过渡 | 顶栏跟随移动；键盘无法退出；系统减少动画后仍滑动 |
| EDIT-03（后续） | 真实外观应用和保存有成功/失败结果，重开后可核对；房间成员看到经允许的同一资产 | 本地颜色演出被报告为保存或同步成功 |

HOME 项属于本批可实施和验证的范围。EDIT 项是后续外观能力的设计门禁，本批不得以原型通过代替正式验证。M7 双机门禁和整个 Phase 2A 阶段状态保持原记录。
