# 独立帽子选择设计

日期：2026-10-05。状态：**独立设计候选，数量与交互待评审，无本轮生产帽子实现**。用户明确捏脸只关乎团子本身，帽子作为另一部分单独设计。本稿只讨论已有帽子预设的选择、预览和保存，不加入[团子自身捏脸](2026-10-05-dango-face-design.md)。

## 1. 范围与单帽位决定

推荐沿用首页独立“换装”入口，首个换装增量只提供帽子选择。捏脸负责身体／眼睛颜色，以及眼睛大小、椭圆度、高度和眼距；帽子不进入捏脸页签、不随捏脸取消或恢复默认改变。

候选仅展示现有 `sprout`、`top-hat`、`bowler` 三种预设，名称可暂为“叶芽／礼帽／圆顶帽”。不新增资源、服装、头发、帽色与尺寸编辑、自制编辑器、绘制或上传。当前预设和 API 没有“无帽”，不把它默认加入；是否允许摘帽留待单独明确讨论。真实身体大小、体型和柔软度继续后置。

首版推荐一个帽位：当前呈现只有一个帽外观和一套顶部附件运动，复用它即可比较已有造型。替代方案是多帽位或叠戴，但需要新增挂接、遮挡与动作组合规则；其后果超出本轮。单帽位意味着选择新帽替换当前帽，不保留叠戴层，未来扩展仍须独立设计。

## 2. 当前实现事实与缺口

- [DangoHatPresets](../../src/Dango.Desktop/Rendering/Dango/DangoHatPresets.cs)只认可上述三个稳定标识；默认 `sprout`。[HatAppearanceGeometry](../../src/Dango.Desktop/Rendering/Dango/HatAppearanceGeometry.cs)已有三种路径与颜色，沿用共同根位置，切外观时会使旧形变资产失效并重建图形。
- [StackedDangoSceneRuntime](../../src/Dango.Desktop/Rendering/Dango/StackedDangoSceneRuntime.cs)已有 `CurrentHatPresetId`、`DisplayHatAppearance` 和 `TryApplyHatPreset`。当前显示值直接等于当前帽；合法切换只更新标识并发出 `HatPresetChanged`，没有独立“帽子草稿”状态。
- [DangoApplicationHost](../../src/Dango.Desktop/AppShell/DangoApplicationHost.cs)启动会读取 `HatPresetId`，保存会写当前 runtime 帽标识；`HatPresetChanged` 触发延迟保存。**不能将这一提交 API 直接用于每次预览**，否则即使不按“应用”，延迟保存、窗口几何保存或退出保存也可能写入草稿。
- 帽标识目前属于[主设置 Schema 4](../../src/Dango.Desktop/AppShell/ControlCenter/ControlCenterWindowSettingsStore.cs)，不是[独立颜色 Schema 2](2026-10-05-appearance-consolidation.md)。本方案复用帽字段，不迁移到颜色文件，不新增主设置字段。未知帽标识当前回退为叶芽并提示，其余有效设置保留；这与整个文件损坏／未知主设置版本的写保护不同。
- [ApplicationSettingsSession](../../src/Dango.Desktop/AppShell/ControlCenter/ApplicationSettingsSession.cs)支持写保护、备份和保存失败状态，但 `Current` 可在保存前成为待写值，不能直接用它证明帽子已成功写盘。部分预设文件保护还可能导致总体返回失败而其他主设置已保存，帽子增量需明确本字段的实际保存结果。
- [DangoHostFrameBinding](../../src/Dango.Desktop/Rendering/Dango/DangoHostFrameBinding.cs)统一应用身体、帽子与步态；[DangoHatVisual](../../src/Dango.Desktop/Rendering/Dango/DangoHatVisual.xaml.cs)将帽型资产和附件帧组合。当前首页“帽子”按钮仍禁用，尚无正式草稿、取消、显式应用和按宿主重绑闭环。

以上是可复用基础，不代表本轮用户已经能在首页选择、取消或保存帽子。旧 runtime 测试保有同一实体／世界／帧的检查，不替代新的 Product 操作与真实宿主验收。

## 3. 独立换装界面候选

保持已认可首页和编辑区整体结构，通过“换装”进入帽子选择；不改首页键位、团子位置或普通房导航。编辑区先只显示“帽子”、三张可键盘操作的预设卡片及选中状态，不将未来服装项目做成可用功能。

预览使用当前同一只团子，选择一张卡片立即比较新帽，身体、眼睛、表情与物理状态保持。底部提供“恢复默认／取消／应用”；默认帽为叶芽，恢复默认只改变帽子草稿。用户无需进入物理诊断面板调整挂接或大小。

候选采用一次只编辑一个部分的边界：从捏脸切换换装，先取消未应用自身外观草稿并清理临时表情比较；反向切换先取消帽子草稿。切换不隐式保存，也不回滚另一部分已经成功保存的结果。关闭编辑区、去设置／门廊、隐藏或退出时同样取消未应用帽子草稿，再按既有导航与退出流程处理。

卡片、按钮和弹窗有焦点时先消费自己的键盘操作；不能一次点击／按键同时切帽、触发团子动作或 W 进门。取消帽子不停止正常眨眼、睡眠、步态或帽附件运动。

## 4. 草稿、提交与失败候选

分开保存“最近已确认写盘的帽标识”“帽子草稿／显示覆盖”和“动态帽附件状态”。建议增加最小预览覆盖接缝，当前已提交标识保持不变；显示可读草稿，通用保存只能读已提交标识。具体类型和 API 尚未批准。

| 操作 | 帽子呈现 | 本地保存 |
|---|---|---|
| 打开换装 | 从最近已保存帽创建草稿 | 不写 |
| 选择帽／恢复默认 | 重绑当前有效完整帧以显示草稿 | 不写，不发提交型帽变更事件 |
| 取消／关闭／切到捏脸 | 清除覆盖，重绑最近已保存帽 | 不写 |
| 应用成功 | 草稿成为已保存帽，清除预览覆盖 | 只在显式应用时确认主设置帽字段保存 |
| 写保护／备份或写入失败 | 保留草稿与最近已保存帽，可重试或取消 | 不标已保存，不能由稍后的自动保存偷偷提交草稿 |
| 画面绑定失败 | 保留可操作入口，提示重试或取消 | 显示结果与写盘结果分别记录 |

应用前验证预设、当前编辑代际和可用呈现，保存沿用集中设置边界，并保留其他当前有效设置；不得用打开编辑区时的整份旧设置覆盖其间的尺寸或宿主偏好变化。草稿不得进入延迟几何保存、关闭保存或其他设置命令的待写状态。失败时清理帽字段的待写候选，重试由显式应用重新提交；其他设置的合法待写项保留。

“已保存”需要帽字段的实际成功结果，不能只取 runtime 切换返回值或设置内存值。既有保存路径可能跨主文件与窗口预设旁文件，具体接线须核对部分成功：若帽字段实际已经写盘而另一文件失败，不能虚报帽子未写，也不能让取消回滚到更旧帽。该技术契约与故障注入在实施前明确，不重构整套主设置，也不承诺未经验证的跨文件原子性。

若帽字段已成功保存后最终画面重绑失败，保留新已保存事实，显示“已保存，画面待恢复”，并提供重试；不将持久结果伪装为取消成功或自动写回旧帽。确认有效完整帧已显示后才标该次应用闭环成功。损坏／未知主设置的恢复仍需明确备份恢复操作，不能通过选择帽子绕过既有写保护。

## 5. 帧绑定与普通房对接

切帽只改变呈现选择，不能调用额外 `Tick`、物理重置、`RegenerateDango`、暂停／重启 runtime，或创建第二团子／第二帧 owner。既有唯一帧驱动继续负责活动；帽附件的倾斜、跟随、滑动与弹跳状态保持，不在切图时重新起步。

每次预览、取消、默认或提交，当前可见宿主都应通过现有共用绑定路径，用当前 runtime／实体／表面／投影对应的有效完整帧，同时应用身体、脸、帽型资产、帽附件及步态；不能只换路径后等待下一次物理步来修复挂接。零物理步刷新也须正确。不能拿另一宿主的旧投影、旧身体帧或过期草稿回调拼接新帽。

首页、门廊、现有 Window／WorkerW 及可见 overlay 分别验证；后续普通房在其接口稳定后接同一已提交外观与共用帧绑定。隐藏宿主只记录待重绑状态，不为预览抢帧 owner或在后台推进；恢复按对应宿主的有效首帧门禁重新显示。编辑区离开时取消草稿，目标宿主接收已保存帽。未接线的宿主如实标未验证，不能凭首页结果宣称跨宿主通过。

若当前没有有效帧或发生真实渲染故障，保留最后可用画面及操作入口，提供重试／取消并标出预览未就绪；不用静态帽子演出冒充真实完整帧。迟到的预览或重绑结果必须经编辑代际核对，不能覆盖新的选择、取消或新宿主。

## 6. 可失败的验收与实施边界

- 三个合法预设可选；未知标识被拒绝，不改变当前已保存帽、草稿、实体或文件。无帽不出现在可用卡片中。
- 选择／恢复默认／取消／页间切换不写盘；等待延迟保存、改变窗口几何及退出也不能将草稿写入。取消恢复帽子且不改变已保存自身外观。
- 显式应用、失败重试、写保护、备份失败、部分保存成功和重启恢复有独立证据；失败不误报已保存、不丢原文件或无关设置，不留下会被自动保存提交的帽草稿。
- 快速连续选择／取消后，旧回调不能重新显示已取消帽；切换到捏脸后帽预览回调不能覆盖新编辑状态。
- 行走、跳跃、轻压、眨眼、睡眠与帽附件动作中切帽，挂接连续，脸部与身体不重置；零物理步和各宿主完整帧重绑也成立。
- 全程 session／runtime／entity 保持；外观事件不额外推进物理，帧 owner 不增加。帽图层保持既有不拦截输入的规则。
- 首页键位、三档布局、减少动画、隐藏／托盘恢复及普通房导航不回归；真实 WPF/native、磁盘重启、各宿主与人工观感分别记录。

本轮只新增这份独立设计稿，不增加帽子生产实现、原型资源、设置写入或测试运行。后续需先确认界面与交互，再制定可失败契约和分批计划；Home／Host／Runtime、通用保存与帧绑定由同一集成负责人协调普通房和捏脸接缝。设计不授权合入、安装、推送、部署或数据恢复操作。
