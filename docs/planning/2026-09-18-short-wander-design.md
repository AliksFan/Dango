## 2. 建议体验参数

| 项目 | 建议规则 |
|---|---|
| 重新取得资格 | 落地且核心速度 ≤0.15 world units/s 连续 500 ms；当前宿主可见、允许交互、无错误，无手动候选/拖动/有效方向输入/手动反馈或冷却 |
| 等待时间 | 获得资格后均匀抽取整数毫秒 8–15 秒；成功步计时，不读取系统空闲时间 |
| 方向 | 两边均安全时左右等概率；仅一边安全时选该边；均不安全则放弃并重抽完整间隔 |
| 单次目标位移 | 每次独立抽取当前显示器可用宽度的 10%–20%（0.01% 步长），核心相对起点横向移动；正常无打断完成后净位移至少 10%，不按窗口宽度或虚拟多屏总宽度计算 |
| 水平输入 | 初始建议幅度 0.35，前 200 ms 线性增至该幅度；不改变手动满幅输入、native 参数或摩擦 |
| 最长驱动 | `2 + 目标DIP / 20` 秒成功步时间，给渐入及正常速度留出余量；到目标或超时撤销自主输入，自然减速。屏幕或 DPI 改变时取消并重排 |
| 再次移动 | 驱动结束且再次连续稳定 500 ms 后，重抽完整 8–15 秒，不连续折返 |

目标位移不是精确落点承诺：撤销驱动后可能继续滑行，不能设置坐标、清零速度或挪动宿主伪造到位。新版自动验收为自由空间最终位移占屏幕可用宽度 10%–20%、撤销后 1 秒内重新达到稳定阈值；继续用真实物理测量。手动打断、离地、边缘或故障取消优先，不能为了凑满距离而延迟接管。两边空间不足时整次跳过，不缩成短距离。

按用户后续确认提高频率至 8–15 秒，距离每次随机抽取。暂不采用“按键左右交替”式脚本，因为满幅输入和固定时间不能保证按屏幕比例移动。

## 3. 输入归属与真实物理

自主输入应保存在 runtime 的独立有限状态中，携带实体身份、交互代际、当前宿主身份；不写入手动 `directionalIntent`，不伪造键盘事件，也不调用会取消自主动作的公共手动入口来驱动自己。

桌面场景增加窄化的可选自主水平输入入口：仅在无手动占用且目标有效时参与现有 `DangoPhysicsInput` 构造，最终仍只调用一次 `world.Step`。手动方向、Jump、Squash、Drag 字段按原逻辑生成；自主输入永远不带跳跃、下压或拖动标志。无自主输入时，逐帧结果必须与当前基线一致。

每步顺序：

1. 处理已有手动、生命周期和宿主取消；用上一成功物理帧检查自主驱动是否仍安全。没有可用样本或坐标刚变化时不驱动。
2. 将本步唯一有效的水平输入交给原物理步。到期时间只使用已成功消费的步数；首个驱动步计时一次，最多一个步长的取整偏差。
3. 成功后读取真实核心位移、速度、落地和可见边界，决定下步继续还是清空自主输入；失败立即冻结本地计划，不向失败世界追加指令。
4. 自主驱动/滑行期间暂停自然眨眼与张望调度，进入驱动前先释放自主眼睛占用；眼睛面向沿用已有方向规则。重新静止后两种眼睛待机重新等待完整间隔。

静止时若移动到期而正在眨眼或张望，放弃本次移动并重抽，避免眼睛动作刚开始就被频繁打断。自主移动没有等待队列，不在隐藏恢复后补播。

## 4. 边缘与异常停止

只使用当前宿主提供的可见逻辑视口和本应用已有的身体/帽子几何，不扩展屏幕、跨显示器或识别其他窗口。候选可视包围盒须包含形变后的身体与帽子，不只依据核心点或名义 160×120 矩形。

采用左右 16 DIP 可视边距，加最多 32 DIP 滑行预留；上下只要求身体和帽子完整可见，保留已验收的落地位置。启动方向必须至少留出“本次目标位移 + 32 DIP”空间；不足时不缩短目标凑动作，按方向规则选择另一边或跳过。每个成功步重查剩余空间，并在进入滑行预留区前撤销驱动；实施前测量须覆盖 10/20/40 ms 步长，确认预留包含最大单步位移及实际停止距离。

若实测 32 DIP 不足，不能通过瞬移、反向猛推、连续 Rehost 或缩放身体遮掩；先修改设计并确认。因用户拖放造成的越界不是自主移动负责纠正的范围；处于视口外、视口过窄、布局警告或坐标无效时跳过自主移动。

驱动中离地、实体数变化、坐标/DPI/视口变化、宿主切换、关闭交互或故障时立即撤销自主输入并丢弃计划；不在空中自行补走。若驱动 500 ms 后位移仍不足 2 DIP，也结束本次，避免长时间顶住或抖动。每步重新确认身份，旧实体或旧宿主回调不能恢复新计划。

## 5. 手动优先与后台

有效 Down 即取消本次自主输入，保持整段候选占用；不用等到 Click/Pet 成立或达到拖动阈值。取消驱动不等于抹去物理惯性：立即接管的定义是下一物理步不再消费自主输入，而不是身体瞬间停止。拖动和方向控制仍按原物理规则接管；点击/抚摸后允许原物理自然减速。

Window 与 Wallpaper 在可见后台均允许等待和移动，不激活窗口、不抢焦点。前台变化边沿取消一次，之后在后台重新等待；不因为后台状态每帧取消。Esc 沿用当前拥有输入资格时的局部处理，不监听其他应用的 Esc。隐藏、最小化、禁用交互、切宿主、故障、显式重置均取消；恢复须重新取得稳定资格并等待完整间隔。

复用既有“允许交互”开关，不增加持久化字段或新的设置项。本批自主移动与自主眼睛动作都随该开关暂停；它仍不是全局低动效开关。

## 6. 实现边界与失败处理

预计修改范围为 runtime、`DesktopPhysicsScene` 的窄输入仲裁、现有自主状态/手动候选和宿主取消接线，另加小型移动调度器与测试。复用成功步、当前宿主所有权及输入会话身份，不建立通用动作框架，不新增依赖、线程、native API 或重编 DLL。

对健康状态的取消只清除本批驱动与自主附件占用；不能清空手动命令或改动已验收的眼帽数学。若附件 Release 失败，沿用可见错误锁存与显式恢复，禁止继续自主移动；物理故障沿用原冻结流程。

设计暂限单实体，是为了避免在这一小步引入逐实体移动仲裁、互相推挤、堆叠支撑与选中项责任。以后扩展多实体时需单独设计，不把本批单客户端表现当作多人行为。
