# Windows UI 前置与 M7 双机验收排期记录

日期：2026-09-30。状态：用户确认调整正式双机验收的先后顺序；UI 具体设计将在另一对话继续。本记录不是 UI 详细设计、实施计划或编码授权。

## 已确认的顺序与现状

1. Phase 2A 的 M0–M6 已完成实现和同机 Server+A+B 验证，用户确认同机小样人工验收通过；实际证据和历史自动门禁限制见[实施记录](../verification/2026-09-30-minimal-multiplayer-sync.md)。
2. 在正式 M7 双机人工验收之前，先设计并做出完整可用的 Windows 客户端 UI（创作编辑器后置）。UI 完成的具体范围和可失败验收标准由后续独立设计确定；不得把只有页面外壳、假数据或无效按钮的界面算作完成。
3. M7 原有的两台 Windows、不同视口/DPI、真实网络中断/恢复、双方同一房间及用户确认等门禁保留，只调整排期。同机成功不替代双机结论；Phase 2A 整体仍未验收。
4. 创作编辑器列为后续工作，不作为此次 UI 前置批次的完成条件。

## 交给 UI 设计任务的输入

用户提出的界面分组如下，属于设计输入，不在此冻结页面、字段、交互或实现批次：

- 登录与账号：注册、登录、个人资料、连接状态。
- 我的团子：团子预览、当前装扮、快捷操作。
- 捏脸与衣柜：身体颜色、基础眼型、帽子和皮肤选择、保存及恢复默认。
- 房间与好友：当前房间、创建/加入、邀请、成员与权限管理。
- 设置：桌面显示、交互、声音、动画、启动与账号设置。
- 后续创作编辑器：制作帽子/皮肤、预览、草稿与保存；若涉及用户自制资产或上传，属于现有首版范围之外，须单独设计。

正式账号、好友、房间权限和持久化目前不在 Phase 2A 小样内。若 UI 设计要求这些入口真实可用，必须连同服务端鉴权、持久数据、迁移、授权和失败处理设计，不得以客户端隐藏或静态演出替代。具体技术与业务范围须先获批，再在独立任务/Worktree 中实施；不得把 Phase 3/4 内容直接混入 Phase 2A 分支或据此提前合并 `main`。

## 双机连接仍待准备

现有小样只支持本机回环服务和本机票据交付，不是局域网入口。正式 M7 的候选拓扑是受控局域网内由电脑 A 运行服务端与客户端 A，电脑 B 运行客户端 B；无需第三台主机。受信任的 HTTPS/WSS、明确监听地址、证书和临时凭证交付、最小防火墙规则，都须在双机设计/准备时确定。此处不批准开放端口、关闭证书验证或启动公网/云资源；此前建议的提前双机连通冒烟也不属于本次已确认的排期。

后续 UI 详细设计和实施计划需明确“完整可用 UI”的验收边界、各模块顺序、内置皮肤与自制资产的区分，以及它与 Phase 3/4 的分支和集成关系。正式 M7 使用整合后的产品入口还是保留隔离小样并增加产品级双机验证，也须据 UI 实现明确；不能把现有回环启动器视为已可用的双机入口。旧 DLL 回归失败、缺失比较产物、第二 DPI 和真实断网未验证等原结论继续保留。
