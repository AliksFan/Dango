# B5 账号、配置与房间交互候选

日期：2026-10-09。用户同意开始 B5，随后明确选择“居中浮层”；按[账号增量计划](2026-10-09-backend-b5-account-execution.md)实施 B5A Windows 账号与配置候选，房间管理、正式 Hub／租约及呈现随后分增量推进。依据[首期设计](2026-10-08-email-backend-design-proposal.md)、[实施计划](2026-10-08-email-backend-implementation-plan.md)的“先给小型可点击交互确认”以及[已确认首页](2026-10-06-home-and-appearance-design.md)。交互选择通过不等同于功能验收。

## 页面与入口

- 沿用 `ProductHomeView` 的暖色首页、居中团子及 W／A／D 入口；启用右上已有登录入口。提供居中浮层、右侧面板两个候选布局供比较。两者只改变账号／管理面板布局，不重做自身捏脸或换装。
- 门廊保留本地普通房、桌宠房两门，增加独立在线目录入口。门廊顶部导航当前隐藏，因此在线目录在未登录时自带邮箱登录入口。
- 本地入口在未登录、登录失败、未选择配置、断网或断服时均可用；在线入口需登录、取得真实准入并完成场景显示就绪。
- 新面板打开时隔离游戏快捷键；关闭后恢复正确舞台焦点，不让表单输入触发团子运动。桌宠单人候选、配饰及既有草稿 worktree 不因本阶段自动合并或安装。

## 最小流程

| 流程 | 交互与已有规则 |
|---|---|
| 登录 | 邮箱、密码、记住登录；受邀注册、找回密码和继续本地入口。登录错误采用统一结果，不暴露账号存在性 |
| 注册 | 受邀邮箱与邀请 → 等待邮件及显式浏览器验证 → 设置密码并确认本机已应用配置 → 注册完成 → 标准登录；请求受理、SMTP 接受和已验证分开 |
| 配置选择 | 已有账号读取两份原配置，先不覆盖；本机来源显式写同一账号 Pet，账号来源显式应用本机。可暂缓并继续本地。当前合同只包含 Schema 3 身体／眼睛颜色和四个眼形参数 |
| 我的房间 | 本人目录与可恢复目录；默认桌宠保护；共同房私密／公共在创建时确定，默认容量 6、范围 1–12，有效共同房最多 3 间 |
| 管理 | 修改名称／容量；解散二次确认及 7 天恢复；恢复不迁回团子、不恢复旧码。版本冲突先读取，再由用户决定 |
| 公共房 | 房主查看／隐藏／确认重置访问码，43 字符高熵秘密、默认 24 小时；访客粘贴码解析房门，再明确确认进入；不是全网发现列表 |
| 在线状态 | 准入成功仍等待呈现就绪；控制与观察区分，接管需显式服务器裁定；正式离房有确认，×／返回首页不等同于离房 |

注册邀请不授予私密房、好友或桌宠第二席权限。首期这些房型仅本人可进入；配饰、完整房间存档及物理／生命状态不因登录自动上传。

## 五项质量与后续实施门禁

| 质量 | 当前交互候选与正式实施门禁 |
|---|---|
| 正确性 | 必须区分待验证、发送失败、明确失败与结果未知；输入校验与服务端错误有可恢复操作；HTML 示例结果均为虚构，不能替代正式 API 结果 |
| 一致性 | 配置／房间更新携期望版本；冲突先读取，未知提交结果先对账，不盲目重试；请求键与注册继续秘密跨重试保持，切账号／旧响应不能污染新界面 |
| 安全性 | 原型不发请求、不保存输入的凭据；正式客户端只向固定可信 HTTPS 服务端发送，同一受控 CookieContainer＋CSRF，默认会话内存保存，记住登录用 Windows 安全存储；不使用原型 joinTicket／匿名 Hub |
| 可靠性 | 两份配置与旧本地文件先保留，磁盘失败不覆盖；断服继续本地，重连读取最新归属和租约；目标窗口打开失败不能标在线，需限定当前租约的恢复／补偿门禁 |
| 扩展性 | 目录游标、有界快照、单实例生命周期所有者；通知仅触发有界刷新，心跳限频，取消和订阅清理可验证；不增加全网发现或分布式客户端复杂度 |

必须用错误实现可失败的客户端→正式 API→PostgreSQL→响应测试，再进行独立 Windows 人工与真实多客户端验收。真实 SMTP、备份还原、生产长期 worker 和 WebSocket 仍保留单独门禁。原型的局部点击不关闭上述门禁。

## 实施顺序与授权边界

1. 确认本次可点击候选的账号面板位置、配置选择和在线房间挂载点。
2. 在独立 B5 Worktree 实现正式账号 HTTP／受控会话与注册恢复，再连接已有 B2 配置编排；随后实现正式房间 HTTP、B4 Hub、租约和恢复编排。
3. 正式目录与本地场景适配分增量交付；服务端准入与本机场景健康联合判断，不能复用旧原型连接冒充正式会话。目标呈现失败和旧租约补偿在实施计划中明确。
4. 真实 B5 测试若需要启动既有数据库、写虚构账号／房间或推进后台状态，先形成精确可审查目标，使用另行授权；本次原型不连接数据库、正式服务或 SMTP。

当前允许已批准范围内的 Windows 实施、局部门禁与本地提交。不合并 main、推送、部署、日常安装或替换 DLL；真实 B5 数据写入按新的精确计划另行授权。候选交互确认不等同于 B5 功能验收。
