## 1. 本批范围与完成标准

首批只交付隔离的单人首页／捏脸候选：真实连续外圈身体、大小／柔软度／落地体型实时调节、正式眼睛和配饰跟随、应用／取消／默认／重启恢复，以及可测量节省计算的单体物理休眠。后续实施仍须按下面各批冻结合同、验证并分别人工验收，不能将计划建立标成产品完成。

完成标准：

- 运行中的单体使用选定的新内核、材料和驱动规则，来源与能力可识别；不以旧内核或仅缩放图片冒充新身体。
- 拖动、键盘或辅助操作修改身体参数时，当前团子在原位置连续更新，不要求松手或再次点击才能生效，不自动重新下落。
- 保存绑定实际成功应用的最新参数和模型版本；取消、默认、隐藏、关闭和重启保留完整草稿／持久化边界。
- 入睡跳过身体求解并等待事件；外观按需继续更新；唤醒不补算睡眠时间、不遗留旧输入、不掩盖故障。
- 每批分别报告自动、实际运行、用户人工和交付状态，失败及未验证项保留。

本批不接正式账号／云同步，不运行服务或数据库，不增加依赖，不改日常安装或受保护 DLL。普通房／桌宠房的新内核接线、多团子、平台／皮球／家具碰撞和多人规则不在本批实现。保留“新身体最终在本地房间生效”的既有目标，作为后续房间批次，见第 9 节。

隔离候选在具备房间能力前，进入未接入的房间必须明确告知支持范围；不得把新参数静默送入旧房间内核并宣称已接入。现有 main 的房间目录、逐房存档、家具和设置成果必须保留，未来候选入口的范围控制不改变当前 main 的功能状态。

## 4. 接入设计

### 4.1 最小产品边界

从实验提取必要 native、托管 binding、参数映射、成功快照、worker／FIFO 和纯呈现能力。产品程序集不能依赖 `eng/tools/Dango.PhysicsLab` 可执行工具；诊断窗口、旧模型对照、参数搜索、失败候选和大批实验脚本留在来源归档。

拟新增 `DangoBeltWorld` 和连续外圈快照适配，围绕现有 Runtime 加最小适配层；不预建多引擎平台。能力明确为单体平地。native ABI 版本、身体模型／调优版本、支持的快照和热更新能力分别校验，不能仅因整数版本同为 1 就视作兼容。缺能力时明确拒绝，不静默选择旧物理。

中性身体、眼睛／配饰基线和实际视口标定使用同一新内核、相同参数／版本。实验为旧模型对照而推进 300 tick 的流程不进入产品每次调节路径。任何缓存须绑定完整参数和模型／调优版本，不能把旧参数基线用于新身体。

### 4.2 真正实时调节

大小保持 80～120%，柔软度／落地体型保持 0～100；默认 100／50／50，沿用当前滑块精度。滑块及数值直接响应输入，不添加数值缓动。连续请求允许合并，下一合法物理步只应用最新完整三元组；不排队补播已过期草稿。

新内核须增加运行中原子重配置能力，而非每次销毁、重新落地：

1. 在唯一物理 owner 的步边界校验目标参数、模型能力和配置完整性。
2. 柔软／体态改变优先保留当前位置与速度状态；大小改变的局部几何、核心相对位置、质量和速度继承按 F4a 的试验合同冻结。候选原则是保留接地点和整体运动连续性，按新尺寸变换真实几何；参数编辑造成的能量变化应单列，不能要求其冒充无外部功的自由演化。
3. 配置、广义坐标／速度、质量、接触／保护缓存以及附件标定以同一代际成功发布。非法或不安全配置拒绝时保留最近合法身体和可重试草稿，不能发布一半新配置。
4. 区分运行生命周期 `epoch` 与普通参数请求的 `configurationRevision`，成功物理 tick 与外观显示版本也分别记录。目标草稿不由消费快照反向覆盖。

普通热更新保持同一 `epoch` 和同一 FIFO：已成功入队的旧配置快照按顺序完整消费，worker 在下一可生产的步边界只接收最新参数请求；从首个新配置成功 tick 起，后续成功快照不可退回更旧配置版本。新请求到达至这一显示屏障前可继续显示先前的真实身体，但界面保持“更新中”，不得标记为新草稿已生效或允许保存。每张快照携带配置值／模型／版本，UI 只能更新“实际显示状态”，不能把旧值写回滑块草稿。

取消、恢复已保存配置、重建和关闭属于生命周期屏障：先使旧 `epoch` 失效，唤醒等待并等待当前有限 native 调用交还 owner，再完成必要的恢复／交接。未呈现的旧代际成功快照允许作废，记录数量和原因并保留故障取证，不再继续推进旧外观；“完整消费”约束适用于仍有效的同一运行代际，不能借普通调参丢帧。恢复成功前保留明确恢复中／失败状态，晚到结果不能打开保存或覆盖恢复结果。F4a 必须包含 FIFO 已满时改参、取消／恢复与在途 Step 同时到达的反例。

拖动中不重置位置、不自动再下落，不使用静态图或显示缩放代替参数实际生效。“重新下落”可保留为用户主动的观察工具，不再是每次编辑和保存的前置。

F4a 是显式可失败的技术停止点：先在单体验证三项连续变化、端点跳变、接地／空中／拖压状态及请求乱序。若无法安全保留状态，报告具体失败再修订方案，不能静默降级为松手更新或自动重建并称为实时。

### 4.3 数据、编辑与恢复

复用 F5 的身体字段、保存原子性和完整草稿边界。拟采用 Schema 5，加入独立 `bodyPhysicsModel` 身份；最终字段及模型名在 F2 冻结。Schema 1～3 补 100／50／50，Schema 4 保留全部原身体值并识别为旧模型来源。读取不写盘，只有显式应用才升级；不承诺旧模型同值会产生相同物理轨迹。损坏／未来版本／重复或无效字段保护原文件，未知模型明确报错。

“成功预览”改为“当前完整草稿已由选定模型成功应用并显示”，绑定参数、模型／调优版本和代际。更新中、失败或仍显示旧参数时保存不可用；颜色和眼睛编辑不能丢身体字段。保存失败保留真实预览和可重试草稿，不声称已持久化。

取消、默认、关闭、隐藏、切页和重启均覆盖身体／眼睛／颜色／配饰。离开编辑器前必须完成恢复或保持明确恢复失败状态，晚到的预览不得再次覆盖。参数请求被拒绝与原生运行故障分别报告；真正物理故障继续锁存并经显式恢复，不通过继续拖动自动抹掉。

### 4.4 物理休眠

新休眠定位为降低长期后台计算的优化，不再作为掩盖自然静置漂移的补丁。先完成不休眠的新内核与实时捏脸闭环，再实施 F6；不移植旧 Box2D 睡眠调用或清零速度修复。

- 入睡判断覆盖真实身体、核心相对外圈的运动／形变趋势、接地／支撑和完整输入占用，不能只看整体 COM 或合成轴为 0。W＋S、A＋D 同按仍是活动输入。
- 保留完整 native 状态和接触连续性；睡着后跳过昂贵求解、无用快照重建及不变身体几何工作，让 worker 等待事件。
- 按键、拖动、参数／默认／取消、重建、支撑或边界改变均唤醒。未来外来物体接近／接触须有可靠唤醒检测，当前单体实现不冒充多体休眠。
- 唤醒不补算睡眠墙钟，不补跳、不恢复旧输入／旧代际；故障不进入正常睡眠状态。
- 身体求解、外观动画和显示时钟分开：眼睛／视线及仍运动的配饰按需推进。休眠重复姿态不得伪称新的成功物理 tick 或新的物理帧率证据。

入睡判定与进入等待必须使用同一 owner／同步边界和可观察的唤醒序号。判定后、真正等待前到达的按键／参数／取消／关闭事件必须保留为待处理事件，不能被清空或漏掉；处理完事件并重新核对最新输入后才可再次入睡。F6b 增加精确控制调度的反例，覆盖该间隙、同 tick 相反键、热更新与取消交错，以及睡眠中的关闭，验证及时唤醒、只消费一次边沿且不死锁。

F6a 先测同工况 CPU 基线并冻结入睡窗口、可见位移／内部形变／速度门、唤醒时限及收益门。上述新阈值尚未测量或批准为既有门禁，不能拿本次长时静置的极小数值直接充当通用睡眠阈值。

## 6. 验证与停止点

### 6.1 固定参数继承门

先对照冻结 C455 和已验托管参数／时序，验证不热更新、不休眠时的八角和失败合同。纯封装／提取预期成功状态通道等价；若因产品必需变化产生差异，先保留轨迹和来源，说明差异再冻结新比较规则，不把提取后结果直接回写为旧实验通过。

复用既有形状／核心包容、残差、接地、速度与能量账、主动受力、释放恢复和实际离地门。不得靠缩小身体、减少子步、放宽保护或跳过外观来换性能。依赖审计和缺失历史模块单列，不能关闭审计后宣称默认门禁通过。

### 6.2 热更新与编辑门

- 固定同一帧输入、配置切换前／后状态和失败前状态，单独报告参数编辑引入的变化；零输入热更新不可被误判为自由演化等价。
- 八角＋默认，以及大小／软硬／胖瘦逐轴往返、两参数快速交替、取消／默认／离开／关闭与最新请求竞态；实际成功配置必须匹配所显示和所保存的草稿。
- 针对已变化的关键门设置真实反例：错误代际、无效配置部分发布、未知模型放行、保存旧预览、取消后晚到覆盖、睡眠吞新 Space 等应被检出。复用有辨别力的现有验证，不机械复制实现断言。
- 实时性能先在 F4a 冻结设备、配置、负载与测量方法。设计目标为滑块值直接响应、物理更新无持续排队且松手最终值及时可见；具体延迟和显示门应在第一次性能测量前写定，不先写成已通过的 57／59 FPS 保证。

### 6.3 休眠门

覆盖自然落稳、左右走停后、跳跃／拖压释放后，以及身体参数更新／取消／默认。原静置长测仅作自然落稳对照，不能替代新增状态。

休眠开／关在同参数、输入脚本、墙钟长度和外观负载下对照，分别记录进程 CPU 时间、物理调用次数／耗时、线程等待、分配／GC、唤醒至成功身体帧延迟。功率未测就只报告 CPU，不能用后台加速吞吐冒充日常节能。收益不明显、误睡或唤醒破坏状态时停止默认开启，保留失败和关闭休眠的可用基线。

### 6.4 真实桌面与人工

尽量先做有效后台检查；前台窗口／全局输入另行说明目的、占用方式和预计时长后获准执行。后台不覆盖的 OS 焦点、真实连续拖动、最小正式／横向／纵向、支持 DPI、高对比／减少动画分别标记。真实捏脸整体确认和休眠手感／视觉确认各自记录，不由构建、截图或旧实验人手反馈替代。

## 7. UI 规则与本页差异

采用 [桌面 UI v0.1](../desktop-ui-design-v0.1.md)（2026-10-10）第 2～6 节：暖白、棕色细强调、少字，复用语义资源；空间充足用图标＋短文字，紧凑用仅图标；参数常驻细滚动条、固定保存／取消区、清楚的待更新／失败／恢复反馈。沿用捏脸横向／纵向布局，不复制实验窗口主题或将技术诊断放入普通用户流程。

本次业务差异为三项身体物性真正实时应用到预览草稿；应用才写盘。可选重新下落是局部观察工具。控件焦点、文字输入、拖动捕获与玩法输入分离；继承实验已修复的 Slider IME／失焦恢复经验，但产品实际控件须重新验证。

## 8. 决策、替代方案与后果

| 决策 | 原因与替代方案 | 后果 |
|---|---|---|
| 从最新 main 建整合支线、按能力提取 | main 已有目录／存档／设置；整分支合并会带入大量历史实验和旧产品接线 | 多做一次有边界的移植，保留最新产品基线，来源归档可对照 |
| 连续实时热更新 | 用户要求实时显示；短暂停顿自动重建更省实现量，但会重置下落，不能当作同一验收目标 | 新增 native 状态迁移和原子校验，F4a 先验证可行性 |
| Schema／物理模型身份分开 | 原 Schema 4 没有充分表达新内核语义；直接复用同值不能证明物理含义完全一致 | 保留旧值、显式迁移、未来模型拒绝；不写真实日常数据 |
| 休眠后置为资源优化 | 新模型自然静置已有稳定证据，旧 Box2D 修复不是接入前置 | 先得到新物理捏脸闭环，再用 CPU 和唤醒证据决定默认开启 |
| 保全式归档、不删除旧工作树 | 忽略产物、历史失败及验收二进制仍有价值，bundle 不包含完整 artifacts | 固定引用／bundle／模块可恢复，源工作树和数据继续保留 |

重要接口决策在 F1／F4a 冻结时补足 native ABI 文档；若形成全产品长期架构决策再新增 ADR，不以当前计划替代已批准 ADR。

## 9. 后续房间批次与未关闭项

原 F7 的用户目标继续保留，但其技术前置改变：新内核目前只有单体平地，必须先补多体、平台／球／家具接触、外来对象唤醒和实际房间生命周期，才能做完整房间验收。该部分须另列实施计划，不把当前 F6 单体休眠套成整个 world 暂停而冻结其它对象。

未来仍需覆盖最大／最小、软硬／胖瘦端点的站台、掉落、跳台、球碰撞、休眠后撤支撑、手套命中、地面／相机、逐房安全位置和退出／重启恢复；多人身体同步与公平规则另案。旧 F5 和 main 的性能／Windows 专项、Phase 2A M7、正式房间／账号侧线状态均不因本计划改判。
