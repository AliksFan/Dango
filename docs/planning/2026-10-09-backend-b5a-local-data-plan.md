日期：2026-10-09。状态：**用户在本计划的精确授权问题中明确回复“允许”；已执行首轮真实集成，5／5 通过、零失败／跳过，实例及测试宿主已退出，数据与密钥保留**。结果见[B5A 验证记录](../verification/2026-10-09-email-backend-b5a.md)。本计划只覆盖 B5A 正式账号客户端与同会话 Pet 适配；B1／B4 的旧批准不授权此次新客户端测试。依据[首期实施计划](2026-10-08-email-backend-implementation-plan.md)、[交互候选](2026-10-09-backend-b5-interaction-proposal.md)及根 `AGENTS.md` 的精确环境和种子写入边界。

## 精确环境

仅启动当前用户 LocalApplicationData 下 `Dango/BackendDevelopment/run20261008b0/pgdata` 的既有独立 PostgreSQL 18 实例，使用 `state.json` 已记录的本机端口、`dango_backend_b0` 库、`dango_b0_owner` 角色，以及既有 `credential.dpapi`、`b1test-state.json` 和 `b1tests-keys`。绝对路径由 runner 依据系统目录展开，仓库不写入个人端口或凭据。

执行前核对运行名／数据库／角色／数据目录／状态版本／记录端口，路径及状态文件没有 reparse point，恢复代际非空，既有密钥目录和数据目录存在，PostgreSQL 版本为 18，实例目前停止。不得在这些检查失败时改用其他目标或生成替代配置。启动参数只监听 `127.0.0.1`；连接后进一步核对实际 `current_database`、`current_user`、`data_directory`、`server_version_num` 和 `listen_addresses`，并拒绝任何待应用迁移。

**无迁移、初始化、新建库、重置、恢复、数据删除或备份操作。** 不生成新恢复代际，不替换旧凭据；复用既有受当前用户保护的正式服务 key ring，正式宿主依照已有合同保护该目录并维护正常 Data Protection 密钥生命周期。没有新的账户密码、Cookie、继续秘密或邮件证明落入普通文件；测试客户端安全存储使用内存实现，不访问或写入 Windows Credential Manager。

## 允许的写入及监听

仅执行 `AccountClientHttpsIntegrationTests` 的以下五项，不运行 B0–B4 回归、不访问其他账号的业务记录：

1. 真实客户端注册开始 → 测试内部读取自身新造挑战 → 受 CSRF 保护的真实邮箱确认 HTTP → 完成注册 → 标准登录 → 同 Cookie 的 Pet 读取及一次配置更新。验证实际数据库版本、身份和默认房保持正确。
2. 记住登录 → 客户端实例重建 → 从内存安全存储恢复 → 实际服务器验证 → 注销 → 重放旧 Cookie 必须被拒绝。
3. 注册开始和完成的提交成功响应分别丢失一次；保留相同请求键、继续秘密和完成键恢复同一结果。完成重放携带另一个虚构密码和配置，原密码仍能登录，替代密码不能登录，配置不得被重写。
4. 同账号两个独立客户端先读取相同配置版本；第一个更新成功，第二个过期版本更新明确冲突，重读获得已提交配置，账号身份和默认房保持不变。
5. 注销在服务器提交后丢失响应；客户端必须报告撤销结果未知并清本机内存材料。通过数据库及另一个独立 HTTP 客户端验证实际撤销，旧 Cookie 不得恢复登录。

每轮完整执行只新造五个随机 `.invalid` 邮箱账号及其邀请、预注册、邮箱挑战／未投递队列、账号团子、默认桌宠房、房主席位和初始归属；登录产生六个持久会话，两个账号涉及记住会话的撤销，两个 Pet 各更新一次配置。完成重放不再创建对象；一次替代虚构密码的失败登录会按既有安全合同增加该新造账号的失败计数。若用例失败后同范围重跑，可留下额外的新造记录；不清理、覆盖或重置已留下的数据。

原始邀请证明、继续秘密、密码、Cookie 和观察用防伪头仅保留在测试进程内存，不打印到输出或 TRX。服务端数据库按既有合同保存必要密码哈希、秘密摘要和业务记录，不写原始 Cookie／继续秘密。测试的“邮件确认”通过新造挑战和真实确认 API 完成，**没有 SMTP 接收器、邮件发送、邮箱网页或浏览器人工验证**；队列保留为尚未投递，不能据此声明真实发信通过。

HTTPS 只使用 fixture 创建的临时 IPv4 loopback 端口与临时证书，客户端测试 handler 仅接受该 fixture 的精确证书；没有系统证书信任安装或生产 TLS 绕过。正式 Email、room live、outbox 和永久到期 worker 均关闭；没有 Hub、入房／离房、公共码、房间管理、好友、配饰或在线场景操作。所有写入只涉及本轮随机生成并明确持有 ID 的数据，不运行全库后台任务。

## 授权隔离与执行方式

runner 新增专用 `-B5A`，拒绝与 `-B1/-B2/-B3/-B4/-Initialize/-CreateDatabase` 混用，只允许 `run20261008b0`。子测试进程明确将 B1／B3／B4 批准置为 `0`，只将 `DANGO_BACKEND_B5A_TEST_APPROVED` 置为 `1`。新 fixture 在连接数据库、探测端口、创建证书或读取 key ring **之前**检查这个专用开关；旧批准不能代替它。

强制筛选同时匹配 `PostgresIntegration`、`BackendB5AIntegration` 和新类的完整名称。额外 `-TestFilter` 只接受一个 `FullyQualifiedName` 的 `= / ~` 条件，总长不超过 512 字符，值仅含英文、数字、下划线和点；拒绝括号、组合表达式、否定或转义，防止额外筛选逃逸强制范围。它只能进一步缩小新类，不能打开其他阶段；其他阶段 runner 排除 B5A 分类，也将 B5A 开关清为 `0`。不带 `-ExecuteApprovedPlan` 只展示计划，不解密凭据、启动进程或连接数据库。

仅在本精确计划获批，且集成后的 Server 测试项目已完成 Release 构建后执行：

```powershell
./eng/invoke-backend-postgres-tests.ps1 -RunName run20261008b0 `
  -PostgresBinDirectory '<已核验 PostgreSQL 18 bin 目录>' -B5A -ExecuteApprovedPlan
```

TRX 保存在忽略目录 `artifacts/backend-b5a/postgres-tests/<本次时间>/backend-postgres.trx`。结果报告必须区分执行／通过／失败／跳过，不能把编译或无授权跳过写成集成通过。

## 五项门禁与收尾

| 要求 | 本次可以证明的边界 |
|---|---|
| 正确性 | 真实 HTTP／JSON 合同、注册状态、登录、恢复和版本冲突；非法输入及响应上限另由静态门禁覆盖 |
| 一致性 | 已提交响应丢失后同键同结果、完成重放不替换密码／配置、旧版本写入被数据库拒绝 |
| 安全性 | Cookie／CSRF 共享且登录后新证明、恢复绑定固定服务端及身份、撤销后旧 Cookie 拒绝；原始秘密不落普通文件 |
| 可靠性 | 客户端实例重建和请求失应恢复；本次没有真实服务进程强杀、磁盘故障或备份还原演练 |
| 扩展性 | 受控单会话请求、有界响应和重试、现有索引／事务约束；不承诺生产吞吐或长期运行表现 |

每个 fixture 的 `await using` 停止且释放本次 HTTPS 宿主和临时证书。runner 的 `finally` 只在 PID、启动时间、可执行文件和目标目录均匹配本次启动时停止这个独立实例；无法证明归属时报告可能残留，不改停系统现有 PostgreSQL 服务。测试结束核对本次 PostgreSQL PID、记录数据库端口、所有本次 HTTPS 监听均已退出，报告残留进程／端口。

保留原有数据、密钥、恢复代际、未投递队列、本次虚构业务记录和日志。停止实例不等于删除数据；本计划不授权清理数据库、密钥、备份、分支或 Worktree。Windows Credential Manager 实写、客户端窗口人工、真实邮箱投递、正式房间／Hub、多客户端在线呈现、备份还原及生产部署仍分别未验证。main 合并、推送、日常安装与受保护 DLL 不在此计划内。
