## TLS 与 Windows 凭据

只读检查当前用户 My／Root 中未发现有效且带 `127.0.0.1` SAN 的适用证书。正常 Desktop 采用系统 TLS 校验，自动测试的内存证书 pin 不能直接用于正常界面。

批准后在仓库外受当前用户保护的 `Dango/BackendDevelopment/run20261010b5cmanual` 新目录准备唯一临时 TLS 证书：SAN 仅 `127.0.0.1`、用途仅服务器认证、非 CA、有效期最多3天，PFX 与 DPAPI 保护的随机密码保留在该目录。目录已存在则停止，不覆盖。只将该次生成证书的公钥导入 **当前用户** Root，不修改 LocalMachine 或其他证书；记录公钥 thumbprint，验收结束按同一 thumbprint 和本轮证书摘要核验后仅移除此次信任。PFX 和非秘密回执保留，不打印私钥或密码。产品没有宽泛证书绕过。

HTTPS 在临时空闲 IPv4 loopback 端口运行，选定后固定该验收 origin。WinCred 精确目标为 `Dango/EmailBackend/v1/<该 origin 规范化 SHA256>/session` 与 `/registration` 两槽：授权本轮产品正常读取／写入／删除及结束后清除此两槽。先只检查指定槽是否存在，已有则停止并改选未使用 origin，不读取／解析或覆盖已有秘密。不能遍历其他槽；不勾记住登录也仍可能正常读／删槽，注册会写 registration 槽，因此这项不能省略。密码、Cookie、CSRF、挑战和公共码不进证据日志。

## 用户操作与通过标准

1. 开账号浮层，以本轮邀请注册并设置密码；维护确认后完成真实注册和登录，显示本人身份。窄窗口／低高度能访问所有操作，错误文字清晰，关闭按钮与键盘焦点可用。
2. 账号唯一 Pet 身份保持，明确选择本机配置；修改本地外观并保存后，回账号重新读取两份配置、明确再次采用本机来源，不能把捏脸保存当自动云同步。使用托盘“退出 Dango”并等待本轮 PID 结束，再通过同一 launcher 重开；非记住登录需再次登录（第二个会话），本地及已确认云端配置能够加载。本轮最多2次配置写入，本地单人入口始终可使用。
3. 创建一间私人共同房和一间公共共同房；私人房改名、解散、查看已解散目录并恢复，状态和版本更新正确。公共码重置两次，旧码被拒绝，关闭浮层后秘密隐藏。
4. 默认桌宠房明确入房；只验收服务器连接、归属、角色与成员快照。关闭后在20秒以内重新打开应恢复原有效租约；再次关闭超过30秒后应显示需要重新入房／睡眠，必须明确 Enter。不能把关闭当离房。
5. 在新私人房、公共房各明确 Enter 一次，清楚显示准入／连接状态；明确离房先确认，取消不修改归属，确认后显示当前服务器事实。全过程最多4次 Enter。
6. 注销第二个会话，第三次登录选择记住；托盘退出并确认 PID 结束后，以同一 launcher 重开应恢复同一个会话而不新建第四个。明确注销后旧绑定不会再操作，凭据仅在专用槽。关闭窗口可能只隐藏，不能用窗口 X 代替进程重开。最后正常退出、结束验收并收尾。

各步骤按真实限流节奏执行，失败保留原请求和数据，先定位，不自动重复新变更或提高配额。界面误导、越权、旧回调干扰、新请求覆盖未知结果、关闭导致离房、日常设置受影响或收尾残留，均阻止通过。

实际验收环境准备完毕后，用户只需操作候选并反馈体验；真实邮箱／SMTP 账号当前无需准备。自动结果和用户人工结果分别记录，用户确认前不标“已验收”。

## 收尾与证据边界

当前 Windows host 的同步退出会启动异步连接清理，不能承诺已 await 每个内部任务。先请求正常退出，再由 launcher 等待并核验本轮每次候选 PID 实际退出；超时只报告，不盲目终止其他进程。随后 await 停止／释放验收 HTTPS 宿主，并仅停止本轮启动的独立 PostgreSQL；核验其 PID、创建时间、路径、实际监听和 pidfile。PID退出证明进程资源结束，不冒充内部 graceful drain 或强杀恢复通过。仅清除本轮专用 WinCred 两槽与此次新加的公钥信任，按精确身份核验，不碰原资源。保留原数据库、原凭据／key ring／恢复代际、人工批次虚构记录、隔离本地存档、TLS 受保护文件及非秘密回执。若不能证明归属，停止清理并报告残留。

本轮不授权 main 合并、推送、部署、日常安装、生产 DLL 替换或持久数据删除。正式协议没有 Move／Action 或批准的场景单位映射；本次不会确认多人场景就绪。WSS、多人移动／动作画面、真实邮件、服务强杀、长期 workers 与备份还原保留独立门禁。人工通过也不能关闭完整 B5。
