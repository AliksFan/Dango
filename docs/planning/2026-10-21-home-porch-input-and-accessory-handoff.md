# 首页／门廊交互调整与配饰保存交接

日期：2026-10-21。用户明确提出本节按键、布局和滑入要求，作为本轮已确认的设计输入；在 `codex/belt-page-completion@497ad4b` 上实施。上一轮共用接触度量修复已获用户“验收通过”，这不授权合main或推送。当前无Agent前台操作授权。

## 行为与边界

| 场景 | 本轮确定行为 |
|---|---|
| 首页 | Q换装、E捏脸、F进入门廊；键帽、提示和帮助同步；WASD继续身体操作 |
| 换装 | 复用捏脸的约440ms转场机制，镜像从左滑入；关闭向左退出，预览在右；不改变草稿／显式保存／取消合同 |
| 门廊 | F操作当前靠近的入口：进入对应房间或打开新建；W拉伸，A/D移动，Space跳跃；E保留普通房布置动作 |
| 房门 | 门本体仅绘制，不响应鼠标悬停／点击；靠近后的显式进入／布置／解散等按钮继续可用；F与进入按钮走同一业务路径 |
| 房门顺序 | 桌宠房最左，现有普通房向右排列；只保留一个新建入口并放最右，普通房数量上限与资格不变，达到上限时入口禁用 |
| 门廊工具 | 首页按钮左上；保留恢复／重新读取入口，放在非房门的工具区，不挤入房门排序 |
| 配饰保存交接 | 先用真实保存／宿主边界复现豆芽回退，再修正已保存配饰向房间runtime的同步；只把成功保存的配置带入房间，草稿不越过取消边界 |

文字输入、下拉、对话框和菜单保留自身键盘输入；快捷动作不在按键重复时反复打开，切页面／失焦清理身体输入。进入已打开的编辑页沿用原收起语义。移除旧A/D/W导航占用，保留WASD身体合同。

## 规范与实施

依据 `docs/desktop-ui-design-v0.1.md` v0.1（2026-10-10）第2节共享资源与尺寸、第3节镜像布局／固定保存区、第4节控件／焦点。首页与捏脸原基线的滑入方向、相同团子尺寸与接地高度、减少动画及快速切换最后请求规则继续保留；按键以本轮用户要求替换旧A/D/W。配饰库、材质、物理、保存Schema及房间授权范围不扩展。

实施分工：主Agent负责首页按键／滑入及帮助；配饰任务负责保存根因和最小交接修复；门廊任务仅负责房门布局／鼠标边界／显式按钮及对应检查，文件所有权互不重叠后集成。

后台验证使用真实保存和产品调用链、WPF路由／布局与转场检查，以及已证明可推进的隐藏源；不把隐藏窗口通过当作前台视觉或真实键鼠验收。检查未保存草稿隔离、成功保存后的门廊／普通房／桌宠一致、旧按键不导航、W确实产生拉伸输入、F只执行一次、房门装饰不命中、按钮仍有效、顺序／数量和横纵向布局。无前台授权时只交付未启动的本地复测包。
