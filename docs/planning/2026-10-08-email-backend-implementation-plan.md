## 1. 起点、范围与所有权

从 `main@1c47930` 的隔离任务分支 `codex/email-backend-design` 开始，保留已有 Phase 2A 管道原型和测试合同；正式入口显式选择模式，不共用匿名原型的入场票据、身份或内存快照。好友、情侣、桌宠第二席及私密非房主准入后置；注册邀请不授予房间权限。

根代理拥有入口、项目依赖、DbContext／迁移、共享合同与基线文档；本轮其他代理只读审查。后续并行代码任务使用独立 Worktree，各自拥有明确模块文件，模型和迁移由根集中集成，不同时写同一分支或 ModelSnapshot。

当前授权包含首期必要代码、局部门禁和本地可审查成果。既有数据库、精确迁移／虚构种子／还原、真实 SMTP、客户端 UI 交互细节、main 合并、推送、部署与日常安装仍分别处理。既有 Phase 1、M7 等验收状态保持原记录。

## 4. B0 结构细化

正式入口采用显式模式选择，保持无参数／错误参数不会意外启动匿名或正式服务。普通启动不调用 `Migrate`、`EnsureCreated`、自动建库或种子工具；迁移入口显式校验环境、数据库与执行意图。

Identity store 使用统一规范化邮箱和数据库唯一索引。Pet owner 唯一，配置记录有 Schema／字节上限／版本；默认桌宠房对 owner 部分唯一且容量固定 2，共同房容量 1–12，类型不可由通用 DTO 修改。房间 owner 外键、成员组合唯一及合法角色、解散时间组合由约束保证。

`pet_room_states.pet_id` 唯一，可空房间外键表示合法无房；无房时清空坐标／睡眠，房内坐标成对存在且有限。先不加入 B4 的控制租约外键，后续以迁移补齐。用户→团子、房间／成员等使用限制删除，避免级联删除绕过生命周期或数据授权。额度、容量与成员／归属一致不假装是单行检查能完成，留给 B1／B3／B4 事务。

模型测试检查真实 Npgsql relational metadata 和迁移 SQL，不能替代 PostgreSQL 执行。正式 readiness 检查可连接且所需迁移已显式应用；失败返回可操作稳定状态，不泄露异常中的连接串。密钥位于仓库外，正式模式固定 loopback；尚未获得 SMTP 配置时真实邮件不能发送。

本轮 B0 不改原 `Program.cs`，正式入口／readiness 随 B1 最小账号端到端路径接入；迁移应用由精确目标的 opt-in 测试工具显式触发。已新增 Identity EF／EF Design **10.0.12（MIT）** 与 Npgsql EF **10.0.3（PostgreSQL 许可证）**，官方 NuGet nuspec 均支持 net10.0，provider 的 EF 依赖范围为 `[10.0.4, 11.0.0)`；原 SignalR 10.0.11 不升级。来源：[Identity](https://www.nuget.org/packages/Microsoft.AspNetCore.Identity.EntityFrameworkCore/10.0.12)、[EF Design](https://www.nuget.org/packages/Microsoft.EntityFrameworkCore.Design/10.0.12)、[Npgsql](https://www.nuget.org/packages/Npgsql.EntityFrameworkCore.PostgreSQL/10.0.3)。

## 5. 五项质量的验收映射

| 要求 | 设计机制 | 证据与停止条件 |
|---|---|---|
| 正确性 | 输入长度／范围／有限值、用途与期限、API／配置／快照版本；稳定错误语义 | 正常、异常、边界及未知版本成对测试；非法值不能变默认并覆盖原数据 |
| 一致性 | 约束、事务、固定锁顺序、expectedVersion、幂等键／事件 ID | 独立 DB 连接＋同步屏障制造竞争；提交前故障、提交后响应前故障及通知前故障；从新连接读事实 |
| 安全性 | 服务端会话与逐对象授权、CSRF／Origin、输入限额、秘密隔离 | A 账号直接访问 B 数据、伪造 owner／角色、旧 Cookie／Hub 重放、未授权广播；日志与差异无凭据 |
| 可靠性 | 密钥／队列／归属持久、租约重建、快照、维护恢复 | 实际进程／数据库重启；真实 pg_dump→独立还原库→比对；旧凭据拒绝；任何一项未做单列未验证 |
| 扩展性 | 必要唯一／查询索引，有界分页／批次／请求大小；迁移和协议演进；单向模块边界 | 列表／worker 上限与游标、已有合法记录前向迁移不丢；按索引验证关键查询，无真实测量不承诺容量 |

后台邮件、租约、到期房间及 outbox 每批固定上限、按状态／截止／稳定 ID 查询。资源上限与退避可配置并测试，不能一次加载全表或无限循环重试。房间列表采用稳定游标，不返回他人邮箱或敏感实体。协议升级先支持／拒绝版本，再迁移，不从未知 Schema 猜测默认值。

## 6. 备份与还原门禁

普通重启和旧备份还原是两套门禁。B0 准备工具及目标保护，B1–B4 存在真实业务状态后完成还原演练，不仅检查 dump 文件生成成功。

1. 对命名测试库生成虚构 User／Pet／房间／归属／期限等数据，记录迁移版本、行数、稳定字段摘要与外键／唯一约束检查结果。备份写仓库外受限目录，密钥另行受保护保存；生产备份需加密与保留政策，不以开发原型替代。
2. 使用同版本 `pg_dump` 自定义格式备份；在同一隔离实例新建 **独立** `dango_backend_b0_restore` 库，使用 `pg_restore --no-owner --no-privileges --exit-on-error` 还原。原库不改。真实执行、目标创建与维护写入需精确授权；不使用清库／覆盖参数。
3. 还原库强制维护模式：API／Hub 不开放，SMTP／outbox worker 禁止发送。先比对身份、配置、房间、归属、外键、约束及迁移版本，再在恢复事务中撤销旧安全状态。
4. 使用新的仓库外恢复代际与密钥隔离；撤销全部恢复库旧会话、未完成注册、邀请、挑战／邮件任务、公共码与设备租约；所有注册继续证明（含 Completed 重试）核对创建时恢复代际；控制代际提高。公共占位进入无房，合法桌宠／私密团子睡眠，身份与配置保留。
5. 全部恢复账号锁定，维护者核对还原点之后的禁用／注销事实并明确批准可恢复账号；无法确认的保持锁定。恢复锁定独立于 Identity 临时登录锁定。审批只允许专用恢复挑战，绑定账号／邮箱／恢复代际／审批版本；完成事务重验审批和账号状态、消费挑战、更新密码与安全戳并撤销会话后解锁，新密码拒绝匹配旧 PasswordHash。公开找回、注册邀请或旧密码不能自行解锁／解除禁用，审批撤销与完成竞争单列门禁。
6. 独立客户端重放备份中的 Cookie、挑战、继续秘密、邀请、公共码、旧密码和控制代际必须失败；批准后的新密码登录、邀请与新公共码可以重新建立合法状态。维护步骤任一失败不能解除隔离；不能在正常启动时自动批量撤销。
7. 报告备份与还原命令结果、比对结果、凭据失效结果、实际恢复用时及残留目标。停止本次进程但保留数据；任何删除或用还原库替换现有库需另行授权。

B0 约束测试数据不能代表上述 B1–B4 安全演练；完整备份还原门禁保持未验证，直到实际执行并核对。
