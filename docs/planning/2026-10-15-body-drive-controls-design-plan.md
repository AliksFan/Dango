## 2. 范围与非目标

### 2.1 目标

1. 保留主动步态，先用相同物理输入拆开真实轮廓与呈现步态的贡献，再比较水平施力分布；不提前宣布抖动根因。
2. 除首页外，本地可操作场景统一 A／D 移动、Space 跳跃、W 拉伸并向上看、S 压缩并向下看；明确桌宠取得键盘控制的方式。
3. F 是交互键，迁移旧 W 进门／选门入口和所有现行提示；无交互目标时不制造假动作。
4. 捏脸和配饰预览共用玩法键语义。WASD 不调滑块参数；非文字控件焦点上的 Space 操作团子，不能误触应用／保存。
5. 在运动、体态、释放及焦点规则稳定后做 F6 混合配置休眠，再做 F7 房间端点及完整输入验收。

### 2.2 非目标

- 不改身体自然骨架、v6 材料映射、质量分布、摩擦、重力、时间步、求解器保护或跳跃基础参数；不新增身体参数滑块，不调力掩盖短走失败。
- 不取消主动步态，不把仅呈现缩放当作 W／S 真实体态，不通过休眠隐藏行走抖动。
- 不改 appearance.json Schema 4、配饰保存事务、家具格式或设备设置；按键体态是临时会话输入，不写入外观、家具或恢复快照。
- 身体参数不上传／不同步；不扩展服务端协议、数据库、多人碰撞、权威物理、承重公平、云端或跨端。不能宣称新体型、体态或注视已被别人看见。
- 普通房壁纸层继续处于搁置状态；盘点其输入桥并保持键义一致，不以本批宣布壁纸产品验收通过。
- 不顺手修帽子隐藏、布局断言、全套主题／滚动性能、历史 DLL 获取或其它未定位问题；保留问题账本。

## 4. 驱动力首个候选与取舍（待批准）

### 4.1 首选比较

比较 C0「F5 核心单点驱动」和 C1「核心＋全部外围节点按实际质量比例分配」：

- 每个小步仍先按同一输入、接地／空中倍率及既有限速规则算出总水平力 F；不改变 F 的大小、方向或调用频率。
- 从实际物体质量求 M＝Σm_i，给每个物体中心施加 F_i＝(m_i／M)F。包含 core 和全部有效外围节点，不把家具、皮球或配饰计入身体 M，不用轮廓几何中心代替质量中心。
- ΣF_i＝F；对于整体质量中心 R，Σ(r_i－R)×F_i＝0（浮点误差范围内）。这是由该控制器新增的净力矩为零，不代表接触摩擦、内部约束或整个身体不会旋转。
- 无接触、忽略其它力时各点获得相同的驱动加速度 F／M；接地后实际加速度仍由摩擦、阻尼、接触与内部力共同决定，不能承诺完全没有形变。
- 保留原核心速度限速与 air_control_ratio，避免同时改施力分布和限速定义。另记录真实质量中心速度，若核心限速导致 C1 端点偏差则判候选不足，回到设计，不能悄悄改限速。

身体大小仍按已批准恒定二维密度映射，质量随尺寸变化；这里的“统一加速度”指同一只身体各节点的控制加速度相同，不承诺不同大小的团子加速相同。装饰没有身体反作用。

### 4.2 为什么不先上移／下移施力点

核心未必在形变后的质量中心。把同一水平力移至上侧或下侧，会新增与偏移量成正比的力矩；它可能抵消某一方向的倾斜，也可能增强滚动、卸载接地点或使镜像方向不对称。圆形软体的接地点还会随胖瘦、软硬、拖甩和地面／平台变化，固定“往上挪一点”不保证跨组合成立。

按质量分配先去掉“控制加速度只集中在核心”的差别，变量少、合力和控制净力矩可直接检验。若不能改善，保留失败并比较受力／接触证据，再提出有限偏置点等第二候选；本页不预批准扫描高低位置。

| 观察项 | C1 可能收益 | 必须防的代价 |
|---|---|---|
| 接地形变与抖动 | 减少核心先跑、外围后被弹簧牵动的剪切激励 | 向接地点直接施力也可能增加滑移；不是必然更圆或更稳 |
| 滑动／滚动 | 控制合力不过度偏离质量中心 | 接触反力矩仍存在，可能由弹性挪动变为滑动／滚动，不能仅看 coreY |
| 起步、速度与自主短走 | 力分配可能改变传力效率 | 总力不增，速度不一定增加；原 7.5 秒／200 DIP 失败必须实测、不得延时或改目标 |
| 停止距离／反向 | 可能减少收步时核心／外围相对运动 | 分布驱动会改变动量、残留形变和边缘余量；停止／反向独立验收 |
| 大小／胖瘦／软硬端点 | 每体真实质量参与计算 | 柔软端与硬端受益可能相反；默认通过不等于八端点通过 |
| 原生稳定性 | 不改弹簧与保护，候选边界窄 | 所有分支仍须有限数值、有效 ID、合力／力矩、接触连续性、无 -96 和故障锁存验证 |

## 5. 先做分层同输入对照，再决定是否采用 C1

### 5.1 预先冻结的输入与采样

D0 将配置、材料版本、候选 DLL 哈希、编译开关、固定步长／小步、初始坐标／姿态、视口／72 DIP 单位、镜头、按键边沿及采样时刻写入可复算清单。人工键盘走路只作补充；对照必须回放同一时间序列，不各自随机走。

基础轨迹：静置 5 秒 → 右行 2 秒起步＋8 秒持续 → 松开 3 秒 → 左行同序列 → 松开 3 秒；另有左右镜像、短按反向、原三档 7.5 秒自主短走及原跳跃／拖甩回归。长时静置和重复轨迹沿用批准材料／休眠的原始清单，不用新脚本替换旧证据。默认配置加八端点（80／120 × 软0／100 × 胖0／100）；同大小／软硬下补胖中瘦方向检查。

D0 在任何数值试验前固定诊断频带 0.5～5Hz、持续走的第 2～10 秒窗口、去均值方法和指标算法；无足够窗口的自主短走只测原目标，不用于频谱改善结论。原始轨迹也须保留，不能通过滤波或只挑最好时段隐藏低频问题。

### 5.2 2×2 对照

| 驱动 | 仅真实物理轮廓（步态诊断关闭） | 真实轮廓＋原主动步态（最终必须开启） |
|---|---|---|
| C0 核心单点 | P00：物理基线 | P01：F5 观感基线 |
| C1 按质量分布 | P10：驱动差异 | P11：最终候选 |

- P00／P01 的 native 输入及逐帧 native 输出必须位级一致；P10／P11 同样如此。步态关闭只用于隔离诊断，不能作为交付降级。
- 第一步先在 C0 同一物理快照上对照轮廓与步态显示，并分别记录；再做 C1。不能同时调整动画幅度／相位、水平力、材料或时间步。
- 原生层记录 core、质量中心、轮廓上下边界／宽高／面积、支撑关系、节点速度、接触与错误；呈现层记录步态应变、变换后轮廓、眼睛／配饰和相机位移。比较世界坐标与屏幕坐标，排除镜头变化被当作身体抖动。
- 除位移、均高和频带 RMS，还记录节点滚动／轮换接地、切向滑移、接触中断、停止距离、反向起步。不能用宽高看似好看掩盖速度或滑动退化。

### 5.3 建议锁定的选择门槛

以下是本次待批准的门槛；获批后在 D0 冻结，不按结果放宽：

1. 合力相对误差及归一化新增控制力矩残差均 ≤1e-5；零输入无新增力，默认路径禁用候选时与 F5 位级一致。
2. C1 的持续走速度、同时间位移相对 C0 在 ±10% 内；停止距离不增加超过 max(C0 的 10%，1 场景 DIP)。两方向及每个组合分别判定，基线接近零时单列绝对值，禁止用平均数吞掉失败。原更严格门槛优先。
3. 默认配置 P10 相比 P00 的真实轮廓高度 0.5～5Hz RMS 至少下降 20%；八端点中任何一个不得上升超过 5%。持续走平均高度相对同配置静置中性高度的压缩幅度，不得比 C0 增加超过1个百分点，避免更矮但不抖被记为全面改善。同时 P11 的最终显示低频波动不得比 P01 增加，实际步态保持可见；不得仅因眼睛或相机抵消而记为改善。
4. 接地不出现新增无故腾空、穿地、平台漏支撑或持续失控滚动；面积／约束／最大速度、原形态方向、原位移／眼距／留白／视口门禁保持。既有 1.99 DIP 等呈现门槛沿用原测试；不擅自改成新宽松值。
5. 三档自主短走各须在原 7.5 秒与原目标下复测。未达标即留失败，C1 即使改善观感也不能称完整移动验收通过；另需定位自主调度、物理效率等责任，不自动加力。

若原层对照发现主要贡献来自呈现层，记录证据后另提最小步态修订，不直接调动画完成“通过”。若 C1 无改善或伤害端点，保留 C0 和主动步态，停止该候选采纳，回到设计。

## 6. W／S 体态与眼睛的设计候选

### 6.1 物理责任

- 建议保留 S 的现有 Downward 路径：按住施加已存在的向下核心力，接地时自然压缩；空中会影响下落，这是已有物理含义。不把落地体型参数或保存草稿随 S 改写。
- W 新增临时 Stretch 输入，不复用负 Downward、不发 jump、不施加全身向上净推力、不改自然骨长／面积。首选验证有界的内部成对力：上／下方向向外，侧向向内，节点与核心之间沿连线成对施加相反的力。每对合力与力矩均为零，以世界竖直为“上”，不锁定身体姿态。
- 可审阅的首个力形：对节点相对核心的单位向量 n，角向权重为 2(n·up)^2－1，节点力沿 n，核心承受相反反力；按实际节点质量分配权重。上限明确采用 L＝Σ_i‖f_i‖（各节点力的模之和，只计节点一侧、不重复计核心反力），所有力统一比例缩放，使 L 不超过该体配置的 DownwardForce；不能用会相互抵消的节点向量合力作上限。零长度／非有限值走已有故障边界，不能只截一个分量破坏平衡。
- Stretch 输入起效 0.15 秒、释放力衰减 0.20 秒是首候选上限过渡；物理形状本身仍由弹簧／重力／接触恢复，不强制 0.20 秒回圆。失焦／隐藏／故障立即清控制力，不等待装饰过渡。
- 该力形是新主动动作，仅在 W 按住时存在，不能用来修静置漂移或替代圆形材料设计。能量由主动输入提供；零净力不等于接地后质心完全不动，也不保证所有硬端都显著拉长。
- 若安全上限内不能在硬端产生可见拉伸，报告候选失败；不增加力、不放宽伸缩保护、不改材料／骨长以补效果。

首选新增独立的本地模块输入能力，不改变既有六浮点 controls 的含义或步长，也不替换正式 ABI 13。具体采用带明确能力版本的附加 step 导出，一次提交该帧全部实体的 Stretch 输入；旧 step 调用它的中性路径。禁止跨帧残留的隐式 setter。托管层先校验能力，缺失时明确拒绝完整新控制候选，不静默只做眼睛。q＝0、S／Space 旧轨迹必须可与 F5 对照。

### 6.2 眼睛责任

- 同一份解析后输入同时产生物理意图和 gaze 意图：W 的 Y 为 -1（屏幕向上），S 的 Y 为 +1；松开释放该 token 的 gaze 通道，交还原朝向／待机注视。不会改 EyeLayout、颜色、眨眼或眼睛形状配置。
- A／D 与 W／S 可形成斜向看；仅上下按键时保留原左右朝向的注视，不无条件将 X 清零。沿用附件弹簧、眼界安全范围与变形后的 FaceLayoutSolver，不能为保证满幅而把眼睛移出身体。
- Runtime 持有临时手动注视 token／generation 和序号，输入变化时提交，不在每次系统键盘 repeat 中堆命令。只拥有 LeftGaze／RightGaze，不用 Release(All) 取消眨眼、比较表情或帽子。
- 手动注视高于自动待机；开始手动输入先取消自主动作／打盹。显式比较工具保留自己拥有的表情通道；如某工具实际占用 gaze，则开始 W／S 时结束该临时 gaze 比较，手动取得通道，松开回到普通状态，不自动重播比较。不让“身体动了眼睛没动”的通道争用静默发生。
- 物理失败时只保留最后合法物理及对应呈现，不让注视继续假装控制成功；清输入／token 随已有显式恢复流程处理。附件单独失败则按已有附件故障报告，不把它写成物理已通过。

### 6.3 按住、松开与组合键仲裁

| 输入 | 建议行为 |
|---|---|
| W 或 S 按住 | 连续体态＋上下看；不依赖键盘重复率，不自动触发多次动作 |
| W＋S | 两种物理体态及垂直注视都中性；仍视为有手动按键，取消自主动作且阻止休眠，不能因合成结果为0而误睡。松开一键后剩余键接管 |
| A＋D | 水平力中性，保留最近有效朝向；仍是手动占用，不启动自主走。松开一键后另一键接管 |
| A／D＋W／S | 水平与体态同时生效；上下看结合左右朝向。主动步态控制器保留，但主动体态期间暂停其额外压缩／舒展，避免双重形变；松开体态后重新采样并按原进入规则恢复步态，不改步态幅度 |
| Space | 新的按下边沿请求一次既有跳跃；长按、repeat 不反复跳；保留接地／冷却。W 绝不别名跳跃 |

| Ctrl／Alt／Win／Shift 组合 | 不产生新玩法动作；进入修饰键组合时清玩法占用，保留系统快捷键和既有 Shift＋鼠标轻抚；释放修饰键后不补发旧玩法按键 |

## 8. 焦点、保存误触和防粘键

### 8.1 桌宠键盘控制的首选方案

由于旧合同明确不抢工作焦点、无全局玩法键，建议在桌宠菜单增加显式“键盘控制”入口，打开一个可聚焦、短提示的本地控制面板。面板只转发命令给现有 room driver，继续由同一 Runtime 推进；不新建团子、物理世界或全屏输入层，不把透明团子窗口永久改成会抢焦点。

只有面板前台且会话有效时接收 WASD／Space／F。Esc 或“结束控制”退出，面板失活／隐藏／关闭、桌宠双表面失效、返回门廊均立即结束会话并清输入；不注册新的全局键盘钩子，不在用户工作应用打字时捕获按键。重新进入必须重新按键。这是待批准的桌宠交互增量，不是当前已实现能力。

### 8.2 编辑器统一路由

| 焦点／上下文 | WASD／Space／F | 参数／按钮正常键盘操作 |
|---|---|---|
| 团子预览、参数 Slider、页签、普通非文字按钮 | 窗口预览层先识别保留玩法键并消费，统一给团子；F 无目标也不应用草稿。按住 Space 再移到应用按钮，松开不得产生 Click | 滑块仍用方向键、Home／End 等原合法路径；按钮用 Enter、鼠标或辅助操作显式激活；Tab 焦点可见 |
| TextBoxBase、PasswordBox、可编辑 ComboBox／数值框、富文本、IME 组合输入 | 开始文本输入前清玩法；WASDF／Space 交给文本及组合输入，既不操作团子也不禁止正常输入 | 原 Enter／失焦提交与非法值反馈、文本选择／编辑快捷键保持；不把文字写入日志 |
| 弹出菜单／模态确认／文件选择、图片画布独立工具 | 清玩法，交给对应上下文 | 模态内 Space 可正常激活该模态按钮；不能穿透操作下层团子或应用外观草稿 |
| Slider／滚动条正在鼠标拖动、拾取附着点 | 清玩法且抑制直到释放，参数直接跟手，不混入游戏动作 | 按原拖动／捕获合同，Esc／失焦终止；滚轮按 UI 规范 §5 分配，不触发团子 |

捏脸与配饰使用同一个规则，移除“编辑面板所有后代一律阻断”与“Space 在普通按钮上优先保存”的差异。此处**非文字按钮 Space 改为跳跃**是明确的编辑预览业务例外，应在提示／辅助说明说明 Enter 激活按钮；不扩展到设置页、首页或模态窗口。鼠标和 UIA Invoke 保存仍进入原保存事务，不绕过身体显式预览门禁。

### 8.3 生命周期与释放顺序

1. 同一输入 session 记录每个已消费键的持有状态、是否被抑制、当前场景 generation。KeyUp 先释放自己持有的键，即使焦点已移至文本、出现修饰键、控件标记 Handled 或场景进入阻断，也不得被早退过滤。
2. 切页／打开编辑器／转场／隐藏／最小化／失活／关闭／Runtime.InputCancelled／失去物理 owner／故障／世界重建前，统一清运动、体态、跳跃边沿、F 边沿、注视 token、指针捕获和自主接管状态。
3. 清理后对当时仍按下的玩法键抑制到对应 KeyUp；恢复焦点／显示／owner 不从系统当前按住态补发动作。即使释放发生在别的应用，重新激活也必须观察中性后才接受新的按下，不能靠 repeat 重启。
4. F 或 Space 按住跨场景、键盘 repeat、延迟排队输入及旧 generation 事件不能在新场景二次触发。所有入口只有一个解析后的输入 owner；WorkerW、Wallpaper 桥与前台窗口不可同时消费同一按键。
5. 清理不得保存草稿、重置身体材料或偷偷恢复旧参数。身体预览／取消恢复失败仍按 F5 阻止离开；输入清理本身不把恢复失败改成成功。

## 9. 实施顺序、文件所有权与依赖

推荐链：**D0 设计批准与门禁冻结 → D1 分层／水平驱动候选 → D2 体态与统一输入／注视／F 接入 → D3 本地全场景输入稳定 → F6 混合配置休眠安全 → F7 房间端点联合验收**。

## 11. F6：混合配置多体休眠安全前置

1. 以最终选择的水平驱动、体态能力和输入规则作为“休眠关闭”基线，再比“休眠开启”。材料与力不再同轮改动。
2. 保留 §7.5 的 -96 原触发时间线；容量3、每体独立配置，至少覆盖本人80/50/0走动入睡／唤醒，默认伙伴、八端点轮流作本人，以及120/100/0和其它极端混合。不能只测容量1或三只相同配置。
3. W、S、A／D、Space、相反键同时按住、拖动、参数重建、平台变更、球／团子接近都走同一活动／唤醒责任；W 在新输入布局中必须同时接入原生休眠的输入判定，不能只改托管 HasDirectionalInput。
4. “全部可暂停”与“部分休眠而其它团子／球仍运动”分开。单体 freeze-only 不能直接当作多体方案：跳过自有力并不保证 Box2D 不积分该体；全 world 暂停也不能冻住其它醒着对象。先验证无接触记录破坏的局部冻结／恢复机制，再允许开启；不能以忽略 -96、重建 world 或清空速度掩盖连续性问题。
5. 按休眠设计 §7.6：不误睡（前0.5秒位移＜0.003 world且无活动输入）、不漏睡（连续1秒的严格静止条件）、0.10 world内整组一致、休眠逐位不变、有效唤醒与醒着路径对照。原生 T_rest／v_rest／d_rest 仍为原批准值，不重新启用“多久入睡”统一硬时限。
6. 运行原39场景与受影响轨迹并增加混合配置；多体位置差≤0.05 world、支撑不变、无穿模／错误承重。先核对休眠关闭基线是否满足场景前置，再归因差异。§9 已有混合体型持续下压约0.26 world差异并未获容差批准，必须保留失败，不把它沿用成0.05以内或“原版也这样所以自动通过”。
7. W／S 释放后可再休眠；持续按住即使形状停住也不睡。醒来不补跳、不延迟跳跃、不恢复旧 gaze token。原生错误、非有限数或任何门禁失败时，产品休眠保持关闭／拒绝该候选，并报告阻塞。
