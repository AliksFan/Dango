# 圆形材料：静置水平漂移的被动观测方案

2026-10-10。**用户明确回复“批准，按方案推进”，授权本方案的隔离实施、固定观测和复核顺序。该顺序已完成：实际 DLL ON/OFF、精确账本、19 个语义反例及独立审查通过，按停止点回到设计复核。** 详见[观测结果](../verification/2026-10-10-round-material-idle-displacement-trace-result.md)；这不代表原稳定性或人工验收通过。当前分支 `codex/round-material-sample`，基于 `830e5e3`。本方案承接[算子尺度证书方案](2026-10-10-round-material-null-certificate-scale-candidate.md)第 5 项的固定失败复核，不授权新的物理算法或恢复后续验收。

## 问题与目标

[实际 DLL 默认长测](../verification/2026-10-10-round-material-operator-certificate-result.md)完成 36,000 帧，水平跨度 `0.018514716299250722`，原门槛 `<0.003` 失败；首次超限为第 6,301 帧。最后小步的证书和物理门槛通过，但该局部证据不能解释累计漂移，也不能证明全期 α 都为零。

本轮只回答：从初始化至首超限，核心和全部 17 体的水平位移在哪些执行边界累计；哪些速度变化、接触状态和反力选择伴随这些位移。先形成可独立复算的账本，再决定是否需要更细的内部观测或新的修复设计。

固定默认大小 100／柔软度 50／停稳 90、模式 7、四个已批准候选宏、步长 `.0166666f`、零输入。每次世界仅运行至第 6,301 帧，预期 100,816 个小步，保持原采样规则和首超限门槛。包括初始化和落地阶段，不跳过早期帧。

## 观测边界

观测只复制现有数据，不重复求解、重新裁定、调整运算顺序或把诊断结果写入物理状态。增加私有观测开关，关闭时保留当前候选路径。默认无宏模块保持原路径；新产物使用独立目录，保留已有失败证据和受保护 DLL。

| 边界 | 必须记录的状态与用途 |
|---|---|
| 初始化、每小步开始、施力后／Box2D 前 | 17 体世界坐标、线速度、实际质量；区分施力阶段是否直接改变速度／位置 |
| Box2D 后／adapter input | 实际积分后的坐标和速度、已有地面 receipt；材料力和 Box2D 的合并边界 |
| positioned | 候选位置副本、速度、位置迭代数；计算本小步位置校正 |
| damped | 耗散／被动自旋后的副本；记录速度变化及动量变化 |
| contact double、float／uncapped | 已经计算的 double 速度与转换后的 float；记录实际反力、模式、有效性和转换差额 |
| cap output | 最终候选状态、cap scale、物理检查与可用性 |
| 实际写回后、外帧读取／发布 | 读取真正的 body 状态；记录候选与实际写回的差额、全部 42 个公开 float 和发布状态 |

所有数据以实际执行标记判定可用性；未执行状态为缺失，不能当作零。尤其不能仅用 `phase=4` 推定块构建或反力选择已执行。全部已执行模式的 α 选择事件按顺序记录：可用状态、零／非零、值、首个非零事件、极值与数量；满秩、未选择及失败路径分别计数。

账本分别保留位置差、速度差、冲量／动量及其单位。耗散、contact、float 和 cap 当前不直接移动位置，它们本小步的位移应为零，但改变下一小步积分的输入速度；零位移不能排除累计作用。材料＋Box2D 段包含材料力、重力、Box2D 接触、缓存和 float 积分，观测到该段漂移只能定位边界，不能直接归因为其中一项。α 为零不能排除特解反力的速度作用。

## 全期账本与有限存储

逐小步保留全部 17 体的紧凑边界数据、receipt、执行标记和选择事件，按帧／阶段累计有符号位移、绝对位移、速度差、动量差和事件计数。质量取实际 `b2Body_GetMass` 并核对全期不变；物理质心用固定实际质量和世界坐标计算。公开轮廓几何 centroid 与物理质心分开记录，不混用。

每小步从实际开始状态依次穿过候选边界，最后写回项只计算 `实际 body 位置 − 候选 output 位置`，避免把候选校正再次计入。另记录上小步实际末态至本小步开始的连续性差额，以及外帧读取／发布差额。

全期紧凑记录用于独立复算，不能用窗口样本代替。完整矩阵／pair／证书等大诊断仅保留固定窗口第 1–4、597–604、6298–6301 帧，以及首个非零 α 和首个观测错误的小步（若出现）。流式写入并设本轮总证据上限 512 MiB；这是上限，尚未证明容量足够。运行前锁定二进制记录宽度，按 17 体、16 receipt、每小步最多 32 个模式事件核算，覆盖 ON/OFF 数据、256 个固定窗口小步、最多两个额外异常小步、元数据／索引／校验及反例。反例可采用最小独立夹具或稀疏修改副本，并计入总成本；不能省略全期原始记录。最坏容量超限即停止设计复核，实际超限或写入失败判为观测失败，禁止丢样或减少模式事件后继续声称通过。文件以独占创建保存，不覆盖旧证据。

## 可失败的验收

1. **轨迹不变**：同源、同配置、同输入、同编译选项的观测 ON/OFF 实际私有 DLL，比较全部 `6,301×42` 个公开 float 原始位型。物理执行、求解／模式／消元／行访问及证书成本的整数原始计数一致；仅新增观测成本和实际耗时另记，耗时不作相等比较。任一差异先判观测失败。
2. **边界完整**：初始化、100,816 个连续小步和 6,301 个外帧数量完整，无缺失、重复、错序或错误阶段可用性；每小步实际末态与下一开始衔接。按原 96 个采样点复算第 6,301 帧首次超限及其跨度。
3. **位移闭合**：每体、核心及质量加权质心的阶段账本能重组小步、外帧及全期端点。使用从存储值、累加运算次数和数值尺度推导的浮点误差界，并以独立高精度复算核对；该界仅验证账本，不替代或放宽 `.003` 物理门槛。
4. **反例有效**：独立复核工具必须拒绝删掉一个阶段差额、重复位置校正、错置速度为位移、漏小步、错帧／阶段、错质量、未执行 α 当零及篡改公开 float 的证据。反例修改证据副本，不改物理实现。
5. **结论有限**：报告全期阶段贡献、速度路径及接触／α 统计，指出已定位边界和仍未区分的内部原因。相关性不能写成唯一根因；本轮观测通过也不表示候选稳定、甩动修复或人工验收通过。

2. 在新的私有目录构建 ON/OFF 模块和匹配宏／布局的实际 DLL 读取器；记录源码／DLL／工具哈希、编译选项、诊断大小和 canary。所有世界操作来自动态加载的实际 DLL，不用源码等效程序替代。
3. 执行固定 ON/OFF 轨迹、逐位与成本比较、全期账本复核及证据反例；默认无宏模块做受影响兼容验证。观测不一致、账本不闭合、容量不足或原生故障时保存首失败并停止，不能继续调参或扩大运行。
4. 保存独立审查与结果文档，可创建本地提交；销毁本轮测试世界、卸载 DLL 并报告进程残留。无服务、数据库、账号或外部资源操作。

本轮完成即回到设计复核：提出证据支持的下一方案，另行批准后才能修改物理行为或恢复长期／甩动／参数组／WPF 验收。保持原自然圆形目标、认可落地轮廓、拖动体验和原门禁；生产捏脸与持久化、正式 DLL、日常安装、合并 main、推送和部署不在本轮范围。
