# 普通房皮球与多家具接入

日期：2026-10-10。状态：用户已通过上一轮普通房家具人工验收，并明确“搞皮球”、多件家具总上限 30、仓库双击生成预览确认后添加、重入球恢复确认摆放位置。本轮按这些业务规则实施独立本地候选；技术合同与失败门禁如下冻结。未实施或未验证的项目不提前标记通过。

## 来源与范围

起点 `63f1222`，包含已通过普通房单平台实现 `776ed4b`、235/235 Release 回归、600.054 秒完整有效观察与用户功能人工通过记录。独立分支 `codex/furniture-ball-room` 保留上一轮验收现场；不纳入当前 main 上其他并行工作。

本轮为 Windows 主程序普通房、本地单人、同一只原造型团子、同一物理世界与唯一帧 owner。家具仅官方木平台与已验收刚性皮球，允许同类型和混合实例，合计最多 30 件。球沿用 q 度量半径 1.1、质量 .02、球重力 .5，名义直径 132 DIP，材质与球面不授予接地／起跳资格的规则保留；不接入新团子模型或可调参数。

本次明确扩大了旧单球设计中的“球与平台互斥、最多一颗球”范围。旧试窗、旧 ABI 尺寸、单平台通过证据及生产 DLL 保留；不能只删除互斥判断，也不能将旧单球通过当作本轮混合接触通过。账号、多人、云保存、自定义家具、桌宠／壁纸房家具仍在本轮之外。

## 已确定的交互与保存

- 仓库保留两列实际家具图片，双击该项创建一件独立 GUID 的新预览，单击不添加。单次只保留一个预览；确认后才提交真实家具和文件。快速重复操作不能重复提交或突破上限。
- 30 件达到上限后仅禁止新增，仍可选中、移动和直接删除。计数以已提交布局为准，未确认预览不占实际实例。辅助操作与双击进入同一个新增路径，不穿透为团子跳跃。
- 场景选择具体 GUID，木平台按矩形命中，球按 native 当前真实圆命中；球在编辑期间继续运动。移动预览不改变真实物体；确认移动球时仅该球进入目标锚点并静止，其余球、团子和世界保持连续。
- 预览与最终确认均拒绝正穿入，允许相切。最终按最新实际物理步检查团子、其他家具、边界；另检查保存锚点之间和固定出生区，保证重入可以恢复同一布局。不能因球已滚走而将平台保存到它的恢复中心里。
- 球保存的是确认的布置中心，平台是顶面中心。球运行中心、速度、角度、角速度、休眠、接触以及相机和抓取不入布局文件。离房卸载不写文件或加版本，重入从布置中心静止创建球；隐藏恢复保留当前真实状态，不补算隐藏时间。
- 每个 Insert／Move／Delete 单独提交；改变一个实例不得覆盖其余实例。平台移动到完全相同的保存锚点为无保存变更，不增加文件版本；球可能已滚走，确认搬回同一保存中心仍是一次真实落位操作，记录一版并只清该球运动。新的确认请求、冲突、去重和溢出仍按完整操作内容检查。

界面采用 `docs/desktop-ui-design-v0.1.md` v0.1 §§2–6：暖白与棕色语义资源、图标操作和中文提示／辅助名称、微调／后续参数／仓库三段侧栏、固定确认反馈和常驻细滚动条。仓库是实际内容图片这一已批准例外，不为球另造操作图标。参数区仍只说明后续开放，不暴露本轮内部物理量。

## 领域与旧文件合同

普通房 writer schema 2 使用有序、深复制且结构值等的多类型 `items`。实例包含非空唯一 GUID、官方预设 ID／修订和合法锚点；球逻辑半径 66，平台尺寸 272×21，坐标仍为 room-floor-height-v1。总数 0–30，最大文件 64 KiB，严格字段和有限数校验，未知类型／修订／身份／版本及重复字段不能覆盖为默认布局。

同一普通房 schema 1 的空／单平台文件可严格读为内存多件模型，保留原版本、operationId、GUID、锚点和原文件字节。仅一次成功编辑自然写 schema 2；读取、开编辑器、隐藏和换场不迁移落盘。独立 Trial 的 schema 1、p 坐标、旧路径及 0／1 件限制保持，不能互读。保留现有独占 lease、原字节冲突检测、临时写入、原子替换与 Unknown 保护。

## 同世界集合能力

新增可选家具 collection ABI，不修改旧 ABI 的签名或布局。collection 最多 30 槽，稳定运行实例 ID 与持久 GUID 显式映射；球定义／状态使用 q，平台使用 p，绘制与鼠标投影共同转换到现有房间逻辑坐标。所有家具与团子读取同一世界 generation、scene revision 和 physics step 的完整帧，不能拼接多个时刻的读帧。

单操作 probe → prepare → 文件 commit → apply/read → 发布沿唯一 owner 步边界执行；Prepare 不改变物体，Apply 无临时求解或新分配，移动保留 ID，删除使 ID 失效，拒绝／取消保持原状态。运行能力缺失时空房可正常游玩但不能编辑；非空布局必须真实载入，不能静默进入无家具房。旧单件读帧或变更不能截断／破坏 collection。

每个固定子步联合处理团子－各平台、团子－各球、球－平台、球－球及边界，采用简单形状预筛和稳定顺序，不新增依赖、世界或调度器。统一检查穿透、有限性和已冻结速度限制；失败停止输入，发布整组最后安全状态。无集合时原无家具与旧单件轨迹不变。删除平台清旧支撑，球面仍不授予起跳，球睡眠与唤醒由 native 真实执行。

原保存恢复状态机继续区分 Synced、Staging、PersistedNotApplied、CommitUnknown、RuntimeUnknown。已保存未应用只核对／恢复真实运行，不重复写文件；未知字节保留原件，未知世界停止 owner，不自动重建掩盖失败。

## 并行所有权与交付

native 与 Physics 由一名协作者负责；Core/Store 由一名负责；Panel/View/Window/共享球图片由一名负责。Session、runtime bridge、统一构建、产品验证、文档与集成本地提交由 root 顺序整合；共享构建目录不得并行写入。测试与构建均使用任务独占 artifacts，候选 native 另行固定 hash，禁止覆盖受保护生产 DLL、改变旧脚本候选 hash 或日常安装。
