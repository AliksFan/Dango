# 桌宠房间：本地单人增量

日期：2026-10-07。用户在选择桌宠／壁纸优先、明确单人为主要体验且局域网仅为联机手段后，明确要求「开始桌宠房间的开发，你直接开始」。本轮从已核实的 `main@8ff78e0` 独立实施。以下是该授权范围内的具体交付与验收，不改变既有正式多人房间规则。

## 设计与范围

- 门廊保留普通房，并新增明确标识「本地单人」的桌宠房门。靠近按 W 或点击进入；当前没有账号、服务端目录或多人准入，不产生虚构权威归属。
- 桌宠显示在本机壁纸层，沿用已认可团子、外观、待机、步态、点击／轻抚与可选键盘控制；桌面原有内容保持可操作。场景不绘制普通房背景，也不增加窗口／文字／平台识别。
- 所有场景共用既有 runtime／实体，仅一个活动帧驱动。门廊先停止输入和帧驱动；WorkerW 挂接且当前代际的新健康身体帧实际应用后才揭示目标、开放输入并收起控制中心。旧 LastFrame、Show、Loaded 或任意回调均不单独代表就绪。
- 右键自己的团子提供房门、隐藏和控制中心；托盘统一处理当前本地房间的恢复、隐藏与房门。回门廊是本地导航，隐藏保留本次选择、清输入并停止运行；恢复重新验证有效首帧，过期回调失效。
- 挂接失败、首帧超时或宿主失效时保留首页／门廊或托盘恢复入口，不静态演出或无限等待。重启继续既有首页承接；本轮沿用已保存外观及偏好，不新增房间／位置存档。

正式账号、固定访客／离线留宿、数据库、局域网、多人状态、位置持久化、桌面平台和普通房壁纸仍属于独立增量。本轮不会以本地显示冒充这些能力；普通房壁纸继续此前搁置安排。

## 分工与顺序

1. 先建立原实现能够失败的门廊入口、世代与单一帧驱动用例。
2. WorkerW 负责人复用现有宿主，补首帧交接和自身右键菜单接缝；新专项测试独立。
3. 集成负责人独占 Home／Host／Porch／Tray，将两种本地房间串入同一生命周期，增加隔离候选入口。
4. 集中构建与受影响回归，核对真实 WorkerW、输入资格、隐藏恢复及返回；设备或前台条件不足的项目如实未验证。

## 可失败验收

- 普通房门与桌宠房门独立且距离限制生效；本地门不改正式 Authority。
- 新首帧之前源保持可恢复，失败或迟到成功不会隐藏错误源。
- 进入、隐藏／恢复、返回和换房后保持同一 runtime／实体，活动 owner 至多一个；隐藏后输入清空且不推进物理。
- 新宿主清理上一场景物理边界，显示完整有效团子与当前已保存外观。
- 自身右键到房门／隐藏／控制中心；图标、任务栏与其他应用输入不会被非必要拦截。
- 隔离候选使用独立设置与实例标识；保护 DLL 不替换；普通房窗口、捏脸和门廊受影响回归保留原断言。

结果分别报告自动／Native、真实桌面、人工、Git 和日常安装。候选待用户人工验收；本轮实施授权不包含 main 合并、推送、日常安装更新或部署。
