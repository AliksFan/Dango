# 本地模式收口需求草案

日期：2026-10-15。状态：首批范围与[产品决策](2026-10-15-local-online-product-decisions.md)已确认；本地目录、门廊入口、安全位置／本机镜头及纯本地解散恢复子集的[具体设计](2026-10-15-local-room-catalog-save-design.md)已通过，并按[实施计划](2026-10-15-local-room-catalog-save-plan.md)形成候选，见[验证记录](../verification/2026-10-15-local-room-catalog-save.md)。该子集当前候选已获用户人工确认；其余细化需求和整体收口批次仍供审阅，不据此扩大产品实施范围。

## 1. 目标与范围

网络较差、断网或服务器不可用时，用户能持续使用一只团子，完成单人互动、捏脸与配饰编辑、普通房和桌宠房游玩、符合资格的家具编辑、本地新建普通房，以及可靠保存和重启恢复。

首批复用已有能力并补齐闭环。本地新建普通房、目录和额度是新增需求；穿搭方案管理、配饰分享、新家具行为、社交、手机、完整双向同步和新物理实现不纳入本批。账号同步只细化数据边界和失败契约，不运行服务、数据库或真实账号数据。

配饰Windows本地第一版已完成人工验收并合入本地main，作为已完成基线引用，不重新立项或要求整模块重新验收。后续仅对本轮实际改动影响的配饰接线、存储或宿主路径做回归；配饰账号同步、分享等仍是独立后续范围。

本地使用状态与正式房间归属分开；不能由本地窗口、缓存目录或头像推定服务器准入成功，也不新增“个人空间”房型。

## 3. 功能需求

### L01 启动与本地可用性

未连接账号、网络不可用或服务器异常时，可进入已有本地功能；网络等待不能阻塞单人输入和本地保存。首次没有文件时生成可理解的默认内容，损坏／未来版本文件则保留原件并提示恢复，不能伪装成首次使用。

本地物理模块自身不可用时，保留首页、诊断和恢复入口，明确失败；不得用静态团子冒充真实游玩。已确认保持首页启动并记住上次房间选择，不自动入房。

### L02 单人身份与场景交接

首页、门廊、普通房和桌宠房使用同一只本地团子与受控运行实例；目标获得本次健康首帧和输入资格后才完成切换。桌宠房环境与上层团子共享同一世界、映射和帧owner。

失败、取消、迟到回调、隐藏及显示配置变化均须清理手势和旧输入，提供可操作的恢复或返回入口。正常切换不改变已保存外观，不生成正式在线占位。

### L03 陪伴与输入

保留已有点击、抚摸、拖动、自主活动、困倦／睡眠和唤醒路径，人工操作优先。普通房沿用A／D移动、S轻压、空格跳跃及现有视角规则；桌宠房沿用局部鼠标互动，不添加全局玩法键盘。

表单、调色盘、配饰图片画布、菜单和弹窗拥有自己的输入，不能同时触发移动、跳跃或进门。首批核对现有回应和退出条件，不新增呼吸变形、攀爬或动作性格。

### L04 捏脸与配饰

配饰部分为已完成基线的保持要求，不是本批待开发功能。既有验收见[配饰第一版本地整合](../verification/2026-10-09-accessory-v1-main-integration.md)，包括本地保存重载；本批若未改动或影响这些路径，沿用该结果。

预览、应用、取消、复位和真实保存结果继续按已有页面合同执行。已应用外观与配饰在切换场景和重启后恢复；基础眼睛参数与临时表情分离。

配饰图片保存在内部资产库，原图移动或删除不影响已保存内容。配饰删除保留双重确认，单独提交目标删除，不顺带保存其他未应用修改。取消本次离线布局草稿方案不删除这些已有编辑语义。

### L05 本地房间游玩与家具资格

沿用桌宠房／普通房区分，普通房以独立窗口呈现，不恢复已移除的普通房壁纸入口。桌宠房暂不增加家具。

容量1且仅房主能进入，或从未邀请／开放入场的普通房，可离线编辑。已开放多人普通房可用最后可用缓存单人游玩，家具只读；房内动态活动不回写在线状态，缓存其他团子不冒充实时在线角色。

本地资格未知、账号归属不明或存档受保护时，不凭当前只有一只团子开放共享布局编辑。联网恢复后先确认房间最新状态，再提供真实在线编辑能力。

### L06 新建普通房与统一额度

本地可创建普通房，不新增房型或独立额度；当前使用档案统一最多3间未解散普通房，桌宠房不占额度，满额先解散一间。新建房取得稳定本地身份，保存布局和必要目录信息；没有云端确认时只能表达本地创建成功。

新房首轮保持尚未对外开放。私密／公共类型及容量沿用产品规则；选择上限1不自动赋予仅房主可进入的含义。未来开放邀请／入场必须在线完成并同步当前布局。

解散和恢复沿用现有后果说明、二次确认、释放额度及7天恢复规则；恢复重新检查额度，不自动迁回团子。移除本机缓存不等于解散服务器房间，也不能据此释放账号额度。已关联房间的正式解散须以服务端确认为准。已确认纯本地未关联房间可离线解散并释放额度，7天内可恢复，到期只关闭常规恢复入口并保留底层文件；满额而当前无法完成有效解散时，继续游玩已有房间，不额外创建第4间。

不得由离线时钟跳变触发不可恢复清理。离线恢复计时和跨设备目录冲突在实施前细化，首批不执行真实持久数据删除。

### L07 保存失败与恢复

每次保存区分未应用编辑、当前生效内容与最近成功持久化内容。布局提交沿用当前逐操作合同，保留已保存未应用、结果不明和受保护状态的恢复能力，不用“已保存”覆盖不明结果。

写失败、部分图片不可用、未知格式和中断不能静默丢失旧数据；恢复前保护原件。对已经完成的删除或提交，离开页面不能宣称全部撤回。账号连接失败不阻断上述本地恢复。

## 4. 保存与重启恢复清单

下表区分已确认选择与其余建议。普通房的安全位置、本机镜头及首页启动已确认；桌宠房的进一步跨进程恢复等仍按第8节审阅。

| 内容 | 建议保存与恢复要求 | 当前边界 |
|---|---|---|
| 已应用颜色、基础眼睛参数 | 恢复最近成功保存值 | 已有独立存储，复核完整闭环 |
| 已保存配饰、图片、佩戴和排序 | 完整恢复；不依赖原图路径 | 本地第一版已完成，引用原验收；仅实际受影响时回归，保持现有参数和坏文件保护 |
| 普通房目录、身份、类型、容量、解散状态 | 每房独立，恢复不串房，最多3间有效房 | 新增需求；不能把本地目录当服务器事实 |
| 已确认家具实例与布置锚点 | 逐房恢复平台／球布置 | 保留现有最多30件和球回布置锚点规则 |
| 球的临时滚动位置、速度 | 首批不作为新的跨重启存档；继续从布置锚点恢复 | 不把运行态同步冒充布局保存 |
| 本地团子落点 | 普通房已确认保存安全逻辑位置，失效时回退安全出生点；安全核验见具体设计 | 当前入房重置和内存resume不能作为跨重启证明；桌宠进一步恢复另列 |
| 房间视距、镜头模式和手动视角 | 普通房已确认按房间在本机恢复，映射变化时安全约束 | 本机内容，不复制本机像素坐标到其他设备 |
| 个人偏好与设备设置 | 本地恢复，账号／设备字段分开 | 延续设置格式兼容和sidecar保护 |
| 拖动、按键、当前预览、跳跃过程 | 不重放输入和抓取，不序列化整个物理世界 | 编辑取消和会话恢复分别遵守原合同 |
| 困倦、睡眠、自主活动阶段 | 普通房本批不保存睡眠阶段，按正常运行规则重新进入，不按离线时长补算动作 | 不据此改动正式在线房的离线睡眠占位 |
| 上次房间和启动入口 | 已确认保留选择信息；恢复内容不等于自动入房 | 首页启动，仍须主动进入 |

隐藏恢复与进程重启分开验收。隐藏按现有暂停／恢复合同保留会话；重启从已保存配置安全构建，不要求还原每个物理节点、速度和接触缓存。

## 5. 双向同步契约

本节规定后续同步实现必须满足的边界，首批只完成契约设计。

| 类别 | 上传／下载边界 | 冲突或失败 |
|---|---|---|
| 账号内容 | 外观、配饰及必要图片、已实现的方案和个人偏好可双向同步 | 保存本地后再同步；基于双方共同版本判断变化，冲突项保留两份供选择 |
| 设备设置 | 窗口位置、显示器、DPI等仅本机 | 连接账号不能覆盖另一设备的环境 |
| 房间目录与新建／解散 | 稳定身份关联，统一3间额度，防止删除状态被旧设备复活 | 云端确认前不声称注册／删除成功；不靠本机缓存证明全局额度 |
| 允许离线编辑的普通房布局 | 按房间身份和版本同步，开放前完成当前布局同步 | 最新服务端状态已开放、权限变化或版本冲突时拒绝旧离线覆盖 |
| 已开放多人房布局 | 在线有权编辑者经最新房间状态和碰撞复核后提交 | 断网立即失去编辑能力；不保存待重连自动回放的家具操作队列，已发请求结果不明时先查询真实结果 |
| 共享运行态 | 在线归属、成员、位置和互动由服务端裁定 | 本地单人游玩不改写在线占位，不上传离线物理轨迹 |

个人内容按需显示“已保存到本地”“待同步”“同步失败”或“需要选择”；未接入真实服务时不展示“已同步”。联网家具提交与个人设置保存使用各自的真实确认结果。

身份、内容版本、图片引用、幂等与中断恢复的字段格式由后续技术设计冻结，不在本次创建数据库表、API或凭据。账号切换须隔离本地数据，首次关联保护两端已有内容。

多设备离线创建可能使双方目录合并后超过3间。建议停止自动关联冲突房间、保全各自内容，明确要求先腾出额度；不得静默丢房、突破云端额度或偷偷另增本地额度。冲突期间如何呈现和游玩这些内容仍待定。

## 6. 界面约束

遵循[桌面界面规范v0.1](../desktop-ui-design-v0.1.md)：第2节暖白与棕色细强调，第3节稳定布局和可达操作，第4节真实状态与输入边界，第5节常驻细条和滚动规则，第6节真实窗口与辅助设置验收。

本地／在线状态及家具只读原因用简短真实反馈表达，不新增常驻诊断卡片或离线草稿／发布页面。捏脸、配饰、设置沿用各自已批准的布局差异；本轮没有新视觉主题例外，也不授权批量改版。

用户已要求本轮新建、解散、恢复及房间选择等功能入口全部融入门廊场景。入口归属房门、空门位或场景标牌，必要表单与确认使用临时浮层；不以常驻目录侧栏或独立管理页面承接。具体设计见[门廊场景方案](2026-10-15-local-room-catalog-save-design.md#7-界面方案及规范引用)。

## 7. 后续验证与交付批次

以下为需求审阅后的候选顺序，不是已批准实施计划。每批先定义能在错误实现下失败的验收，再在独立环境实施。

已完成模块引用其原验收和整合记录，不把未受影响模块重跑全部历史测试或再次人工验收作为额外收口前提；工作流规定的变更批次必要门禁仍须执行。新房间目录、物理接入或存储变更确实影响既有模块时，先明确影响范围，再补相应回归。整体Windows、性能等未完成门禁单独保留，不据此把配饰本地第一版重新标成未完成。

| 批次 | 目标 | 必须能失败的验收示例 |
|---|---|---|
| L0 本地入口与交接 | 服务不可用仍可单人使用，失败可恢复 | 虚构隔离配置下覆盖未连接、连接失败和服务不可用；旧帧冒充就绪、重复owner、返回后遗留输入均失败 |
| L1 内容保存与重启 | 补齐新增保存／恢复路径；已有外观、配饰、家具和偏好按实际影响定向回归 | 新增或受影响路径写失败不丢原件、重启可恢复；未应用外观不得保存；家具取消不回滚此前已提交操作；配饰本地第一版未受影响部分沿用原验收 |
| L2 房间目录与额度 | 新建、解散、恢复、逐房布局与本地资格 | 第4间拒绝；解散释放额度；恢复满额拒绝；不同房间存档不串；已发邀请／有效公共入口／睡眠成员不能因只剩房主在线而放开离线编辑 |
| L3 恢复细化与真实体验 | 在已批准恢复选择下复测普通房与桌宠房 | 隐藏与重启分开；球回布置锚点；失效落点安全回退；桌宠双表面同步就绪；真实键鼠、DPI、辅助设置及持续操作分别记录 |
| 后续同步批次 | 对接真实账号和房间服务 | 同项冲突保留双方；换账号不串档；额度竞争拒绝；先开放后收到旧离线布局必须拒绝；预览后团子走入目标位置使在线确认失败 |

本轮仅作源码与文档核对，未执行上述产品验收。既有家具600秒有效观察、真实DPI／辅助设置、前台捕获及59 FPS等未完成门禁继续保留；单人历史通过不替代新模型或多客户端验证。
