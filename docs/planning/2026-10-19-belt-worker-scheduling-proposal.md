# 连续闭合带实验：独立物理线程调度候选

日期：2026-10-19。状态：**用户已批准实施，独立线程候选自动57门通过，新增调度手感待人工验收**。仅用于独立PhysicsLab窗口，不授权正式宿主接入、合并、推送或安装。

## 1. 问题与目标

用户目标是稳定57帧以上。现有等价缓存的八角物理输出已逐字节保持，但实际窗口仍有长帧。原timer和新增Rendering候选都在UI线程连续完成物理、眼睛、配饰及绘制准备；一次较慢的物理步可能形成积压，随后2至4步追赶又占住UI线程。事实和逐轮限制见[实验记录第14节](../verification/2026-10-16-force-walking-outline.md)。

建议将原生物理计算移到一个长期存在的专用线程，WPF外观与输入继续由UI线程处理。这样可让物理计算与上一帧的绘制并行。它不会让原生算法本身变快，因此仍须真实测量57帧门，不能承诺仅改线程便达标。

本方案会改变输入交接、暂停/重置及帧同步的内部机制。依据AGENTS.md第2节“新功能或行为变化先形成设计并获批，再制定计划和实现”，本方案已单独提问并获用户明确同意。此前数值等价优化已在本地提交1dd995d独立保留。

## 2. 所有权与状态

- 一个worker独占native world的创建、配置、Step、全部诊断读取和Dispose。UI线程不直接调用该handle，不用锁把原生长计算搬回UI。
- worker只接收不可变输入，输出拥有独立数组的完整物理快照；不访问WPF控件、DispatcherObject或外观presenter。
- 暂停、失焦、最小化、重置、模型切换和关闭使用串行命令及generation号。新generation拒绝旧输入/快照；Space有单调序号，每次按下最多消费一次。
- reset/close等当前有限原生调用结束后由worker释放旧world，再确认完成；不强行中断native，不在另一个线程释放正在使用的handle。UI保持响应，等待期间不接受新的玩法输入。

## 3. 不变合同与交接

- 保留当前F参数、8点/后压、W/S/跳跃、固定dt、4子步、全部迭代/保护/限速及积压丢弃规则；禁止降低采样、精度或安全预算。
- A/D/W/S及拖拽以UI最新有效快照在下一物理tick采样；文字输入、失焦/取消立即发布输入失效命令。精确的跨线程输入延迟须记录和人工验收，不能沿用旧候选的反馈。
- 每个成功物理tick仍推进一次眼睛、配饰和步态，按tick顺序在UI应用；不丢中间tick来减少外观工作，不跨tick复用几何。渲染只呈现最新完整外观帧，诊断与该帧绑定。
- 快照FIFO必须有界并记录深度/等待时间。出现持续回压时明示实验暂停并保留诊断，不能悄悄覆盖快照或靠重复旧姿态刷FPS。预览期间不引入插值或显示平滑。
- 原生失败继续带完整前状态、真实输入、dt和失败诊断返回，保留原故障取证与原子回滚语义；异常不吞掉、不自动重置身体。

## 4. 最小实施与验证

1. 先加可独立测试的worker命令、epoch和有界快照队列，窗口原模式保持默认。实现入口仅为显式实验选项，切换需重置。
2. 同原八组极值输入，核对worker与原串行world的11通道逐帧字节；另测Space不丢/不重发、失焦取消、快速重置、关闭、队列回压和故障传播。测试需能在旧generation误入/数组别名/跳跃重复时失败。
3. 实际WPF验证所有外观tick连续、FIFO不跳帧、主推/后压诊断同帧，原44项交互及拖压/限速检查继续通过。原64/256点轮廓、眼睛和测试配饰的安全门保持。
4. 在没有其它本任务测试并发的可见窗口运行相同1860步脚本；记录生产物理tick、UI已应用tick、Rendering实际观察tick及队列年龄，57门只统计渲染时已有新完整外观的回调。
5. 稳定段每个完整滚动1秒至少57次新tick画面更新，间隔P95<=1000/57ms，无稳定段积压丢弃/队列溢出。完整冷启动数据保留；不冒充GPU实际present或全机器负载保证。
6. 自动门通过后打开独立预览，验收转向、松手、W/S、Space、拖压及暂停/恢复的手感和眼睛/配饰跟随。未获人工通过不替换默认候选。

## 5. 替代方案与取舍

继续微缓存改动较小，仍可采用有实测收益的部分，但当前数据不能证明足够消除UI长帧。减少物理子步/保护、改材质或降低外观更新频率会改变已认可结果，不采用。仅显示插值可以提高绘制更新率，却不能证明物理及时推进，也不符合本轮判定口径。

独立线程的代价是明确的并发/生命周期复杂度及可能新增一帧输入/呈现延迟；上述epoch、单一handle所有者、有界FIFO和实时人工验收是必要约束。若原生单步在实际负载下仍长期超过预算，worker也可能不达标，届时必须据新测量重新定位，不进一步自动扩大为算法或物理机制改造。

## 6. 实施中的完整tick缓冲

首次有效worker测量仍出现0/2快照消费；修正等待预算后无积压丢弃，但稳定段新画面最低35次/秒。为落实上节列出的约一帧呈现延迟取舍，在FIFO内先积累2个完整快照，之后通常每个Rendering应用1个，深度达到4时应用2个追赶。生产停止、回放结束或故障时全部flush；epoch、Cancel、Stop和Reset清除prime状态。队列容量8、持续回压暂停和全部外观tick仍保留，不插值、不跳步、不以旧姿态计fresh。

详细观测只在性能模式保存在内存，记录每次回调前后队列深度/最老年龄、prime等待、underflow、追赶与flush。等待计算须扣除本轮native工作耗时；回调间隔用真实Stopwatch入口，另记录入口至完整外观处理后observer的耗时。自动57门不变，最终新增延迟及真实输入手感仍须独立人工验收。实施和失败证据见[实验记录第15节](../verification/2026-10-16-force-walking-outline.md)。
