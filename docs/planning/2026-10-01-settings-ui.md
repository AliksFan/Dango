# 设置页（Settings UI）范围与验收设计

> 历史基线：2026-10-15 用户已批准并授权[设置页重做](2026-10-15-settings-refresh.md)。新产品设置页移除旧宿主的显示／模式／层级及鼠标／键盘开关，改用真实当前场景诊断与恢复；以下保留原版本合同和验收历史。

> 状态：设置页隔离视觉预览及独立 Product 宿主人工验收均获用户确认；完整自动门禁仍未完成。
>
> 日期：2026-10-01

## 目标与范围

本批在已验收的产品首页壳层内增加“设置”页，而不是恢复旧侧栏。当前设置页只保留显示/隐藏、交互开关、`Wallpaper`/`Window` 显示模式、图标层级、键盘控制及方案、帮助与安全诊断、保存失败后的重试/恢复与正常退出。

页面只把操作请求交给现有桌面宿主控制器，并以宿主实际观察到的状态刷新显示；持久化只保存允许长期保留的偏好，不把短暂可见状态伪装为已保存设置。

用户已决定移除“设置中的外观”入口。该决定只改变设置页信息架构：不删除首页中的换装体验，也不删除底层既有帽型能力。外观应归入首页、独立外观功能或其他位置，及其具体交互、持久化和验收标准，均待实际功能实现时再定；本批不预先指定。

本批不包含：多人同步、物理参数或 native DLL 改造、拖动/贴贴等新互动、全局键盘 hook、设置中的外观入口、正式设置同步、安装更新或发布。

## 设计取舍

- 设置页放在产品首页壳层内，返回首页与 Escape 应恢复首页及焦点；不重新启用旧侧栏。
- 设置内容使用可滚动、受可用宽度约束的单列：320、480、940 DIP 均不能横向溢出；诊断展开后应在当前视口可见，不要求用户先手动滚动查找。
- 所有开关、模式、层级和键盘选项都以桌面宿主确认值回写 UI。宿主拒绝或执行后报错时，保留明确失败提示，恢复观察到的原值，且不得保存“已应用”的虚假结果。
- 宿主操作已成功而本地写入失败时，保留已生效的会话状态，显示未保存警告；一次设置动作最多立即尝试一次写入，“重试保存”只重试写入，不能再次下发宿主命令。
- 正式页面复用现有诊断摘要；专项测试只用虚构数据，不记录窗口内容、原始输入、桌面文件、凭证或完整敏感报文。

## 实施顺序

1. 在既有产品首页壳层中建立设置页、返回导航、固定状态/失败提示和窄屏布局。
2. 移除设置中的外观入口及其设置页专属动作/测试断言；首页换装和底层帽型能力不在此步骤删除或重定归属。
3. 将保留的设置动作统一接到现有宿主命令控制器；每次操作后读取观察状态，再决定是否保存。
4. 接入设置会话的失败、重试和恢复提示，并保持诊断、退出与焦点路径可达。
5. 先完成修订后的专项自动测试，再在正式物理桌面上进行实时行为和人工验收；后两者不由虚构宿主替代。

## 能失败的验收

- 破坏壳层内导航、返回或 Escape 焦点恢复时，设置专项测试必须失败。
- 把固定单列改为按文本宽度收缩、或让按钮越过 320/480/940 DIP 边界时，布局测试必须失败；诊断展开但首屏不可见也必须失败。
- 让宿主忽略/拒绝显示、交互、模式、层级或键盘操作时，UI 不得显示成功、不得写入设置文件。
- 让宿主先应用、后抛出异常时，必须回到观察到的状态，不能保留乐观值。
- 让首次保存失败时，未保存警告必须持续可见；壁纸恢复不能在同次点击中二次写入掩盖失败，明确重试也不得重复宿主命令。
- 设置页不得重新暴露帽型、外观预设或其持久化入口；首页换装与底层帽型能力是否仍可用，应由各自功能的测试和验收单独确认，不能由本设置页结论替代。
- 正式物理桌面实时检查应确认设置操作不破坏现有宿主、物理表现、退出路径或日常设置隔离。该检查及设置页人工观感目前均为未验证项。
