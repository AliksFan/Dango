# 设置页（Settings UI）范围与验收设计

> 状态：本批实现范围与验收定义已记录；设置页人工验收、正式物理桌面实时行为仍未完成。
>
> 日期：2026-10-01

## 目标与范围

本批在已验收的产品首页壳层内增加“设置”页，而不是恢复旧侧栏。设置页提供以下已实现边界的入口：显示/隐藏、交互开关、`Wallpaper`/`Window` 显示模式、图标层级、键盘控制及方案、三种现有帽型、帮助与安全诊断、保存失败后的重试/恢复与正常退出。

页面只把操作请求交给现有桌面宿主控制器，并以宿主实际观察到的状态刷新显示；持久化只保存允许长期保留的偏好，不把短暂可见状态伪装为已保存设置。

本批不包含：多人同步、物理参数或 native DLL 改造、拖动/贴贴等新互动、全局键盘 hook、正式设置同步、安装更新或发布。

## 设计取舍

- 设置页放在产品首页壳层内，返回首页与 Escape 应恢复首页及焦点；不重新启用旧侧栏。
- 设置内容使用可滚动、受可用宽度约束的单列：320、480、940 DIP 均不能横向溢出；诊断展开后应在当前视口可见，不要求用户先手动滚动查找。
- 所有开关、模式、层级、键盘和帽型都以桌面宿主确认值回写 UI。宿主拒绝或执行后报错时，保留明确失败提示，恢复观察到的原值，且不得保存“已应用”的虚假结果。
- 宿主操作已成功而本地写入失败时，保留已生效的会话状态，显示未保存警告；一次设置动作最多立即尝试一次写入，“重试保存”只重试写入，不能再次下发宿主命令。帽型运行时事件走延迟保存，若同次由控制中心发起则由立即保存取消延迟任务。
- 正式页面复用现有诊断摘要；专项测试只用虚构数据，不记录窗口内容、原始输入、桌面文件、凭证或完整敏感报文。

## 实施顺序

1. 在既有产品首页壳层中建立设置页、返回导航、固定状态/失败提示和窄屏布局。
2. 将各设置动作统一接到现有宿主命令控制器；每次操作后读取观察状态，再决定是否保存。
3. 接入设置会话的失败、重试和恢复提示，并保持诊断、退出与焦点路径可达。
4. 先完成专项自动测试，再在正式物理桌面上进行实时行为和人工验收；后两者不由虚构宿主替代。

## 能失败的验收

- 破坏壳层内导航、返回或 Escape 焦点恢复时，设置专项测试必须失败。
- 把固定单列改为按文本宽度收缩、或让按钮越过 320/480/940 DIP 边界时，布局测试必须失败；诊断展开但首屏不可见也必须失败。
- 让宿主忽略/拒绝显示、交互、模式、层级、键盘或帽型操作时，UI 不得显示成功、不得写入设置文件。
- 让宿主先应用、后抛出异常时，必须回到观察到的状态，不能保留乐观值。
- 让首次保存失败时，未保存警告必须持续可见；帽型与壁纸恢复不能在同次点击中二次写入掩盖失败，明确重试也不得重复宿主命令。
- 正式物理桌面实时检查应确认设置操作不破坏现有宿主、物理表现、退出路径或日常设置隔离。该检查及设置页人工观感目前均为未验证项。
