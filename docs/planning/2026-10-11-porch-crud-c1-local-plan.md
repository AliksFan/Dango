# 门廊正式房间 CRUD C1 本地验证计划

日期：2026-10-11。状态：候选与离线检查准备完成，等待本阶段新的精确资源批准；真实旅程尚未执行。业务方向沿用已批准的登录／昵称／门廊设计。本计划不授权合入 main、推送、部署或更新日常安装。

## 范围与可失败验收

实际 DangoApplicationHost、现有 B772 native、同一个运行时与团子进入正式门廊；使用 A／D 实际行走到建房牌、旧门册、恢复后的真实房门，W 互动。表单直接位于门廊场景。以独立 HWND／进程 UIA 操作生产控件，不能改投影、直接呼叫 controller 或使用 fake room service 代替旅程。

固定旅程一次：两个虚构邀请邮箱注册 → B 登录并设置昵称 → A 实际客户端登录并设置昵称、相同捏脸无需选择 → 门廊读取 → 空名称／容量 13 的表单均零写入 → 创建私密共同房（6 席、版本 1）→ B 读／改该房均 404 → A 改为“门廊茶室”（8 席、版本 2）→ 打开解散确认与取消均零写入 → B 解散 404 → A 明确确认解散（版本 3）→ B 恢复 404 → 行走到旧门册读取已解散目录、选择并恢复（版本 4）→ 已解散目录为空、当前目录两房 → 行走到恢复后的门并重新读取 → 两个会话注销。

四次成功操作各需实际 HTTPS 回执、随后独立 GET 详情与 UI 确认。数据库另外核对账号／邀请／挑战／未发邮件／默认房／占位／会话归属与恢复代际、共同房最终版本 4／准入代际 2、唯一 owner membership、零共同房占位、四条 audit 与四条 outbox 逐版本／请求号／目标用户匹配，B 三个写入请求无回执记录。所有原 22 表摘要以多重集合保全；只允许下表增量。错误实现必须因缺少读回、外来账号成功、错误版本／数据增量、伪造旅程或收尾失败而被拒绝。

## 精确资源目标

只启动已有 `run20261008b0/pgdata` 隔离 PostgreSQL 18，位于本机 LocalApplicationData 下 `Dango/BackendDevelopment`；固定 127.0.0.1:63237、库 `dango_backend_b0`、角色 `dango_b0_owner`。实际目标、监听地址和完整七迁移历史须逐次核验。零迁移，不连接其他 PostgreSQL 服务。沿用原 DPAPI 凭据、服务密钥目录 `b1tests-keys` 和原恢复代际；不主动重置或轮换，保留正常服务运行可能产生的新密钥。

新证据目录固定为同级 `run20261011porchcrudc1`。CreateNew 一次性预留、当前用户私有 ACL、父进程身份与清单摘要；目录一旦存在即拒绝重跑。独立 `DANGO_BACKEND_PORCHCRUD_C1_APPROVED`，旧阶段 grant 不能授权本阶段。源码／候选二进制／脚本／native／PostgreSQL 工具完整哈希冻结后才申请批准。

仅一个本机临时 HTTPS 端口、一个服务宿主、一张 1 小时测试证书、一个隔离实际桌面宿主。证书精确 pinning，不导入系统信任。账号秘密仅在测试进程内存，不操作 WinCred。关闭邮件、过期清理、在线租约和 outbox 后台 worker；不发送邮件，不创建多人租约或占位。证据截图仅本次自有 WPF 窗口。

## 不可退还预算

| 操作 | 次数上限 |
|---|---:|
| 邀请／注册开始／确认／完成 | 各 2 |
| 登录／昵称／注销 | 各 2 |
| 创建 | 1 |
| 修改／解散／恢复 | 各 2（各含 B 拒绝一次） |
| 合计 | 21 |

最多两个虚构 `.invalid` 账号及注册图、两个会话、一个新增共同房。HTTP 最多 128 次，包括所有读取和失败请求；实际 Send 起始间隔至少 600ms，单调时钟验证。业务时限 10 分钟，测试进程最多 300 秒。没有隐式重试；预算在持久登记前消耗，失败不退款。空表单和取消只允许零业务写入。

| 表组 | 新增 |
|---|---:|
| invitations／registrations／challenges／emailJobs／users／pets／petStates／sessions | 各 2 |
| rooms／memberships | 各 3 |
| audit／outbox | 各 4 |
| 其余十表（含配饰四表） | 0 |

固定十工具序列：version、status、start、before-size、before-full、vstest、after-size、after-full、scoped、stop。全量快照先测量，最大 1MiB，不自动扩大。仅固定只读 SQL；scope 采用有界规范身份再生成全文并比对，禁止额外诊断查询。start 输出采用已验证丢弃合同，其余输出完整 EOF。失败只收尾，不补跑、不补查。

## 五项设计检查与阶段边界

- 正确性：真实控件、异常输入、状态／版本、每次写后读回与恢复目录核对。
- 一致性：本轮逐版本事务／审计／outbox 一致；并发、丢响应与原请求重试沿用已有后端合同，本轮没有新增真实故障覆盖，后续 C2 单独覆盖。
- 安全性：B 实际独立会话访问 A 房间四种操作拒绝；scope、角色、路径、预算和私有证据有界。
- 可靠性：错误不冒充成功；独立收尾检查任务、计时器、native、HWND、HTTPS、PostgreSQL、桥进程及临时 CNG 私钥；全部持久数据与原密钥／代际保留。本轮不是备份还原或服务中断演练。
- 扩展性：生产目录每页 4、HTTP／时间／输出／对象数量有界；公共码、成员、准入／离房与完整多人画面在后续阶段，不能据此报告已验证。

界面采用 `docs/desktop-ui-design-v0.1.md` v0.1（2026-10-10）第 3 节场景内布局、第 4.2 节真实结果／破坏性确认、第 6 节实际输入及分层报告。沿用已确认门廊直接展开功能；本轮不批量改主题、滚动组件或图标。技术测试由助手执行；主观手感／界面效果／流畅度仍需用户验收。

无论失败或通过，先结束自有输入和桌面宿主、排空可观察原任务，停止并释放实际 HTTPS，再确认临时 CNG 私钥消失。外层仅在精确进程／数据目录／端口／启动区间／桥进程归属证明成立时停止本次 PostgreSQL。资源未确认清理则不得报告通过。保留原数据、所有本次新增数据、全部新旧服务密钥、epoch、凭据与全部证据；不删除、不还原。
