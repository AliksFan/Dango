# 实时家具编辑与手套限制

日期：2026-10-10。状态：**用户已通过手套限制设计，并明确编辑者已在房间时不得自动挪走自己的团子；实时交互稿和首个本地增量实施准备已更新，未开始产品编码或多人验收。**

## 决策来源与范围

用户提出：编辑页面同步房内所有团子，包括自己；添加／移动家具先预览、确认后才应用，有碰撞穿入时不能确认；删除已选家具直接执行；使用家具选择／拖动、删除、手套工具，右键拖动视角。用户随后通过不逐次征求被拖者同意、以主动操作保护和限时／冷却约束手套的设计。

用户进一步澄清“正在编辑的人如果已进入房间也不要移开”指：**进入编辑时不自动挪走团子，团子留在原房间继续活动，仍适用普通手套限制**。编辑期间免受他人手套抓取并未获批。

本文件记录最新交互方向及已批准的手套规则。此前[本地布局设计](2026-10-10-official-furniture-layout-design.md)与[单平台实施计划](2026-10-10-official-furniture-layout-implementation-plan.md)中的“编辑暂停、取消整个草稿、保存后重建世界”不适用于这一方向，暂不能据其原样开始 L0–L5 编码。三段侧栏、仓库两列纯图标、官方预设及参数后置仍保留。

最新[首个本地增量实施计划](2026-10-10-live-furniture-editing-implementation-plan.md)已拆分同世界变更、逐操作提交、输入路由和 C0–C4 验收批次。当前仅为准备产物，计划中的 native 接口尚未实现。

设计确认不表示在线房间、家具组合、球参数调节或多人同步已经实现，也不扩大后端现有批次。离线睡眠团子能否被搬动、首次从门廊进入编辑如何进入目标运行世界，仍需独立明确，不能由“已在房间不挪走”推定。

## 实时房间与编辑者留场

- 编辑界面是同一房间的操作层，显示同一批团子。进入／退出编辑不复制团子、不迁出已在场的编辑者、不自动改变其位置。
- 房内物理与同步继续运行，编辑者的团子同样能活动、碰撞、落下及被合法抓取；“不自动挪走”不意味着冻结位置或免受普通物理影响。
- 家具确认或删除不能重建所有玩家来应用布局。保持现有团子身份、运行实例、位置和速度，接触／支撑状态仅按实际家具变化更新。
- 编辑状态本身不授予手套保护。本人团子控制命令触发正常保护与挣脱；家具微调、图标按钮激活不冒充本人团子控制，也不得穿透为跳跃。

## 家具预览、确认与删除

- 添加／移动先产生私人预览，预览不参与碰撞。确认前原家具保持现有真实状态；移动校验排除被移动家具的旧实例。
- 使用官方真实碰撞几何检查房间边界、其他家具和所有团子，正常贴边／相切与穿入分开判定。确认时按最新状态复核，本地绿色预览不能替代联机服务器裁定；失败保留原家具和可继续调整的预览。
- 删除是针对已选家具的一次动作，不需要额外确认框。联机删除成功以服务器确认为准；拒绝时保留家具及明确原因。
- 删除接触中的家具允许团子自然掉落。实际应用需在物理步边界清除旧接触与支撑、重算接地并让受影响身体继续参与物理，保持位置和速度；不得遗留空中接地或注入异常能量。
- 退出编辑不回滚已应用操作。取消只针对当前未确认预览；逐操作提交／持久化的成功和不明结果处理需在实施合同中冻结，不能沿用旧“保存整房／取消全部”的界面语义。

家具选择／拖动与手套为两种模式，垃圾桶为删除当前选中家具的动作；右键在两种模式下均只平移视角。失焦、捕获丢失、切换工具或退出编辑时结束当前手势。[交互稿](../prototypes/dango-furniture-layout.html)已改为逐件预览／确认／取消、直接删除、两只示意团子留场及手套 5／10 秒示意。它没有真实物理、多人或存档，也未演示他人主动保护 3 秒和本人挣脱；本轮操作证据见[准备记录](../verification/2026-10-10-furniture-layout-design.md)，旧稿浏览器证据不继承为新版通过证据。

## 已批准的手套限制

不逐次征求被拖者同意，以有限互动规则约束拖动。以下数值是首轮体验验收起点，后续根据真实手感调整，不是未经验证的最终物理参数。

| 规则 | 行为 |
|---|---|
| 主动操作保护 | 最近 3 秒有本人团子移动、跳跃或拖拽操作，不能被别人抓。持续本人控制持续保护；自动走动、被碰撞不算本人操作，无需判定长时间挂机 |
| 本人控制优先 | 被抓后本人发出团子移动、跳跃或拖拽控制，立即解除他人抓取，并继续执行本人的有效控制命令；迟到消息不能恢复旧抓取 |
| 抓取时限 | 拖别人的团子每次最多 5 秒，到期自动释放 |
| 目标冷却 | 释放后同一团子 10 秒内不能再次被任何其他玩家抓；冷却绑定目标并在全房间生效，本人控制不受此冷却阻止 |
| 抓取独占 | 每人同时只能抓一只团子，每只团子同时只能被一人抓取；竞争请求由服务器裁定，失败方不能移动目标或释放成功方的抓取 |
| 物理力度 | 限制拖动速度、拉力及释放速度，沿真实碰撞路径移动，不能穿墙、塞进家具或拖出房间；具体上限待新物理模型手感核验 |
| 结束与异常 | 松手、切换工具、退出编辑或断线时释放；联机不能因客户端不再发送消息而无限抓取，到期与断线由服务器处理 |

规则主要约束拖别人的团子，不把 3／5／10 秒限制直接施加到本人拖动。物理边界和同一实体的唯一控制仍需遵守。多人交替操作、更换工具或编辑会话不能绕过目标冷却。

界面使用图标和悬停提示，抓取拒绝时简短说明“正在操作”或冷却剩余时间，不增加常驻权限面板。联机服务器验证房间上下文、目标状态、时限、独占和冷却，分配顺序并同步结果；连续拖动沿用服务端限频，不上传逐帧动画。

## 实施准备顺序与缺口

当前源码中平台世界拒绝多团子、平台与球互斥、不同平台定义不能直接替换；Clear→Set 不是拒绝时保持旧场景的原子更新。现有单人计划保存后重建会重置运行现场。这些静态事实不证明实时家具编辑已可运行。

| 顺序 | 准备内容与退出条件 |
|---|---|
| R0 物理合同 | 核对可用物理来源，将既有平台兼容模型的隔离增量与新圆形模型后续准入分开；明确家具变更的原子应用／拒绝、多人接触、删除支撑及可靠状态观测；保持玩家运行状态的能力缺失时不能打开伪多人玩法 |
| R1 操作与保存合同 | 区分已发布布局、未确认预览、待确认请求；冻结操作标识、版本冲突、逐操作保存和提交结果不明的处理。单人本地与在线权威接口分开，不能用本地锁冒充在线裁定 |
| R2 界面与输入 | 更新可点击稿和真实窗口计划：两种工具＋删除动作、右键视角、三段侧栏，以及保留编辑者同一团子。本人控制与家具微调的输入路由须不抢占按钮 |
| R3 单人真实增量 | 在独立验收窗口先验证空布局／单平台、物理不停、预览确认、接触删除和真实存档，不接假账号或模拟服务器；新物理修改与正式编码另行安排批准范围 |
| R4 多人专项 | 单独制定正式房间接入、服务器操作裁定、抓取控制与冷却、断线及双客户端验收计划；本次设计批准不提前实施该批次 |

同房间同时一名家具编辑者是降低提交冲突的实施候选，仍需在 R1 冻结；不能用它推定编辑者的团子免抓。原固定平台存档的校验、坏文件保护与原子文件写入要求可复用，暂停／整房回滚／重建世界的生命周期不可复用。

## 能失败的验收

以下是未来验证要求，本轮未执行。边界时间按权威时间检查，计时容差在实施时冻结到实际处理周期。最终包含实际输入、物理和多客户端证据，不能只测按钮禁用。

| 场景 | 应观察结果／错误实现应如何失败 |
|---|---|
| 已入房者进入编辑 | 团子身份和运行实例连续，初始位置不自动改变，房间物理继续；迁出、换副本、传送旁边、全房暂停或重建将失败 |
| 编辑者适用普通抓取 | 静止编辑者在合法时段可被别人抓，本人控制立即接管；仅因编辑状态而拒绝抓取将失败 |
| 3 秒主动保护 | 本人控制后的保护期内拒绝，期满且满足其他条件后可抓；持续控制不失效，自动走动不续期，家具微调不冒充团子操作 |
| 本人抢占 | 抓取中本人移动／跳跃解除抓取并实际执行；丢掉输入、只改 UI 或迟到抓取消息复活旧控制将失败 |
| 5 秒强制释放 | 持续按住或停止发送更新均不能无限抓取；仅由客户端松手决定结束将失败 |
| 全房 10 秒冷却 | 同一目标释放后换操作者／工具／编辑会话仍被拒绝，期满后可抓，本人可立即控制；按操作者分别冷却将失败 |
| 独占与异常释放 | 两人抢同一团子仅一人成功，一人不能同时抓多只，失败方不能释放成功方抓取；断线／切工具／退出后释放，重连和旧状态不能继续控制 |
| 物理限制 | 快速拖动仍遵守墙、家具和边界，释放速度有上限；瞬移穿墙、高速甩飞或无限拉力将失败 |
| 家具确认复核 | 预览期间真实家具不变，团子临时进入目标位置导致确认拒绝；只信旧绿框、与自身旧实例误判或拒绝时旧家具丢失将失败 |
| 接触删除 | 团子从支撑面自然掉落，接地／支撑及时更新，其他团子现场连续；悬空、空中起跳、重置玩家将失败 |

静态文档检查、实现自动验证、实时行为、人工体验及 Git／推送／安装状态分别报告。当前批准的是设计规则，交互稿只提供明确标注的简化示意，生产代码尚未提供这套能力。
