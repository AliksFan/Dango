# B3 房间管理执行计划

状态：用户“下一步”承接已批准首期实施范围，准备并实现 B3 候选。B2 实现提交为 `8c7bb5a`，人工及环境限制保留原记录；不扩展 B4 准入／Hub／公共码、B5 UI 或好友授权。

## 合同与事务

创建共同房选择 privateShared／publicShared，默认容量 6、范围 1–12；有效共同房最多 3，桌宠房不计额度。查询首期仅本人所建房间（含默认桌宠房），稳定 ID 游标、每页默认 20／最高 50；公共持码与临时在场目录由 B4 接入，不开放全网列表。名称 trim／规范化，1–64 Unicode 字符且拒绝控制字符及无效 Unicode；类型和房主不允许更新。桌宠容量始终 2。

查询 state 支持 active／dissolved／all，默认 active。固定模板随房间持久保存：桌宠为 desktop-pet-default／1，共同房为 ordinary-default／1；本批不开放模板编辑。模板迁移回填既有桌宠房，仅增加配置标识，不改旧身份、成员和归属。

修改、解散和恢复要求 expectedVersion；解散还要求 confirmed=true，展示后果与二次确认 UI 由 B5 完成。解散同事务清空实际归属本房的在线／睡眠团子，清位置／睡眠并提高归属版本与控制代际；保留身份，不迁往桌宠房。房间冻结 168 小时并释放额度；恢复需期限、原房主和额度，不自动回迁团子。B4 公共码尚不存在，B4 接入时必须使用房间新版本或显式撤销保证解散／恢复不复活旧码。

每个写请求携带随机 Guid requestId；同账号唯一，审计中保存规范请求摘要和原提交 roomId／appliedVersion／operation。相同请求只重放原操作确认，更换参数或操作拒绝；结果不表示房间当前仍在原状态，读取详情获得最新事实。会话每次重新检查，重复请求也不能绕过撤销。

锁顺序：现有账号 email→User→Session，然后房主额度 advisory key→房间 ID→pet state ID。额外额度键使维护任务和后续领域用例共用同一配额边界，维护任务不在持有此键后补锁账号凭据。锁后 reload，更新仅在拥有者的房间上进行；缩容私密按长期成员计数，公共按唯一归属记录计数。提交前重验会话／到期；故障回滚变更、审计与 outbox。

新增 `audit_logs` 与 `domain_outbox` 前向迁移。两者保留稳定标识及有限操作信息，不保存输入原文、凭据或邮箱；不对已删除房间建立 FK，使永久删除后仍保留审计／原提交确认和待通知意图。outbox 不在事务内通知，B4 实现投递、收件人重新授权与快照纠错。

## 到期与数据权限

到期任务每批最高 50、固定时间／ID 游标，重查 owner quota、room、期限，事务解除残余实际归属、删除该房成员／房间并保留审计／outbox；重复执行无副作用，恢复与清理竞争只有一方能提交。后台执行需运行环境显式启用，默认不自动永久清理现有数据；启用后也先等待维护周期再查询。测试通过精确房间 ID 范围调用维护用例。

本轮先实现、生成迁移及静态验证。真实数据操作另按精确计划批准：只复用 `run20261008b0`／`dango_backend_b0`，前向应用本次新增迁移，虚构测试数据独立标识，到期删除仅限本次测试生成的指定房间。不能据 B0／B1 授权直接执行新迁移或永久删除。实例、已有数据、密钥保留，不重置、还原或触及用户现有服务。

## 验收与所有权

根负责共享合同、模型／迁移、正式 HTTP／DI、工具、目标保护和最终集成；独立 Worktree A 负责管理用例／政策／服务测试，B 负责到期服务／worker／到期测试。审查只读，不共同修改同一分支或 ModelSnapshot；旧客户端 worktree 的未提交草稿保留。

- 正确性：正常流程、非法 DTO、名称／类型／容量边界、桌宠保护、exact 168h 截止，错误不得返回成功。
- 一致性：第三间并发、创建响应丢失／重复 key、同版本更新竞争、缩容席位／占位、解散与实际归属、恢复额度、恢复／清理竞争、提交前逐步故障回滚；audit／outbox 同事务只有一份。
- 安全性：他人访问／伪造 owner／旧会话、CSRF／Origin、恢复不建立新准入资格；系统清理精确范围、有界查询，日志无敏感内容。
- 可靠性：真实独立连接读库、新宿主读取提交结果、任务中断后重复执行；备份还原与强杀恢复仍单列未验证，不把 outbox 行当已发送。
- 扩展性：owner／状态／ID、恢复期限、原请求、outbox 索引；分页／批次／输入有限，不引入消息队列或分布式锁。

本轮不合 main、不推送、部署、安装或替换 DLL。完成后报告实际门禁和未执行项，数据授权不足时保留可审查候选及精确操作计划，不伪报 PostgreSQL 集成通过。
