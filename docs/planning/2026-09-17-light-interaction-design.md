## 2. 推荐的两个功能

| 功能 | 用户操作 | 唯一反馈 | 建议取舍 |
|---|---|---|---|
| 点击 | 在团子现有命中区内，左键短按并松开 | 双眼眨一次：闭合 40 ms、保持 10 ms、睁开 80 ms | 复用 `Blink.Default(Both)`；不跳跃、不抖帽、不发声、不弹提示 |
| 抚摸 | 先按住 Shift，再在团子现有命中区内按住左键，向左或右轻划一小段 | 双眼柔和眯起约 0.6 秒，再自然睁开 | 复用 `SetEyes(Both, 0.35, Soft, 1)`，到期释放；不抓身体、不累积好感、不连续刷表情 |

在现有帮助/操作说明增加一句：“点一下会眨眼；按住左键移动可拖动；Shift＋左键左右轻划可摸摸。”不新增常驻模式、工具栏或持久设置；原“允许交互”同时控制这两项，键盘方向控制关闭时仍可使用鼠标与 Shift 修饰手势。

**推荐本小步保留两个功能。** Shift 在按下时明确分流，能避开普通拖动；比长按变抚摸更少误判，也省去模式开关及忘记退出的问题。代价是需要记住一个组合键。点击引入 3 DIP 的抓取起步阈值，是本批唯一主动调整的拖动入口手感；跨过阈值即走原物理拖动，不修改抓取算法与释放效果。若不接受该起步阈值或 Shift 入口，应修改本设计再实施，不默默换成另一套手势。

## 3. 输入判定与时序

### 3.1 共用约定

“命中区”沿用 `DangoHostFrameBinding.Bounds/HitTest` 的实体逻辑矩形和现有 WPF 身体控件区域，**不是精确软体轮廓**。不在本批改命中几何；帽子超出身体框的部分不独立接输入，图标优先和空白穿透保留。所有距离先转换成场景 DIP，按下点固定在场景坐标；不得拿跟随身体移动的局部坐标累计距离。

仅在 Product 场景可见、运行健康、交互开启、实体及其附件有效、宿主输入条件成立时接纳新反馈手势。条件在每次事件和提交前复核；附件故障只禁用新反馈，不借此删除已有身体拖动能力。

一次按下锁定实体 ID、有效场景代际、宿主输入会话、起点、单调时间和分支。后续不能因选中项变化或松开 Shift 改绑实体、转换分支。捕获失败立即取消；取消后必须重新按下才能开始。保存最大位移/竖向偏移，不能只比较最后松开点而把“拖出去又回来”当点击。不保留原始轨迹列表。

### 3.2 普通左键：点击候选 → 拖动或结束

1. 无 Shift 按下：捕获鼠标，开始点击候选；暂不提交反馈，也不调用物理 `BeginDrag`。
2. 持有期间距按下点的最大欧氏距离 **达到 3 DIP**，立即进入原物理拖动；无需等待点击时限。以跨阈值时的当前指针开始既有抓取，随后沿用原 `MovePhysicalDrag/EndPhysicalDrag`，不重放积累路径或额外施力。
3. 松开时，按住时间 **≤250 ms**、最大距离 **<3 DIP**，且仍命中同一实体，才请求一次眨眼。恰好 3 DIP 判拖动，恰好 250 ms 可判点击。松开事件也必须纳入最后位移校验；越阈值却漏收 Move 时不得误发点击。
4. 超过 250 ms 仍没移动：仅失去点击资格，不自动抚摸、不自动抓取；之后移动仍能拖动，直接松开无反馈。离开命中区松开无点击。拖动一旦成立，释放时绝不补点击。
5. 后按 Shift 不改变已选普通分支。双击不定义新功能，两个短按按同一冷却规则处理。

### 3.3 Shift＋左键：一次轻划

1. 仅按下时 Shift 已按住才进入抚摸候选；左右 Shift 等价。此分支从头到尾不调用物理抓取。
2. 按住 Shift＋左键，在 **600 ms 内**达到相对起点的水平净位移 **|Δx|≥16 DIP**，历次最大 **|Δy|≤8 DIP**，且采样点持续命中锁定实体，识别一次抚摸。不是累计折返长度；静止、微抖或单纯 Shift 点击均无反馈。对有位移的相邻采样线段也检查命中，不能越过框外再返回补算。
3. 超时、越出命中区、竖向偏移超限、Shift 先松开或取消事件发生：终止本次候选，不退回点击/拖动；等待左键释放。阈值正好 600 ms / 16 DIP / 8 DIP 时允许识别。
4. 识别后本次手势被消费，继续移动不能重复触发；正常松开左键或 Shift 只结束捕获，已触发的短眯眼按时完成。意外失捕获等异常仍取消反馈。最终 Up 坐标在修饰键仍有效时可完成判定，避免依赖 Move 事件频率。

### 3.4 反馈时钟与限频

手势 250/600 ms 使用本地单调实时时间；眼睛动画及 600 ms 眯眼期限只累计**成功物理固定步**。不加第二个物理/动画循环，不按鼠标事件数或渲染帧数计时，不补算隐藏时间。请求在下一成功步开始显示。

- 点击使用既有 40/10/80 ms 事件；自接纳起 **300 ms** 内不接纳下一个反馈。
- 抚摸在第一次消费眼姿命令起累计 **600 ms** 后、下一次附件消费前释放本次眼姿；误差不超过一个固定步。既有弹簧负责进出过渡，建议验收：开始 200 ms 后两眼 openness 在 0.30–0.40，释放后 200 ms 内 openness≥0.98、Soft strength≤0.02。释放不是瞬间切圆眼。
- 抚摸自接纳起 **1000 ms** 内不接纳下一个反馈；两种反馈共用该实体的一道门，已有反馈未结束也不叠加。冷却用同一成功步时钟。Busy/冷却中的新请求直接丢弃，不排队、不重试、不刷新期限；新的拖动仍立即可用。
- 到期、取消或拒绝后清除本批待处理状态。恢复新会话不补播冷却期内丢弃的请求；冷却不持久化。

## 4. 抢占、取消和故障恢复

这里只协调一个按压会话和一个短反馈。优先顺序为：生命周期/故障取消 → 已成立的物理拖动或方向控制 → 点击/抚摸反馈。按压候选不新增方向控制策略；已有有效方向输入时不接纳眼睛反馈，之后出现有效方向输入会取消本批反馈，原方向键语义继续。物理惯性、下落与落地不因这两个反馈停顿。

| 事件 | 本批必须做到 |
|---|---|
| 普通松开 | 先用 Up 坐标做最终判定，将按压会话标为完成，再释放捕获；已完成或会话号不匹配的 LostCapture 忽略，未完成会话的异常失捕获才取消。已触发反馈的期限独立于完成的按压会话 |
| 转物理拖动 | 先终结候选、清本批反馈并释放旧捕获，按旧会话号忽略其 LostCapture；调用原 `BeginPhysicalDrag`，允许其 `SelectEntity → InputCancelled` 正常清旧输入；调用返回后复核实体/宿主仍有效、左键仍按住，再重新捕获。仅捕获成功且 `IsDragging` 成立才登记拖动会话并接 Move；失败立即 End，不回退点击/抚摸。无需改变既有清输入事件或身体算法 |
| Esc、异常失捕获、Window 失焦 | 立即清候选、消费标志、反馈期限与本批通道；释放捕获；不把取消当 Up 完成，不恢复按住状态 |
| Wallpaper 失去桌面前台、Explorer/WorkerW 失效 | 同上。复用既有桌面前台判定，检查范围覆盖候选/抚摸/反馈，不能仍只检查 `IsDragging`；保持不激活窗口、不抢焦点。非桌面前台不接纳新手势 |
| 隐藏、最小化、关闭交互、切宿主、DPI/坐标映射变更、退出 | 在暂停/拆除宿主前撤销本批命令，清会话并使旧回调失效；保留已有 world/眼帽跟随规则。恢复后等一次新按下，不续播旧眨眼或旧眯眼保持时段 |
| 物理故障 | 清本地状态，不再提交动画、不补偿物理步，保留最后安全帧；既有错误状态和显式恢复入口继续有效。公共 `SubmitAttachment` 会检查健康状态，故障路径不能无条件调用它发 Release 导致二次异常；显式重置时旧 ledger/代际一并失效 |
| 单实体附件故障 | 该实体不再接纳反馈；沿用冻结和故障说明，身体按既有规则运行。恢复只走现有显式恢复团子，不用点击偷偷清错 |
| 重置/移除/重新初始化 | 丢弃旧 ID/代际/期限；旧 Up、旧 Release、重复取消均不能作用于新实体或其他实体 |

取消健康可运行的反馈时，只释放本批实际占用的 `Left/RightBlink` 或 `Left/RightEyePose`，不清 Gaze、帽子或别的入口。**所有健康暂停路径必须在 `attachments.SetPaused(true)` 前成功 Release**，不能先 Stop 再调用公共提交接口。取消提交成功后，下一成功步同步清除缓存眨眼并自然回眼，建议 200 ms 内达到上述恢复容差；隐藏恢复仅做这段回自然眼过渡，不继续旧事件。重复/已经暂停的取消只能幂等清理已终结会话。若仍有命令却无法取消，视为取消失败，保留安全状态并走现有显式恢复入口，不能假报取消成功或静默续播。故障时清本地状态，不重试 Submit；显式重置才创建干净附件 ledger。不得为取消而推进额外物理步、偷偷重置全部眼帽或改弹簧参数。

只在已有局部鼠标会话读取 Shift/Esc 状态；不新增全局键盘钩子、轮询轨迹记录或网络请求。当前宿主已具有的 Esc/前台检测仍可复用。Wallpaper 捕获期间即使方向键控制关闭，也要能正确检测 Esc 和取消。
