## 3. P0 冻结清单

实施开始前记录基线 module／源码 hash、当前双体轨迹、碰撞容差和原异常门槛；Windows 同源旧候选与准入候选在同输入下保持无变化路径对照，不能看到失败后放宽容差。跨平台不要求软体节点逐位相同，但接触、支撑、反作用和安全门必须符合先冻结的预算。

冻结逻辑坐标到 native p 的仿射映射、中心／落脚语义、地面与边界、两处不重叠出生点、旧持久 `0,0` 的严格处理和模板支持范围。新模板对实际两人验证房开放；旧模板仍提供现有管理／状态，不能悄悄当可玩。玩法入口先预检本机 native 能力／模板／版本／人数，服务端在要求可玩的准入提交处重验适用性；不支持时在迁移前明确失败，不截断成员。预检后出现的真实宿主故障仍走捕获租约补偿。

共享最小状态包括版本、实体身份、中心、必要速度校正、朝向、落地／支撑关系、成对接触语义和已处理输入。Tick 与事件序号分开，状态包丢失取下一共同帧，有序事件缺口重新快照；不得拼接不同时刻身体。P0 冻结数组上限、DTO 字节上限与 checkpoint 大小／版本，均有恶意输入反例。

冻结频率／时延的首轮起点：固定步 60 Hz；输入变化立即发送，持有意图约 10 Hz 续期；状态发布 20 Hz；watchdog 候选 350 ms，以 0／75／150 ms 往返时延及有限抖动验证，再在实现前确定限频、burst 与最大排队预算。身体误差依据源码 oracle 和逻辑度量定义，不用像素或截图相似度替代。停止输入与物理惯性分开；不可把 Stop 定义为瞬时清速度。

冻结服务器接收时刻派生的命令应用期限与持续意图有效期；出队时重新验代际、期限和 ordinal，过期 Move／Jump 不迟到复活，旧 Move 不越过新 Stop。queued、applied、rejected 与有界去重的结果更新须可观察；排队接受不冒充起跳成功。冻结 ready 挑战的 lease／instance／实际连接／归属与控制／PresenceGeneration／PlayEpoch／输入代际／模板版本／到期绑定，并列出全部失效条件。受保护出站发送前再次验会话、lease、房间资格和连接绑定。

冻结 PresenceGeneration 的语义及完整变更路径：初始进入、离房后重入、迁移、公共超时、同房接管、租约重绑及私密睡眠。现有 state.Version／ControlGeneration 在接管时也递增，不能用它们决定是否重建身体。冻结 RuntimeRevision 持久 claim／旧 writer fence、同运行者 checkpoint revision／Tick 的 CAS、最后成功存档保留、无记录首次初始化与坏记录阻止就绪的区别。P0 只定义合同，必要前向迁移及真实写入属于 P3 的另行批准范围。

持续运行候选需记录有效活动 600 秒及共同世界 Tick 增长、健康状态、CPU／内存／句柄／线程／网络和事件时延；WPF Rendering 不代表 compositor 59 FPS。200 人、50 房、6／12 人容量与完整 OS 环境矩阵继续是独立专项，本批不承诺通过。

## 4. P1：服务器玩法物理准入

2026-10-11恢复改约：[安全出生ADR](../adr/proposals/2026-10-11-world-loss-safe-spawn.md)已批准。下列完整solver checkpoint导入／续步对照为原要求，失败证据保留但不再作为修订后首版恢复准入项；以world丢失／释放后安全出生及领域恢复语义门替代，不把旧红灯补成绿灯。R0及获批R1已完成隔离验证，见[R1报告](../verification/2026-10-11-dual-player-p1-r1.md)；已准备[安全出生恢复首轮计划](2026-10-11-dual-player-p1-safe-spawn-plan.md)，恢复实现尚未开始，P2仍停止。

目标模块：`eng/native/box2d/dango_physics_module.h`、`dango_collision_review.c`、独立 headless 验证工具、`src/Dango.Physics` 的中立 adapter 与对应测试。新增能力采用独立版本化可选 ABI；旧导出签名、状态槽和无变化单人路径保留，不能靠改既有帧尺寸迫使日常 DLL 失效。

现行恢复增量只依赖已有authority API与原参数：健康world的重连／接管／内存暂停保留原身体；实际丢失／合法释放后校验领域元数据、最新成员及运行所有权，全组安全出生并发布新epoch及原因。先在独立工具验证，不接旧匿名Server或正式数据库；完整checkpoint capability继续unsupported。首轮合同、失败矩阵、预算和P3后置项见上述计划。

以下两段保留**修订前完整恢复门的历史来源**，不是现行首版实现任务：

输入来自两份独立虚构控制流，由唯一线程按固定步送入同一个世界。增加可校验的中心速度、支撑／接触输出以及整房内部 checkpoint export／import；checkpoint 无句柄／地址、包含完整恢复必要状态及版本，导入先验证再原子应用，失败保留旧世界与最后安全帧。

checkpoint 门禁须至少覆盖动态相撞、承重堆叠、空中起跳、原惯性及移除下层。恢复后的后续固定步与同构建不中断对照在冻结预算内一致；不把 Add(anchor) 后重新落下称完整恢复。不同模拟版本或损坏数据拒绝。内部 checkpoint 不经玩家网络上传。

专用线程用有界队列接纯 DTO；验证跨线程调用能失败、全生命周期同线程、取消／异常后 owner 与 native allocation 释放。调度慢于预算时记录并进入明确暂停／恢复状态，不无界补步、不静默加速。固定步中不执行数据库或广播。

客户端准入先验证“低频中心／运动校正＋接触语义＋局部形变”的接口：两个独立呈现实例在不同帧率／插值下仍保持正确中心、支撑和落地。P1 允许隔离可视验证窗，但不能称正式在线入房。若需要传完整顶点／轮廓才能维持效果，停止并提交新方案，不偷偷扩大当前 ADR。

服务器 Linux 验证包括固定 Box2D 源码／许可证、`linux-x64` 构建、纯 .NET host 加载、无 WPF／桌面依赖、双体实际步进、错误安全与释放。当前仅检查到 Windows 上存在 wsl／docker CLI，不证明可用发行版、容器运行时或 Linux gate 已通过；不得未经授权安装／启动持久资源。Windows 构建通过而 Linux 无法执行时只报相应部分结果。

P1 成功后记录新的 solver 来源／ABI／参数 hash、状态合同、平台证据与渲染结论；批准后才以其作为 P2 的依赖。失败时保存原始证据和停止原因，不自动切到简化碰撞。

## 5. P2–P4：正式接入边界

拟新增中立 `FormalPlay` DTO 于 `Dango.Protocol`，新增 `Rooms/Play` 应用／运行时边界于 Server；正式 Hub 只连接、验上下文并分发。沿用 `/api/v1/room-hub` 与正式会话，不接匿名临时票据。玩法限频与既有 30 次／10 秒领域预算分开。

正式 gameplay 封套不允许客户端自报 Actor／PetId；绑定实际身份、lease、归属／控制版本、play epoch、输入代际及序号。Jump 的接收／拒绝原因来自权威接地／支撑，不凭客户端 native 判定。Stop 包丢失由 watchdog 清意图，重连不补发 Jump。接管、撤权、离房与授予输入之间必须有真实数据库事实和物理步 fence，不能仅依赖 group 或延迟 outbox。

P2 同时实现准入提交前玩法适用性复查、当前 ready 挑战验证、输入出队期限／代际检查与结果更新，以及玩法帧／事件／快照逐次出站资格复核。已排队发送在撤权后不得泄漏旧房数据；控制浮层和 SignalR group 都不是授权事实。真实服务启动与集成在后续已批准资源计划下执行。

P3 新迁移只维护必要恢复元数据／模板版本、PresenceGeneration、RuntimeRevision及一致恢复事实，不在 `pet_room_states` 逐帧堆积状态，不保存完整solver checkpoint。后台写入来自一致边界的不可变领域／配置记录；按当前运行所有权、PlayEpoch、单调记录revision及同epoch内Tick条件提交，新epoch的Tick重新起算。测旧Tick晚完成、旧运行者在新世界之后迟写、写失败后重启；旧写不得覆盖新状态，所有权递增不能删除最后合法成功存档，未保存状态不标成持久成功。

恢复按最新 RoomId＋PetId＋PresenceGeneration 过滤；world健康时接管保留位置、速度和支撑，旧生命周期移除、新成员或重入成员安全出生且幸存身体不重建。world实际丢失／释放时当前合法成员整组安全出生，新PlayEpoch、零旧输入／惯性／支撑并明确提示；首个健康步仍正常受重力。首次确实无记录可以初始化，坏／不兼容记录阻止就绪。全房保存／休眠以最新正式有效租约事实为准，包含控制和观察设备，保持30秒业务容错，不能由UI隐藏或bare disconnect触发。专用数据计划列出迁移ID、虚构账号／房间数量、写入额度、端口／进程、目录、保留与收尾方式；不把上轮B5C额度当无限授权。

Client 新增唯一 `FormalPlaySession` 和共同 Replica，稳定 PetId 映射独立呈现实例；只接受当前账号、房间、epoch、模拟／几何版本的共同帧。原 `FormalRoomSession` 持有 lease owner 的职责需与账号绑定一致，控制浮层关闭只取消订阅。Desktop 接线在 `DangoApplicationHost`／房间 handoff、输入与普通房场景模块；不让 `LocalRoomSceneDriver` 的隐藏暂停或本地随机走动改变在线世界。

呈现保持桌面规范 v0.1 §§2–6：暖白／棕色共享资源、简洁图标菜单、必要状态与真实失败反馈；只增加连线／观察／恢复所需提示，不新增整套主题。输入与焦点核对 Space、A／D、Esc 菜单、失焦／隐藏清理，不让文字框或按钮操作变成团子输入。双方镜头独立，原低跳保持地面／高跳跟随与底部留白继续适用。

## 6. 必须能失败的验收

| 场景 | 正确结果／错误实现应暴露的失败 |
|---|---|
| 两人同时相向移动 | 同一 Tick 两个独立意图、真实反作用，不穿过对方；两份本地演出不算通过 |
| 上层站在下层并跳跃 | 支撑、承重和起跳反作用由服务器裁定；浮空接地、单边能跳或简化阻挡将失败 |
| 下层离开／被移除 | 上层自然落下，旧支撑及时清除，原身体不被重建／传送 |
| 单人及原参数对照 | 新增网络 adapter 不改变既有单人轨迹、资源和本地家具文件；“调软一点消除碰撞错误”将失败 |
| 身份与控制争用 | 观察设备、过期租约、旧账号／房间／连接／控制代际不能操作；接管后旧输入不再推进 |
| 旧 ready 挑战／健康帧 | 接管、重绑、重建或到期后旧挑战拒绝，不能开放新绑定输入；观察 ready 不授予控制 |
| 重复／乱序 Jump | 同 ID 重试仅一次，异正文拒绝，低 ordinal 与旧 epoch 拒绝；重连后不补跳 |
| 命令积压／过期 | 从服务器接收时刻计时；晚出队 Move 不复活输入、Jump 不补跳、旧 Move 不越过新 Stop；queued 不伪称 applied |
| Stop 丢失／窗口失焦 | 本机按键清理，服务端 watchdog 清持续意图；另一人、重力和惯性继续 |
| 旧连接迟到断开 | 不停止新有效绑定；撤权／迁移成功后的旧意图不能继续 |
| 已排队出站后迁移／注销／撤权 | 实际发送前拒绝已失去会话／租约／房间／连接资格的收件人，不依赖旧 group 成员继续广播 |
| 关闭控制浮层／隐藏 | 不丢正在使用的 lease，服务端继续；恢复用新帧，不从旧位置重建全房 |

| 首帧／模板就绪失败 | 来源恢复入口可用，无输入权限；不以 0,0／旧快照／部分身体假装入房 |
| 断线重连／公共超时 | 有效租约取共同快照恢复；过期不自动 Enter 或抢控制，无资格时明确需要重新准入 |
| 服务重启／合法释放后唤醒 | 原world确实丢失后新epoch、最新成员整组安全出生、零旧输入并明确提示；健康world不得误重生 |

| 队列／资源／故障 | 有界积压与补步、整房安全帧、唯一线程／owner、所属进程和 native 正常释放 |

故意关闭双体反作用、保留陈旧支撑、重复应用 Jump 或跳过控制代际的变体必须出现预期失败，证明门禁能识别错误实现。不得仅测按钮禁用、静态快照或“看到两只团子”。
