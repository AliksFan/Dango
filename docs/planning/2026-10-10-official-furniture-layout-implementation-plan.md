## 首个交付与工作区

先交付独立 Windows 单人窗口中的 **空布局／一件默认尺寸木平台**：选择、预览落位、拖动、方向微调、移除、保存，退出进程后重新打开恢复。编辑期间暂停同一个世界；取消恢复进入编辑时的现场，保存成功后按初始布局重新建立世界。

窗口必须有真实团子和平台碰撞。它是隔离交付入口，不冒充已接入日常安装、正式普通房、桌宠房或在线房间。沿用已验收平台小样的物理及呈现能力，保留原小样作为回归对照；不直接给 `LocalRoomWindow` 加第二个物理 owner。

本批保持一只团子、一件平台上限、默认平台尺寸和摩擦。球正式摆放、大小／弹性调节、平台加球、多件、旋转、PNG 导入、蹦床和窗帘后置。参数区保留平台“大小”的后续入口，明确暂不可调；不保存假参数。圆球可保留为暂不可用的仓库图标，不能点击后演出一个没有真实碰撞的球。

- 设计及只读源码盘点基线：`codex/furniture-layout-design@889f9a3`，包含平台、球的独立小样和布局交互稿。
- 当前准备阶段只修改文档；实施时从包含本计划的设计提交建立独立 `codex/furniture-layout-platform` Worktree，先核对既有修改、分支占用和候选来源。
- 本批仅使用现有 .NET 10、WPF、System.Text.Json 和物理 API，不新增依赖，不改已验收身体参数或 native 求解器。
- 构建、数据和证据进入新的 `artifacts/furniture-layout/<RunName>/`。验收存档根目录显式注入并带任务所有权标记，不触碰日常数据；不覆盖旧输出或正在运行的 DLL。
- 不接账号、网络、数据库、对象存储或付费资源。main 合并、推送、安装更新、正式 DLL 替换和持久数据删除各自保持独立授权。

## 界面收紧

侧栏顺序保持微调、参数、仓库，各段按内容占高；仓库固定两列、纯家具图标。首版不复制原平台诊断窗口的多行按钮和技术数值面板，游玩时收起侧栏。编辑与浏览切换不能改家具坐标或造成额外物理推进。

|---|---|

| 保存布局 | 保存图标，提示“保存布局”；只有真实提交成功才结束编辑 |
| 取消本次修改 | 取消图标，提示“取消本次修改”；与取消单次摆放分属不同区域 |

| 待放置确认／取消 | 勾／叉图标，提示“放置到预览位置”／“取消放置”；确认仍执行合法性校验 |
| 方向微调 | 紧凑四向箭头；选中已落位家具时可用 |
| 未保存离开 | 保留“保存并离开／放弃修改／继续编辑”文字，明确三个结果 |

图标参考 `AccessoryEditorTheme.IconButton` 的现有 Path 绘制方式，图形不参与命中；家具保留自己的业务事件，不复用配饰删除确认或全局重构主题。使用真实 Button、中文 `AutomationProperties.Name`、ToolTip、禁用原因 HelpText、可见键盘焦点及 Tab／Space／Enter。细指针按钮可沿用现有 32 DIP 规格；触控输入目标至少 44 DIP，避免贴边误点。按钮获得焦点时的 Space 不得跳跃。

移除重复操作条、开发数值、长期占位说明和预览专用按钮；保持一处简短状态，非法位置或保存失败用持续原因。灰色参数控件保留一句必要的“后续开放”，不添加不支持的数值。界面模块显隐和按钮切换不得改变场景逻辑边界或取消已完成的草稿；真实 resize、DPI 变化及失焦仍终止未完成手势。

## 数据、几何与状态合同

### 初始布局

采用设计中的 0／1 件 schema，首版冻结 `schemaVersion=1`、`sceneId=local-single-window`、`coordinateSpace=static-platform-p-v1`、`sceneGeometryRevision=1`、`presetId=official-static-platform`、`presetRevision=1`。`instanceId` 为非空 GUID；锚点是平台支撑顶面中心，X 向右、Y 向上，使用当前平台原世界 `p` 单位。

映射固定为 `CenterX=anchor.x`、`CenterY=anchor.y-.175`，宽 3.4、高 .35、摩擦 .72。HTML 归一化位置和球 `q` 坐标不得写入此合同。保存不含窗口像素、DPI、相机、身体状态、速度、接触、物理步号或资源绝对路径；参数字段不进入本版。

布局文件上限 64 KiB UTF-8；拒绝多件、未知或重复字段、重复／无效 ID、未知预设或版本、非有限坐标、越界和出生保护区相交。不截断多余家具、不钳制载入坐标、不部分应用。空 `items` 是有效布局。

L0 在第一笔存档写入前冻结固定场景边界、地面与玩家出生区的实际数值，记录同一份 `LocalFurnitureSceneGeometry`，供显示、点击逆变换、DTO 校验及 native 建立共同使用。边界固定于场景，不能从窗口像素反算出另一套房间大小。首版保持平台水平、完整碰撞矩形在合法区域内；平台大小与出生区来自同一官方目录和选定身体配置。微调初始步长为 .05 `p` 单位，重复输入每秒最多 20 次，不补跑积压重复。

L0 几何数值冻结前，L1／L2 可使用虚构几何夹具验证纯规则及文件故障，但不能形成玩家可载入的正式 `sceneGeometryRevision=1` 布局。高处平台可用独立落地夹具验证支撑与起跳，不要求固定玩家出生点能跳到每个合法位置。

### 编辑与世界

状态显式区分浏览、编辑、待放置、拖动、保存中、已保存但场景启动失败，以及存档受保护／提交结果待确认。进入编辑复制初始布局为草稿，暂停原世界并清空游玩输入；缓存安全帧仅用于绘制，读取或绘制不调用 Step。

待放置和拖动临时位置不进入已确定草稿；确认合法落位才改变草稿。Enter 仅在场景编辑焦点内确认当前合法预览，不抢走按钮激活；Esc 先取消手势；方向键仅在场景编辑焦点内微调已落位家具。拖动取消或非法松手回到起点，微调越界拒绝本次变化。

取消编辑丢弃草稿并恢复原 session 的现场；不可重建相似世界来冒充恢复。保存期间拒绝重入，未完成手势先要求完成或取消。成功提交后停止并释放旧 session，再建立新初始布局，任一时刻最多一个活动世界和计时 owner；新场景健康前不开放游玩输入。

建立顺序使用同一创建线程：校验布局和能力 → 建立世界／平台与固定出生团子 → Add 完成后设置水平边界 → 得到首个健康帧 → 开放输入。具体顺序由 L0 的出生不重叠和边界反例验证；不能认为 native 平台通用校验自动包含玩家房间边界。Reset 保留旧平台，不用 Reset 代替应用新布局。

失焦、隐藏、菜单、resize、DPI 变化或失去捕获清输入并终止当前手势，保留已落位草稿；编辑恢复仍处于暂停。游玩恢复重置计时基准，不补跑挂起时间。关闭或离开有未保存修改时走三选确认，保存失败留在编辑；异常终止不承诺未保存草稿恢复。

暂停门禁的实际观测在 L0 冻结。现有平台小样的 `Steps` 是托管计数，`LastFrame` 是缓存，不能只比较它们就宣称 native 步号及完整状态未变。优先核验选定模块的 `ReadRoundBallFrame()` 共同只读帧导出、ABI 和无球平台读取，仅作 native 诊断，不创建球或替代平台能力检查；同时记录唯一消费者的实际 Step 调用。若不能取得可靠的独立只读状态，则该门禁标为未验证并停止相应运行验收，不能调用 Step 取得“静态观察”或把缓存比较升级为 native 证据。

### 文件提交

新增家具专用 Store，注入数据根目录。将加载结果区分为不存在、有效、损坏／不支持、临时读取失败及写入争用；只有“文件不存在”可自动当作可保存的空布局。坏文件保留原始字节，允许本次空场景游玩但禁止覆盖式保存；恢复与清理不是本批范围。

同一布局路径用家具专用锁文件和 `FileShare.None` 取得跨进程编辑所有权，第二实例明确拒绝写入，持锁到保存／取消／退出完成。操作系统在进程退出时释放句柄；不依赖记录 PID 或超时强行抢锁，不删除不属于本次操作的锁／临时文件。

锁文件存在不等于被占用，允许重新打开，以句柄竞争判断。每次取得编辑 lease 后重新读取正式文件，不能沿用上次浏览缓存作为最新布局；记录编辑基线的原始字节指纹或“不存在”状态，提交前再次比较。发现另一实例或外部修改时报告冲突、保留当前草稿并拒绝覆盖，不自动覆盖或合并。该检查用于协作实例间的冲突识别，不宣称可以阻止任意绕过锁文件的外部进程写入。

提交流程：校验草稿及平台能力 → 同目录唯一临时文件 → 写完并 `Flush(flushToDisk:true)` → 重读全部字节并完整校验 → 首次无覆盖 Move，已有文件使用受支持的原子 Replace → 确认目标为完整候选 → 更新已保存状态。文件系统不支持所需提交方式时明确失败，不回退到删除旧文件再写。只清理本次未提交临时文件，异常终止残留不自动当正式布局。

提交结果必须区分未提交、已提交和暂无法判定。提交前失败应保持旧正式文件字节不变、草稿与 dirty 不变；提交阶段抛错时重读目标确认：目标等于候选则按已提交处理，目标仍是旧文件则报告未提交，无法重读或可读但既非旧文件也非候选时进入保护／待确认状态并禁用下一次覆盖保存。不能对无法判定或外部变化的情况承诺旧文件完整不变。文件已提交而新世界启动失败时明确报告“布局已保存，场景启动失败”，保留可恢复界面，不假装文件回滚。

## 能失败的验收与停止点

| 层级 | 核验 | 错误实现应如何失败 |
|---|---|---|
| 数据 | 0／1 件往返；未知字段／版本／预设、多件、非有限值、越界和出生冲突拒绝 | 只解析 JSON、截断多件、缩放屏幕坐标或忽略出生区会失败 |
| 编辑 | 以 L0 核实的独立只读观测检查 native 步号与完整状态，核对实际 Step 调用不增加；取消恢复原 session；手势取消不提交临时位置 | 绘制偷偷 Step、只比缓存、改草稿就改 native、取消重新造世界会失败 |
| 输入 | 实际 HWND 下 Tab、按钮 Space／Enter、拖放、松键、失焦／捕获丢失、隐藏和 resize | 图标只支持鼠标、点击穿透为跳跃、恢复残留输入或旧指针会失败 |
| 文件 | 真正关闭进程后读取同一隔离文件恢复平台；空布局不误判 | 仅内存／交互稿状态恢复会失败 |
| 提交故障 | 写入、flush、重读、提交前失败和进程终止；旧字节保持、草稿可重试；提交后抛错及目标第三种内容另行确认 | 先删旧文件、半写正式文件、失败清 dirty、提交已完成却称未保存或不明状态继续覆盖会失败 |
| 争用／保护 | 第二实例或真实文件锁拒绝；重新取得锁重读及提交前基线检查；损坏与暂时读取失败保留原始文件并禁止覆盖 | 依靠按钮防重入、抢锁、用陈旧缓存覆盖新提交、坏文件自动变空文件会失败 |
| 真实物理 | 任意合法摆放中的左／中／右、高／低位置真实顶部支撑／起跳，侧底不误接地，边界不互相破坏；无平台回归 | 只移动图片、错误坐标尺度、Add 后丢 bounds、只跑原固定位置会失败 |
| 投影 | 100%、150% 与调整窗口尺寸；保存锚点不变，图片与碰撞同源，身体造型不受非等比缩放影响 | 将像素写存档或再次引入身体横向比例回归会失败 |
| 资源 | 至少 50 次进入编辑／取消／保存重建／关闭循环，世界与 timer owner 不累积，捕获释放；至少 10 分钟真实游玩观察 | 双世界、恢复补跑、关闭仍步进或残留进程会失败 |
| 人工 | 用户判断图标是否看得懂、侧栏是否简洁、平台摆放和恢复是否符合预期 | 自动检查不能代替这一项 |

平台顶部支撑、起跳、侧底碰及接触误差沿用[既有平台计划](2026-10-09-static-platform-implementation-plan.md)的门槛与独立几何 oracle，不降低历史预算。新模型只报告该模型实际执行的证据；旧模型通过不能转移为新模型通过。原性能、正式 Windows、多人和其他设备门禁仍保留。

候选模块缺能力或平台＋边界组合失败时，只阻止依赖真实物理的部分；纯数据、文件和编辑规则可以继续。若必须修改 native 求解器、改变官方尺寸或出生／坐标语义，保留失败证据并先补设计，不能扩大本批或换假物理展示。准备阶段不运行这些验证；它们是实施退出条件。
