## 3. 验证矩阵与证据要求

### 3.1 物理与配置

- 默认 100／50／50＋八个端点；分别保存每种配置与模块身份。混合体型接触和 30 件家具另成组合矩阵，不把九种单体等价当作全部笛卡尔组合通过。
- 每个端点覆盖静态平台站立、边缘掉落、跳台、拖压释放、球碰撞及支撑变化。多体包括双体正面／偏心、不同软硬与大小、三体接触链和继承的必要承重场景。
- 每次接触／热更尝试记录输入、配置、接触对象／版本、全世界成功 tick、残差／穿透／能量／工作预算与失败前后状态。数值门在 F7-0 及对应接触实验开始前冻结；若尚无充分指标，保持技术停止，不以截图判通过。
- 特设反例：错误 ABI／能力、半帧发布、部分热更、错 scene revision、丢合法 FIFO 帧、非法平台重叠、过期 token、清零睡眠状态、迟到旧房间结果覆盖新房间，均应被测出。
- 家具事务专门控制调度：异步 staging 期间身体进入候选区域，应在 prepare 前重新拒绝；prepare 后试图 step／热更不得穿插；提交后超时须核验真实结果。FIFO 已满时移／删承重平台，逐帧消费旧布局＋旧身体，最后才显示新布局＋新身体；不得混画、错命中或清空旧帧绕过。

### 3.2 休眠与性能

- 覆盖自然落稳、走停、跳跃／拖压释放、热更、取消／默认、睡眠中编辑／隐藏／关闭，以及睡体被球／另一身体碰撞、删／移支撑。
- 冻结最大支持视距／缩放下的可见形变预算，再测入睡；镜头或 DPI 变更重校准。保留当前 v2 及严格门的历史 FAIL；`120/0/100` 当前拒睡不改判。
- 可静置的同房间同配置至少 10 秒有效实秒 A/B：身体求解调用减少 ≥99%、进程 CPU 时间减少 ≥30%，包含接近检测／外观负载，报告 native 耗时、线程等待、分配／GC。活动球场景单独报告，不把未睡其它对象算作节能失败或假称全世界睡着。
- 真实输入到 WPF 成功显示在本机正常负载下目标 ≤100ms，明确其不是 GPU present。正式性能仍保留既有 59 FPS 门禁；不拿首页约 60 次姿态消费、加速 native 吞吐或短测关闭它。真实 120Hz、GPU present、支持 DPI／高对比另列覆盖，不要求虚构不可用设备。

### 3.3 数据、房间和实际产品

- Schema1～5 的受支持读取／显式应用、损坏／未知模型不覆盖；未应用草稿不入房，隐藏／退出不隐式保存；失败保留原文件与可重试草稿。已存在的间歇失败根因仍须单独核实。
- 三间稳定 roomId 的不同布局、相同／不同体型入房、地面检查点恢复、平台上退出保留旧安全地面点、改布局后落点失效、球重启回锚点；未来／坏恢复文件保护与准确提示。
- 原家具事务、目录额度／解散恢复不变；用跨房误绑定、外部文件变更、保存结果不明、入房取消及迟到帧制造可失败反例。
- 实际 EXE 至少两个独立进程验证保存／关闭／重新启动，绑定文件摘要、模型、参数、roomId、布局与实际显示；不以同进程重建替代跨进程恢复。
- 沿用既有家具房间负载：至少 50 次编辑／房间往返和 10 分钟有效运行，记录对象／线程／句柄与退出收尾；若最小化／遮挡使计算停止，暂停时段不计入有效观察。

### 3.4 界面、焦点与人工

按[桌面 UI v0.1](../desktop-ui-design-v0.1.md)第 2～6 节核对：最小正式窗口、常用横向、纵向；窗口普通控件焦点下 WASD／Space、文本／菜单隔离、失焦／捕获丢失、相反键和单次跳跃边沿；镜头、滚轮和家具输入优先级不变。保留圆形参数滑块及现有焦点／选中规则。

普通房与桌宠分开人工确认：相同身体／眼睛／配饰、平台和球的实际手感、拖压／手套、睡眠及外物唤醒、保存恢复、桌宠双表面／穿透／不抢焦点。后台先行；前台使用按 AGENTS 的屏幕授权要求执行。已授权范围和时段仍有效时不重复请求。自动、截图、虚拟时钟和局部人工均不替代未覆盖专项。

## 4. 失败与交付状态

每个增量用新的证据目录和原始日志；不得覆盖旧 FAIL，重跑需说明变化／根因。文件保存问题未查清时保留错误码、writer／校验阶段与文件摘要，不能靠重试隐藏原失败。物理失败锁存并保留全世界最后安全状态；不能对外称已入房或保存成功。

最终报告分别列：自动门、真实运行、人工确认、模块与数据保护、仍未验证的设备／性能和 Git 状态。只有必需门与对应人工完成后才把 F7 标为已验收；本地 main 合并、推送、安装／部署和归档回收均另行授权。本草案当前没有实现结果。
