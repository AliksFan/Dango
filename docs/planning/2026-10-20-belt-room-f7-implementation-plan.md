## 2. 当前接入位置与实际阻断

下一实施项从现有 `LocalRoomSceneDriver`、`StackedDangoSceneRuntime`、`DesktopPhysicsScene` 的调用边界开始，先接通新模块的创建／步进／成功帧／销毁，以及现有呈现和输入。只在现有职责容纳不了新ABI时补充最小适配类型；不预先建立第二套房间框架或新房间UI。

接线与接口检查可以使用既有测试夹具和隔离数据先行；实际玩法开放前解决该路径的阻断：

| 已知问题 | 影响 | 处理时机 |
|---|---|---|
| 新room模块尚无桌面调用 | 新模型不能沿现有房间链路运行 | 下一实施项，完成现有框架的物理／状态帧适配 |
| 默认离边／角点／跳台返回 `-707` | 常用平台运动会停在安全帧 | 与接入定向修复，相关玩法开放前完成；未决不冒充穿透或通过 |
| 横向bounds仅为guard拒绝 | 不能提供现有房间的实体边界体验 | 边界玩法开放前适配 |
| 新模块没有球和家具集合能力 | 无法完整载入现有球／多家具布局 | 对接相应布局前补齐新内核能力；不阻塞无关接线，不清空实际布局 |
| 新模型的家具／恢复校验仍待适配 | 旧160×120中性包络不能代表新体型 | 接入家具变更、加载恢复时处理；沿现有事务和文件格式工作 |
| 历史迁移保存间歇失败根因未知 | 持久化交付仍有独立开放风险 | 在[原收尾调查](../verification/2026-10-20-belt-body-closeout.md)继续跟踪；不凭本轮文档或重复绿灯关闭 |

## 4. 验证按接入影响安排

- **运行接线阶段**：核对新模块身份／能力、唯一物理更新、完整成功帧、坐标与命中一致、输入与生命周期交接。已有单体FIFO和事件机制以现实现为起点；只验证房间适配改变的边界，不重新开发整套机制。
- **静态玩法阶段**：针对现有失败输入验证离边／角点／跳台及墙。九配置和54动作表保留为风险诊断，不要求全部组合清零才能接线；未触发的行为仍是未验证。
- **球／家具阶段**：验证真实接触、集合容量、布局版本和支撑变化；保存、失败保护与恢复沿既有实现，只补新模型相关反例和回归。30件负载、长时编辑观察在该阶段执行，不作当前接口适配前置。
- **休眠阶段**：先正确运行，再按房间可见尺度验证入睡／外来唤醒，测实际CPU收益。原99%求解调用／30%CPU数字作为比较目标，不把固定收益或任意叠放稳定当全部接入的绝对前置；旧拒睡记录保留。
- **产品验收阶段**：普通房与桌宠分别体验，覆盖现有WASD／Space焦点边界、拖压／手套、相机、家具、保存恢复及新体型外观。UI沿[桌面规范v0.1](../desktop-ui-design-v0.1.md)第2～6节和现有页面；本轮没有页面设计变化。后台测试优先，需占屏时按AGENTS授权规则执行。

原接口、模块和数据路径可以继续独立开发；实际入口只声明已接入并验证的能力。加载真实房间须按其原布局检查能力，不删除对象、不静默回退旧模型、不制造保存成功。支持范围、失败与未验证项明确记录。
