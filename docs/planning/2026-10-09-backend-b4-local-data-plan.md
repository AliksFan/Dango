## 精确目标

仅使用当前用户 LocalApplicationData 下 `Dango/BackendDevelopment/run20261008b0/pgdata` 的既有独立 PostgreSQL 18 实例。复用 `state.json` 中已记录的本机端口、`dango_backend_b0` 库、`dango_b0_owner` 角色、受当前用户保护的 `credential.dpapi`、`b1test-state.json` 与 `b1tests-keys`。不生成新恢复代际，不初始化、创建新库或重置旧数据；不连接或停止系统现有 PostgreSQL 服务。

绝对路径由工具依据系统目录展开，仓库不提交个人端口或凭据。检查路径无 reparse point、运行名／库／角色／版本一致、实例目前停止后才启动；只监听 IPv4 loopback。连接后核对数据库、data_directory 和 PostgreSQL 18。任何不匹配立即拒绝，不替换目标。

## 迁移与写入

按下列顺序仅前向应用两个源码迁移；已应用则保留，不执行 Down：

2. `20261009062701_RoomAccessIntegrity`：补码恢复代际、租约 user／pet／session 对应复合外键、控制租约同 Pet 外键、睡眠／无房不能持控制资格检查。既有 Pet／Session 只增加关联唯一键；现有归属控制列为 null，新增码表在执行前应为空。

维护入口只接受精确 pending 迁移序列或该序列已应用的后缀。不会自动应用其他新增或缺失迁移。正常服务启动也不迁移。

执行虚构 B1–B4 回归：生成随机 `.invalid` 邮箱、注册邀请、挑战、受控邮件队列、会话、账号团子和默认房；创建虚构共同房、公共码密文／摘要、封禁、设备实例／租约、归属、审计与 outbox。不记录原始码、密码、证明或 Cookie。邮箱测试只用受控本机 SMTP 接收器，不向真实收件人发邮件。

B4 额外写入范围：

- 入房／迁移／离房、接管、attach／心跳、租约结束、到期裁定，仅涉及本次新造账号、团子、房间及设备。
- 公共码重置、移出／封禁／解除封禁、解散／恢复和到期清理。公共预准入的独立到期裁定只扫描新造目标房的团子；主准入失败时这些正确的独立到期裁定可已提交，主准入归属和请求收据必须回滚。
- 租约维护 `permittedPetIds`、outbox 投递 `eventIds` 和永久房间清理 `roomIds` 全部使用测试显式记录的新造 ID，上限分别 50／20／50；禁止用 null 范围启用全库任务。B3 回归的永久清理也只针对其新造 ID。
- 为验证检查／外键，允许在显式事务中尝试非法虚构记录并回滚；为验证故障允许受控 checkpoint 抛出，不能真实破坏文件或结束无关进程。
- 允许 B1 回归按现有受控邮件分发合同推进虚构邮件任务状态；未采集全部旧数据前后快照，因此不宣称旧每一字段完全不变。原有账号身份、Pet 配置、房间与业务数据不做重置／批量撤销。
