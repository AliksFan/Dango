## 1. 背景与结论

P2D-007A 的多体候选在连续修正中混入了与既有基线不一致的局部规则：预览使用直接二维 Box2D 力代替 P2D-006 的正式方向控制手感，三体接触另设高摩擦或低摩擦实验值，骨架显示也从 P2D-007 的完整拓扑逐步退化为径向线、最终变成只有节点。这样虽然能分别满足局部自动断言，却无法稳定回答“正式团子究竟应如何移动、重叠、承重和滑落”。

本方案不再继续叠加局部补丁，而是恢复单一来源：

1. Core 权威运动恢复并复用 P2D-006 已验收语义；
2. 单体轮廓恢复并复用 P2D-005 的完整默认参数；
3. 团子间有限重叠恢复并复用 P2D-007 已人工接受的接触边界；
4. 调试骨架恢复 P2D-007 的完整拓扑：核心、径向弹簧、相邻节点弹簧和节点；
5. P2D-007A 直接替换当前正式桌面场景的表现实现，在 `Wallpaper` 与 `Window` 两种宿主中验证真实重力、三体承重、偏心失稳和滑落，不再创建独立预览窗口；
6. 当前观察到的 Z 字形暂不在本轮修复。完整骨架用于暴露真实拓扑，用户先观察恢复效果，再决定是否单独立项诊断。

## 2. 目标与非目标

### 2.1 目标

- 形成一份可直接指导恢复实现、测试和桌面观察的团子特性账本。
- 让正式桌面场景中的单体、双体和三体表现使用一致的轮廓、材质、碰撞与权威边界定义。
- 恢复 P2D-007 完整骨架，使节点顺序、弹簧拓扑、核心位置和碰撞形变可见。
- 在三体场景中证明：严格居中可以承重；偏心后受重力滑落；移开支撑后能够分离；帽子不承重。
- 保留 P2D-007 双体强挤压的已验收观感和有限重叠，不因三体调整而退化。

### 2.2 非目标

- 本轮不修复、隐藏或重新命名 Z 字形；只记录并观察。
- 不进入 P2D-008 的 1/6/12 只性能采样。
- 不实现好友、房间、网络同步或服务端碰撞裁定。
- 不重做团子美术、DIY、帽子种类、眼睛系统或正式群体行为。
- 不修改 P2D-006 已验收的正式键盘手感来迎合局部实验。
- 不新增 P2D-007A 控制中心验收定义、验收会话、草稿或 Markdown 导出；本轮由自动门禁与用户直接观察桌面效果形成证据。
- 不删除或改写 P1-002/P1-003/P1-006 已经存在的历史验收记录；“不再使用验收记录”只约束本次物理恢复任务。
- 不提交、合并、推送或部署；这些仍需单独授权。

## 3. 分层权威模型

| 层 | 负责 | 不负责 |
|---|---|---|
| Core | 权威位置、工作区边界、方向控制、跳跃、落地、拖动和动作状态 | 软体节点、局部弹簧、视觉重叠 |
| Presentation Contract | 把 Core 快照和接触 cue 转成有界表现输入 | 回写 Core 位置、制造业务接触结果 |
| Box2D Adapter | 重力、外圈节点、弹簧、碰撞、局部形变和表现偏移 | 决定权威落点、角色权限或房间状态 |
| WPF Visual | 绘制身体、眼睛、帽子和调试骨架 | 修改物理、输入或 Core 状态 |

Box2D 输出只能进入局部轮廓、附件挂点、诊断和临时 `RenderOffsets`。任何节点、碰撞冲量、动态核心或表现偏移都不得修改 Core `VisualBounds`。

## 4. 正式桌面承载决策

### 4.1 直接替换范围

- 恢复候选直接进入当前正式 `DangoScene`，替换桌面上现有团子的表现控制器和物理 world。
- `Wallpaper` 与 `Window` 两种正式宿主消费同一个场景、同一份 Core 快照和同一套物理表现，不分别维护实验实现。
- 当前用户自己的团子仍是唯一 Core 权威实体；正式场景启动时只显示这一只。控制中心可在本次运行中按顺序添加最多两只本地虚构测试参与者，并按最后添加优先移除；数量不持久化，不创建账号、好友、房间或多人同步结果。
- 未显示的测试参与者必须禁用物理 body 和碰撞；显示/隐藏、宿主切换、Explorer 恢复和应用退出必须统一管理同一个最多三体的表现 world。
- 恢复期间不保留“正式单团子”和“实验三团子”两套可切换运行路径；自动 fallback 只用于 native 不可用或形变越界，不用于静默切回旧候选。

### 4.2 控制中心职责

- 控制中心继续使用现有“桌面体验”页面管理 `Wallpaper/Window`、显示/隐藏、允许交互、键盘控制开关和方向键/WASD 方案。
- 在现有桌面体验设置中增加开发期“显示完整物理骨架”开关；它直接控制桌面上的正式场景，默认关闭，不创建第二个窗口。
- 控制中心只显示必要的运行诊断与测试入口：native 状态、当前团子数量、多体 world 状态、contact 数、最大节点速度、fallback 原因，以及“添加团子”“移除团子”。
- P2D-007A 不接入“实验与验收”页，不创建验收清单、人工结论下拉框、备注、草稿或导出报告。
- 既有“实验与验收”页面及历史数据保持原样，避免把本任务扩大为控制中心删除或重构。

### 4.3 独立预览退役

- `--stacked-contact-preview` 不再作为实现、验证或人工观察入口；恢复实施时删除该启动分支和独立窗口文件。
- `--paired-contact-preview` 与早期单体预览不再作为本轮人工验收入口；其无窗口物理回归测试继续保留。
- 若这些历史预览入口仍被其他已批准验证文档引用，实施时同步标记为历史入口或删除运行说明，不能留下看似仍受支持的命令。
- 开发者不能为了方便调参重新增加临时独立窗口；需要观察的诊断必须叠加在正式桌面团子或显示在控制中心运行状态中。

## 5. 正式方向键/WASD特性

桌面上的主团子通过正式宿主已有的 `DirectionalControlIntent` 和 `SingleDangoMotionController` 驱动，不得直接把 WASD 映射为任意二维 Box2D 力。

### 5.1 键位与焦点

- 方向键/WASD 二选一；产品默认方向键，键盘控制默认关闭。
- 用户通过控制中心现有键盘开关选择方向键或 WASD；不得增加“预览专用 WASD”旁路。
- 左/A、右/D：地面水平移动。
- 上/W：单跳。
- 下/S：有界原地挤压。
- 普通窗口只在自身获得焦点时生效；失焦立即清空 held 状态。
- 只处理当前方案四键，不记录原始键码、次数、时间线或前台窗口标题。

### 5.2 已定运动参数

| 参数 | 基线值 |
|---|---:|
| 最大水平速度 | `55 DIPs/s` |
| 水平加速度 | `110 DIPs/s²` |
| 默认地面减速度 | `320 DIPs/s²` |
| 默认地面摩擦系数 | `1.0` |
| 可站立表面摩擦范围 | `0.05–3.0` |
| 满速默认停稳时间 | 约 `172 ms` |
| 跳跃高度 | `48 DIPs` |
| 跳跃时长 | `640 ms` |
| 方向跳锁定速度 | `±55 DIPs/s` |
| 完整方向跳距离 | 约 `35.2 DIPs` |
| 长按复跳冷却 | 落地后 `450 ms` |
| 下压形成时间 | `120 ms` |
| 下压恢复时间 | `160 ms` |
| Landing 自动回 Idle | `750 ms` |

### 5.3 行为规则

- 禁止二段跳，空中左右输入不改变已经锁定的方向跳轨迹。
- 左右同时按下时目标速度为零，并按当前表面摩擦减速。
- 单一左右方向更新 `Left/Right` 面向；松开保留最后面向；左右同时按下不改变面向。
- 表现层只让眼睛挂点沿面向偏移 `0.075`，不镜像身体或帽子。
- 下压不改变 Core 边界和底边，空中下压无效。
- Core `VisualBounds` 始终通过 `ClampInside(workArea)` 完整限制在工作区内；抵达左右边界后朝外速度归零。

## 7. 团子间接触与有限重叠

### 7.1 P2D-007 已验收基线

- 两个团子共享一个 paired Box2D world，但仍各自保留独立 Core 权威锚点。
- 接触由唯一共同 cue 激活；双方不能独立裁定接触对象或最终位置。
- 节点与对方节点、对方核心碰撞代理产生真实 contact。
- 碰撞节点半径为视觉轮廓节点半径的 `10%`，视觉仍绘制完整半径。
- 强挤压 cue 为 `1.0`，双方接触锚点额外靠近 `8 DIPs`。
- 允许的物理局部轮廓间距为 `-0.16～-0.09`，负值代表有限重叠。
- 已验收稳定值约 `-0.0977`；WPF 映射及接缝补偿后约 `-2.01 px`。
- 接触侧节点内缩约 `0.1023`，远侧变化约 `0.000031`，形变必须保持局部。
- cue 取消后 contact 在有界时间内归零，弹簧恢复常态参数。

### 7.2 三体恢复原则

- 三体接触的材质、碰撞半径、渲染采样和视觉重叠从 P2D-007 派生，不保留 P2D-007A 当前独立的 `0.02` 团子间摩擦实验值作为产品基线。
- 地面摩擦与团子间接触材质分开定义；不能为了让团子滑落而改变 P2D-006 的地面起停手感。
- 严格居中的三体应能形成两组相邻接触并稳定承重。
- 偏心团子的质心投影超出有效支撑区后，应在重力和真实接触法线作用下滑落；不得额外播放预制位移或施加隐藏横向力。
- WASD 移开底层时，上层不应被摩擦永久拖走；接触应在有界时间内解除。
- 三体的目标视觉重叠先采用 P2D-007 的约 `-2 px` 基线，允许在人工观察后形成单独、有证据的新容差；当前 `-4.52/-4.15 px` 只保留为失败候选证据。

## 8. 完整骨架恢复

### 8.1 显示内容

恢复 P2D-007 双体接触阶段的完整骨架语义，并直接绘制在正式桌面场景中：

1. 一个物理核心点；
2. 核心到每个轮廓节点的 16 条径向弹簧；
3. 每个节点到下一节点的 16 条相邻轮廓弹簧，末节点闭合回首节点；
4. 16 个轮廓节点；
5. 身体轮廓仍在骨架下方正常绘制，以便比较视觉轮廓与物理拓扑。

### 8.2 绘制约束

- 骨架只在用户通过控制中心桌面体验设置显式打开“显示完整物理骨架”时出现，默认关闭。
- 径向线、轮廓线、核心点和节点必须用不同颜色或透明度区分。
- 连线必须严格使用 native 返回的当前帧节点顺序，不能按 X/Y 重新排序。
- 相邻轮廓弹簧必须按 `(i, (i+1) mod 16)` 绘制，不允许跨索引连接。
- 调试绘制只观察现有拓扑，不修改弹簧、节点、碰撞或渲染轮廓。
- 帽子不出现在物理骨架中，因为它没有 stacked 碰撞对象。

### 8.3 Z 字形边界

- 本轮不把 Z 字形定义为骨架显示失败，也不隐藏对应连线。
- 若恢复后仍出现 Z 字，保留截图、帧号、节点坐标、核心位置和接触状态作为后续诊断输入。
- 后续单独判断它属于：轮廓节点顺序翻转、节点穿越、局部面积翻面、核心跑出轮廓、物理/渲染坐标映射错误，或正常径向拓扑的视觉误读。
- 未经新的诊断与设计批准，不通过删除线段、降低节点数或切换 authored fallback 掩盖现象。

## 9. 眼睛、帽子与绘制层

- 眼睛由运行时表情和面向驱动，不是固定捏脸资产；眼睛不参与碰撞。
- 帽子保持独立 WPF 配饰层，没有 stacked native body、shape 或 joint。
- 所有帽子在全部身体之后绘制，始终位于最高显示层。
- 帽子只消费顶部动态挂点和有界旋转，不能承担上层团子的重量。
- 身体之间出现缝隙或重叠时，必须调整身体接触/映射，不能用帽子遮挡接缝。

## 10. 恢复实施范围

### R0 — 冻结当前失败候选

- 保留当前 Z 字截图、无线骨架候选、`0.02` 摩擦实验、偏心滑落和粘连反馈。
- 核对分支、HEAD、dirty worktree 和 P2D-007 回归基线。
- 停止当前仍在运行的独立预览后再重建 native DLL；只停止本任务启动的精确 PID，此后不再启动该入口。

### R1 — 先失败验收

- 骨架测试要求 1 个核心、16 条径向线、16 条闭合相邻线和 16 个节点。
- 相邻线的索引必须严格为 `(i, i+1)`，错误跳号或跨接必须失败。
- 三体参数与 P2D-005 默认值不一致时失败。
- paired 局部间距不在 `-0.16～-0.09`、实际视觉间距明显偏离约 `-2 px` 时失败。
- 三体严格居中不能承重、偏心不滑落、移开支撑后持续粘连时失败。
- 帽子进入 native stacked section 或绘制在任一身体之下时失败。
- Core 权威边界被 Box2D 位移改写时失败。
- 正式桌面场景仍走旧单体 world、宿主之间使用不同物理实例，或启动任何独立预览窗口时失败。
- P2D-007A 创建控制中心验收会话、草稿或导出记录时失败。

### R2 — 正式桌面场景切换

- 将三体表现 world 接入现有共享 `DangoScene`，由 `Wallpaper` 与 `Window` 两种宿主共同消费。
- 主团子复用 `DirectionalControlIntent` 与正式 Core 控制器；两只虚构测试参与者只用于本地物理接触。
- WASD 保持左/右移动、W 单跳、S 下压，不再直接映射成上下左右 Box2D 推力。
- Core 输出权威边界；stacked world 消费边界和接触 cue，只生成局部轮廓。
- 控制中心桌面体验页增加完整骨架开关和只读物理诊断，不接入验收会话。

### R3 — 恢复 P2D-007 接触基线

- 从 paired 实现提取或复用明确的接触材质/碰撞半径定义，避免复制魔法数。
- 三体 world 使用同一有限重叠语义，同时保留真实重力和两组相邻 contact。
- 删除只服务于失败候选的独立 `0.02` 摩擦、对向偏心演出或过宽重叠断言。

### R4 — 恢复完整骨架

- 恢复径向与相邻轮廓弹簧绘制。
- 开关放在控制中心桌面体验页且默认关闭；打开后直接显示桌面正式团子的完整真实拓扑。
- 不在此步骤修复 Z 字形。

### R5 — 正式桌面验证

## 12. 桌面观察清单

用户在正式桌面场景中直接检查：

1. A/D 是否恢复为 P2D-006 的低速加速、松开减速，而不是直接力推或滑行。
2. W 是否为一次完整跳跃，S 是否为底边不动的轻微下压。
3. 完整骨架是否恢复：核心、径向弹簧、相邻弹簧和节点都可见。
4. 严格居中时是否能自然承重，不像三个硬球或严重塌陷。
5. 偏心时是否沿另一只团子的身体滑落，而不是悬空、穿透或预制平移。
6. 移开底层后上层是否自然失去支撑，双方是否及时分离。
7. 身体接缝是否接近 P2D-007 已接受的轻微重叠，而非明显缝隙或过深吞入。
8. 帽子是否始终显示在身体上层且没有承重感。
9. 记录 Z 字形是否仍出现及出现时机；本轮只观察，不以其是否消失作为通过条件。
10. Wallpaper 与 Window 切换后是否仍是同一组三体状态，没有复制、重置或同时出现两套团子。
11. 隐藏、恢复、Explorer 重启和退出是否正确释放或重建整组表现，不残留独立预览窗口。

## 13. 停止点与交付边界

- 若恢复 P2D-007 接触参数后无法同时保持三体承重和有限重叠，停止并报告冲突，不新增另一组未经批准的三体材质。
