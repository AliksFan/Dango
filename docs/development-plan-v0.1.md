## 1. 计划原则

- 先验证最危险的体验假设，再建设完整业务系统。
- 每个阶段都产出可运行、可验证的增量。
- 阶段结束必须区分自动门禁、真实运行和人工验收。
- 当前阶段未通过时，不用下一阶段功能掩盖问题。
- 每个阶段使用独立分支；获用户批准后才合入 `main`。
- 移动端、自由绘画、公开广场和随机匹配不属于首版阶段。

## 2. 阶段总览

|---|---|---|---|
| Phase 0 | 工作区与技术基线 | 如何让后续开发可重复、可验证、可治理？ | 已验收 |

## 4. Phase 1 — 桌面生命感原型

### 目标

证明一只团子可以在真实 Windows 桌面和悬浮岛之间自然活动，同时不破坏正常电脑操作。

### 范围

- 单机、无账号、无正式服务器。
- Windows 桌面承载方式验证。
- 一只临时团子和一个悬浮岛。
- 待机、移动、爬岛、下岛、点击、抚摸、拖动、隐藏和退出。
- 输入穿透、焦点、任务栏、桌面图标、显示缩放和基础多显示器行为。
- 基本资源加载、帧率和内存监控。

### 不包含

- 好友、房间权限和情侣关系。
- 多人状态同步。
- 正式账号和数据库。
- 完整换装和家具编辑器。

### 必需交付物

- 可运行的 Windows 原型。
- 桌面宿主技术决策记录。
- 团子和悬浮岛坐标/碰撞约定。
- 基础动作状态机。
- 真实桌面验证记录。

### 阶段门禁

- 原型可反复启动、隐藏和退出，不遗留失控进程。
- 团子能够从桌面爬上岛并返回。
- 交互区域不会普遍阻断桌面图标和正常窗口操作。
- 至少两种分辨率或缩放配置下表现可接受。
- 用户人工确认空间感、治愈感和干扰程度达到继续开发的标准。

## 5. Phase 2 — 共享房间同步原型

### 目标

证明两个及以上客户端可以可信地观察同一个服务端权威房间，而不是各自生成一组团子。

### 范围

- 最小临时身份与房间接入。
- 统一房间坐标和时间基准。
- 房间快照与有序事件协议。
- 两只团子的移动、拖动和一次自动贴贴。
- 断线、重连、重复事件、乱序和快照恢复。
- 不同分辨率客户端的同一状态映射。
- 初步 WebSocket 负载与延迟测量。

### 不包含

- 完整账号注册。
- 正式好友、情侣和房间管理界面。
- 完整家具与多人动作库。
- 生产数据库和公网正式部署。

### 必需交付物

- 两客户端同步演示。
- 同步协议 v0.1。
- 房间权威状态和客户端预测边界。
- 重连恢复测试。
- 初步容量与带宽实测报告。

### 阶段门禁

- 两个真实客户端看到一致的位置、动作和动画时序。
- 一端拖动时，另一端看到同一次服务端确认的交互。
- 断线重连后不会生成团子副本或长期分叉状态。
- 模拟延迟下仍能通过平滑显示保持可信观感。
- 用户人工确认这是“同一个房间”，而不是两边相似的演出。

## 6. Phase 3 — 社交领域闭环

### 目标

实现熟人邀请、多房间和关系权限，使用户能够全天进入、离开和恢复自己的社交空间。

### 范围

- 正式账号和会话。
- 一名用户一只主要团子。
- 默认个人房间。
- 每人最多 3 个有效共同房间。
- 私人/公共房间、默认 6 人和最高 12 人。
- 好友申请与双方确认。
- 房主、可管理成员和访客权限。
- 唯一情侣关系和轻量标记。
- 设置家、私人睡眠、公共房间回家/消失。
- 房间解散、7 天恢复和永久清理。
- 服务端持久化、事务和权限测试。

### 不包含

- 广场、随机匹配和聊天。
- 正式内容商店或经济系统。
- 自由绘画上传。
- 移动端。

### 必需交付物

- 社交领域数据模型和迁移。
- API 与实时权限实现。
- 关键事务和审计记录。
- 完整正向、冲突、越权和并发测试。
- 可供熟人使用的全天测试环境方案。

### 阶段门禁

- 并发请求不能突破房间额度和情侣唯一约束。
- 未授权用户无法读取或进入私人房间。
- 私人下线、公共下线、失去权限和房间解散均正确迁移团子。
- 7 天恢复与永久清理可重复执行且结果一致。
- 三名以上真实用户可以完成添加好友、进入共同房间、下线和再次返回。

### 11.1 已登记的后续工作：团子 DIY 产品化

在 P1-004 只完成物理表现与参数验证，不把诊断调参台直接提升为面向用户的捏脸系统。Phase 4 创建团子流程开始前，单独完成 DIY 设计与实施计划，至少包括：

- 将宽高、顶部圆度、下半部鼓度、底部平坦度、常态压缩、恢复弹性和整体阻尼转换为用户可理解的控件与预设；
- 保留纯色和帽子选择，眼睛不作为固定捏脸预设；
- 定义组合参数的安全区域、版本迁移、恢复默认、性能降级和跨客户端一致表现；
- 明确外观/柔软度配置的持久化与服务端校验，不同步 Box2D 逐帧状态；
- 通过极端组合、旧版本兼容、多人同屏性能和人工观感验收后，才进入首版创建团子闭环。

地面、碰撞、节点数、子步、固定步长和熔断阈值继续由引擎管理。动作高度与撞击速度是否成为独立“动作性格”留待该设计阶段评估。

### 11.2 首版之后

首版之后再单独立项评估：

- Android 桌面小组件、悬浮宠物或 App。
- iOS 小组件或 App 内房间。
- 自由绘画上传和内容审核。
- 广场、随机匹配和公开多人空间。
- 更丰富的家具、房间装饰和创作者生态。

这些方向不属于当前六个阶段，不得提前作为首版依赖。
