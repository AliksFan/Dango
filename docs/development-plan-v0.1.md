> 日期：2026-08-31

> 当前阶段：Phase 0 — 工作区与技术基线

## 1. 计划原则

- 先验证最危险的体验假设，再建设完整业务系统。
- 每个阶段都产出可运行、可验证的增量。
- 阶段结束必须区分自动门禁、真实运行和人工验收。
- 当前阶段未通过时，不用下一阶段功能掩盖问题。
- 每个阶段使用独立分支；获用户批准后才合入 `main`。
- 移动端、自由绘画、公开广场和随机匹配不属于首版阶段。

## 3. Phase 0 — 工作区与技术基线

### 目标

建立自包含的工作规则、阶段计划、技术决策方法和可重复开发环境，为原型开发提供稳定起点。

### 范围

- 根级 `AGENTS.md`。
- 开发工作流和阶段计划。
- 仓库目录与模块职责草案。
- Windows 客户端候选技术调研。
- 服务端候选技术调研。
- 动画与渲染方案调研。
- 记录关键技术选择的 ADR 机制。
- 最小构建、测试和格式检查框架。
- Phase 1 的详细设计与实施计划。

### 不包含

- 正式团子美术。
- 多人服务器实现。
- 账号、好友和房间业务实现。
- 公网部署。

### 必需交付物

- `AGENTS.md`。
- `development-workflow-v0.1.md`。
- `development-plan-v0.1.md`。
- 技术栈选择记录及被放弃方案。
- 可重复执行的本地开发命令。
- Phase 1 桌面原型设计和验收清单。

### 阶段门禁

- 新环境可以按文档完成依赖安装和基础构建。
- 测试和格式命令能够运行并返回真实状态。
- 客户端、服务端和共享协议的职责边界明确。
- 技术栈选择有原型或资料证据，不只凭偏好决定。
- 用户批准 Phase 1 的详细范围和验收方式。

## 4. Phase 1 — 桌面生命感原型

### 目标

证明一只团子可以在真实 Windows 桌面和悬浮岛之间自然活动，同时不破坏正常电脑操作。

### 范围

- 单机、无账号、无正式服务器。
- Windows 桌面承载方式验证。
- 一只临时团子和一个悬浮岛。
- 待机、移动、爬岛、下岛、点击、抚摸、拖动、隐藏和退出。
- 输入穿透、焦点、任务栏、桌面图标、显示缩放和基础多显示器行为。
- 基本资源加载、帧率和内存监控。

### 不包含

- 好友、房间权限和情侣关系。
- 多人状态同步。
- 正式账号和数据库。
- 完整换装和家具编辑器。

### 必需交付物

- 可运行的 Windows 原型。
- 桌面宿主技术决策记录。
- 团子和悬浮岛坐标/碰撞约定。
- 基础动作状态机。
- 真实桌面验证记录。

### 阶段门禁

- 原型可反复启动、隐藏和退出，不遗留失控进程。
- 团子能够从桌面爬上岛并返回。
- 交互区域不会普遍阻断桌面图标和正常窗口操作。
- 至少两种分辨率或缩放配置下表现可接受。
- 用户人工确认空间感、治愈感和干扰程度达到继续开发的标准。

## 5. Phase 2 — 共享房间同步原型

### 目标

证明两个及以上客户端可以可信地观察同一个服务端权威房间，而不是各自生成一组团子。

### 范围

- 最小临时身份与房间接入。
- 统一房间坐标和时间基准。
- 房间快照与有序事件协议。
- 两只团子的移动、拖动和一次自动贴贴。
- 断线、重连、重复事件、乱序和快照恢复。
- 不同分辨率客户端的同一状态映射。
- 初步 WebSocket 负载与延迟测量。

### 不包含

- 完整账号注册。
- 正式好友、情侣和房间管理界面。
- 完整家具与多人动作库。
- 生产数据库和公网正式部署。

### 必需交付物

- 两客户端同步演示。
- 同步协议 v0.1。
- 房间权威状态和客户端预测边界。
- 重连恢复测试。
- 初步容量与带宽实测报告。

### 阶段门禁

- 两个真实客户端看到一致的位置、动作和动画时序。
- 一端拖动时，另一端看到同一次服务端确认的交互。
- 断线重连后不会生成团子副本或长期分叉状态。
- 模拟延迟下仍能通过平滑显示保持可信观感。
- 用户人工确认这是“同一个房间”，而不是两边相似的演出。

## 6. Phase 3 — 社交领域闭环

### 目标

实现熟人邀请、多房间和关系权限，使用户能够全天进入、离开和恢复自己的社交空间。

### 范围

- 正式账号和会话。
- 一名用户一只主要团子。
- 默认个人房间。
- 每人最多 3 个有效共同房间。
- 私人/公共房间、默认 6 人和最高 12 人。
- 好友申请与双方确认。
- 房主、可管理成员和访客权限。
- 唯一情侣关系和轻量标记。
- 设置家、私人睡眠、公共房间回家/消失。
- 房间解散、7 天恢复和永久清理。
- 服务端持久化、事务和权限测试。

### 不包含

- 广场、随机匹配和聊天。
- 正式内容商店或经济系统。
- 自由绘画上传。
- 移动端。

### 必需交付物

- 社交领域数据模型和迁移。
- API 与实时权限实现。
- 关键事务和审计记录。
- 完整正向、冲突、越权和并发测试。
- 可供熟人使用的全天测试环境方案。

### 阶段门禁

- 并发请求不能突破房间额度和情侣唯一约束。
- 未授权用户无法读取或进入私人房间。
- 私人下线、公共下线、失去权限和房间解散均正确迁移团子。
- 7 天恢复与永久清理可重复执行且结果一致。
- 三名以上真实用户可以完成添加好友、进入共同房间、下线和再次返回。

## 7. Phase 4 — 首版内容整合

### 目标

把桌面原型、多人同步和社交闭环整合为具有完整气质、流程和基础内容的首版作品。

### 范围

- 初次使用和创建团子流程。
- 有限颜色、表情和配饰。
- 基础家具与悬浮岛布局。
- 单人、双人和小群体自动互动。
- 普通贴贴与情侣专属贴贴。
- 房间、好友、权限和设置界面。
- 静音、隐藏和降低动画强度。
- 错误、满员、无权限、断线和恢复提示。
- 安装包和基础更新方式。

### 不包含

- 移动端、UGC、AI、聊天和公开广场。
- 大规模内容生产和商业化系统。

### 必需交付物

- 可安装的 Windows 首版候选包。
- 完整核心用户流程。
- 首版动作和家具清单。
- 性能、兼容性和易用性修复记录。
- 面向熟人测试的使用说明。

### 阶段门禁

- 新用户可以在没有开发者协助的情况下完成安装、创建团子和邀请好友。
- 多人房间连续运行时动作不会长期冲突、拥挤或冷落同一团子。
- 核心流程和异常提示完整。
- 产品在没有聊天和重养成时仍能传达陪伴价值。
- 用户人工确认首版内容和气质可以进入封闭测试。

## 8. Phase 5 — 封闭测试与发布准备

### 目标

在大陆节点全天运行，验证约 200 人规模下的稳定性、安全、恢复能力和真实使用反馈。

### 范围

- 大陆单节点初始部署。
- 2 vCPU / 4 GB 起始规格的真实容量验证。
- 200 个模拟 WebSocket 连接压力测试。
- 监控、告警、日志轮转和运行手册。
- 每日备份、每周备份和真实恢复演练。
- 安装、升级、卸载、崩溃和自动重连验证。
- 隐私政策、用户协议和大陆公开服务准备核对。
- 小范围封闭用户测试、反馈分类和阻塞问题修复。

### 不包含

- 企业级跨地域高可用。
- 未经重新立项的首版后功能。

### 必需交付物

- 封闭测试构建与版本记录。
- 压力测试和容量报告。
- 备份恢复证据。
- 监控与运维手册。
- 安全和隐私检查表。
- 用户验收记录和已知问题清单。

### 阶段门禁

- 200 个模拟连接可以建立并保持，指标处于已批准范围。
- 真实客户端可以全天连接、重连并恢复房间。
- 备份已经实际恢复验证。
- 高风险权限和删除流程通过测试。
- 没有未披露的阻塞级崩溃、数据丢失或隐私问题。
- 用户明确批准是否公开发布；通过技术门禁不等于自动授权上线。

## 9. 阶段状态规则

阶段状态只能使用：

- **未开始**：没有已批准的实施工作。
- **设计中**：正在澄清和批准阶段设计。
- **实施中**：已批准设计正在实现。
- **待验收**：实现完成，等待实时或人工验收。
- **已验收**：用户明确批准阶段结果。
- **暂停**：保留现场和证据，暂不继续。
- **撤回**：用户撤销该阶段工作；持久数据和分支是否清理需另行授权。

不得因为代码已经提交、测试部分通过或新阶段已经创建，就把上一阶段标记为已验收。

## 11. 后续路线

首版之后再单独立项评估：

- Android 桌面小组件、悬浮宠物或 App。
- iOS 小组件或 App 内房间。
- 自由绘画上传和内容审核。
- 广场、随机匹配和公开多人空间。
- 更丰富的家具、房间装饰和创作者生态。

这些方向不属于当前六个阶段，不得提前作为首版依赖。
