- 先验证最危险的体验假设，再建设完整业务系统。

## 4. Phase 1 — 桌面生命感原型

> 范围修订：原悬浮岛与爬岛路线已暂缓，留待独立专项设计和验收；以下当前门禁不再以它们为前提，历史验证记录保留。

### 目标

证明一只团子可以在真实 Windows 桌面安全区域内自然活动，同时不破坏正常电脑操作。

### 范围

- 单机、无账号、无正式服务器。
- Windows 桌面承载方式验证。
- 一只临时团子；悬浮岛留待后续专项。
- 待机、移动、点击、抚摸、拖动、隐藏和退出；爬岛、下岛暂缓。
- 输入穿透、焦点、任务栏、桌面图标、显示缩放和基础多显示器行为。
- 基本资源加载、帧率和内存监控。

### 不包含

- 好友、房间权限和情侣关系。
- 多人状态同步。
- 正式账号和数据库。
- 完整换装和家具编辑器。

### 必需交付物

- 可运行的 Windows 原型。
- 桌面宿主技术决策记录。

- 基础动作状态机。
- 真实桌面验证记录。

### 阶段门禁

- 原型可反复启动、隐藏和退出，不遗留失控进程。
- 团子能够在桌面安全区域内自然活动；爬岛与返回不属于当前门禁。
- 交互区域不会普遍阻断桌面图标和正常窗口操作。
- 至少两种分辨率或缩放配置下表现可接受。
- 用户人工确认空间感、治愈感和干扰程度达到继续开发的标准。

## 5. Phase 2 — 共享房间同步原型

### 目标

证明两个及以上客户端可以可信地观察同一个服务端权威房间，而不是各自生成一组团子。

### 范围

- 最小临时身份与房间接入。
- 只验证最小服务端权威同步，不实现正式桌宠房间、私密/公共共同房间、成员席位、建房额度或“返回桌宠房间”等领域规则。
- 统一房间坐标和时间基准。
- 房间快照与有序事件协议。
- 同步方案提前明确外观配置及物理预设的版本、保存、服务端校验与兼容边界；首轮只携带已实现且受支持的配置。
- 两只团子的移动、拖动和一次自动贴贴。
- 真实行走快慢节奏与共享移动规则共同设计，由服务端裁定；客户端基于共享状态呈现步态。
- 断线、重连、重复事件、乱序和快照恢复。
- 不同分辨率客户端的同一状态映射。
- 初步 WebSocket 负载与延迟测量。

### 不包含

- 完整账号注册。
- 正式好友、情侣和房间管理界面。
- 完整家具与多人动作库。
- 生产数据库和公网正式部署。

### 必需交付物

- 两客户端同步演示。
- 同步协议 v0.1。
- 房间权威状态和客户端预测边界。
- 重连恢复测试。
- 初步容量与带宽实测报告。
- 明确记录所用客户端、房间类型边界和验证环境；同机 Phase 2A 演示不得记录为正式房间或跨端交付。

### 阶段门禁

- 两个真实客户端看到一致的位置、动作和动画时序。
- 一端拖动时，另一端看到同一次服务端确认的交互。
- 断线重连后不会生成团子副本或长期分叉状态。
- 模拟延迟下仍能通过平滑显示保持可信观感。
- 用户人工确认这是“同一个房间”，而不是两边相似的演出。

## 6. Phase 3 — 社交领域闭环

### 目标

实现熟人邀请、多房间和关系权限，使用户能够全天进入、离开和恢复自己的社交空间。

### 范围

- 正式账号和会话。
- 一名用户一只主要团子。
- 每个账号自动拥有一间默认桌宠房间：仅映射到电脑当前桌面，房主和一名固定授权访客可进入，最多容纳两只团子；离线睡眠的团子仍占名额，房主离线不关闭访客进入权。
- 每人最多创建 3 间未解散的共同房间；桌宠房间不占此额度。
- 共同房间独立于真实桌面，分私密和公共两类，默认上限 6、最高 12；私密房按长期成员预留席位并允许离线睡眠，公共房只按当前在场团子限额且不留宿。
- 一只团子在任一时刻最多归属一个有效房间，允许合法无房间状态；进入、离开、断线恢复和多设备并发操作由服务端原子裁定。
- 好友申请与双方确认。
- 房主、可管理成员和访客权限。
- 唯一情侣关系和轻量标记。
- 不设置“家”或强制归处；公共正式下线和被移出／封禁、撤权、共同房间解散等被迫离房进入无房间状态，短断线保留原房重连。
- 房间解散、7 天恢复和永久清理。
- 服务端持久化、事务和权限测试。

### 不包含

- 广场、随机匹配和聊天。
- 正式内容商店或经济系统。
- 自由绘画上传。
- 手机端客户端交付；共同房间的手机进入规则只作为后续跨端客户端的服务端契约，不在本阶段交付手机界面或运行时。

### 必需交付物

- 社交领域数据模型和迁移。
- API 与实时权限实现。
- 关键事务和审计记录。
- 完整正向、冲突、越权和并发测试。
- 可供熟人使用的全天测试环境方案。

### 阶段门禁

- 并发请求不能突破桌宠两只团子、私密成员席位、公共当前在场人数、每人 3 间共同房间或情侣唯一约束；同一团子不会同时归属两个房间。
- 未授权用户无法读取或进入桌宠房间和私密共同房间；桌宠固定访客在房主离线时仍可进入，手机端直接进入桌宠房间的请求被服务端拒绝。
- 桌宠和私密共同房间中的正常离线团子继续占位；公共正式下线及被迫离房正确释放原房占位并进入无房间状态，不生成桌宠副本、不保留失效权限、不在再次启动时自动入房。
- 7 天恢复与永久清理可重复执行且结果一致。
- 三名以上真实用户可以完成添加好友、进入共同房间、下线和再次返回。

2026-09-08 叠放先行采样：居中双体/三体、0.020/0.045 四组原生 36,000 帧几何长测完成，但均散开落地，**持续叠放承重未通过**。没有稳定承重窗口，尚未固定压缩统计阈值。新增测试专用三体上下文、全配对联合约束及支撑必要条件门禁；下一步隔离横向散开来源，不调整满意参数或以隐藏扶正力维持堆叠。详见[评估记录](phase-1-dango-ground-contact-evaluation.md)。

### 11.1 已确认的后续工作：行走自然感与团子 DIY

P1-004 的物理参数验证不等于面向用户的 DIY。2026-09-22 确认将此工作拆为以下顺序，具体范围、理由及验收方向见[分批路线](planning/2026-09-22-gait-and-customization-roadmap.md)：

1. 当前下一小步：步态小样，仅轻微压缩/舒展/放松和起步/收步姿态过渡，先保留碰撞与位移规则。
2. 多人实现前：基础外观轻量版，分小批提供纯色、帽子、基础眼睛大小与眼型、最小保存及恢复默认；眼型与动态表情共同工作。
3. 最小多人同步：真实快慢节奏与服务端共享移动规则共同确定；方案设计时提前明确后续外观/物理预设配置契约，不提前实现全部 DIY。
4. 多人同步与碰撞原型稳定后：真实大小、体型和柔软度，从安全预设起步，再考虑有限滑条；定义组合安全区域、版本迁移、降级及跨客户端一致表现。
5. Phase 4：整合创建团子、编辑器和预设管理，通过极端组合、旧版本兼容、多人同屏性能和人工观感验收。

各批均先形成具体设计与实施计划，不把本次文档记录视为功能实施授权。地面、碰撞求解、节点数、子步、固定步长和熔断阈值继续由引擎管理；动作高度与撞击速度是否成为独立“动作性格”仍留待后续评估。岛设计与剩余专项延期安排保持原决定。
