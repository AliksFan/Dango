# Dango Phase 1 动画预生产设计

> 状态：Approved
>
> 日期：2026-09-01
>
> 批准日期：2026-09-02
>
> 所属阶段：Phase 1 — 桌面生命感原型
>
> 对应任务：P1-004 的非宿主前置工作；不改变 P1-003 → P1-004 的实施顺序

## 1. 目的

在 P1-003 WorkerW/Shell 宿主 Spike 继续按既定顺序推进的同时，提前完成不依赖桌面宿主的动画预生产准备，降低 P1-004 开始后的美术探索、资产整理和协议对接风险。

本设计采用“占位原型先行、正式资产可替换”的两步路线：第一步以低成本资产验证重量、呼吸、柔软感和动作可读性；第二步在 Phase 1 人工验收后保留动作 ID、画布、图层和锚点契约，用正式美术逐项替换占位素材。

本设计落实 [ADR 0003](adr/0003-animation-assets-and-rendering-validation.md)。运行时二次运动最初由 ADR 0004 定义，现已由 [ADR 0005](adr/0005-box2d-visual-soft-body-presentation.md) 取代；本预生产设计仍只负责资产与动作语义，不提前接入 Box2D、WPF 或最终渲染后端。

## 2. 范围

### 2.1 包含

- 一只虚构占位团子的视觉基准和分层源文件规范。
- Phase 1 首批动作的动作设计表、关键姿势、时序和缓动建议。
- 身体、眼睛和一个简单帽子的图层与遮挡规则；不制作嘴、腮红或地面阴影。
- 地面接触、点击、岛边抓取、站立和配饰等语义挂点。
- AI 草稿、人工修整、资产导出、清单生成和质量检查的生产流程。
- 与现有 `AssetPackage`、`DangoActionState` 和占位资产 Schema 的映射。
- 一个项目专用 `dango-animation-pipeline` Codex skill 的职责和资源结构设计。
- 资产来源、许可证、生成方式和人工修改记录要求。
- P1-004 开始前可以自动检查的资产完整性门禁。
- 手工关键姿势与 Box2D 视觉软体表现层的资产接口和 Spike 输入门禁。

### 2.2 不包含

- P1-003 WorkerW/Shell 实现或宿主选择结论。
- WPF Rendering Adapter、托盘交互或完整 P1-004 纵切实现。
- 正式美术风格、正式角色设定、完整换装或家具资产。
- Spine、Live2D、Rive、Godot 或新的渲染依赖。
- 用 AI 视频直接转换成运行时资产，或把概念视频称为完成的动画。
- 好友、房间、多人同步、关系动作和正式协议实现。
- 完整软体/刚体物理引擎，或让视觉物理裁定位置、碰撞和互动结果。
- 创建、安装或发布 Codex skill；这些属于设计批准后的实施工作。

## 3. 前置关系与分支边界

- 动画预生产在 `feat/p1-004-animation-preproduction` 独立分支和 Worktree 中进行。
- 当前 `phase/1-desktop-life-prototype` 继续承载 P1-003 及其既有修改。
- 预生产不得修改 `DesktopHost`，也不得以尚未验证的宿主行为约束资产格式。
- P1-003 完成且满足 C3 宿主可行性门禁后，才把获批的预生产成果集成到 P1-004 实施分支或阶段分支。
- 两个分支需要修改同一基线文档时，先完成 P1-003 集成，再重放动画文档变更，禁止互相覆盖。

## 4. 两步资产路线

### 4.1 第一步：Phase 1 占位资产

占位资产的目标是可验证，不追求正式美术完成度：

- 使用项目自有、虚构且无第三方角色权利风险的团子造型。
- 轮廓简洁，允许快速判断挤压、拉伸、重心和接触关系。
- 采用透明分层位图、少量逐帧轮廓姿势和运行时 Transform。
- 手工关键姿势负责动作语义；接触挤压、回弹和次级晃动允许由有界弹簧—阻尼层补充。
- 保留可检查的源文件、导出 PNG 和资产清单。
- AI 生成内容只能作为草稿或关键姿势参考；进入资产包前必须人工检查轮廓、透明边缘、图层、挂点和一致性。

### 4.2 第二步：正式资产替换

只有 Phase 1 人工验收确认桌面空间感、重量感和干扰程度后才开始：

- 冻结正式视觉方向、线条、材质、调色和标准视图。
- 保留已验证的动作 ID、逻辑画布、语义挂点、事件和 fallback。
- 逐动作替换占位素材，不让美术替换改变 Core 状态结果。
- 动作量、换装量或轮廓形变确实超过当前管线能力时，再通过新 ADR 评估 Spine 等工具。

## 5. 工具职责

| 工具 | 当前职责 | 明确边界 |
|---|---|---|
| Codex `imagegen` | 造型探索、透明分层草稿、关键姿势参考和变体比较 | 不直接保证连续帧一致性，不自动成为可交付资产 |
| Krita | 免费的分层修整、透明边缘处理和逐帧整理基线 | 不把 KRA 内部结构作为运行时唯一事实 |
| Clip Studio Paint EX | 可选的付费手绘与逐帧生产工具 | 购买前不把专有工程格式写入运行时契约 |
| Figma Motion | 位移、缩放、旋转、透明度和缓动的低成本节奏试验 | 不生产角色位图，不作为 WPF 动画格式 |
| Runway / Higgsfield | 可选的动作情绪、节奏和参考视频 | 视频只作为参考，不自动拆帧进入资产包 |
| 现有 Dango 资产运行时 | 解析和验证运行时资产包 | 不依赖任何上述编辑器的内部对象 |

Phase 1 不因用户接受付费工具而提前购买或绑定专有运行时。付费优先用于提高人工绘制和逐帧修整效率，而不是绕过现有资产契约。

## 6. 首批动作包

### 6.1 必须准备

| 动作状态 | 预生产交付 | 主要表现方式 |
|---|---|---|
| `Idle` | 标准姿势、呼吸高低点、轻晃范围、眨眼附加轨道 | Transform + 少量脸部帧 |
| `Wander` | 起步、移动循环、减速和转向姿势 | 位移 + 轮廓关键帧 |
| `ApproachIsland` | 接近岛边、降低重心和准备抓取 | Transform + 关键姿势 |
| `ClimbUp` | 抓边、提身、翻越和站稳 | 少量逐帧 + 抓取事件 |
| `OnIsland` | 岛上待机和安全站立姿势 | Transform |
| `ClimbDown` | 探身、离边和进入下落 | 少量逐帧 + 离边事件 |
| `Dragged` | 被抓取、悬空和有限弹性 | Transform + 拖动姿势 |
| `Falling` | 下落轮廓和朝向 | Transform + 单一轮廓姿势 |
| `Landing` | 接触、压扁、回弹和恢复 | 少量逐帧 + 落地事件 |
| `Reacting` | 点击后的短反应和表情恢复 | 脸部帧 + Transform |
| `Hidden` | 无可见帧和无持续动画 | 运行时状态，不制作假动画 |

### 6.2 延期

- 睡眠、醒来、贴贴、群体动作和情侣动作只保留方向说明，不在首批资产中制作。
- 抚摸识别属于 P1-004 输入实现；预生产只准备可复用的短反应，不定义鼠标轨迹采集。
- 多方向完整走路、复杂服装和任意颜色延期到首版内容验证以后。

## 7. 画布、图层与挂点规范

设计批准后的实施计划需要从现有 `phase-1.asset.json` 读取实际数值，并在首个样本通过后锁定；本设计不预先拍脑袋规定像素尺寸或帧率。

所有帧必须遵守：

- 同一逻辑画布、原点、角色基准尺寸和地面接触线。
- 源资产只保留 `body`、`eyes` 和 `hat` 三类职责；组合预览不能代替独立图层。
- 眼睛作为唯一默认表情元素独立播放；简单帽子不得烘焙进所有身体帧。
- 每个轮廓关键帧记录配饰挂点，避免播放时漂移。
- `ground-contact`、`island-grab`、`island-stand` 和点击区域使用语义坐标，不写死屏幕像素。
- 导出文件使用稳定、可排序且不包含美术软件对象 ID 的命名。
- 透明 PNG 禁止残留白边、黑边、半透明脏像素或图集渗色。

### 7.1 Box2D 视觉软体资产契约

- 所有接触在统一交互坐标系中表达为语义锚点、接触法线、强度和共同时间线；视觉求解不修改 Core 权威位置或状态。
- 手工姿势继续定义语义和 fallback；Box2D 运动学核心、节点环与弹簧关节只生成视觉形变，参数数值等待 P1-004 Spike 测量。
- 眼睛跟随身体局部形变但独立切换表情；帽子使用动态挂点并只允许很小的受限延迟。
- 双团子接触由单个 interaction director 生成成对约束，双方不得各自独立求解同一接触。
- 同一 Windows 构建的固定步长下，相同动作意图、时间、接触方向或锚点、参数版本与种子必须在批准容差内可重复；显示插值不得回写结果。
- 降低动画默认关闭连续软体求解；native、模拟、渲染或性能失败时回退到手工关键姿势。
- 当前 Schema 尚缺 Box2D profile、软体拓扑、接触法线、参数版本和动态帽子挂点；这些是 P1-004 契约缺口，不在预生产中借用无关字段。

## 8. `dango-animation-pipeline` skill 设计

### 8.1 定位

该 skill 用于把 Dango 动作需求转换为可审查的动作规格、AI 草稿提示词、资产清单和验证报告。它不替代动画师判断，不自动批准美术质量，也不修改运行时代码。

建议保持自动发现，名称为 `dango-animation-pipeline`，并明确只在 Dango 角色动画资产生产、整理或验收时使用。

### 8.2 结构

```text
dango-animation-pipeline/
|-- SKILL.md
|-- agents/
|   `-- openai.yaml
|-- references/
|   |-- asset-contract.md
|   |-- motion-language.md
|   `-- review-checklist.md
`-- scripts/
    `-- validate_export.py
```

- `SKILL.md`：任务路由、授权边界、草稿与正式资产区分、最小工作流。
- `asset-contract.md`：从仓库当前 Schema 提取的画布、图层、动作、挂点、事件和 fallback 规则。
- `motion-language.md`：重量、呼吸、挤压、回弹、安静程度和降低动画的项目语言。
- `review-checklist.md`：逐帧一致性、透明边缘、挂点漂移、穿插和许可证检查。
- `validate_export.py`：只在重复检查确有价值时实现，用确定性方式检查尺寸、Alpha、文件引用和清单一致性；不得代替仓库现有 C# 资产解析测试。

### 8.3 工作模式

1. **动作设计**：根据一个状态或交互输出关键姿势、时序、事件和降低动画版本。
2. **草稿生成**：调用 `imagegen` 生成明确标记为草稿的造型或关键姿势参考。
3. **导出整理**：检查人工修整后的图层、命名、挂点和来源记录。
4. **资产验收**：运行确定性检查和仓库现有资产验证，分别报告自动门禁与人工观感。

skill 每次只处理已授权的动作集合，不得自行扩展为正式美术重做、购买服务、安装插件或修改 WPF 渲染器。

## 9. 资产来源与费用控制

- 每个资产文件记录来源类型：项目人工绘制、AI 草稿后人工修整或项目代码生成。
- AI 提示词、输入参考和人工修改摘要随预生产记录保存，但不得包含个人敏感内容或无权使用的第三方素材。
- 不使用游戏、动漫或桌宠产品的角色图作为可交付训练参考或直接衍生素材。
- 购买软件、订阅或插件前单独列出用途、预计使用周期、导出格式、许可证和退出成本，由用户确认后执行。
- Phase 1 优先使用现有内置能力和免费工具完成第一个可验证样本，再根据人工工作量决定是否购买 Clip Studio Paint EX 或参考视频服务。

## 10. 预生产交付物

设计批准后，实施阶段应产生：

- 项目专用 skill 及其验证结果；
- 一份占位团子视觉基准页；
- 一份动作设计表和关键姿势表；
- 分层源文件以及导出的透明 PNG；
- 与现有 Schema 兼容的新版占位资产包；
- 资产来源与许可证清单；
- 自动资产检查结果；
- 人工检查表，明确哪些重量感、柔软感和干扰程度仍待真实桌面验收。

所有产物必须区分草稿、候选和已验收状态。图像生成成功、Schema 通过或 WPF 能显示都不能单独证明动画观感通过。

## 11. 设计验收标准

本设计获批需要确认：

1. 预生产不改变 P1-003 → P1-004 的实施门禁。
2. 首批动作集合足以支持 P1-004，且没有提前加入多人或正式内容范围。
3. 工具职责不会把视频、Figma 或专有编辑器格式变成运行时事实。
4. 占位资产可被正式资产按相同语义契约替换。
5. 自动检查、真实桌面表现和人工观感分别报告。
6. 付费工具在出现明确效率收益后逐项授权，不预先绑定。

## 12. 批准后的下一步

设计获批后再编写动画预生产实施计划，明确任务顺序、文件所有权、生成成本停止点、验证命令和提交边界；实施计划再次获批后才创建 skill、调用图像生成或制作第一批资产。

## 13. 2026-09-02 补充视觉要求

用户在 AP-003 重试前补充：首版计划提供简单捏脸；随后确认眼睛属于表情的一部分，暂不进入捏脸预设。因此当前只把身体纯色和帽子作为两个独立可配置类别；视觉采用简约纯色，不使用光影。

本分支据此调整资产预生产，但边界保持不变：

- 身体底色、表情层和帽子必须独立，不能为每个组合重画整套身体动画；
- 纯色要求排除光照、明暗面、高光、渐变、光晕和材质纹理；
- 完全取消接触影和地面阴影；落地点只通过 `ground-contact` 语义锚点与身体接触形变表达；
- 本分支只验证资产模块化与动画兼容，不实现捏脸 UI、数据保存、权限或多人同步；
- 当前 Schema 缺少调色参数、资源变体集和逐帧帽子挂点时，只记录 P1-004 契约缺口，不静默扩展运行时。

用户同时批准把无法稳定满足硬约束的图像生成路线切换为确定性分层 SVG，再可重复导出透明 PNG。SVG 是编辑器中立源文件，导出的 PNG 才进入现有位图候选流程；该调整不改变运行时资产格式，也不授权提前接入 WPF。
