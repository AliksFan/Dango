# 单体外围角度硬约束修订方案

> 用户已确认本方案；联合约束及 Window 地面修复后，用户确认桌面表现和操作手感通过。顶部圆润度另行开展局部试验，不代表 Phase 1 整体结束。

## 1. 已核实问题

- 当前 90° 下限与 180° 上限均依赖有限纠正力，不是硬约束；角度纠正强度为零还会关闭两种力。
- 原生步进结束检查交叉、速度和面积，没有角度合格检查。
- 原生输出将轮廓节点沿核心径向外扩一个节点半径。外扩前后的角度可能不同，不能仅验证物理点。
- 单独投影角度会与长度关节、地面接触和旧速度冲突；此前试验存在冻结，不能直接重复并把冻结算稳定。

## 2. 范围与保持项

保留 Box2D、核心和 16 节点、两组等长初始骨架及固定长度比例；保留桌面宿主、帽子眼睛、折叠面板、鼠标施力和 WASD 语义。不引入多体碰撞，不增加依赖，不通过预制轮廓或显示滤波掩盖物理问题。

先以顶部柔软度为零隔离角度求解验证。现有顶部试验代码保留，待角度门禁通过后做开启对照，不把关闭功能当作顶部修复完成。

## 3. 候选求解方式

### 3.1 小步推进与联合约束

将一个外部帧拆为原生固定小步，每个小步重新计算状态相关力，再运行 Box2D；初始候选最大步长为 1/240 秒。小步数量是内部实现细节，不新增面板参数。跳跃冲量只消费一次，抓取节点在一次拖动期间不改变，冷却按真实累计时间推进。

每个小步之后，在暂存位置上联合迭代以下约束，而不是只修一个角度就写回：

1. 两组骨架的最小和最大长度；径向下限沿用顶部柔软度定义。
2. 相邻外围边的有向转角在 0°～90°，等价于内角在 90°～180°。
3. 节点不得穿入地面；保持有向面积为正、固定节点顺序且没有非相邻边相交。

修正按逆质量分摊，内部约束不平移整体质心；地面约束属于外部反作用。采用有界迭代次数、修正步幅和退化边检测。收敛标准同时检查全部约束，不能以“迭代结束”代替“约束满足”。候选实现须通过测试确定数值容差和迭代预算，不能预先宣称对任意参数组合保证收敛。

### 3.2 速度和接触一致性

位置修正必须同步处理速度，消除继续指向越界方向的相对速度，并检查是否引入异常动能或整体漂移。不能把全部位置修正直接除以步长当作新增速度，也不能每帧把速度清零。需要验证 Box2D 的接触和关节缓存与外部修正兼容；若持续冲突，则停止该混合方案，不无限提高迭代次数。

### 3.3 软力与硬范围分工

保留“外围角度纠正强度”作为靠近边界时的软缓冲强度；调至零只关闭缓冲，不关闭硬范围。局部角度均衡力继续负责范围内的圆滑程度，不承担硬约束职责。

### 3.4 输出与失败处理

同时验证原始物理节点和最终显示轮廓的角度、自交。优先保留现有外扩规则；如果外扩导致显示轮廓越界，应明确调整物理节点到轮廓的映射并单独验证视觉尺寸、命中与帽子挂点，不把渲染修改悄悄算成求解成功。

无法收敛时不发布非法帧，沿用显式故障锁存，不自动重生。但任何正常或压力验收中的锁存都算失败，不是成功的保底结果；必须同时检查错误码、`IsRestartBlocked` 和连续运动响应。

## 4. 可失败验收与实施顺序

1. 先补测试：明确构造小于 90°、超过 180°、短边退化及合法轮廓；约束关闭软缓冲时仍需有效。原始角度与输出角度分别验证。
2. 实现暂存位置的联合约束及速度处理；先跑几何、守恒、长度和地面专项测试，再接入完整小步循环。
3. 每帧验证自由落地、强拖动和释放、A/D/S、W 起跳、连续大小切换；覆盖顶部柔软度 0、0.5、1。现有 180° 上限和角差测试不得放宽。浮点误差应靠内部安全余量吸收。
4. 测试不得只读最后一帧：检查全程角度、边长、无穿地、无自交、无锁存、速度有界以及输入后的实际位移；静置检查持续抖动与质心漂移。
5. 保留顶部降低、下宽上窄和局部角差门禁；角度通过不等于顶部试验通过。
6. 运行格式、构建、受影响测试及全量自动门禁。全部通过后再替换正式桌面 Release，不开独立预览窗口。正式桌面稳定性与用户观感单独验收。

## 5. 风险与停止条件

主要风险是外部位置修正与 Box2D 内部接触、关节缓存相互干扰，造成速度跳变、抖动或穿地。若联合求解在规定压力场景不能稳定收敛，报告具体失败，不引入无上限重试、不放宽角度或长度要求；是否转为统一的软体约束求解器须另行评审。

## 6. 本次实施与验证（2026-09-07）

- [用户满意参数基线](phase-1-dango-parameter-baseline.md)中的 16 项写入代码默认，顶部柔软度默认 0。保留原先的径向外扩输出方式，对其使用映射的解析梯度一起约束；没有额外修改视觉尺寸、宿主、帽子眼睛或输入桥。
- 增加 `dango_self_constraints.h`：暂存 17 个物理体的坐标和速度，按逆质量迭代角度、两组长度及地面。内部角度求解留 0.002 弧度安全余量，残差容差 0.00001；输出测试仍严格要求 90°～180°，未放宽。
- 原生每个小步不超过 1/240 秒，重新计算力和伸缩参数，跳跃每外部帧至多消费一次。输出速度使用当前核心速度；面积统计改为一致使用外扩后的相邻坐标，避免混合原始与外扩坐标。
- 第一轮 64 次迭代在关闭软角度力的落地场景第 52 帧未收敛；测得残差约 0.00001037，接近求解容差，而不是大幅角度越界。采用交替正反顺序、上限 96 次迭代后通过同场景；上限固定，不无界重试。失败仍返回 native `-91` 并锁存，测试把锁存视为失败。
- 速度修正仅移除约束闭合方向的相对速度，不将位置误差折算为额外动能。专项测试验证合法初始形状不动、锐角/内凹恢复、退化拒绝、内力质心与线动量保持、动能不增加以及地面和边长合法。

### Window 切换地面错位修复

用户反馈切换到 Window 后团子消失，重新生成后也会掉出窗口；用户尚未实际验收手感。

复现根因：`Show → Loaded → StartMotion` 与 `SetVisibility → StartMotion` 可在首帧前连续调用运行时 `Start()`。旧实现第二次调用清除了 `rehostPending`，把新宿主坐标差叠加到 canonical 锚点，但物理地面和世界参考点仍固定在旧值。回归场景测得显示纵向偏移从约 7.343 增至 547.343 像素。窗口缩放也存在同类坐标混用，拖动目标则缺少逆向宿主映射。

修复限于 `StackedDangoSceneRuntime` 的坐标映射：保持 canonical 物理空间和地面参考不变，宿主位置只参与显示映射，拖动指针使用对应逆变换；重复 Start 不再依赖一次性切换标记。不改 native 求解器和参数默认值，不靠自动重生修复。

新增重复启动/切换/显式重新生成测试，验证接地仍存在、可见底部落在新窗口范围内；新增缩放后的拖拽与未缩放参考模拟的逐帧对照。后者顺序运行两个独立 world，避免现有单体分配探针的进程全局计数相互干扰。受影响测试 6/6、Desktop Release 172/172、Core 36/36 通过，Release 构建零警告错误，格式检查通过。正式桌面已重新构建替换；真实模式切换与手感仍待用户复验，不能将本次自动回归算作人工验收。旧托管程序集保留于忽略的 `artifacts/before-window-ground-fix-20260907/`；未提交、合并或推送。
