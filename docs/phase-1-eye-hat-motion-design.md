## 本轮修订：保留旧版帽根埋入感

用户确认的是旧版的帽根位置和埋入感，不是新增固定深度数值。中立状态首先精确复现旧版显示变换后的帽根中心与角度（包括原素材坐标和旧绘制限幅）；不能仅把帽子整体再下移一个猜测像素值。

新的静态候选以头冠曲线作为滑动/倾斜的几何参考：保存旧版中立帽根中心 C0、角度 a0，以及参考轨道中立中心 G0、角度 g0。沿轨道到 s 后，视觉帽根为 `C0 + (G(s)-G0)`，角度为 `a0 + (g(s)-g0)`。这保留旧位置与几何参考间的偏移，s=0 与旧版一致；平顶上仍是平移，不重引入固定支点旋转。

非零宽区域仍用于稳定估计几何趋势；不再把整段帽底到表面的间隙/穿入数值作为视觉挂接门禁，不以抬高帽根满足严格表面距离。原严格距离用例保留为历史几何诊断，新候选另设旧版中立变换等价、滑动平移、角度有界、非法姿态拒绝与身体不变门禁，不删除失败记录或简单放宽旧测试阈值。

候选仍只读身体，不脱落、不独立碰撞、不施加反作用。动态接入时在初始化/明确重置时建立参考偏移，不逐帧重新读取旧最高节点角度而带回其换序跳变；连续形变的参考迁移仍留给后续动态增量验证。左右眼、帽身先弯曲后轴向形变及统一强度预算的已确认方向不变。

## 1. 目标与边界

后续动作能够表达“看向右上、闭眼、眨一下、帽子轻轻倾斜”，不需要知道 WPF 元素、轮廓节点编号、插值公式或像素坐标。身体运动时，眼睛保持在脸上，帽根持续贴合头部，帽身有有限惯性；动作中断后从当前姿态自然恢复，不突然跳回默认值。

这里的“自然运动”是只读身体状态驱动的附件二次运动，不是新的刚体/软体求解器。眼睛和帽子不施力于身体、不参加碰撞、不形成支撑；两只团子叠放时帽子仍按已验收规则在所有身体上层绘制，不承诺防止与另一只身体视觉相交。

本轮设计提供接口及验证方案，不实现完整待机、睡眠、抚摸、攀爬或随机眨眼调度。未来睡眠只需调用闭眼接口，但现在不会自动进入睡眠。

## 2. 现状核实与推断

代码核对路径：

- `src/Dango.Desktop/Physics/Presentation/DangoPhysicsPresentationAdapter.cs`：按实体实例保存左右眼、帽子位置及角度；眼睛目标为固定高度和间距，朝向使中心左右移动 0.06；以 `1-exp(-8*dt)` 平滑。帽子位置参考最高节点，角度参考最高三个节点的左右端，以 `1-exp(-6*dt)` 平滑。
- `src/Dango.Desktop/Physics/Presentation/PhysicsPresentationModels.cs`：附件输出只有位置/角度，现有 `PresentationPoint` 要求有限且位于 [-1,1]；没有眼睛开合与表情形状输出。
- `src/Dango.Desktop/Rendering/Dango/DeformableDangoVisual.xaml`：双眼当前为圆形。其 code-behind 对附件位移限制 ±0.2，帽角限制 ±0.35 rad；眼睛不使用旋转。
- `src/Dango.Desktop/Rendering/Dango/DangoHatVisual.xaml(.cs)`：独立帽子用于全局层级；同样包含绘制限幅和固定 160×120 素材空间，当前旋转原点与最终帽根挂点需校准，不能假定一致。
- `tests/Dango.Desktop.Tests/Physics/Presentation/DangoPhysicsPresentationAdapterTests.cs`：已有旧映射与提取后适配器严格相等测试，必须保留其历史契约，不能为了新效果直接删除。

据代码推断而非已复现的缺陷：最高节点集合变更可能让帽角目标不连续；绝对帽位置整体平滑可能在头部快速变化时形成暂时空隙；眼睛固定高度不反映局部挤压；显示层二次限幅可能遮蔽适配器输出。上述问题需用录制的虚构帧序列与隔离窗口验证，不能把推断写成已证实的现场故障。

## 3. 架构与所有权

`动作调用 → 按实体仲裁意图 → 从同一身体帧提取挂点 → 附件运动控制器 → 只读附件帧 → 两种宿主绘制`

- 建议纯数据意图类型放在 `Dango.Core/Animation`，自然运动控制器先放现有 Desktop 表现层，使用普通数值类型，不引用 WPF。暂不新建程序集、不升级依赖。
- 每个稳定实体 ID 持有一个控制器，跟随现有 presenter 生命周期；不是每个窗口或帽子控件各有一个控制器。
- 每个物理固定步只更新一次附件。Window、Wallpaper 和独立帽层消费同一输出；额外绘制回调不推进眨眼或弹簧。
- 物理帧只读：保持原有轮廓归一化、映射与求解输入。倾斜及滑动由形状和显式意图驱动，本候选不使用身体世界位移差分制造附件冲击。
- 核心命令不使用 `DangoEntityId` 作为 Core 对 Physics 的依赖：桌面入口负责将业务目标路由到现有实体 ID，并验证存活性。

## 4. 最小动作接口（候选契约）

以下为语义草案，不声称这些类型或方法已存在。调用入口统一携带实体、调用者 token、单调序号；参数有限性、范围、时长在入队前检查，不用静默 clamp 隐藏非法命令。

| 接口 | 参数与意义 | 持续与完成 |
|---|---|---|
| `SetGaze` | `eye = Left/Right/Both`，`x,y ∈ [-1,1]`，脸部局部坐标，X 向右、Y 向上；表示安全注视范围比例 | 每只眼独立目标及响应；持续到对应通道新命令/取消 |
| `SetEyes` | `eye = Left/Right/Both`、`openness ∈ [0,1]`、`shape = Round/Soft`、`strength ∈ [0,1]` | 每只眼独立开合/表情；Round 保留现有圆眼，Soft 是柔和眯眼候选；不开放任意路径注入 |
| `Blink` | `eye = Left/Right/Both`，闭合、保持、睁开三个正时长，默认候选 70/40/120 ms | 每眼独立事件与计时；不改变 SetEyes 目标，结束回到该眼当时有效开合目标 |
| `SetHatSlide` | `offset ∈ [-1,1]`，表示有效头顶轨道左右可滑范围比例，0 为形状定义的中立位置 | 控制轨道目标，不直接指定角度或世界坐标；角度由当前滑动位置的一段轨道拟合产生 |
| `PulseHat` | 带符号轨道速度增量，单位为参考体宽/秒，受配置上限约束 | 只激励沿轨道的滑动回弹，不施加独立角冲量或身体冲量 |
| `BounceHat` | `direction = Left/Right/Down/Up`、`strength ∈ [0,1]` | 一次帽身形变激励；左右对应弯曲，上下对应伸长/压缩后的恢复；不是直接缩放控件，也不改变轨道目标 |
| `Release` | 调用者 token 和通道掩码 | 清除该调用者对应意图，从当前运动状态回有效低优先级目标；不清零弹性速度 |
| `ResetAttachments` | 内部生命周期操作，无动作调用者直接使用 | 清意图/序号缓存/速度/计时，按首个有效身体帧重新挂接；不是每次动作结束使用 |

返回 `Accepted/Rejected`、请求序号和原因；一发事件可查询或消费 `Completed/Cancelled`，不把“被新命令覆盖”报成完成。过期实体、重复/逆序命令、NaN/Infinity、越界参数或无效时长明确拒绝；序号按存活 token 维护，实体销毁即清理。

示例语义：一次温柔回应可以 `SetGaze(Both,0.3,0.2)`、`SetEyes(Left,0.65,Soft,0.5)`、`Blink(Right,...)`、`SetHatSlide(0.15)`；需要帽身轻弹时调用 `BounceHat(Left,0.2)`，持续意图结束时 `Release`。这些数字只说明 API 用法，不是获验收的动作参数。原 `SetHatPose` 直接指定倾角方案在本草案中被替代，不保留平行控制入口。

暂不做：瞳孔材质、嘴巴、任意表情脚本、通用动画图、帽子换装编辑器。左右眼独立控制已纳入本次设计，但不扩展为通用动作编排器。未来扩展必须兼容中立状态。

## 5. 通道仲裁与叠加

持续通道为 LeftGaze、RightGaze、LeftEyePose、RightEyePose、HatSlide；左右 Blink、轨道 PulseHat 与帽身 BounceHat 是独立受限事件。动作只能通过已注册入口获得固定优先级，不能自行填无限大的优先级数字。

Both 是同一固定步内的原子双眼提交，不是第三只共享眼状态：先校验两侧许可，任一侧 Busy/拒绝则整笔拒绝，不发生半次成功。单眼命令只覆盖该眼对应通道；两眼分别保存目标、当前量、速度、事件和完成状态。Release 的通道掩码能只释放左眼而保留右眼。共享脸部基准不等于共享开合或注视状态。

- 生命周期安全控制最高；显式用户预览命令高于后续动作命令；默认朝向最低。此处预留层级，不实现完整动作系统。
- 同通道同优先级以新的有效序号覆盖旧目标；不同通道可组合，不同调用者的位置不求和。
- 更高优先级接管时取消低优先级同通道意图，不无限排队，不在接管结束后突然复活过期动作。没有目标时回中立/默认朝向。
- 每眼 `Blink` 输出作为包络乘以该眼当前有效 `openness`：闭眼目标下眨眼不会突然睁开。同眼眨眼活动时再发 Blink 返回 Busy，不阻止另一眼眨眼；取消从当前开合量平滑回该眼目标。
- 形状给出的滑动目标加当前唯一有效的动作滑动偏移，经过统一轨道范围限制后驱动弹性；不叠加多个调用者的角度。脉冲每实体候选冷却 150 ms，轨道速度有上限，防止重复事件积能。
- 同时发 Release 和新命令时按固定步入队序处理，序号确保旧取消不删除新 token 意图。停止控制器后所有新请求拒绝。

## 6. 眼睛自然跟随

### 共享视觉倾斜，不跟随物理旋转

从当前几何形状估计轻微歪头趋势，眼睛和帽子共同消费；不读取刚体角度、角速度或追踪材料节点方向。相同几何轮廓即使循环更改起始节点，估计结果也应相同。身体真实旋转导致形状变化时可以响应这些变化，但不是对物理角度做限幅。

推荐使用上半身多条水平截线的中心偏移作为主要信号，头冠较宽区域的走势作为辅助，按体宽/体高归一化。对称压扁、对称拉长应为中立；近圆形、退化截线或两个信号明显冲突时降低置信度，将目标平滑衰减到零。不上来就用主轴角度，因为近圆形的主轴容易翻转。采样高度、权重和死区须由形状正反例确定，不在本次确认中视为冻结。

共享视觉角 `theta` 有独立于身体的阻尼弹簧状态，候选范围 ±10°、频率 4 Hz、阻尼比 0.9。双眼连线围绕脸部中心采用该倾角，安全区检查在倾斜后进行；不旋转整个团子轮廓。帽子将同一趋势转换为轨道目标位置，但保留独立滑动弹簧，因而可以稍晚恢复。帽子不再把 `theta` 加到轨道拟合角上，避免重复倾斜。其实际角度由贴合区决定，与眼睛趋势一致但不强求逐帧角度相等。

形状恢复后目标为零，弹簧自然回正；长期非对称时允许保持小幅倾斜。无动作时不添加身体平移加速度驱动视觉倾斜，避免又以运动方向替代形状判断。需要额外帽子轻摆时通过显式 PulseHat 接口表达。

### 脸部基准与安全区

眼睛是脸上的图形，不是两颗自由小球。双眼共享形状推导的脸部中心与视觉倾斜基准，各自拥有注视偏移、开合、表情和平滑/回弹状态。共享倾斜先作用于两眼基准，再计算各自局部响应，最后做联合安全约束以保持左右顺序及最小间隔；不因为身体转一圈就把左右眼交换。

建议在已渲染归一化轮廓上，取脸部候选高度附近的水平截线，求包含局部中心的内区间；结合相邻截线做稳定估计。凹陷或多区间时只采用能容纳眼睛的中心区间，不选择最宽但远离脸部的孤立区间。候选高度从当前 -0.05 开始，根据上下可用空间温和修正。

把双眼图形包围范围而非仅眼睛中心纳入安全区。空间减少时依次减小注视幅度、双眼间距、眼图形尺寸（各有下限）；仍容纳不下则进入可诊断的安全闭眼/隐藏表现，不能把图形画出身体或反向扩大身体。原始身体有效时不以附件布局失败触发物理重置。

### 平滑与表现

- 注视目标用无明显超调的阻尼响应，建议初值频率 5 Hz、阻尼比 1；参数属于附件配置，不进入物理配置面板。
- 自然跟随主体来自脸部基准，而不是给眼睛施加大惯性。受挤压时允许间距小幅收缩，松开后恢复；候选间距范围为中立值的 80%～100%，需验证极端挤压时的安全策略。
- 开合通过眼图形局部变换/闭眼曲线表达，不缩放整个身体。闭合时仍保留可辨的一条线，不用零尺寸缩放造成布局异常。
- 首轮不自动追随真实全局鼠标、不随机改变视线。无动作意图时继承已有左/右/中朝向；未来调用者自行决定看哪里。

## 7. 帽子沿头顶轨道滑动与回弹

### 从形状建立轨道

轨道是当前上轮廓中的连续平滑曲线，不是新增碰撞体。按几何位置从左到右取头冠采样，沿用身体显示轮廓的共享映射，不按某几个材料节点编号定义头顶。均匀弧长重采样用于避免节点密度影响拟合；平滑不能把贴合轨道移离真实显示表面，距离误差须单列验证。

使用参考体宽归一化的弧长 `s` 表示滑动位置，0 为当前几何定义的中立位置。候选左右范围各不超过参考体宽的 8%，并受有效上冠长度、帽底覆盖宽度及姿态安全界限进一步缩小；不能滑到侧脸或轨道端点外。范围与 ±10° 视觉角均为待人工调节初值，不是用户已确认数值。

中立位置用中央上冠的宽区域确定，不用单个最高点。局部尖峰、最高节点换序不应使整个轨道或中立位置跳变。轨道每帧改变时按上一贴合区的几何邻近关系重映射 `s`，保持左右和连续性；不通过保存旧节点索引维持身份。

### 一段贴合区决定姿态

帽底对应以 `s` 为中心、有非零宽度的接触区间。在区间内取多个等弧长样本，拟合整体走向和偏移，联合计算帽子平移及角度；不使用单点切线，不将帽子钉在固定支点上。素材可以有变换原点，但它只是绘制坐标基准，不是运动约束。

刚性帽底与弯曲轨道无法处处完全重合，设计允许有限贴合误差：以整个区间的间隙/穿入约束评估姿态，不能只检查帽底中心。叶芽素材也需定义有限宽度的虚拟贴合底座，不能退化为一个点。接触区宽度和允许误差需按现有素材标定，并在实施计划固定正反例。

拟合出的倾角如果超出候选总界限 ±0.35 rad，应优先缩小/调整合法滑动区间并重新拟合；不能仅在绘制端截断角度，造成帽底不贴合。平顶上滑动时允许角度几乎不变，不为追求歪头强行绕点旋转。眼帽共享的是趋势，不是对任意形状强制相同角度。

### 弹性作用在轨道坐标

根据共享视觉倾斜趋势生成自然滑动目标，加唯一动作偏移后得到 `sTarget`。具体左右符号由镜像形状夹具校验，保证眼睛歪头与帽子滑动观感协调；映射增益为候选配置。

`s'' + 2ζω s' + ω²(s-sTarget) = 0`，其中 ω=2πf。候选 f=3.5 Hz、ζ=0.8。PulseHat 只对 `s'` 作有界增量。弹簧更新 `s` 后，在当前轨道重新求整段贴合姿态；不再对最终角度单独弹簧积分，不再做固定根部转动，避免位置与角度脱节。

形状恢复且没有显式动作时滑回中立；Release 从当前位移/速度继续，不瞬移。采用稳定解析更新或明确有界内部步长，具体实现方式在计划中选定。碰到轨道界限清除朝外的速度分量，不能在边界外积能。不累计隐藏时间，也不把宿主平移、物理转角或角速度注入滑动。

轨道突然缩短时先重投影到最近可行贴合区并消除朝外速度，不能让帽子为了平滑暂时离体；记录这种约束修正用于人工检查。没有合法区间时进入明确的附件降级，不跳到身体另一侧、不增加吸附力改变身体。连续正常形变应保证正常连续滑动，不能靠频繁重投影冒充回弹。

### 帽身自身形变：第二层弹性

轨道滑动不等于帽身形变，两者分开保存状态。前者决定整顶帽子的贴合位置/姿态；后者只改变贴合底座以上的局部几何。帽子仍无独立碰撞，不向身体施加反作用。

建议在现有叶芽矢量素材上定义局部高度权重 `w(h)`：底座覆盖区域权重为零，离开底座后平滑增加，帽尖最大。弯曲使用随高度递增的侧向位移，压缩/伸长沿帽身局部竖向作用；底座处位移及一阶变化为零，避免连接处折断。不是给整顶帽子加 ScaleTransform，也不是改轨道/身体轮廓。茎与叶片共享连续变形场，首轮不再叠加两片叶子的独立弹簧。

帽身保存弯曲 `b`、轴向形变 `c` 及各自速度，以中立零值为目标阻尼回弹。候选初值：弯曲频率 5 Hz、阻尼比 0.75；轴向 6 Hz、0.85；最大帽尖侧移为素材高度的 6%，轴向长度变化 ±5%。均为预览起点，不是已验收数值。零强度严格保持原始素材，出现翻折、自交或底座间隙时视为失败，不通过改变身体来遮掩。

`BounceHat` 注入有界形变速度，而不是直接跳变 `b/c`，让形变连续发生。自然反馈来自轨道滑动的急停/反向和归一化身体形状的快速变化，经低通、死区与限幅后作用于形变；不读取物理转角/角速度，不从宿主位移推算冲击。恒定形状和匀速滑动应逐渐停止受激。初始化、重置、轨道重投影/失效恢复时重新建立差分基线，不把安全修正当作自然撞击。

先实现弯曲候选；轴向能力尚未实现时，上下 BounceHat 必须明确返回 Unsupported，不能假报 Accepted。支持后再开启轻压缩/伸长测试。PulseHat 与 BounceHat 语义区分，普通一次“弹一下”不默认同时发两者。

轨道滑动、自然形变与显式 BounceHat 使用统一强度预算：按各自允许位移/速度归一化，先保留轨道贴合和有效动作目标，再对剩余形变激励按同一比例缩减；接触几何永远优先。候选显式形变事件冷却 150 ms，冷却内返回 Busy，不排队；自然激励也限幅，不因同帧人工事件再叠一倍冲击。具体预算公式必须在实施计划固定，不能仅在渲染端截断结果。

输出顺序为：更新轨道弹性 → 求整段贴合姿态 → 更新帽身局部形变 → 将变形后的素材映射到该姿态。两种帽渲染路径复用同一几何计算。Release 取消对应调用者的待发激励，已有形变自然衰减；Reset 清所有形变状态；隐藏暂停、故障安全帧与轨道一致；降低额外动效关闭自然激励并平滑减弱形变，但不允许底座漂移。

## 8. 坐标、输出和生命周期

- 动作使用局部无量纲比例；视觉角使用 rad，轨道位移/速度按参考体宽归一化，绘制最后转 DIP。不从显示或身体位移计算额外加速度激励。
- 建议新 `AttachmentPresentationFrame` 含视觉倾角/置信度、左右眼各自中心/图形尺寸/开合/形状、帽子轨道位置/贴合区间/最终平移和角度、帽身弯曲/轴向形变以及安全限制诊断。内部求解允许普通有限数值向量；输出转换到现有有界类型前完成约束，不能用放宽 `PresentationPoint` 的全局限制解决局部问题。
- WPF 仅绘制已约束输出，两处帽子统一共用变换计算；去掉隐藏的重复 clamp 前须证明所有输出都经过同一验证。保留顶层防御性有限值检查，不能因非法姿态崩溃整个宿主。
- 渲染坐标标定使用现有 160×120 素材与虚拟帽底贴合区域建立测试；变换原点不代表固定支点。身体绘制顺序和全部帽子全局在上保持不变。

| 事件 | 规则 |
|---|---|
| 动作覆盖/结束 | 从当前值/速度过渡；不是重建 presenter |
| 拖动开始 | 保留自然附件运动；动作层可显式取消目标，输入层不绕过仲裁写坐标 |
| 隐藏/暂停 | 暂停所有计时/更新，不补帧；恢复首帧重新校准差分基线但保留合法姿态 |
| 宿主切换/DPI | 复用附件实例及相同局部输出，不将显示平移注入惯性 |
| 身体 Reset | 附件硬重置并绑定首个有效帧，不从旧位置弹回出生点 |
| 移除/退出 | 清对应 token、队列和事件；旧 ID 拒绝，不能污染新实体 |
| native 故障 | 与身体一同保留最后安全帧，不继续眨眼或弹性更新冒充运行 |
| 附件数值/几何失败 | 清异常速度，在有效身体几何上使用确定性中立挂接并报告附件降级；无有效挂点时隐藏帽子而非悬浮，作为需修复失败，不称验收通过 |
| 降低额外动效 | 抑制惯性和额外摆动，保留注视/开合等明确命令；不改变身体步进或输入结果 |

## 9. 验证与交付门禁

### 可失败自动用例

1. 非法参数/过期 ID/序号重复被拒绝；实体 A 的命令不影响 B；移除再添加不继承旧速度。
2. 眨眼完整闭合和恢复，闭眼目标不被 Blink 打开；抢占和 Release 不产生位置跳变，不复活旧目标。
3. 恒定姿态收敛，匀速不持续受激，阶跃/反向/角度跨界有界；30/60/120 Hz 等长轨迹终值候选误差不超过局部 0.002、角度 0.005 rad（相同已采样输入定义下）。阈值须在红灯测试中固定，不随失败放宽。
4. 圆形、平顶、偏心挤压、快速形变和最高节点换序序列：多点贴合区间持续有效，轨道相对显示表面的候选误差不超过局部 0.005；另测帽底整段间隙/穿入，不能用中心点距离代替。连续非退化序列无角度翻转；将拟合换成单点切线、将滑动换成固定支点旋转必须使专门构造的曲率变化/平移用例失败。
5. 双眼图形边界留在安全区、左右不交换，严重挤压触发明确安全策略；测试只检查中心不足以通过。
6. 同一固定输入运行 1/2/3 体，附件旧/新路径的物理输入、轮廓、位姿、ID、错误码逐帧一致；新增行为允许附件不同，不允许改身体容差。帽子始终没有碰撞/反作用。
7. 只增加渲染调用不增加附件或物理步数；隐藏后恢复无大步；宿主/DPI 迁移无惯性冲击；Reset 清所有瞬时状态。
8. 真实 compiled WPF 检验眼开合、双眼连线倾斜、帽底区间贴合、两处帽变换一致及全局帽层；旧映射等价测试保留在旧基线验证入口，新机制使用独立明确的期望，不重写历史通过含义。
9. 相同几何循环变更节点起点不改变视觉倾斜与轨道；对称压扁/拉长中立，左右镜像形状反号，近圆形不产生主轴翻转。改变物理角度元数据而保持几何不变，附件结果必须不变。
10. 形状恢复后视觉角和轨道位移分别有界回弹；平顶滑动不强制旋转，合法滑动命令必须产生位置变化而不只是角度变化；轨道缩短、失效及恢复不越界积能、不传递虚假身体冲量。

11. 左眼眨眼时右眼保持原状态；反向注视不交叉；取消左眼不清右眼；Both 遇单侧 Busy 整笔拒绝。错误实现若把两眼共用一个计时器/目标必须失败。
12. 帽身形变前后底座覆盖区位置完全一致；零强度还原原素材，局部形变不改变轨道、身体帧或碰撞结果。测试弯曲/压缩/伸长方向、越界/连续脉冲、隐藏/Reset/故障与几何重投影不产生虚假激励；禁止以整体缩放通过底座固定用例。
13. 轨道和形变同时激励仍满足预算、无积能，静止后衰减到中立；两种帽绘制使用相同变形几何。人工单列“仅滑动、仅弯曲、仅压缩、组合”的对照，观察帽底贴合、叶芽连续和是否摇晃过度。

### 隔离人工入口（待授权实现）
