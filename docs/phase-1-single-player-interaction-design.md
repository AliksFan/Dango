# 单人完整交互与动作设计草案

> 日期：2026-09-12；状态：用户已要求搁置，未批准、未实施。2026-09-13 优先推进[眼睛与帽子接口设计](phase-1-eye-hat-motion-design.md)，本草案保留作后续参考。
> 属于 Phase 1 / P1-004 的 B 动作设计。A 正式宿主物理接入已获人工认可，但历史旧 DLL 自动门禁失败仍保留，整个 Phase 1 未完成。
> 本轮只写设计；批准后还须形成实施计划。岛平台与攀爬必须先有物理契约/隔离验证，不能从本草案直接进入正式 DLL 修改。

## 1. 推荐体验：安静的小室友

团子平时不催促你；你伸手逗它，它有回应；你继续工作，它会自己找个舒服的地方待着。

三个可直接讨论的场景：

- **摸鱼十秒**：轻点团子，它看过来、眨一下眼；切到“摸摸”，来回摸两下，它眯眼；退出摸摸后提起放下，身体按已验收物理下落和恢复。没有奖励结算或必须完成的任务。
- **陪我工作**：不操作时，大多数时间发呆、眨眼，偶尔慢慢挪一小段；进入“安静陪伴”后不自主走动，只保留轻微表情。不会抢焦点、弹通知或追着光标跑。
- **小岛午睡**：团子走到岛边，停一下看向上方，抓住边缘、拉起身体，真实落在岛面上；休息后从边缘下来。用户在任意时刻提起它，动作立即让位给拖动，不播完再响应。

参考事实、替代方向和许可证边界见[项目参考调研](research/2026-09-12-single-player-desktop-pet-reference.md)。以上场景是推荐设计，不是当前已实现效果。

## 2. 范围与不能变的东西

首轮设计一个本地用户、一只主要团子、一个固定位置的岛；Window 和 Wallpaper 体验语义相同。保留已有添加到三只、选择、移除、重置能力；暂不让第二/第三只参与自主社交或同步。这不是账号、好友、房间服务器或持久身份实现。

覆盖：待机、转向、移动、睡醒、点击、抚摸、拖放、跳跃、下压、落地恢复、接近岛、爬岛、岛上停留/边缘休息、下岛，以及所有中断和恢复。

排除：联机、贴贴、情侣/群体动作、喂养与数值养成、AI 对话、投球、任意窗口攀爬、声音/通知、新美术商店、四体以上、岛编辑器、跨屏寻路。单人优先不取消未来多人产品目标。

冻结：16 节点、已验收外形/配色/帽子层级、3% 团子间接触、承重规则、移动/下压/跳跃力度、拖动与释放手感、自然滑落、错误锁存、一个场景一个世界。正式参数仍只读；不因动作好看而改物理参数。

## 4. 用户操作与输入仲裁

下列时间/距离是候选起点，仅用于手势和调度测试，不是已验收参数；正式实现前用隔离版人工调节，不修改 native 手感。

| 输入 | 推荐行为 | 冲突和退出 |
|---|---|---|
| 左键按下团子 | 立即选择并沿用现有 BeginDrag，不延迟已验收抓取 | 同时记录“可能是点击”；捕获失败取消本次操作 |
| 左键短按释放 | 同一 ID、时长不超过 220 ms、指针最大位移不超过 4 DIP 时，在 EndDrag 后给一次表情回应 | 不施额外力、不触发跳跃、不打开窗口；已拖动、失焦或捕获取消不算点击 |
| 左键移动/长按 | 沿用现有拖动；即使开始像点击，超过任一点击阈值后也不补发点击 | 释放恢复真实物理，禁止补一条人造抛物线 |
| 控制中心“摸摸”开关 | 显式进入一次抚摸会话，指针悬停且移动于团子轮廓内时识别抚摸，不要求按住左键 | 此模式内左键仍能拖动并退出摸摸；Esc、失焦、隐藏、切换、移除、故障退出 |
| 摸摸识别 | 本地命中内以最高 30 Hz 采样；最近 600 ms 累计移动至少 20 DIP 且有一次水平反向，触发眯眼；静止悬停不算摸 | 不拦截轮廓外输入、不读取全局轨迹；离开轮廓 250 ms 结束表情，10 秒无有效抚摸退出模式 |
| A/D 或左右键 | 沿用选中实体水平控制 | 人工输入抢占自主动作；按住键不得转移给新选择 |
| W/上键、S/下键 | 沿用跳跃边沿与下压 | 冷却由模块裁定；空中无效跳跃不由动作层伪造成功 |
| “来岛上休息”/“下来走走” | 控制中心对当前主角提交一次目标请求 | 不可达或能力未就绪时明确说明，不播放成功动画 |
| “安静陪伴” | 关闭自主移动、爬岛和随机活跃动作，保留轻微表情/睡眠和人工操作 | 不等于暂停物理；切换后若在攀爬，先安全解除约束再由重力决定落点 |

选择显式摸摸的理由：把“按住移动”同时解释为拖动和抚摸会改变已验收抓取手感；无模式的悬停抚摸又容易把经过的鼠标误认成互动。代价是多一个入口，建议先在控制中心并列展示“摸摸”和“安静陪伴”，不新加全局快捷键或隐藏手势。手写笔/触屏不在首轮鼠标验收内，不声称兼容通过。

输入优先级：退出/故障 > 隐藏暂停 > 显式重置/移除 > 拖动 > 人工方向控制 > 抚摸/点击表现 > 用户岛目标 > 自主行为。表情不拥有身体位置；空中可以看向用户，但不因此终止下落。

## 5. 动作目录与完成条件

| 动作 | 进入与表现 | 正常结束/失败恢复 |
|---|---|---|
| 待机/眨眼/转向 | 支撑稳定且无更高优先级任务；看向最近一次局部互动方向，轻眨眼 | 表情结束仍待机；不抖动整个轮廓冒充呼吸，低动效关闭额外眼帽摆动 |
| 自主移动 | 稳定支撑上选取短距离目标，提交现有水平意图 | 到达目标范围或超时停止；不会把目标位置直接写进物理 |
| 点击回应 | 短按释放判定成功，眼睛转向/眨眼约 0.6～1 秒 | 到时按真实支撑回待机/空中；重复点击刷新有限表情，不叠加力或无限队列 |
| 被抚摸 | 有效摸摸采样，眯眼，帽子延续现有惯性 | 最后一次有效样本后约 0.8 秒恢复；拖动/人工控制立即退出 |
| 睡眠/醒来 | 稳定支撑、无人工交互 60～120 秒后可入睡；闭眼但世界继续真实求解 | 点击、拖动、键盘立即唤醒并执行本次输入；支撑丢失直接进入空中，不等醒来演出 |
| 拖动/释放 | 所有普通状态立即可提起；纯物理悬挂 | EndDrag/取消后清输入；有支撑则站稳，无支撑则落下 |
| 跳跃/下落 | 原模块接受起跳后，依据实际速度与支撑变化标记 | 首次真实支撑恢复触发落地，不以动画定时器判定落地 |
| 落地恢复 | 支撑由无到有，去抖后给一次表情/帽子反应 | 约 0.3～0.6 秒表现后回支撑态；身体反弹完全交给物理，键盘和拖动可立即打断 |
| 接近岛 | 可达性检查通过，走到选定一侧抓取区 | 到达且有稳定地面支撑才请求攀爬；阻塞/超时取消，回待机 |
| 爬上岛 | 短暂看向边缘，真实限力约束牵引软体爬升 | 到达顶面后必须真实承重才结束；失败释放约束，正常回落，不传送 |
| 岛上停留/边缘休息 | 平台支撑已确认；先走向安全休息区再闭眼或看向外侧 | 边缘姿态只改变表情，不把身体外移造成假悬空；支撑丢失进入下落 |
| 下岛 | 到达可用出口，水平意图离开边缘 | 支撑真实丢失后下落，落地恢复；无安全出口则拒绝，不向用户假报已完成 |

“睡觉”是动作状态，不是新的 native 休眠算法。首轮呼吸不新增轮廓缩放；若需要明显身体起伏，应另行设计并证明不破坏接触显示一致性。

## 6. 自主行为节奏与导航

推荐默认“自然陪伴”，另有“安静陪伴”；不新增多维性格滑块。时钟只累计可见、未暂停的场景时间，不按离线时长补算动作或惩罚。

- 每次人工操作后留 8～15 秒安静期。每个可执行决策点再等待 12～25 秒，初始权重为待机 65%、短移动 25%、休息 10%；这是隔离调节起点。
- 同一活跃动作不连续选三次；睡眠最短候选停留 20 秒，但人工操作随时打断。退出睡眠后重新抽样，不清空旧输入后再假造输入。
- 自主短移候选距离为 0.5～1.5 个未变形参考体宽，单次最长 5 秒；不自主跳跃或持续下压。到边缘先停止；受外力滑落是物理结果，不设置隐形墙“保住路线”。
- 有岛且可达时，最多每 60～120 秒产生一次自主上/下岛意向；岛任务覆盖一次短移决策，不与其同时提交控制。
- 无进展持续 1 秒或整体接近超时 8 秒则取消；攀爬失败同一入口冷却 30 秒，连续两次失败停止该入口的自主重试，人工可重新请求。全部时间是建议值，不修改物理失败阈值。
- 随机种子与逻辑时钟可注入测试，真实运行只需内存随机源，不存鼠标历史。目标在本场景可见边界和真实支撑区内选择；无可用目标就待机，不进行无限重采样。
- 保留第二/第三只时，仅第一只主角启用单人调度；主角被移除后暂停自动行为，明确选定存活主角后才恢复。任意实体仍可人工选择控制；其他身体可能阻挡路线，超时退出，不推开或传送它们。

## 7. 岛平台与攀爬：独立高风险增量

### 推荐空间与替代方案

先做一个固定的、有限宽度、有顶面和侧面的真实静态岛，不做拖动家具。岛外观应在两种宿主中与同一世界几何对齐，顶面可站立，侧面不能随意穿透；首轮不采用从下方穿透的单向平台。顶面至少能容纳一只团子及两侧安全区，放置高度必须在已验证的攀爬能力范围内；尺寸以参考体宽定义，具体 world 数值由隔离物理实验确定。

不推荐“跳跃替代攀爬”：它不能完整表达既有爬岛目标。不采用关键帧搬运或临时关闭碰撞。推荐**显式、限力、可释放的攀爬约束**，仅攀爬时启用；常规地面/团子接触仍无吸附。

### 正常路径

`检查入口 → 接近 → 观察边缘 → 建立抓取约束 → 提拉越缘 → 顶面真实支撑 → 解除约束 → 岛上停留`

1. 入口由平台几何生成左右候选；路径与顶面安全区被占据或在视口外时不启动。
2. 核心只请求平台 ID 和入口侧，native 校验距离、状态、承载能力和句柄有效性；不能让宿主提交任意空中坐标当挂点。
3. 抓取/提拉的施力点分布、最大力、速度限制与结束区间必须在专项物理契约中确定。约束不得绕开已有节点限制、接触或故障锁存。
4. 顶面支撑须来自真实接触且满足去抖，不能单凭核心超过岛高度即完成。解除约束后能继续站住或自然滑落，才算确实落到岛上。
5. 下岛不需要人造向下轨迹：走到出口、解除目标、由重力落地。顶面无安全路线则取消目标。

### 候选接口与失败边界

以下是需要补设计的接口职责，不是已存在 API 或已冻结 ABI：

- 平台注册/移除：稳定 `PlatformId`、同一物理世界中的静态几何和几何版本；禁止渲染层单独移动平台。
- 支撑反馈：`SupportKind(None/Ground/Body/Platform)`、支撑对象 ID、接触法线/点、质心速度、是否承重；多接触裁定与事件去抖应在物理契约里统一定义。
- 攀爬请求/取消：实体 ID、平台 ID、入口侧、请求序号；返回 Accepted/Rejected/Active/Completed/Cancelled/Failed 与原因。重复取消幂等，旧 ID 或过期几何版本拒绝。
- 新能力单独版本化/能力查询，旧 ABI 1 不静默重解释。无岛场景关闭扩展时，1/2/3 体原输入轨迹必须逐帧等价。
- 攀爬超过候选 4 秒、无进展、抓取丢失、支撑物移除或用户抢占：解除约束，依据当前接触回到支撑态或下落。原生异常则进入原有故障锁存，不把异常改成一次普通回落。
- 岛移除/位置变化首轮不提供用户入口；故障注入仍验证移除时释放约束、不能悬浮。尺寸/DPI/宿主迁移不改变岛相对物理坐标，视口容纳不下时停自主任务并提示调整窗口，不搬运身体。

本草案给出推荐机制和观察标准，尚未解决力学数值与完整 ABI 布局。批准体验方向后，应先补专项物理扩展设计和失败用例，再授权隔离原型；不能将这里当成已可直接编码的最终力学规格。

## 8. 状态所有权与中断矩阵

建议按生命周期、身体状态、任务、表情四个维度处理，避免“正在眨眼”覆盖“正在下落”。Core 决定任务许可；物理唯一裁定位置、速度、接触；表现层只消费结果。旧单一枚举的迁移方案须在实施计划列出受影响测试，不能删除转移校验了事。

| 事件 | 立即处理 | 恢复依据 |
|---|---|---|
| 任意任务被拖动 | 清任务/点击候选，解除攀爬约束，清方向，再 BeginDrag | 释放后看真实支撑，不恢复旧路径 |
| 键盘抢占自主/爬岛/摸摸 | 取消低优先级任务及攀爬，提交当前人工意图 | 松键后进入人工安静期 |
| 失焦/失捕获/Esc | 清按键、拖动、手势和当前任务；Esc 不退出应用 | 保持物理按现有宿主规则推进；重新开始动作，不恢复挂起的按住输入 |
| 隐藏/全屏抑制 | 清操作和约束，暂停动作时钟及物理步进 | 显示后依据安全帧恢复，不补算隐藏时间 |
| 宿主切换/DPI 变化 | 取消手势与攀爬，复用同一世界，重新映射可见目标 | 安全可见时重选任务；不保留屏幕像素路径 |
| 支撑丢失 | 取消睡眠/边缘休息，清过期支撑目标 | 落下，真实新接触后恢复 |
| 重置 | 调用现有 Reset 语义，清所有受影响实体的任务/表情/约束 | 依据重置后的世界重新开始；不额外承诺单体独立物理重置 |
| 移除实体 | 取消该 ID 的输入/任务/引用；保留幸存世界 | 不转交持续输入；主角移除后自主暂停 |
| 错误/缺库 | 保留安全帧，停止普通输入/调度，显示真实原因 | 显式重置或退出；无静默旧算法 fallback |
| 退出 | 取消会话、约束和回调，释放同一 world 和宿主资源 | 不保存正在拖动/攀爬的瞬时状态 |

每个固定步：收集事件 → 处理取消与优先级 → Core 依据上一物理帧生成各实体唯一意图 → world 只 Step 一次 → 消费真实反馈更新状态 → 渲染。完成反馈影响下一步，不为完成表情再推进一帧物理。

## 9. 配置、隐私和表现交付

- 新配置仅建议保存“自然/安静陪伴”和“降低额外动效”；默认自然陪伴，摸摸是临时会话不持久化。延用已有设置存储，缺失字段兼容默认，损坏配置遵循现有回退机制，不写新数据库。
- 不持久化动作历史、局部指针采样、真实窗口信息或键盘文本；采样窗口到期即丢弃。测试回放只用虚构输入与固定种子。
- “降低额外动效”仅影响新增表情和装饰摆动，不改固定步、碰撞、移动结果或用户操作；“安静陪伴”才控制自主任务，两者不能混称节能保证。
- 首轮原创表现清单：注视/短眨眼、满足眯眼、闭眼睡眠、醒来、腾空/落地表情、攀爬注视；全部贴合既有身体和帽子，不引入新角色素材。
- 无声音、弹窗奖励或惩罚；动作失败只在用户主动请求时提供轻量且真实的原因，自主失败不反复通知。

## 10. 候选实施分段与可失败验收

这些是设计拆分建议，尚不是编码授权或正式实施计划。

| 增量 | 内容及前置条件 | 必须能失败的验证 |
|---|---|---|
| B1 即时回应 | 输入仲裁、点击、显式摸摸、表情；不扩展物理 | 220 ms/4 DIP 边界、失捕获不点击、拖后不补点击、摸摸不改坐标；关闭新行为后已验收输入轨迹相同 |
| B2 安静生命感 | 待机、睡醒、自主短移、安静模式；补足所需只读支撑语义 | 同种子/时钟决策相同；人工输入下一固定步抢占；隐藏十分钟不补动作；阻塞超时退出；不能以表情计时伪造落地 |
| B3 真实岛支撑 | 专项物理设计与能力版本先获批，隔离原型后再接入 | 从上方落岛有真实支撑，侧面不穿透，走出边缘必下落；移除平台不能悬浮；无岛 1/2/3 体等价 |
| B4 爬岛闭环 | B3 通过且限力机制获批 | 上/下岛成功、不可达拒绝、超时失败、每个攀爬阶段拖走/失焦/隐藏/移除支撑均无残留约束；解除牵引后确实承重 |
| B5 单人宿主验收 | 上述自动检查通过，原 DLL 仍保留 | Window 与 Wallpaper 图标上/下分别测试完整单人流程，不沿用 A 的人工结论 |

人工场景：

1. 戳、慢拖、快速拖、长按不动各反复十次，确认“想拿就拿”，没有等待手势分类的迟滞。
2. 摸摸进入、持续、离开、超时和被拖动打断；普通鼠标经过不误触，桌面图标仍正常。
3. 自然陪伴观察至少十分钟，记录动作频率、重复与干扰；安静模式确认不自行走动，但手动拖放/跳跃照常。
4. 睡眠中失去支撑、按键、点击、提起；确认不会睡在空中或吞掉第一下输入。
5. 上岛、站稳、边缘休息、下岛逐段观察；每段人工打断一次，再主动请求重试。看是否真的承重，不能只看状态文本。
6. 两种分辨率/缩放下检查身体、岛面、抓取命中重合；切换宿主、最小化、隐藏恢复、退出分别留痕。未测设备组合标未验证。
7. 保留原双体/三体物理回归，分别测持续碰撞、偏心叠放、抽走支撑、反复拖放/重置；单人 B 通过不能替代多体回归通过。

故意注入重复 Step、手势未取消、假支撑、无限重试、旧任务抢回控制等错误，实现对应测试必须失败。自动构建、实时运行、人工手感和 Git 交付仍分开记录；历史旧 DLL 导出失败不通过删测掩盖。

## 11. 审阅重点与后续停止点

建议先确认三个体验选择：采用“安静小室友”而非养成；以显式摸摸保护拖动手感；岛按真实支撑/受控攀爬独立推进。用户不必设计状态机或指定数值，可直接说喜欢/不喜欢哪个场景。

本轮只交付参考与设计草案，不更新产品基线为已批准，也不启动新物理实验。收到方向反馈后修订设计；批准后再写具体文件、红灯测试与交付门禁的实施计划。B3/B4 的物理规格未补齐前不得开始岛实现。
