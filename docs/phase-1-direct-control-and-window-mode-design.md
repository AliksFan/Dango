## 1. 决策摘要

本设计用可控、低速的方向输入替代 P2D-006 当前仅用于串联状态的自动快速平移，并把正式本地宿主收敛为两种：

1. **壁纸层模式**：默认模式；团子运行在已验证的 WorkerW 桌面层。
2. **普通窗口模式**：团子和当前场景运行在可移动、可缩放、可最小化的普通独立窗口内。

透明覆盖层不再作为用户选项或最终故障回退。窗口模式验证可用后，删除 Overlay 运行路径、控制中心选项和相关当前实现；历史设计与验证记录继续保留，不改写已经发生的事实。

方向控制提供两套可选键位：方向键或 WASD。它们不是全局快捷键。壁纸层模式只在 Explorer 桌面实际获得焦点时启用；普通窗口模式只在场景窗口自身获得焦点时启用。生效时仅独占当前方案的四个按键，其他按键不观察、不拦截、不记录。

本文件只定义产品行为、职责和验收边界。用户批准后另写实施细节文档；批准设计本身不授权编码、创建分支、提交或合并。

## 2. 当前问题

- P2D-006 当前自动按固定时间串联移动、接近岛、爬岛和下岛，位置采用短时间线性插值，实际观感是快速平移，不是自然走动。
- 自动演示不利于逐项调整跳跃、挤压、走动和落地，也无法让用户稳定复现某一个动作。
- 控制中心仍把 Overlay 和 WorkerW 表述为“实验宿主”，与现在选择 WorkerW 作为默认桌面承载方式的方向不一致。
- WorkerW 不拥有键盘焦点。若要在 Explorer 桌面获得焦点时控制团子，需要严格受限的桌面焦点输入桥；普通 WPF 键盘事件不足以覆盖该场景。
- 当前缺少一个不依赖 Explorer/WorkerW 的普通窗口入口，不利于调试、兼容性恢复和用户主动选择传统桌宠窗口体验。

## 3. 目标与非目标

### 3.1 目标

- 用户能够稳定、可重复地触发上、下、左、右动作，并逐项判断观感。
- 左右移动有加速和减速，不再出现匀速快速平移。
- 跳跃只能从可起跳表面发起；长按连续跳有落地和冷却约束，不出现二段跳或逐帧重复起跳。
- 向下只产生轻微身体挤压，不让团子穿入地面或改变权威位置。
- 桌面键盘控制只在明确焦点和设置同时满足时生效，且不采集普通键盘输入。
- WorkerW 成为默认宿主，普通窗口成为显式备选宿主；两者消费同一 Core 场景与表现契约。
- 控制中心只展示真实、可用、可确认的设置。

### 3.2 非目标

- 不加入平台跳跃关卡、冲刺、二段跳、蹲走、攻击或复杂连招。
- 不支持自定义任意键位；首版只在方向键与 WASD 两套固定方案间选择。
- 不注册系统全局快捷键，不在其他应用获得焦点时控制团子。
- 不记录按键历史、原始键盘流、输入文本、桌面文件、图标名称、窗口标题或窗口内容。
- 不在本设计中实现多人网络输入、客户端预测或服务端回滚。
- 不因为增加普通窗口模式而同时维护三套宿主；最终实现不再保留 Overlay。
- 不在本设计中确定完整自主行为调度。没有用户输入时先保持安静的 `Idle`，后续自主动作另行设计。

## 4. 控制语义

### 4.1 输入方案

| 语义 | 方向键方案 | WASD 方案 |
|---|---|---|
| 跳跃 | `↑` | `W` |
| 轻微挤压 | `↓` | `S` |
| 向左走 | `←` | `A` |
| 向右走 | `→` | `D` |

默认键位方案为方向键。控制中心提供独立的“键盘控制”开关，默认关闭，避免首次运行时意外占用 Explorer 的图标导航键；用户开启后选择方向键或 WASD。现有“允许与团子互动”是鼠标与总体交互总开关：它关闭时键盘控制即使已配置也不生效。

只有当前选中方案的四个键进入控制状态。方向键方案不得同时响应 WASD，WASD 方案也不得同时响应方向键。

### 4.2 上：跳跃与长按连续跳

- 首次按下只在团子处于 `Grounded` 或等价可起跳表面时创建一次跳跃意图。
- 空中再次按下被忽略，不排队为二段跳。
- 持续按住时，团子必须先完成下落并由 Core 明确确认落地；只有落地且起跳冷却已结束，才能再次起跳。
- 初始内部冷却候选为两次起跳至少间隔 `450 ms`。该值属于动作调参，不作为普通用户设置；人工验收后可在实施计划中调整。
- 释放按键立即取消“后续连续跳”意图，但不截断已经发生的本次跳跃。
- 切换焦点、宿主、键位方案或关闭交互时，必须清除按住状态，恢复焦点后要求新的按键事件。
- 起跳瞬间若只按住一个水平方向，则以当前最大地面速度作为固定水平起跳速度，形成向前抛物线；起跳后不允许空中转向。
- 起跳瞬间未按水平方向或同时按住左、右时原地跳。方向跳到达宿主边界时仍由 Core 夹紧，不能越界。

### 4.3 下：轻微挤压

- 只在落地或稳定站立时生效；空中按下不改变轨迹。
- 按下后身体在约 `120 ms` 内轻微降低并横向展开，建议首轮上限为高度减少约 `8%`、宽度增加约 `5%`。
- 权威碰撞底边和地面接触点不移动，不能通过挤压穿入地面。
- 松开后在约 `160 ms` 内平滑恢复，不附带起跳或明显反弹。
- 挤压是表现 cue，不是新的房间位置，也不由物理碰撞自行改变 Core 状态。

### 4.4 左右：走动

- 按下左或右后从静止逐步加速，松开后逐步减速，不使用瞬时匀速平移。
- 初始最大速度候选为 `55 DIPs/s`，约每秒移动三分之一个当前团子宽度；速度属于动作内部参数，不进入首版普通设置。
- 松开方向后由当前接触表面的摩擦系数决定减速度。默认地面的目标是从最大速度约 `160–220 ms` 内停稳，并通过有界的身体滞后/回弹表现出“踩住地面”，避免滑行观感。
- 摩擦属于可站立表面的领域属性，不写死为唯一地面常量。后续地板、地毯等家具可以提供不同系数；它们只改变 Core 的有界停止曲线和表现 cue，Box2D 接触仍不能反向决定权威位置。
- 同时按住左、右时目标速度为零，按减速规则停下，不选择“最后按下者获胜”。
- 只按住一个水平方向时更新面向；停止后保留最后面向，同时按住左、右不改变面向。Core 只输出目标面向；眼睛和帽子作为 Box2D 内的独立附件物体，通过阻尼关节连接身体节点并逐步响应转向，不使用表现层瞬移或整体镜像。
- 到达当前宿主安全边界时，Core 夹紧最终位置并清零朝边界方向的速度；物理表现无权把团子推出边界。
- 地面走动不自动触发爬岛。后续需要“走到岛边自动爬”时另行设计明确的环境动作规则。
- 手动控制期间禁止 P2D-006 当前自动时间线抢占；输入结束后回到 `Idle`，不立即补播被跳过的自动动作。

### 4.5 输入优先级

优先级从高到低为：宿主隐藏/退出、拖动、跳跃、挤压、左右走动、Idle。

- 拖动开始时清除键盘方向和连续跳状态；拖动结束仍走 `Falling → Core ConfirmLanding → Landing`。
- 空中忽略挤压和后续左右输入；方向跳只使用起跳瞬间锁定的水平速度，避免轨迹怪异。
- 点击反馈不得中断正在进行的跳跃或落地；稳定 Idle 时才能进入点击反馈。

### 4.6 拖动局部受力

鼠标开始实际拖动时，把按下位置映射为团子局部表现坐标，并在该位置建立 Box2D 弹性抓取支点。支点随鼠标移动，轮廓其余节点在受限重力和软体约束下产生轻微悬垂；点击位置不同，受力和形变也必须不同。目标形变保持克制：肉眼能看出提拉感，但不能拉成长条、翻转轮廓或突破既有面积、半径、速度和质心稳定上限。

局部支点只属于表现层，不改变 Core 记录的拖动偏移、权威位置、工作区边界、释放下落和落地裁定。松手、取消、失去捕获、隐藏或宿主失效时必须销毁支点并恢复原弹性，随后继续现有平滑回正与自然下落。

## 5. 焦点、独占与隐私

### 5.1 壁纸层模式

输入同时满足以下条件才生效：

1. 当前宿主为 WorkerW 且团子可见；
2. “允许与团子互动”和“键盘控制”均开启；
3. 前台焦点属于 Explorer 的桌面表面，而不是任务栏、开始菜单、文件管理器窗口或其他应用；
4. 当前按键属于选中的四键白名单。

WorkerW 自身不抢键盘焦点。实现需要桌面焦点输入桥，但不得注册全局快捷键。输入桥只在桌面焦点成立期间启用受限键盘钩子；回调先检查焦点与虚拟键白名单，其他键立即透传且不进入业务对象。

当控制键生效时吞掉该键，避免 Explorer 同时移动桌面图标选择。任何焦点判定失败都采用“桌面优先”：不控制团子、不吞键。

### 5.2 普通窗口模式

- 只使用窗口自身的预览键盘事件，不安装桌面输入桥。
- 场景窗口未激活、最小化或被关闭时不响应控制。
- 文本输入控件获得焦点时不截获控制键；首版场景窗口不放置文本编辑器。

### 5.3 数据最小化

- 内存中只维护四个控制键的按下状态、必要的单调时钟时间和归一化控制意图。
- 不保存按键时间线，不写日志，不导出按键次数，不把原始虚拟键发送到 Core 或未来服务端。
- 诊断最多显示“键盘控制开启/关闭、方案、焦点门禁是否满足、输入桥状态”，不得显示最近按键。

## 6. 宿主模式

### 6.1 壁纸层模式（默认）

- 应用首次启动和设置缺失/损坏时选择 WorkerW。
- 保留团子位于桌面图标之上/之下的现有对象层级能力。
- Explorer/WorkerW 失效时停止输入和物理调度、释放 native 世界并进入安全隐藏；不自动弹出普通窗口干扰用户。
- 控制中心显示安全错误，并提供“重试壁纸层”和“切换到窗口模式”。

### 6.2 普通窗口模式

- 使用标准可调整大小的 WPF 顶层窗口，有系统标题栏、最小化/最大化/关闭按钮和任务栏入口。
- 窗口不置顶，不透明或透明穿透，不伪装为桌面层；普通应用遮挡它是预期行为。
- 初始建议尺寸 `800×600`，最小 `480×360`；保存非敏感的窗口尺寸和位置，恢复时必须夹入当前显示器工作区。
- 窗口内部显示与 WorkerW 相同的团子、岛和后续家具场景，并复用同一 Core 动作状态、物理参数和渲染视觉。
- 切换宿主时暂停调度，取得单一权威快照，把团子中心按源宿主可用区域的归一化位置映射到目标宿主并夹紧，然后创建目标表现世界。不能复制第二只团子，也不补播切换期间的离线物理帧。
- 用户关闭场景窗口时只关闭桌面显示并保留托盘与控制中心，不自动切回 WorkerW，也不退出整个应用。

### 6.3 删除透明覆盖层

最终宿主枚举只保留 `Wallpaper` 与 `Window`。实施时遵循以下切换原则：

1. 先使普通窗口达到最低可用和生命周期门禁；
2. 再把默认值和设置迁移到 WorkerW；
3. 最后删除 Overlay 的运行代码、控制中心选项、当前测试和 fallback 分支；
4. 历史文档、旧验证记录和 Git 历史不删除。

旧设置若保存了 `Overlay`，升级后迁移为 `Wallpaper`；WorkerW 当时不可用则安全隐藏并提示选择窗口模式，不伪造迁移成功。

## 7. 控制中心调整

“桌面体验”页改为以下正式设置：

```text
显示模式
● 壁纸层（默认）
○ 普通窗口

允许与团子互动                         [开/关]

键盘控制                               [开/关]
仅在桌面或团子窗口获得焦点时生效
● 方向键：↑ ↓ ← →
○ WASD：W S A D

团子与桌面图标层级（仅壁纸层）
● 图标之下
○ 图标之上
```

- 删除“实验宿主”标题和透明覆盖层单选项。
- 普通窗口模式下隐藏或禁用桌面图标层级设置，并明确说明其只适用于壁纸层。
- 每次宿主或输入设置变更都先进入“正在应用”，由运行组件确认后才显示“已生效”；失败则恢复旧设置。
- 设置写入现有版本化本地设置文件，新增字段至少包括显示模式、键盘控制开关和键位方案。未知值回退到安全默认并显示非阻断提示。

## 8. 状态与职责边界

- **输入适配层**只产生 `Left/Right/Jump/Squash` 语义意图，不直接移动 WPF 元素或调用物理世界。
- **Core 动作控制器**验证地面状态、冷却、互斥和工作区边界，计算权威位置与动作开始时间。
- **动作采样层**把走动加减速、跳跃曲线和挤压时序转换为权威动作帧或表现 cue。
- **物理表现层**只消费 Core 输入，生成身体、眼睛和帽子的局部形变；不能产生权威 landed 事件。
- 两只眼睛分别作为独立附件，每只通过三条阻尼距离关节连接左右及顶部身体节点；正面眼距约 `38 px`，转向后约 `34 px`，眼睛尺寸不变。帽子附件通过两条带局部锚点的阻尼距离关节连接顶部相邻节点。转向改变附件关节的目标长度，Box2D 输出两个眼睛及帽子的位置和帽子旋转。
- 附件禁用碰撞且保持小质量，只能影响表现软体，不能改变 Core 权威位置、落地或边界结果。原生不可用时使用既有手工 fallback，不把 fallback 称为物理附件通过。
- **WorkerW/Window 宿主**只负责焦点门禁、调度生命周期、坐标映射和渲染表面。
- **控制中心**提交设置命令并显示确认状态，不直接安装键盘钩子、操作 HWND 或改写 Core 状态。

未来进入多人房间后，手动控制必须转换为经过服务端验证和限频的动作意图；不得逐帧上传键盘状态、物理节点或本地坐标。本阶段仍是单机原型，不能据此声称多人控制已完成。

## 9. 失败与恢复

- 焦点离开允许范围：立即清空全部按键状态，不产生一次额外移动或起跳。
- 键盘钩子安装失败：键盘控制显示为不可用，按键全部透传；鼠标和宿主继续可用。
- 设置切换中按键仍按住：先释放旧方案状态，再应用新方案；不得把 `D` 误解释为新方案的其他动作。
- WorkerW 丢失：停止输入桥、计时器和 native 世界，安全隐藏并允许切换普通窗口。
- 普通窗口关闭或最小化：停止不可见帧调度；恢复时从 Core 快照重新创建表现世界。
- 宿主切换失败：保持旧宿主；若旧宿主也不可用则安全隐藏，控制中心和托盘必须仍能退出。
- 设置文件损坏：默认壁纸层、键盘控制关闭、方向键方案；不猜测旧值。

## 10. 验收标准

### 10.1 自动门禁

- 非 Explorer 桌面焦点时，方向键和 WASD 都不产生控制意图，也不被吞掉。
- Explorer 桌面焦点成立时，只独占当前方案的四个键；方案外按键全部透传。
- 焦点丢失、宿主切换、隐藏和退出均清空按住状态并释放输入桥。
- 单击上键只起跳一次；空中再次按下不能起跳；长按只能在落地且冷却结束后再次起跳。
- 下键在地面产生有界挤压，底边不变；空中下键无效，松开后有界恢复。
- 左右移动具备加减速，同时按住左右会停下；跨边界后位置被 Core 夹紧。
- 手工输入期间不会运行自动动作时间线，停止输入后回到 Idle。
- WorkerW 与 Window 使用同一 Core 快照和表现帧契约；切换后不存在重复团子或重复物理世界。
- 默认模式为 WorkerW；旧 Overlay 设置可迁移；最终运行代码和控制中心不存在 Overlay 选项。
- 窗口位置跨 DPI、显示器移除和设置损坏后仍恢复到可见工作区。

### 10.2 真实 Windows 验收

1. 分别选择方向键和 WASD，确认只有选中方案有效。
2. 桌面获得焦点时可以控制；切到任意普通应用后立即失效且不残留移动。
3. 控制键生效时桌面图标不同时改变选择；方案外按键保持 Explorer 原行为。
4. 单跳、空中重复按键、长按连续跳、松开终止连续跳分别符合规则。
5. 下压轻微、不穿地、不触发跳跃，恢复不抖动。
6. 左右走动速度安静、起停自然、到边界不抖动或越界。
7. WorkerW 与普通窗口之间来回切换，团子唯一、位置合理、状态不重复、进程不崩溃。
8. 关闭普通窗口只隐藏场景；控制中心、托盘和退出仍可用。
9. 重启 Explorer 后壁纸层安全恢复；失败时可以主动切换窗口模式。
10. 在 100% 与当前高 DPI 环境验证键位、坐标、窗口恢复和团子可见性。

### 10.3 人工观感

- 跳跃有重量，连续跳不会像高频弹簧。
- 挤压幅度轻微可爱，不像被压扁或受伤。
- 左右移动能看出“走动”而不是图形平移，速度不会干扰桌面工作。
- 两种宿主中的颜色、轮廓、眼睛和帽子一致；继续保持无脚、无嘴、无腮红、无阴影和纯色风格。

## 11. 建议实施顺序与分支边界

当前 `feat/p1-004-box2d-soft-body` 含有尚未提交的 P2D-005/P2D-006 共同修改，并正在修改 Core 动作、WorkerW、控制中心相关路径。现在从旧 Phase 1 基线并行创建窗口模式分支，会重复修改同一批文件且无法安全取得最新动态轮廓，因此不建议并行或先做窗口模式。

设计获批后建议按以下顺序：

1. 先写独立实施细节文档，定义可失败测试、文件所有权、设置迁移和真实验收步骤。
2. 在当前 P2D-006 分支先完成方向控制，删除自动快速时间线并通过 WorkerW 人工验收。
3. 经用户另行授权后提交、集成到最新 Phase 1 基线。
4. 再从该基线创建 `feat/p1-006-window-mode-host-cutover` 独立分支，完成普通窗口、默认 WorkerW、Overlay 删除和恢复矩阵。

两项工作必须顺序集成；不得让两个执行者同时修改宿主协调器、控制中心设置或动作控制器。用户若明确决定改变集成顺序，需要先形成一个包含当前未提交成果的安全基线，不能从旧分支直接复制代码。

## 12. 待批准结论

批准本文表示同意以下设计方向：

- 用方向键/WASD 可选控制替代当前自动快速动作演示；
- 默认 WorkerW，另提供普通独立窗口，不再保留 Overlay 最终实现；
- 壁纸层输入严格受 Explorer 桌面焦点、交互开关和四键白名单约束；
- 跳跃有落地与 `450 ms` 起跳间隔，不允许二段跳；
- 下键仅轻微挤压，左右采用低速加减速走动；
- 先完成当前分支的方向控制，再顺序创建窗口模式宿主切换分支；
- 设计获批后仍先写实施细节文档，不直接开始编码。
