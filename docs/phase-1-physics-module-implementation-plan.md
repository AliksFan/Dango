## 3. 先行失败门禁

实现前必须看到以下门禁因缺失模块而失败：

1. native target 和完整模块 ABI 不存在时，加载测试失败。
2. 空世界添加两体、第三体超容量、移除后过期 ID、再添加新 ID、其他实体状态保留尚不能通过。
3. 重置、重复释放、多个世界、错误配置、错误 ABI、缺失库和非所属线程访问尚不能通过。
4. 对照 DLL 与模块在同配置、布局、固定步和动作序列下尚不能逐帧比较。

## 4. 预先固定的一致性判据

- native 逐帧比较使用每体既有 42 个浮点槽位：32 个局部轮廓坐标、核心、质心、有向面积、最大速度、接地、拖动节点、接触数和点数。
- 同一编译器、配置、初态和输入下要求所有槽位按位一致，允许最大绝对误差为 `0`；不能在发现差异后放宽。
- 场景覆盖一体/二体静置、左右运动、下压、地面跳跃、软体支撑跳跃、侧碰、头顶支撑、拖放、释放和重置。
- 显示适配继续使用 0.98 最大坐标归一化、160×120 尺寸契约、横向 72/80 与纵向 58/60 的现有映射及二次 B 样条；不改配色、骨架或帽子 Z 序。

## 5. 实施顺序与停止点

1. 把 self rig 的跨编译单元内部契约显式化，令正式 DLL 与新模块复用同一算法实现；重新构建并证明正式 DLL 源码路径回归。
2. 实现容量为 2 的 native 世界。删除实体必须实际销毁该 rig；不得通过重建世界丢失另一实体状态。容量溢出、无效/过期 ID 和错误输入明确失败。
3. 实现无 WPF 的 .NET 所有权封装和版本 1 默认配置，固定创建线程访问规则，释放幂等，释放后访问失败。
4. 实现显示适配并把 `Dango.JointReview --collision` 改为第一消费者；不接正式宿主。
5. 运行逐帧等价、生命周期、比例、支撑、抗推、轮廓、正反例、Release 构建、受影响测试和格式门禁。
6. 若任一冻结轨迹不一致、必须改变手感、需要三体求解或需要替换正式 DLL，立即停止实施并报告。
